## WHAT

Closed the .NET direct-recipe honesty gap found during agent-usefulness dogfooding. Parameterized MSTest and NUnit native identities now reuse the provider's native selector parser and filter-term builder, report `MatchingTests`, set `IsExact=false`, and explain that the method filter runs all data rows. MTP xUnit method filters now also report `MatchingTests` because they execute every theory row. Ordinary proven MSTest methods remain exact and configured exclusions remain composed into the filter.

## WHY

A recipe generated for one discovered MSTest data-row ID executed both rows sharing the fully-qualified method name while claiming `SingleTest` and `IsExact=true`. The command was valid, but its declared scope was false.

## HOW

Added focused MSTest/NUnit contract coverage using real native ID shapes, then used `GenericSelectorFromTestCaseId`, `GenericFilterTerm`, `GenericFilterProperty`, and the display marker to detect known parameterized selections. The generated filter follows the same method-level behavior as the runtime provider. The real VB MSTest Scale fixture runs the generated recipe, observes two passed Positive rows, and verifies the ordinary Adds case remains exact.

## IMPACT

Direct recipe output no longer overstates row-level precision for .NET parameterized tests. The change does not alter actual runtime selection semantics, configured commands, ordinary exact methods, or exclusion behavior. Root still owns the combined fast/Scale/build gate.
