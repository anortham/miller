## WHAT
Prepared Miller for julie-extract 2.41.1 without changing the download pin before public assets exist. Advanced the independently qualified family-store reader capability to 2.41.1, extended its compatibility matrix, corrected the native Java fixture to use a real single-segment package, and preserved a published 2.40.6 control binary plus epoch-upgrade artifacts.

## WHY
Fresh stores stamp the creator version as `min_reader_version`. A Miller build that only changed `PinnedJulieExtractVersion` would reject every fresh 2.41.1 family because `FamilyStoreReadSession.ReaderContractCapability` remained 2.40.6. The Java native fixture also used `package sample.exact` while the dogfood ledger claimed it proved the repaired single-segment `package sample` path.

- Native Java RED with published 2.40.6: single-segment package produced class/method without Namespace, so Miller's native binding was null.
- Native Java GREEN with certified source 2.41.1: one selected test passed and the unrelated failing class was excluded.
- Source-candidate all-language family read: `ReaderRetentionLanguageScaleTests.AdmittedSnapshotServesEveryProducerLanguageAndReleasesItsRegistration` passed 1/1 against a newly created 2.41.1 family.
