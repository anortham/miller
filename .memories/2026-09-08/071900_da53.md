## WHAT

Finished and verified JVM native source-identity mapping for CT across Java, Kotlin, and Scala. Candidate name discovery, complete candidate-file hydration, file evidence, and the post-load bound now execute through one `IWorkspaceReadSession.Read` callback and one deferred SQLite snapshot. The resolver binds exact package/class/nested-class/method identities, refuses ambiguity or stale evidence, and expands class-suite aliases only to extracted test bodies.

## WHY

Native Gradle/Maven/sbt reports do not reliably carry source paths. Without exact extraction-backed binding, source changes could return a false `KnownEmpty`. A real Java test also exposed a producer defect: single-segment `package sample;` was silently omitted because Java extraction accepted only `scoped_identifier` package nodes.

## HOW

Added real legacy and family-store adapter coverage, same-file parent-chain refusal, bounded candidate limits, and exact selection tests. Ran native Gradle/sbt fixtures with unrelated failing suites to prove narrow execution. Upstream `julie-extractors` now accepts both `identifier` and `scoped_identifier` package nodes with a focused RED/GREEN test and regenerated Java goldens. Qualified the current source binary through the explicit absolute `MILLER_TEST_JULIE_EXTRACT` test override; default runs still use the pinned 2.40.6 binary.

## IMPACT

Java, Kotlin, and Scala now have real extraction-to-selection-to-provider proof. Missing package facts still fail closed, while producer 2.41 supplies the previously absent single-segment Java namespace. Miller's checked-in Java Scale fixture remains compatible with pinned 2.40.6 through a dotted package, so root can run the normal full Scale gate without a hidden source-binary dependency. No pin, release, commit, or push was performed.
