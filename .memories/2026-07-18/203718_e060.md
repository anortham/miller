## Adopted julie-extract 2.16.0 (deferred HTTP client lane)

**WHAT:** Bumped the julie-extract pin from 2.15.0 to 2.16.0 and added live bridge coverage for the release's new `http.client_request.v1` client families.

**WHY:** julie-extractors v2.16.0 completes the deferred HTTP-client lane: Kotlin (OkHttp/Retrofit/Spring WebClient/RestTemplate), PHP (Symfony HttpClient/cURL/Guzzle request forms), Elixir (Tesla/HTTPoison/Finch/:httpc), and Rust (hyper/ureq). No schema, contract, or pattern-catalog change (still schema 4 / contract 3 / report 3; 194 pattern ids) — the two Blazor/Razor rows added to the sqlite-schema-v4 doc were doc catch-up, already emitted in 2.15.0.

**HOW:**
- `scripts/julie-pins.json` → 2.16.0 with fresh sha256s computed from the live GitHub release assets; `MillerExtractContract.PinnedJulieExtractVersion` + the two pin test assertions updated; binary restored and build guard green.
- **No consumer code change needed:** `StructuralRouteFactAdapter.TryReadClientRequest` and `BackendHttpBridgeProvider` are generic over the fact's `client` label — new clients bridge automatically.
- New Scale test `BackendHttpV2160Group_DeferredHttpClients_LiveBridges` in `LiveBridgeTraceTests`: same-language server/client pairs (Ktor↔OkHttp/Retrofit/Spring, Symfony↔Symfony-HttpClient/cURL, Phoenix↔Tesla/HTTPoison/:httpc, axum↔hyper/ureq) prove all 12 new client labels emit live and bridge High verb-known; group registered in the parity gate. New `StructuralClientLabels` helper reads `json_extract(metadata_json, '$.client')`.
- Docs synced: `trace-json-v1.md` backend-http section, `BackendHttpBridgeProvider` XML summary, `miller-bridge-trace` SKILL.md (mirror synced).

**IMPACT:** Bridge tracing now covers the major HTTP client libraries in all 12 client languages against 18 backend route families. Residual extractor silences (instance/field receivers, Tesla middleware base URLs, Elixir alias resolution) are recorded upstream as `open_gaps` in capabilities.json — nothing for Miller to consume yet.
