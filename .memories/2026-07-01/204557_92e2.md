## Cross-repo review of web structural facts + bridge trace (Miller + julie-extractors)

Read-only review of the last two days of htmx/vue/react/next/nuxt cross-border tracing work. No code changed.

### Miller-side findings
- **BUG (verified live): dynamic file routes never bridge.** `StructuralRouteFactAdapter.RoutePath` prefers `normalized_route_template` (`/users/:id`, emitted only when a route is dynamic) over `route_path` (`/users/[id]`), but `FileRouteMatcher` only recognizes `[param]`/`{param}`/`[...slug]`/`[[...slug]]` — never colon forms `:id`, `:slug*`, `:slug*?`. Verified with julie-extract 2.5.9 + `miller trace` on a fixture: `<Link href="/users/42">` → `app/users/[id]/page.tsx` yields "facts exist but no navigation edge was built". All Miller tests (unit + Live) use static routes only, so the suite is green while dynamic bridging is broken. Fix: prefer `route_path` for file-route facts and/or teach FileRouteMatcher colon templates; add dynamic-route tests.
- **Verb honesty tension:** vue/react/next/nuxt route references and file routes get assumed `verb=GET` via carrier synthesis (`vue.get` etc.), producing verb-KNOWN RouteVerbMatch High edges against ASP.NET endpoints — inconsistent with the "never assume GET" fetch doctrine.
- **dotnet-web over-consumption:** it treats next/nuxt file routes and all framework route refs as client calls to ASP.NET endpoints, so it reports "active" in pure frontend repos and creates duplicate TsType observation nodes (normalized vs raw path) alongside FileRouteBridgeProvider.
- **No vue/react navigation provider:** react/vue reference→definition NavigatesTo edges don't exist (only next/nuxt file-route providers), so pure SPA repos get no bridge.
- **Ambiguity policy:** two matching file routes → edge dropped instead of Next.js specificity precedence; matching computed twice (Resolve + CountAmbiguousMatches).
- **htmx `data-hx-*`:** unsupported on BOTH sides (extractor scan + Miller `HtmxVerb` switch).

### julie-extractors findings (subagent, verified against 2.5.9 binary)
4 HIGH: vue nested `<template>` slot truncation loses route refs; Next `@slot`/`(.)`intercepting segments leak into `route_path`; vue-router defs in plain .ts files never extracted; `find_enclosing_object_range` wrong-object bug when `meta:{...}` precedes `path`. MEDIUM: data-hx-*, nextjs.file_route false positives for React SPAs with `pages/`, vue children relative paths dropped, contract drift (`route_source`, `verb`, `target_path` vs `route_path`). Full report in the review conversation.
