## Fixed the three critical review findings in query-time resolution

**WHAT:** TDD fixes for the three Critical findings from the Phase 1 plan review, plus the relationship-target export drop that the same retired-SQL restoration required.

- `QueryTimeResolutionReader`: evidence and export surfaces now read `site_provenance`, `is_exact`, all six span columns, and `containing_symbol_id` from `reference_sites` (LEFT JOIN for identifiers/pendings with a HasSiteRow flag; inner JOIN for relationships), replacing the synthesized `'target_token'` literal, span-derived `is_exact`, and constant pending span columns. Rows without a site row are dropped from evidence/export (retired inner-join semantics) but still feed graph edges. Export relationship rows without a target `symbols` row are dropped, matching the retired export SQL.
- Legacy-artifact version keying: every `CAST(file_id AS INTEGER)` in `RevisionFactCacheLoader`, `IdentifierSiteReader`, and the reader's legacy arms now keys by `files.rowid`, so text `file-<hash>` ids no longer collapse multi-file artifacts to one slice. Legacy relationship reads use LEFT JOIN files (COALESCE rowid -1) so a missing language-projection row still serves evidence.
- Gates: `QueryTimeResolutionParity.SerializeExport` widened to the full documented column set; export column shape is now gated by the Scale parity tests.

**WHY:** The code-review pass on the Phase 1 range confirmed three contract violations: synthesized site facts (references-export-v2.md forbids), fabricated pending spans, and the legacy file-id cast collapse — three ticked acceptance criteria were untrue on real data.

**HOW:** TDD: fixtures gained divergent-site parameters (`siteProvenance`, `siteExact`, `siteSpanless`, site column overrides) and realistic `file-<hash>` ids; 7 tests watched red, then SQL fixes landed. `FamilyStoreReadSessionTests` store fixtures gained the `reference_sites` table real stores always have. Base-commit SQL (`git show 9161ce7c`) was the oracle for every restored join and column source, including inbound relationship/pending `containing_symbol_id` coming from the site row (which restores the EditService rename spanless-relationship refusal).
