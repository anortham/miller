## P0 Task 7 complete — embedding model benchmark → pin recommendation

Built `eval/model-bench/` (reproducible, sha256-pinned benchmark harness) and ran it end to end on macos-arm64. Produces the P0 model gate for Miller's semantic integration program.

### WHAT
- 24 scored arms: 6 Qwen3 lanes (256/512/1024 x f32/int8), 2 fallbacks x f32/int8, 2 BM25 baseline modes — each under two threshold policies.
- Corpus: 34,481 units (symbol cards from symbols.db + docs/config chunks from content.db) across the pinned miller + julie workspaces.
- Findings doc: docs/findings/2026-07-19-model-benchmark.md

### PIN
- Default: Qwen3-Embedding-0.6B, f16 weights, 1024 dims, int8 vector storage.
- Fallback: bge-small-en-v1.5, 384d, int8 — evidence-backed, both fallback lanes completed.

### KEY RESULTS
- Semantic beats lexical where predicted: prose recall 0.479 vs BM25 0.223 (2.1x); intent clusters 10/14 to 14/14.
- int8 vector storage is FREE — within 0.0002 nDCG of f32 at every dims lane.
- Identifier non-inferiority holds: every arm recall@10 = 1.0000, matching baseline. Pin loses only 0.0020 nDCG (ordering only).
- The design's favored 256d lane should CHANGE. 256d costs -9.6% recall and -22% relative worst-language nDCG. Recommending 1024d int8; 512d int8 as the storage-pressure compromise.

### TRAPS DISCOVERED (load-bearing for any future retrieval arm)
1. Golden-set self-retrieval: eval/retrieval-eval/sets/ lives inside the miller workspace and holds query text AND answer paths. Worse, the live miller index covers .claude/worktrees/, so unfiltered BM25 retrieved the harness's own SANITY_PAIRS literal as top hit. Identical exclusions (eval/, .razorback/, .claude/) must apply to EVERY arm — filtered 1,519 of 4,843 raw BM25 hits.
2. Prebuilt llama.cpp ships NO llama-embedding binary — it lives under examples/ and upstream release.yml sets -DLLAMA_BUILD_EXAMPLES=OFF. Must drive llama-server HTTP /v1/embeddings instead.
3. Wrong pooling fails SILENTLY and looks better: Qwen3 forced to cls gave HIGHER cosines (0.898 vs 0.601) but margin collapsed 0.449 to 0.056. Only a margin check catches it. Qwen3 needs last; BGE/Arctic need cls.
4. Short-context models (bge/arctic, 512 tok) get HTTP 400 on over-length input — llama-server rejects rather than truncating. Caller must fit the text.
5. Threshold policy is a confounder: a thresholded semantic arm emits ~1.5 docs/query, capping recall@10, while BM25 baseline is unthresholded top-10. Comparing those directly would understate every model. Ran both policies per lane.

### OPEN FOR P1
- No arm rejects a single negative query at default (FP 1.0 on all 24 arms). Sweep: floor 0.45 is strictly free (FP 1.0 to 0.667 at identical recall); full abstention needs 0.65 where recall drops below BM25. P1 blocker for any "semantic can decline to answer" claim.
- Qwen3 LOSES docs-like/markdown to BM25 and to both fallbacks. Suspected corpus chunk-window shape, not the encoder, but n=4 is too small to conclude.
- Initial-build throughput 52 units/sec puts a 500k-unit workspace at ~2.7 hours vs design's "minutes not hours".
- Neither fallback has a first-party GGUF; both are community conversions.
