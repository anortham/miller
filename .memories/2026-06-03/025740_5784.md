## Restart Dogfood Follow-up Fixes

### WHAT
- Fixed current display-ID prefix routing in `WorkspaceIndexProvider`: selectors like `miller-816` now resolve through the registry, detect they target the served workspace, and use the live current index without attempting a cross-workspace refresh.
- Added the missing `JulieSchemaGate.Verify` call to `ContentSearchProjectionLoader` before it reads the `files` table.
- Added regressions for both failures found during live dogfood after restarting onto `aa4e15f`.
- Updated the active Miller brief to record the follow-up findings and the current `julie-extract` v2.0.1 pin.

### WHY
Live dogfood found two product-level rough edges after the search UX cleanup: `workspace_id=miller-816` was treated as a registered target and returned `unconfirmed_lock_busy`, and cross-workspace content search against an old Julie-shaped DB leaked raw SQLite `no such column: content_hash` instead of the normal incompatible-artifact guidance.

### HOW
- `SelectorTargetsCurrent` now checks exact current aliases first, then resolves unique registry prefixes and recognizes rows whose workspace id or canonical root match the current served workspace.
- Content search projection now uses the same artifact compatibility gate as other DB readers, so legacy/corrupt DBs fail before column-specific SQL runs.
- Tests first reproduced both failures, then passed after implementation.

### IMPACT
The next restarted binary should preserve the cleaner display-ID selector UX for current workspace prefixes and provide actionable content-search errors for stale/incompatible registered DBs.
