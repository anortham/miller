## Phase 3 complete: content/docs search projection (search-projections design)

Finished the phase-3 work in `docs/plans/2026-06-02-search-projections-design.md`: a docs-like
**content search** projection + `search mode=content` (alias `docs`), independent of symbol search.

### What shipped (all TDD red→green, then adversarially reviewed)
- **Core** `Miller.Core.Search.ContentSearchIndex` — its OWN BM25 over full file text (K1=1.2, B=0.75,
  shared `CodeTokenizer`), best-matching-line + ±2-line snippet window. NOT a reuse of the symbol-coupled
  `MillerSearchIndex`. (+ `ContentDocument`, `ContentSearchHit`.)
- **Indexing** `ContentSearchProjectionLoader` — reads the v1 `files` manifest, keeps only docs-like
  (`ContentFileClassifier.IsDocsLike`: prose+config exts / markdown lang / under-docs-tree), `indexed`,
  in-size (≤1 MiB) files, re-sourced from disk and BLAKE3-verified. Skips (never errors) stale/missing/
  oversize/non-utf8/unreadable/out-of-scope. Extracted shared `WorkspaceRelativePath.ResolveUnderRoot`
  (§7 trust boundary) so `ExtractReader` and the loader can't drift. (+ `IContentSearchIndex`,
  `ContentSearchProjection`.)
- **Server** third provider cache on `WorkspaceIndexProvider` via `IWorkspaceContentSearchProvider`
  (revision/path-keyed, single-flight, generic eviction; current-workspace builds lazily keyed on holder
  revision; registered parity, no full/symbol load). `SearchTool mode=content` routes to it, renders
  `path:line` + indented snippet (compact) / `{file,line,score,snippet}` (json, never fake symbols);
  `exclude_tests` is a no-op for content. DI registers the 3rd interface as the same singleton.

### Adversarial review (Workflow, 6 dimensions × 2-verifier refute)
Result: **0 prod bugs**; 3 confirmed + 1 disputed, all LOW (doc + test-coverage gaps). All four closed:
- Agent-instructions inline mode enum now lists `content` + an `AgentInstructionsTests` anti-drift guard.
- Loader tests added: permission-denied skip (POSIX, root-probed), root-escape skip (mutation-verified to
  actually catch a defeated under-root check), and current-workspace revision-invalidation.

### Adjacent breakage fixed
`SearchTool`'s new content-provider ctor arg broke a live MCP scale test + an inspect DI test + 4
`new SearchTool(...)` sites; all updated. Test doubles (`RecordingWorkspaceIndexProvider`,
`HolderWorkspaceIndexProvider`) now implement `IWorkspaceContentSearchProvider`.
