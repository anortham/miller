## Search Dogfood UX Cleanup

### WHAT
- Added file-path-fragment search for `mode=file` and auto-routed path-like `mode=auto` queries to file search.
- Added registry selector resolution for display IDs, unique prefixes, full workspace IDs, `current`, and `primary` across read tools and workspace admin paths.
- Made compact read/workspace output favor display IDs and concise telemetry lines instead of raw SHA-256 workspace IDs, DB paths, and verbose status blocks.
- Updated embedded MCP instructions, README, milestone docs, and AGENTS/CLAUDE sync to point agents at display IDs.

### WHY
Dogfood showed Miller's search surface worked but was noisier than Julie: long raw workspace hashes polluted tool calls/results, compact workspace status/list output was token-heavy, and file mode behaved too much like symbol search instead of path lookup.

### HOW
- Introduced `WorkspaceRegistrySelector` and propagated display IDs through `WorkspaceFacts` and routing contexts.
- Extended `ISymbolLookupIndex` with `FindByFilePathFragment`, shared by the full index and symbol projection.
- Reworked compact banners/status/list rendering to omit roots from read-tool banners and to show one telemetry summary line.
- Strengthened fast and scale tests around selector aliases, ambiguity errors, compact output shape, file search, auto path routing, and live status rendering.

### IMPACT
Miller should now be easier to dogfood live: agents can use short display IDs or prefixes, search/file mode is useful for code paths, and compact outputs spend fewer tokens on implementation details while preserving JSON compatibility.
