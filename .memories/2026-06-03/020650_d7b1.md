## Reviewed and hardened Miller content search changes

### WHAT
- Reviewed Claude's Miller search implementation against the phase 3 content-search plan.
- Fixed `ContentSearchProjectionLoader` so the runtime enforces the 1 MiB cap from actual disk bytes, not only manifest metadata.
- Added regression and compatibility coverage for content projection loading, search tool output shapes, content-search ranking, and workspace search cache races.
- Aligned benchmark/TODO text with the implemented docs-scoped content search behavior.

### WHY
- The original content loader could index an oversized file if the manifest reported a stale small `content_bytes` value.
- Search output compatibility and concurrent projection cache behavior were high-risk areas after adding `mode=content`.
- Benchmark defaults and TODOs had drifted from the production content scope.

### HOW
- Added an actual `FileInfo.Length` guard before reading content bytes and a second post-read byte-length guard.
- Pinned exact compact and JSON output for search modes that must remain stable for MCP consumers.
- Added concurrency tests for shared content/symbol cache misses and stale in-flight loads losing to newer cache entries.
- Validated search quality/performance on local Miller plus large Hermes/OpenClaw v1 symbol DB artifacts.

### IMPACT
- `mode=content` is ready to dogfood on the new binary with the known quality caveat that broad one-word content queries are naturally generic, while targeted docs queries land in relevant plan/tool docs.
- The branch has a clean full fast+scale test gate immediately before commit.
