## Dashboard interactive-audit fixes: $root, popover hit-test, pattern padding, prune affordance

**WHAT:** Four dashboard fixes driven by a real-input Playwright audit (WebKit + Chromium):
1. `alpine-components.js`: every `this.$el` → `this.$root` (9 sites, both components). Inside an `x-on` handler, Alpine's `$el` is the DIRECTIVE's element (the sort button / filter input), so `applySort`/`applyFilter`/`reflectSortButtons` queried inside the button and silently no-oped — **workspace sort, workspace filter, and telemetry sort were dead on real user input in every browser**. `init()` masked it ($el == root there), so page load looked correct.
2. `dashboard.css`: `.ws-index-row:has(details[open]) { z-index: 3 }` — the remove popover hangs over the NEXT row, whose stretched-link `::after` won the hit-test and swallowed every click inside the popover (Confirm remove navigated to the row below instead). 
3. `.pattern-family-list` styled (was completely unstyled: browser-default numbering, zero padding, text to the panel edge) + empty/notice states padded.
4. `.panel-collapse-summary::before` disclosure caret (▸/▾) + stale copy "prune below" → "expand to prune" (the prune button was invisible behind an unmarked collapsed details).

**WHY:** User reported broken text/layout and "remove is broken"; called out sloppy verification. The branch's task-level verification exercised component methods synthetically (evaluate/direct calls) which masked both interaction bugs — synthetic dispatch bypasses hit-testing, and direct method calls resolve $el to the root.

**HOW (diagnosis chain worth remembering):** plain-listener trusted-vs-synthetic → capture-phase target logging (click target was a DIV, not the button) → `elementsFromPoint` at button center (next row's stretched anchor on top) → instrumented handler logging (`state changed, DOM didn't`) → `$el=BUTTON $root=SECTION`. **Lesson: UI verification must use real trusted input events and hit-testing (Playwright real clicks), not evaluate-driven synthetic dispatch.**

**Guards added:** `AlpineComponents_QueryTheComponentRootNotTheDirectiveElement` (bans `this.$el` in alpine-components.js), `WorkspaceRows_LiftAboveSiblingsWhileTheirRemovePopoverIsOpen` (pins the :has z-index rule).

**Verification:** 8/8 interactive checks PASS in BOTH WebKit and Chromium (popover open/cancel/confirm-hit-test, filter narrows + ignores remove copy, both sorts by real click, sort persists across live morph swap); popover persist-open across morph confirmed; fast suite 3589/3589 (25s); Release build 0W/0E. Playwright harness at scratchpad audit2.mjs; Chrome CDP at 9222.

**IMPACT:** Sort/filter/remove actually work for users now. These fixes must ship in the 1.11.0 release (pending). USABLE_WITH_WARNINGS question for AccessIQ answered separately: parse_diagnostics (razor 223 + sql 817 grammar gaps) + indexer_leader_unknown (benign, no live leader session).
