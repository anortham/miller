## Fixed dashboard stale-asset caching (post-merge defect)

**WHAT:** Dashboard static assets now carry a per-build `?v=<sanitized MillerVersion>` query (`DashboardFormat.Asset`, used by `DashboardHead.razor`/`DashboardScripts.razor`) and are served with `Cache-Control: no-cache` (`DashboardHostPipeline.StaticAsset` now takes HttpContext). Two new tests: `StaticAsset_RevalidatesInsteadOfHeuristicCaching` (no-cache + If-Modified-Since → 304, which `Results.File` handles natively) and `AssetReferences_CarryTheBuildVersionQuery`.

**WHY:** User's browser rendered the new dashboard markup with the OLD binary's cached `dashboard.css` — broken layout (clipped "5h ago", misplaced state chips, giant rows). Root cause: assets served with only Last-Modified (no Cache-Control → heuristic caching) at unversioned URLs, so every binary upgrade pairs stale CSS/JS with new markup.

**HOW:** Version query changes the cache key each build (fixes the user's browser with no manual hard refresh); no-cache makes bare-URL assets (fonts referenced from CSS) revalidate. Rejected: fingerprinted filenames (overkill for a local dashboard) and MapStaticAssets (Razor-integration churn).

**IMPACT:** Every future dashboard upgrade renders with matching assets. 3587/3587 fast suite, 0-warning Release build.
