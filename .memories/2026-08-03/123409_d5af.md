## julie-extractors v2.22.0 released; Miller W4/W5/W6 wired

User approved the release 2026-08-03 ("release julie-extractors, get to work") and
asked for a local merge to main so sibling worktrees see it.

### julie-extractors (main @ 5fb4a6b, tag v2.22.0 pushed)

- Merged `fleet-safety-flags` (`--spool-dir`, `--progress-file`, `--parent-pid`) to main.
- **Closed the Windows hard-link hole** (was task #13, framed as "documented limit vs new
  dependency"). It was never a new dependency: `same-file 1.0.6` was already in
  `Cargo.lock` via `ignore` → `walkdir`. `is_one_file` is now one cross-platform function;
  the `#[cfg]` split and both contract-doc limit paragraphs are gone. Decision 8a.
- **Cross-model adversarial review** (Codex gpt-5.1-codex-max + Grok grok-4.5, independent):
  12 findings. The three both models hit independently were the three that were real.
  - **Progress file was truncated BEFORE identity was proven** (critical, both). Guard-path →
    `File::create` (truncates) → guard-path again. Fixed: open without truncating, prove on the
    handle with `Handle::from_file`, then `set_len(0)`. Decision 8b.
  - **Reaper released the sentinel lock before unlinking** (high, both). `claim_sentinel` now
    returns the locked handle and the claim outlives the unlink. Decision 11a.
  - `cli.md` self-contradiction on Windows identity (leftover from my own earlier fix).
  - **Refuted**: "report codes need a schema bump" (Codex 0.98). `ReportCode` is a closed Rust
    enum internally but serializes to a string, and Miller parses `code` as a plain string with
    no allow-list. Grok reached the correct conclusion at 0.72.
  - Full triage: `docs/reviews/2026-08-03-fleet-safety-flags-cross-model-review.md`.
- All 7 CI gates green on rustc **1.97.1** (rustup's local `stable` is 1.94, below the 1.95 floor —
  use `+1.97.1` locally; CI uses `dtolnay/rust-toolchain@stable`).

### Miller (fleet-safety @ 737f53ef)

- `ExtractSupervisionPolicy` resolves the three flags from the **artifact's directory**, so a
  full rebuild into `symbols.db.rebuild` and a cross-workspace refresh supervise correctly.
- `ProgressStamp` SUMS the heartbeat length with artifact bytes + output lines (does not replace
  them), so a dead progress file degrades to the pre-2.22.0 signal, not to nothing.
- `WindowsBrokerJob` → `WindowsKillOnCloseJob`, moved to `Miller.Indexing`; every julie-extract
  spawn is attached (Windows half of W6, since `--parent-pid` is Unix-only).
- **Deviations from the plan, deliberate**: `.miller/spool` not `.miller/tmp`; the progress file
  is a SIBLING of the spool dir (a file inside it fires `spool_dir_excluded` on every scan
  forever); a FIXED `scan.progress` not a nonce (the v1 contract is written for that shape, it
  leaks nothing, and it is a post-mortem); Miller does NOT delete the child's spool (that would be
  the pid-probe design julie rejected).
