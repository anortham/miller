## W9 — linked-worktree HEAD watch + root disappearance/replacement, and the Scale gate de-flaked

**WHAT.** Two deliverables plus the pre-existing Scale-gate flake, all on `f35c3d51`.

**W9 D1 — the HEAD watcher never attached in a worktree.** `IndexerWatcherSet` did
`Directory.Exists(Path.Combine(root, ".git"))`. A `git worktree add` checkout has a `.git` **FILE** holding
`gitdir: <path>`, so that test is false in EVERY worktree — the dedicated HEAD watch was silently absent fleet-wide,
and each branch switch flooded the 64 KiB watcher buffer, overflowed, and forced a rescan storm instead of the ONE
reconcile the watch exists to produce. Now resolved through `GitWorktreeLayout` (no git subprocess), watching
`GitDir` and never `CommonDir` — a linked worktree has its own HEAD; the shared one reports the MAIN checkout's
switches.

**W9 D2 — path reuse served the wrong tree.** `workspace_id` is SHA-256 of the canonical root, so
`git worktree remove wt && git worktree add wt other-branch` produces the same id, the same registry row, and an
artifact whose `root_path` still matches. New `WorkspaceRootIdentity` (git admin dir + creation time) and
`WorkspaceRootPresenceMonitor` (Present/Disappeared/Absent/Restored/Replaced): a disappearance detaches watchers,
marks the row missing, and SUSPENDS the tick (a delta against an absent root deletes every file in the artifact);
a return with a different identity releases leadership and re-bootstraps at `RootRebind` — an existing intent
that already means "the artifact describes another tree", folded in via `ScanIntentPolicy.Strongest` rather than
decided in parallel.

**HOW — what I found that the 3 review lenses did not.** Identity is compared only across a disappearance (right
call: comparing every tick reads an ordinary branch switch as a new checkout on any filesystem without a birth
time). But the "re-sample while unknown" branch was UNBOUNDED, and a non-git workspace — a fully supported case,
Miller indexes any directory — is `IsKnown: false` **permanently**. Probed it directly: `Capture` on a plain
directory returns `Unknown`. So every non-git workspace ran a `GitWorktreeLayout.Resolve` on the 250 ms debounce
tick forever, against a root that may be a network mount, to learn nothing. Bounded to 8 attempts (covers the real
transient — a `git worktree add` still writing its admin dir — which settles sub-second). Mutation-proven: without
the bound, 401 probes over 400 polls.

**Confirmed review finding (1 of 8 raised).** `EscalateForReplacedRoot`'s hardcoded `Ready` had ZERO coverage —
the verifier ran the whole 5704-test fast suite with the mutant and nothing died. The branch IS production-reachable
(the loser path where `WinnerArtifactProbe` says usable). Fixed by asserting on the test that already builds a
`LoadedExisting` decision and never checked it.

**De-flake (task #14).** Two distinct races, both test-side, no production change. The killed-holder test now
ARRANGES the admission window (takes the target's `content.lock` so the spawned scan parks inside its own
admission) instead of hoping a 40-file scan is slow enough. The second was not the governor at all:
`Process.WaitForExit(int)` returns without joining async output handlers, so under ThreadPool starvation the
captured buffer is empty and `JsonDocument.Parse("")` throws — reproduced with a starvation harness (an externally
busy CPU does NOT reproduce it, 0/40).

**IMPACT.** W9 was the last implementation workstream. Remaining: W10 (74k-file scale repro), the final
cross-model review, and the two approval-blocked items (julie release + pin bump; the Windows hard-link policy
call).
