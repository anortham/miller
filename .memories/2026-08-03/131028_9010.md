## Cross-model review of the supervision wiring: 2 findings fixed, 1 consequence refuted

Reviewed `2d5440bf..HEAD` (16 files) with Codex `gpt-5.1-codex-max` and Grok
`grok-4.5` independently, same five named attack surfaces.

- **Grok: approve, 0 findings** — 25.5k reasoning tokens, enumerated what it
  attacked per surface, and independently classified the Windows job object as a
  documented platform gap rather than a defect. Substantiated, not a rubber stamp.
- **Codex: needs-attention, 2 medium.** Could NOT run tests — its read-only
  sandbox blocked MSBuild's temp dir — so both were static-analysis claims that
  the lead verified in code before accepting.

### Fixed 1 — Windows containment failed silently (convergent: Codex 0.97 + lead)
`Run` kept only `.Job` from `WindowsKillOnCloseJob.Attach` and threw away
`FailureReason`. A failed `AssignProcessToJobObject` meant the scan ran
**uncontained and unannounced** on the one platform where nothing else covers it
(`--parent-pid` is Unix-only) — exactly the failure the change exists to prevent.

`JulieExtractRunner` now takes an optional `Action<string>` sink, matching the
pattern `RepositoryIndexLoader` already documents (Miller.Indexing is logger-free
by design; the caller holding an ILogger supplies the sink). Wired in
`IndexerService` + `IndexBootstrapService`. An internal ctor makes the attach
function injectable so a test can force a failure unreachable off Windows.
CLI/dashboard runners stay unwired — a deliberate stopping point, recorded.

### Fixed 2 — unterminated tail consumed as a record (Codex 0.99, non-convergent)
Contract v1: "A trailing line without a terminating newline is an incomplete
tail. Parsers must drop it." `LastIn` parsed the final split segment anyway.

**Codex's stated consequence is wrong and the record says so.** Any strict prefix
of a JSON object fails to parse, so the only unterminated tail that parses is one
whose object was written whole — its counters are genuine, and dropping it
reports *staler* data. Miller also reads the file only after the child is dead.
Fixed anyway for the reason that holds: Miller consumes a written contract, and
surfacing live scan progress in `workspace status` would inherit a wrong parser.
