## Routed CLI search and summary inspect through symbol projections

- **WHAT:** Changed the one-shot CLI read path so `miller search` and non-full `miller inspect` use a symbol lookup index instead of always loading the full repository graph. Added CLI regression tests that drop the `relationships` table to prove those commands do not need full graph hydration. Updated TODO and read-path dogfood docs with the new large-repo evidence.
- **WHY:** OpenClaw dogfood after the search-quality slice showed CLI symbol search, scoped symbol search, summary inspect, and context all paying about 6.5s because `CliDispatch` still called `RepositoryIndexLoader.Load` for lightweight reads. The MCP registered-workspace path was already projection-specific, so this was a CLI routing gap.
- **HOW:** Added `TryLoadSymbolSearchIndex` in `CliDispatch`: it opens a revision-fresh `search.db` sidecar when available and falls back to `SymbolSearchProjectionLoader`. `search` now calls `SearchTool.Run` over `ISymbolLookupIndex`; summary `inspect` calls `InspectTool.RunSummary`; full `inspect`, `context`, `impact`, and `trace` stay on `RepositoryIndexLoader`.
- **IMPACT:** OpenClaw Release CLI dogfood improved `miller search "workspace status"` from `real=6.55s` to `real=1.88s`, scoped symbol search from `6.53s` to `1.91s`, and summary inspect from `6.57s` to `1.75s`. Full inspect/context remain intentionally full-path around `6.6s`, which is documented as post-beta work only if one-shot graph-heavy workflows need lower latency.
