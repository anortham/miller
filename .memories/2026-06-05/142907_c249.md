## Implemented root miller.json bridge provider selection

- **WHAT:** Added root `miller.json` bridge provider selection to the production repository index load path.
- **WHY:** Bridge support is provider-scoped evidence, so committed project config needs to be able to explicitly select or disable providers instead of Miller always assuming the current dotnet-web model.
- **HOW:** Added `BridgeProviderSelection` in `Miller.Indexing` to discover `<root>/miller.json` from `<root>/.miller/symbols.db`, parse `bridge.providers`, map `dotnet-web` to `DotnetWebBridgeProvider`, and represent unknown providers as skipped capability entries. `RepositoryIndexLoader.Load` now threads selected providers into `BridgeGraphBuilder.Build`.
- **IMPACT:** No config preserves the current default behavior; explicit `["dotnet-web"]` builds the bridge; explicit `[]` disables bridge providers; unknown provider IDs do not silently run dotnet-web and instead surface as skipped providers.
