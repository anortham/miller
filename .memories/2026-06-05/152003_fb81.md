## Improved dotnet-web bridge trace ergonomics

- **WHAT:** Added symbol-backed client-call bridge starts and C# server-type filtering for dotnet-web DTO/entity resolution.
- **WHY:** MyraNext dogfood showed `trace bridge` worked from controller actions but not from frontend API functions, and generated TypeScript symbols made C# `AppSetting` / `ApplicationUser` resolution ambiguous.
- **HOW:** `RouteBridge` now uses a URL literal's `containing_symbol_id` as the `Hits` source node when present, falling back to the route node only when no containing symbol exists. `DotnetWebBridgeProvider` now builds a provider-local resolver filtered to C# user type symbols for route DTO, CreateMap, and DbSet/entity legs.
- **IMPACT:** Agents can start bridge traces from frontend service functions for captured client-call literals, and C# DTO/entity/table chains no longer get dropped because generated TS interfaces/imports/exports share names.
