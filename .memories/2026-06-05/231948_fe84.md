## Implemented dashboard single-instance launcher

### WHAT

Completed the beta dashboard slice by adding a `miller dashboard` CLI command that starts or reuses one loopback dashboard instance and opens the current workspace selector URL.

### WHY

Multiple Miller sessions across workspaces should not each spawn their own dashboard. Beta testers need a minimally functional operational view without managing a separate dashboard process manually.

### HOW

- Added `DashboardCliLauncher` with health probing, launch locking, metadata reuse, stale pid-file handling, and current-workspace URL selection.
- On Unix/macOS, launches the dashboard through a small Python helper using `start_new_session=True` so the child survives CLI process exit; on Windows, uses the native process group flag.
- Added `/healthz` to the dashboard host.
- Updated CLI dispatch/tests for `dashboard`, `--port`, `--json`, launch failure handling, stale pid cleanup, and metadata-based single-instance reuse.
- Updated README, TODO, beta checklist, and dogfood evidence.

### IMPACT

Dashboard minimum functionality is now beta-usable: the UI shows registered workspaces and telemetry, avoids full-index hydration, and can be opened from any Miller session through a stable CLI command.
