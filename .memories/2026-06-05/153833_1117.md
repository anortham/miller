## Closed cross-workspace selector dogfood

- **WHAT:** Validated cross-workspace Miller usage from the Miller checkout and fixed the rough edge where `workspace_id` rejected an exact registered root path.
- **WHY:** Agents often receive a repo path from the user, not a Miller display ID. For beta ergonomics, they should be able to route `search`, `inspect`, `context`, `impact`, and `trace` to another registered workspace without translating path -> display ID first.
- **HOW:** Added failing registry selector tests for canonical root path and trailing separator selectors, then updated `WorkspaceRegistrySelector` to match absolute registered root paths using the existing workspace path-safety comparison. Updated MCP parameter descriptions, embedded agent instructions, `TODO.md`, and added `docs/findings/2026-06-05-cross-workspace-selector-dogfood.md` with evidence.
- **IMPACT:** Cross-workspace querying remains viable for beta. Display ID selectors already worked; registered absolute root paths now work after rebuild/restart. First-read latency remains tracked separately under projection-specific read-path work.
