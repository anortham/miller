## Added dashboard telemetry health context

### WHAT

Extended the dashboard telemetry view so historical development errors no longer look like active tool failures.

### WHY

The aggregate `Errors` count was accurate but misleading: old search failures from development were still visible and could be mistaken for a current search problem.

### HOW

- Added per-tool `last_call_ts`, `last_outcome`, `last_error_ts`, and `last_error_kind` to `DashboardToolStat`.
- Added `recent_errors` to `DashboardTelemetrySummary`, sourced from the same `tool_telemetry` table without hydrating indexes.
- Updated the telemetry panel to render `Last call`, `Last error`, and a compact `Recent errors` list.
- Updated dashboard tests, JSON contract assertions, TODO, beta checklist, and dogfood evidence.
- Dogfooded against the live Miller workspace: `search` shows 27 historical errors, last call `ok` at `2026-06-05T23:25:41.655Z`, last error at `2026-06-05T20:44:49.700Z`.

### IMPACT

Beta testers can now distinguish current health from old development failures directly in the dashboard instead of querying the raw telemetry DB.
