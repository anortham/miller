## Implemented source-region search on julie-extract 2.1.1

### WHAT
- Bumped Miller's pinned `julie-extract` contract to v2.1.1 with verified release digests.
- Added schema-v3 `search.db` region tables (`regions_fts`, `search_regions`) populated when `MILLER_REGION_INDEX=1`.
- Added source-region readers, fail-closed `FtsRegionSearchIndex`, workspace region provider, `search regions=...` MCP routing, CLI `--regions`, and `has_doc` symbol annotations from `symbols.doc_comment`.
- Added fast and Scale tests, renamed the fixture schema guard to `JulieDbFixtureV2SchemaTests`, and updated docs/TODO/agent instructions.

### WHY
`julie-extractors` 2.1.1 now emits all-language `source_regions`, clearing the 2.1.0 JavaScript-only blocker. Miller needed to consume comments/doc-comments/string literals without widening symbol search or reusing docs/content search incorrectly.

### HOW
- Kept symbol/content/region as separate read models.
- Built region text from verified workspace file bytes under the writer lock, using BLAKE3 freshness checks and strict UTF-8 spans.
- Kept region search explicit and fail-closed, with no symbol/content fallback.
- Reused Miller's C# BM25 ranking over FTS5 recall candidates.

### IMPACT
- `search "TODO" regions=comment` and `miller search TODO --regions comment` can now find text only inside comments.
- String-literal search works via `regions=string_literal`.
- Symbol results can show `has_doc` without indexing docs into symbol BM25.
- Active follow-up is dogfooding opt-in region search before deciding default-on, `embedded`, trigram recall, or exclusion queries.
