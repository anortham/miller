## Added trace disambiguation for bridge/search quality

- **WHAT:** Added `scope=<file>` support to `trace`, taught bridge trace to choose the single bridge-connected candidate from duplicate symbol rows, updated CLI/MCP guidance, and recorded the result in TODO plus the Julie-vs-Miller search-quality matrix.
- **WHY:** MyraNext dogfood showed useful bridge evidence but agents could need a second JSON query to disambiguate function/export/import duplicates. That hurts token efficiency and first-query success.
- **HOW:** Threaded optional `scope` through `TraceTool.Trace` and `TraceTool.Run`, reused `SmartTargetResolver.Resolve(target, scope)`, and added bridge-specific candidate filtering when exactly one ambiguous candidate has bridge edges. Updated CLI help, embedded Miller agent instructions, and the project-local bridge-trace skill.
- **IMPACT:** `miller trace getAllSecurityUsers --mode bridge` now resolves the MyraNext route edge directly, and `--scope` is available when ambiguity remains. This moves Miller closer to Julie-style small, decisive result sets without embeddings.
