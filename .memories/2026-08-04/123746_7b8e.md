## v1.16.0 levels dogfood complete — full timing matrix + 5 findings

Finished the progressive-levels benchmark across 8 repos and exercised all nine MCP tools
plus the CLI equivalents on Miller 1.16.0+98b63273.

Artifact at symbols level is 1.9-2.7x smaller. **Live in-place `miller workspace full` on
this repo: 18.3s CLI-side**, then the resident leader reconverged search.db/vectors.

The upgrade rebuild costs the same as a blocking full (guava 40.5 vs 40.2; samples 21.6 vs
21.4) — the symbols pass is pure additive overhead, so the trade is "2.3-3.3x faster to
first usable, ~33-45% more total indexing work."

### Findings
1. **CLI bypasses the converging diagnostics for `patterns` and `search --regions`.** The
   guard lives inside `PatternsTool.Patterns` (the `[McpServerTool]` method, guard at
   PatternsTool.cs:130); the CLI verb calls `PatternsTool.Run` (CliDispatch.cs:1184)
   directly and skips it. Same shape in SearchTool (guard at 337/587 inside the MCP
   `Search`). MCP correctly emits `reference_layer_converging`; CLI prints bare
   "No patterns." / "No results." CLI `trace`/`impact` are fine (own guards at
   CliDispatch 2225/2333/2356/2399). Matters because the CLI is the documented Eros contract.
2. **Validation errors logged as `error_category=internal_failure`** (bad marker list,
   ambiguous workspace selector) when `bad_input` / `unknown_workspace` already exist.
3. **`inspect` on a nonexistent path reports "No indexed symbols in \<path\>"** — reads as
   "file has no symbols" rather than "no such file".
4. **`SidecarStagingReaper` is build-triggered only**, so a workspace whose builds keep
   failing never reaps: 1.18 GB orphaned in `~/.hermes/hermes-agent/.miller`.
5. **`mode=markers` reinterprets `query` as the marker list**, undocumented in the MCP description.
