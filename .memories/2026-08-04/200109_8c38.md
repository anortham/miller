## Rebind program plan reassessed against post-levels reality (Codex + Grok + lead audit)

**WHAT:** Revisited `docs/plans/2026-08-02-worktree-delta-rebind-program.md` (skipped while fleet-safety and progressive levels were implemented). Wrote `docs/findings/2026-08-04-worktree-rebind-plan-reassessment.md` recording the full reassessment; plan document itself NOT yet amended.

**WHY:** User asked to revisit the plan; the world moved underneath it — fleet-safety W1–W10 merged (start gate met), julie-extract 2.23.1/2.24.0/2.25.0 fixed the four P0-gating bugs and cut dotnet/runtime full scan 76.3→23.7 min, and the plan's own "candidate follow-on" (levels) shipped in v1.16.0/v1.16.1 with symbols first-open at 3.9 min.

**HOW:** Lead repo audit + independent read-only Codex and Grok reviews (same prompt, both investigated the repo). Both converged: do not execute as written. Key verified findings: W10 74k fixture harness was never committed; registry has `level_policy` but no lineage columns; `ScanIntent.RootRebind` must NOT be reused for rebind (it means foreign-root repair); rebound artifacts inherit the immutable `index_level` so the P1 contract needs a level eligibility matrix; clone economics (20 GiB full copy × N on non-CoW filesystems) is the go/no-go measurement; P4's ≥10× bar must re-base on 2.25.0 matched-level baselines.

**Converged recommendation:** narrow v1 to full-source→full-target CoW clone + rebind + delta (~3–5 sessions), gated on a thin 2.25.0 measurement pass (clone cost per platform + re-based denominator); or defer with a telemetry trigger.

**IMPACT:** Plan is now safely revisitable; three user options recorded in the findings doc (narrow+proceed / defer with trigger / amend only).
