## De-flaked ColdLoadHolderDeath + recalibrated ubuntu CI budget

Second CI round after the teardown reorder: the original health-silence test now PASSES, but two new failures appeared.

- **ColdLoadHolderDeath (windows-fast, Expected 1 owner / Actual 2):** pre-existing race, not a regression. `Snapshot.IsOwner` means "my candidate process is alive"; while unconnected, each factory re-spawns an election candidate every ~20ms poll tick, and losers (exclusive lock file refused) exit on their own. A factory's FINAL loser candidate can still be mid-exit when handshakes complete, so a one-instant owner count can read 2. The file lock guarantees only one broker ever serves — owner count is eventually consistent. Fix: assert with the class's existing `WaitUntilAsync` (settles to 1 within 5s) instead of a single sample. My teardown reorder exposed it by removing the ~1s Windows stall in the crash-retry path that used to give losers time to die first.
- **build-test 58s > 45s ceiling:** local interleaved A/B (HEAD vs HEAD~1, two rounds: 21/18s vs 21/22s) proved the reorder adds nothing; hosted-Ubuntu wall time spans 30-58s across identical suites (runner variance). Raised FAST_BUDGET_SECONDS 45 → 90 with measured evidence in the comment, mirroring the Windows job's earlier measured recalibration (720s).
- **Impact:** last two red CI causes addressed; local fast suite green 5,842 passed, ColdLoad 3/3.
