## Bound live evaluation rows to the binary's policy capability

The first fail-loud implementation stamped a Python `POLICY_VERSION = 2`, duplicating the production source in `SemanticQueryPolicy`.

- **Change:** `run-live-arm.py` now invokes `miller capabilities --json` before semantic preflight or query loading, requires exact integer `semantic.query_policy_version: 2`, and stamps the returned integer on result and latency rows.
- **Failure behavior:** Missing, wrong, string, malformed, timed-out, or nonzero capability responses abort before `read_queries`.
- **Lexical behavior:** Lexical runs validate the capability but still skip semantic preflight and keep semantic work disabled.
- **Privacy:** Capability validation and semantic preflight both precede sealed query loading.
- **Compatibility:** The generic retrieval scorer remains unchanged and accepts minimal third-party result rows.
- **Impact:** The binary is the single output source for policy-version evidence; a stale or mismatched runner/binary pair cannot emit drifted rows.
