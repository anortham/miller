## QML continuous-testing Task 4 correction

### WHAT

Closed the inline-review gap in unscoped QML project fallback and added the missing Task 4 report plus acceptance ticks.

### WHY

The first implementation rejected every unscoped QML fallback whenever more than one QuickTest project existed, so a changed file in project A could not select A while project B was also indexed.

### HOW

- Kept an explicit `request.ProjectPath` authoritative.
- Changed unscoped scope evaluation to test each case's own project root or evidence root against the changed path.
- Refused cases with neither root, preserving fail-closed behavior and avoiding global fallback.
- Added a two-project regression that changes project A and asserts only A's target is selected.
- Added `.razorback/sdd/2026-08-24-qml-continuous-testing-implementation-plan/task-4-report.md` and ticked all Task 4 acceptance boxes.

### IMPACT

Multi-project QML workspaces now select the affected QuickTest project at target granularity without leaking to unrelated projects. The correction is ready for lead reconciliation.
