## Task 8 regression isolated

### WHAT
Reproduced the Task 8 regression on the fixed workload: one warm-up plus three sequential warm runs, workspace `/home/murphy/source/miller`, current release binary versus the pre-change graph binary. Current output hashes are stable and match the baseline, but current timing is ~1.82s Context / ~5.0s Impact versus baseline ~1.55s / ~3.55s.

### WHY
The acceptance requires both graph tools to beat the pre-change binary; the first batching implementation was not accepted, so each complementary optimization needed an independent toggle.

### HOW
Controlled variants in temporary env-gated source changes showed: disabling complementary scratch reuse worsens to ~1.88s / ~5.69s; disabling identifier-detail batching is near current (~1.76s / ~4.99s); disabling bounded prefetch worsens to ~2.49s / ~7.41s. Restoring the old point-slice loader for `EnsureSlice` while keeping scratch, detail batching, and prefetch yields ~1.76s / ~3.22s. Disabling prefetch plus the old point loader yields ~1.40s / ~2.48s. SQLite EXPLAIN plans for point versus `IN` symbol/type/identifier/relationship reads use the same indexes; the material cost is the new filtered `LoadStoreSlices` path used for per-version lazy misses, which replaces the old specialized point loader and performs broad propagation batch reads. The current `ReadRelationships(candidateIds)` and batched graph work are beneficial.

### IMPACT
Root cause is identified: keep `PrefetchSlices` batch loading for the frontier, but restore `EnsureSlice` to the existing `LoadStoreSlice` point path. The temporary env toggles are uncommitted and must be removed before the final fix. Next: add a deterministic guard for the point loader path, implement one fix, focused-test it, then measure at least three identical warm runs with matching output hashes.
