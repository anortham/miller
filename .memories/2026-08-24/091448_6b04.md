## Task 6 round 1 fixes

### WHAT
Fixed both review findings in the Task 6 cache janitor: machine-eligible roots now hold an exclusive operation lease from snapshot through candidate selection and every `_reap` call, and detailed reap results now carry the actual remaining path after rename/delete failure.

### WHY
The previous machine sweep released its root probe before deleting, allowing a provider to acquire the root between snapshot and prune. Delete failures also persisted the original cache path after it had been renamed to a `.reap-*` remnant.

### HOW
- Added nonblocking existing-marker acquisition to `CtBuildRootOperationLease`; `ReadMachineRoot` returns a held lease only for complete eligible roots, while current/locked/recent/ambiguous roots remain fail-closed. `EnforceMachine` disposes all held leases in a `finally` block after candidate deletion/reporting.
- Changed `TryReapDetailed` to return `CtReapResult(Outcome, RemainingPath)`. Rename failure reports the original path; delete failure reports the renamed remnant. `CtBuildCacheJanitor.PruneCandidate` persists/logs `RemainingPath`.
- Added real-filesystem regressions for lock state at the actual reap call, lease release after sweep, direct remnant debt, and coordinator-persisted remnant debt.

### IMPACT
Task 6 focused tests and the Miller.Testing Release build pass. The ignored Task 6 report is updated separately and is not part of the commit; lead-owned plan/docs remain untouched.
