## WHAT

Round 1 corrected Task 4's two follow-up findings. `RecentContinuousTestOutcomes` now sends all affected case IDs as one JSON parameter through the repository-proven `json_each` pattern, so completion no longer depends on SQLite's variable limit. Each row retains its result ID and is ordered in memory by `observed_at DESC, id DESC` before the stable flakiness score sort, preserving the old equal-time tie order without a multi-case temp sort.

## WHY

The prior implementation generated one SQL parameter per distinct case and had no explicit batch result ordering. Larger suites could fail atomically with `too many SQL variables`, and equal observation timestamps could change transition counts because `ContinuousTestFlakiness.Score` only sorts by time and preserves input ties.

## HOW

Added a real regression that lowers `SQLITE_LIMIT_VARIABLE_NUMBER` to 16 on the test-owned write connection, completes 20 distinct cases, and still proves the exact 43-statement `3 + 2R` trace. Added a same-timestamp hand-derived flakiness test: expected ID-desc tie order yields one transition/stable; a mutation to ID-ascending failed with actual three transitions. Updated the query-plan test to use the JSON/`json_each` shape and retain `USING COVERING INDEX idx_test_results_workspace_case_observed` with no temp B-tree. Updated the ignored task report with Miller calls, TDD chronology, timestamps, mutation evidence, scope expansion, and judgment calls.
