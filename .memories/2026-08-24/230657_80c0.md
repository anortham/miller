## QML CT Task 3 implementation

### WHAT

Implemented `QtQuickTestProvider` and registered `qt-quick-test` in the default continuous-test provider factory. Added focused provider and factory tests.

### WHY

Miller needs a production CMake/CTest Qt Quick Test provider that keeps configure/build artifacts outside source, reuses the discovery generation for the following run, executes exact or whole-suite CTest selections, and maps JUnit results to stable QML target cases.

### HOW

- Used `CtGenerationHandoff` and `CtGenerationPaths` for generation-scoped out-of-source configure/build and one-shot discovery-to-run reuse.
- Probed and validated CMake 3.21+ through the existing Qt tooling contract; discovery uses CTest JSON v1 and runs use `--output-junit`, `--no-tests=error`, and exact escaped `-R` filters.
- Stable IDs encode the project identity and UTF-8 test target name; JUnit rows are grouped and mapped through the shared parser.
- Preserved an existing `QT_QPA_PLATFORM` value and defaulted it to `offscreen`; coverage requests fail before process execution; truncated/missing/zero-result and nonzero tool outcomes become typed provider failures.
- Registered the provider source as `ct-provider:qml` and framework key as `qt-quick-test`.

The serial CT Task 3 packet is ready for lead review and the later selection/whole-suite integration task. No real Qt Scale test or Windows verification was run in this worker packet.
