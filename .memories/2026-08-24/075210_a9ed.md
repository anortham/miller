## Task 3 selection and live-state hardening

### WHAT

Added CT schema version 4 with normalized nullable `test_cases.project_path` and migration backfill; added project-filtered provider/status reads; added revision-keyed selector snapshots; filtered queue reads; evicted terminal retry keys; and excluded disabled-project lifecycle rows from active detailed and aggregate status while preserving history.

### WHY

Continuous-test selection was materializing every workspace case and status for each project. Unknown associations needed to remain fail-closed, retry bookkeeping could grow across revisions, and disabled discovery-failure pseudo-cases could keep an intentionally disabled project partial forever.

### HOW

The schema stores normalized project paths and indexes `(workspace_id, project_path, source, selector, id)`. The selector lazily caches one project case/status read per `(workspace, index identity, revision)` and invalidates after discovery refresh. Queue coverage, fresh trimming, backfill ordering, inventory, and red-count reads use project filters. Retry entries remain only for queued/in-flight retry work and are removed on terminal paths. Status joins `test_cases` to `ct_test_projects` and suppresses only disabled `ct-project-status` rows. Added migration, selector, store, disabled-status, and real flaky retry tests.

### IMPACT

The owned focused suite passed 241 tests with zero failures/skips. This packet is ready for a serial commit; the pre-existing plan and Task 7 provider changes must not be staged with it.
