## QML continuous-testing Task 4

### WHAT

Added selector support for QML project fallback and extended the shared whole-suite provider contract with Qt Quick Test artifact and missing-case checks.

### WHY

CTest discovers Qt Quick Test targets but does not provide QML function ownership. QML, CMake, and named runner changes therefore need project/target-level evidence without claiming function precision, while unrelated QML applications must remain outside a QuickTest project.

### HOW

- Classified `.qml` changed paths as `qml`.
- Added scoped `ct-provider:qml` fallback for `.qml`, CMake, and runner paths; exact project requests stay scoped, and workspace-level fallback requires the changed path to be under the QML project/evidence root.
- Added selector tests for QML fallback, CMake/runner isolation, and unrelated QML applications.
- Added QML whole-suite contract tests that assert artifact creation, no `-R`, complete results, and missing selected-case failure.
- Preserved the existing provider rejection for empty non-whole-suite selections.

### IMPACT

The QML provider now participates in impact selection at its supported target granularity, and the shared contract guards whole-suite result/artifact semantics. Focused selector and whole-suite tests pass; no full suite, Scale, Qt, or Windows verification was run in this worker packet.
