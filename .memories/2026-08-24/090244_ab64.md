## CT cache enforcement packet

### WHAT
Implemented the bounded cache-janitor slice on `perf/ct-audit-2026-08-23`: per-build-root cache TTL/cap enforcement, machine-wide locked cache pruning, operation/root locks, detailed rename/delete outcomes, and coordinator maintenance integration.

### WHY
The audit found CT build caches were counted but never enforced. Provider processes and older daemons also needed a cross-process safety signal before a machine-wide sweep could remove cache data.

### HOW
- Build roots are accepted only through the exact two-level 12-hex Miller layout for the machine sweep.
- Workspace maintenance runs after protected-generation reaping and deletes cache/tool directories older than seven days, then oldest-unused candidates until the 2 GiB root cap; the machine sweep uses one lock under the Miller CT root and an 8 GiB cap.
- Active operation locks, missing lock markers, recent roots, ambiguous roots, symlinks, and non-Miller directories fail closed. Generation directories are never cache candidates.
- Cache deletion uses detailed rename-before-delete outcomes and returns debt paths; the coordinator persists those paths through the existing reap-debt table without failing the test verdict.
- Real filesystem tests cover TTL, workspace/global order and byte caps, operation/machine lock contention, recent/ambiguous/non-Miller/symlink protection, generation survival, failed reap debt, and protected excess.

### IMPACT
Focused janitor tests (10), cache maintenance/lifecycle tests (23), daemon-engine tests (156), generation/lease tests (19), and Release solution build all pass.
