## Fixed CT write-path migration ordering

### WHAT

Added `ContinuousTestStore.EnsureSchemaForWrite()` and invoked it before the first CT store read in `TestsCore.Run`, `ServeHost`, `Enable`, and `Disable`. Added a temporary SQLite regression class covering a schema-version-1 store with a legacy `test_cases` table missing `project_path`.

### WHY

The live gate showed a v1.21-era `tests run` failed before migrating because `TestsCore.Run` listed projects through the read path first. Read-only status must remain non-mutating and fail closed.

### HOW

The new method reuses the existing guarded `WithWrite` path, so newer schemas and corrupt files keep the existing refusal behavior. The regression injects a no-provider foreground hook, asserts the stored case/project rows survive migration, and verifies status leaves the legacy bytes and schema marker unchanged. Miller context/inspect/trace/impact were used before editing and after the change.

### IMPACT

Foreground run and daemon host/mutation entry points now prepare existing CT schemas before querying new columns. Status and failures remain read-only. No live `.miller/ct.db` was read or touched. Focused tests and Release builds are green; the lead must rerun the live gate.
