## CT v1.21.1 performance audit found a size-threshold result-transport regression

### WHAT

The released xUnit whole-suite path completes the tests but fails before persistence because its full JSON event stream exceeds Miller's bounded stdout capture. Findings and A/B evidence are recorded in `docs/findings/2026-08-23-performance-audit.md`; production code is unchanged.

### WHY

At 8,310 executed cases, partial JSON already reached 48.5 MB while the valid JUnit artifact was 2.0 MB. Raising the 8M cap would increase memory and only move the threshold.

### HOW

Measured warm CLI baselines, compared v1.20.1 and v1.21.1 on identical data, reproduced the quiet CT failure twice, traced the error through `RequireCompleteStandardOutput`, and verified xUnit v3.2.2's official `silent`, `noAutoReporters`, and result-artifact surfaces.

### IMPACT

A correctness/performance repair is design-approved only after user confirmation. The preferred local seam reuses the coordinator's existing JUnit artifact import fallback and leaves bounded selected/chunked JSON behavior unchanged.
