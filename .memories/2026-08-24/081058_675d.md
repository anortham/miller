## WHAT

Task 4 batches CT run-completion flakiness work and materializes result observation time. `CtSchema` is now schema version 5 with `test_results.observed_at` and the covering `idx_test_results_workspace_case_observed` history index. `CompleteContinuousTestRun` writes result rows first, performs one newest-50-per-case indexed history query, computes scores in memory, and folds each score into the existing fresh/stale state upsert.

## WHY

The old completion path issued one history query and one extra score update for every result, producing 6 statements for one result and 10 for two. The approved closure contract requires a fixed small constant plus two statements per result, while preserving flakiness, freshness, normalization, rollback, and stale behavior.

## HOW

The schema migration backfills `observed_at` from the owning run's ended time, then started time, then the existing minimum timestamp fallback. The batch query uses a correlated indexed count to retain exact newest-50-per-case semantics without a temp B-tree. The score is written in the existing state upsert, eliminating the extra update. Tests cover exact 3+2R traces for R=1,2,3, migration timestamp choices, covering-index/no-temp query plan, and existing store/readiness behavior.
