## Completed Task 5: target-bound edit

- **WHAT:** Added per-target edit context construction and registered-workspace write-through. Explicit edits now use the selected index, source root, edit lock, convergence queue, bounded refresh fallback, and telemetry attribution.
- **WHY:** A stateless user-level MCP edit must never write through the process primary or cwd when the call names another workspace.
- **HOW:** Resolve mutations with `WorkspaceSelectorIntent.Mutate`, carry `IndexDbPath` in the symbol-read context, create the applier against the target `.miller`, queue file convergence first, and refresh only after the bounded recovery wait finds no revision advance.
- **IMPACT:** Non-primary preview/apply is isolated to the named workspace; ambiguous or dead targets create no lock or file writes.
