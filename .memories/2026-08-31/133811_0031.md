## Pre-release review of stateless workspace targeting (BRE-57) — 8 defects found, 7 fixed

### WHAT
Reviewed branch `codex/bre-57-stateless-workspace` before release approval. Found and fixed seven defects plus a flaky test. Three items left open as product decisions.

### WHY
The branch is a breaking MCP contract change: nine tools now require `workspace_id`, and `current`/`primary` are refused at the MCP boundary. Main is fully released at v1.25.4, so this branch is the entire release candidate.

### HOW — blockers fixed
- **Every MCP call threw with no primary bound.** The `IndexFreshProbe` DI factory resolved `IndexHolder`, whose getter throws until bound; `TelemetryCallToolFilter` reads it outside any try. This broke the exact user-level GUI case the branch targets. Fix: `IndexFreshProbe.Deferred` takes a holder supplier resolved inside `Compute()`, which already reports null as "not measured". Used a static factory, not a second constructor — the overload pair made `new IndexFreshProbe(null!, ...)` ambiguous in existing tests.
- **`workspace remove` could delete the machine-global `~/.miller`.** `protectedMillerDir` had changed from the global registry dir to the current workspace's own `.miller`, and went null with nothing bound. Restored to `_hostPaths.MillerDirectory`.

### HOW — other fixes
- Current-workspace telemetry read empty: the DI ledger opens `workspaceId: null` and is never rebound. Both call sites now pass the ID explicitly.
- MCP edits lost complete-recall symbol reads (always carrying a `workspace_id` routed them to the recall-limited search sidecar). Added `ResolveCompleteSymbolRead`.
- `McpWorkspaceTargetPolicy` refused `workspace ... path=/abs`, contradicting the tool's own schema. The policy now accepts `path` as an explicit target.
- `RegisteredWorkspaceWriteThrough.TargetFiles`: `Path.GetRelativePath` returns an absolute path across Windows volumes, carrying no `..`, so a cross-drive file passed containment. Added a rooted-path test.
- `CLAUDE.md` still stated the deleted `MILLER_BOOTSTRAP_GRACE_SECONDS` rule as load-bearing.
- **Shipped guidance taught calls that now fail:** 10 plugin skills with ~110 unscoped example calls, and `docs/agent-guidance.md` still calling `workspace_id` optional. Added a targeting block to 10 skills and scoped 83 example calls.

### Discoveries worth keeping
- `scripts/sync-plugin-skills.sh` does `rm -rf skills/` and re-copies from `.agents/skills/`. **`.agents/skills/` is the source.** Editing `skills/` and then syncing silently discards the work — it cost a full redo here.
- `DashboardIndexFactsCache` is process-wide static state with a global `Count`/`Clear`. Five test classes raced on it, making the capacity assertion flaky under full-suite parallelism while passing in isolation. They now share a `DisableParallelization` collection.
- `win-test sync` refuses a dirty host tree, so the required Windows pre-release gate cannot run until the fixes are committed.

### IMPACT
The branch was unshippable as written. Recommended withholding release approval.
