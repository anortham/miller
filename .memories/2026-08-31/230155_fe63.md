## CT daemon poll no longer blocks the loop

### WHAT
Split `ContinuousTestRevisionPoller.PollAsync` into `ReadAsync` + `ApplyRead`. The daemon loop collects completed reads, runs idle-drain/ready work, then fires the next `ReadAsync` on the thread pool.

### WHY
A long `symbols.db` poll froze `StampLoopTick` and `ProcessCommands`, so `tests run` stayed unacked and the loop looked wedged.

### HOW
- `PollAsync` is a facade: `ReadAsync` then `ApplyRead`.
- Loop order: collect completed reads, idle drain, ready scan, fire `Task.Run(ReadAsync)`, delay.
- Skip drain/ready while `PollReadTask` is incomplete.
- Shutdown awaits in-flight reads before releasing contexts.
- Loop tests that parked on the first delay now tick extra iterations because apply happens on the next collect.

### IMPACT
`Loop_AcksRunCommandWhilePollReadInFlight` proves a run command acks while a poll read is blocked. Daemon bucket: 541 passed.
