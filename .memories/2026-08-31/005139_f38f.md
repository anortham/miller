## Completed Task 2: explicit MCP target policy and schemas

- **WHAT:** Added centralized MCP workspace target validation, required `workspace_id` in nine workspace-bound tool schemas, kept mixed workspace lifecycle operations schema-optional, and removed request-time Roots binding from the call filter.
- **WHY:** Stateless MCP calls cannot safely infer a workspace from cwd, prior requests, connection state, `current`, `primary`, or deprecated Roots.
- **HOW:** `McpWorkspaceTargetPolicy` classifies request scope before handler construction. Missing and implicit selectors return stable typed diagnostics. `content workspace_id=all` is limited to read-only search. Direct methods keep nullable defaults for CLI/internal use.
- **IMPACT:** MCP callers must list/open a workspace and pass its registered selector on every workspace-bound call. Ambiguous requests fail before DI constructs a tool.
