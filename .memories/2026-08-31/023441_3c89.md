## WHAT

Fixed the only failure from the first full fast-suite gate. `WorkspaceSymbolReadContext` no longer exposes raw `IndexDbPath`; target-bound edits obtain the path from the selected registry row or the lazy authoritative primary `WorkspaceContext`.

## WHY

Task 5 had added `IndexDbPath` to a session-backed read context, violating the established invariant that read contexts expose pinned `WorkspaceReadHandle` sessions instead of raw artifact paths. Updating the failing test would have weakened a load-bearing boundary.

## HOW

Removed the duplicate path property and provider arguments. `WorkspaceEditContextFactory` now uses `WorkspaceRegistryRow.IndexDbPath` for explicit MCP targets and `WorkspaceContext.CanonicalExtractDbPath ?? ExtractDbPath` for null/current CLI routes, while preserving ID/root consistency checks, target edit locks, telemetry, and write-through selection. Added a regression proving a nonstandard primary index path controls the edit lock without leaking through the read context.

## IMPACT

The session-only read contract is restored without losing explicit workspace editing. The bare fast suite must be rerun once on the corrected committed tree.
