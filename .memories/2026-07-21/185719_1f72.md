## Fixed: sidecar never received Miller's selected encoder (bge builds wedged forever)

**WHAT:** `MILLER_SEMANTIC_MODEL` never worked on the live serve/CLI paths — both `ProcessSession` sites launched `julie-semantic-sidecar` bare, so the child always loaded its own default (qwen3, 512-dim) while Miller created the selected encoder's lane (bge, 384-dim). The dim mismatch only surfaced at vector-commit time, permanently wedging the build. Found by impl-t6 during Task 6 bge cost runs; verified in source; user approved lead fix.

**HOW:**
- `ProcessSemanticSidecarLauncher.ForServe(executable, pin)` — explicit `serve --model <id>` argv (the sidecar reads no env; `--model` is the only channel), plus an `Arguments` accessor so wiring is provable without spawning.
- `MatchEncoder(health, expected, out reason)` overload — refuses a sidecar serving a *known but not selected* encoder (old handshake validated the sidecar against itself, letting the mismatch through to commit time).
- `SemanticEmbeddingSession` optional `expectedEncoder` ctor param; both production `ProcessSession` sites pass `SemanticEncoderSelection.Active` to both the launcher and the session.

**WHY it was invisible:** default qwen3 matches the sidecar default, so the default lane (all dogfood/canary traffic) never failed.

**IMPACT:** unblocks the bge-small pin move (Task 5's pin-rule outcome) and impl-t6's bge cost lane. Plan escalation trigger fired (serving-path change beyond Task 7's files) → scale suite added to the branch gate. Fast suite 4406/0, Release 0W/0E.
