## Planned the shared semantic broker release gate

Miller v1.14.0 was prepared, but default-on semantics cannot ship safely while every Miller process owns a model-loaded sidecar.

- **What:** Wrote the full cross-repo implementation plan at `docs/plans/2026-07-27-shared-semantic-broker-implementation-plan.md`.
- **Why:** Concurrent Miller sessions on a 6 GB Windows NVIDIA laptop could multiply VRAM consumption, while a broad detached daemon would repeat Julie's prior reliability problems.
- **How:** The plan uses a narrow lease-owned compute broker, Unix-domain sockets or cancellable Windows named pipes, stdin owner lifetime plus a Windows kill-on-close Job Object, deterministic protocol/model identities, one global accelerator lease, bounded scheduling, and CPU demotion on typed resource exhaustion.
- **Impact:** Semantic retrieval becomes eligible to default On only after real multi-session, owner-death, cross-platform, and Windows/NVIDIA soak gates pass. The v1.14.0 release remains paused and requires fresh approval after the verified final state.
