## Completed Miller shared-broker lifecycle integration

- **WHAT:** Added deterministic broker endpoints, Unix/named-pipe client connections, connect-first/spawn-on-demand ownership, Windows kill-on-close Job attachment, reconnect/re-election, immutable broker snapshots, lazy server DI, invocation-scoped CLI ownership, and strict semantic-Off zero work.
- **WHY:** Multiple Miller sessions must share one model-loaded sidecar without recreating the unreliable unowned daemon pattern, and Windows teardown must remain bounded even when Job assignment degrades.
- **HOW:** One factory retains the spawned process, stdin, and optional Job handle; non-owners retain only connections. Cold-start waiters re-elect once per second inside the 120-second budget if a holder dies. Exited owners are retired before replacement. Factory disposal cancels and drains active/waiting connects before closing stdin then Job. Production server/CLI no longer use `ProcessSemanticSidecarLauncher.ForServe`.
- **IMPACT:** Task 7 is locally complete and unblocks multi-session crash/soak verification. Real Windows Job/named-pipe runtime and rc.5 broker Scale evidence remain later release gates.
