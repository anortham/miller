## Added phase 1 symbol search projection

### WHAT
Implemented the first projection-specific read path in Miller: registered-workspace `search` now resolves through a symbol-only projection instead of the full repository index.

### WHY
Large-repo dogfood and the search projection spike showed first-read `search` was paying full graph/bridge hydration costs. OpenClaw full loads were several seconds and hundreds of MB, while current symbol projections were around 1.8s and +55MB.

### HOW
- Added `ISymbolSearchIndex`, `SymbolSearchProjection`, and `SymbolSearchProjectionLoader` in `Miller.Indexing`.
- Added `IWorkspaceSearchProvider` and `WorkspaceSymbolSearchContext` in `Miller.Server.Workspaces`.
- Made `WorkspaceIndexProvider` implement both full and search provider interfaces with separate revision/path-keyed caches.
- Moved `SearchTool` to the search provider while leaving full-read tools on `IWorkspaceIndexProvider`.
- Added design doc `docs/plans/2026-06-02-search-projections-design.md` and updated `TODO.md` to mark phase 1 as complete.

### IMPACT
Registered workspace `search` no longer calls `RepositoryIndexLoader.Load`, keeping graph and bridge hydration out of the search path. This unblocks the next projection phase: basic `inspect` lookup/search projection, then content/docs search.
