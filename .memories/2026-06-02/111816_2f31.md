## Implemented Miller julie-extractors review fixes

### WHAT
Fixed the concrete migration review findings in `/Users/murphy/source/miller`:

- Windows packaging now copies `.tools/julie-extract.exe` into the app output alongside the Unix binary.
- CI now has a scheduled/manual Scale lane that restores `julie-extract` and runs `scripts/test.sh scale`.
- Bash restore fallback now reads `archiveInnerPathTemplate` without `jq`.
- Partial `julie-extract` reports now surface through workspace open/current refresh/registered refresh output.
- Registered workspace status now renders typed `missing_index` when the DB is gone and marks the registry row missing.
- Registered workspace status now summarizes telemetry for the requested workspace instead of the current process workspace.
- Inspect full body output now distinguishes no span, missing hash, missing file, unsafe path, stale file, empty file, and invalid span.
- Active `CLAUDE.md`/`AGENTS.md`/Goldfish brief now describe the `julie-extractors` v2.0.0 contract.

### WHY
The migration review found several places where Miller's new `julie-extractors` integration was functionally correct in the happy path but still unsafe or misleading at product boundaries: Windows packaging, CI coverage, partial artifacts, target status, inspect body failures, and active handoff docs.

### HOW
Used TDD for behavior changes. Added caller-facing tests around restore/package contracts, workspace status/refresh/open output, telemetry scoping, and inspect body reasons. Kept changes local to the existing seams: `WorkspaceRefreshResult.WarningText`, `WorkspaceRender` result records, `TelemetryLedger` summary aggregation, and `ExtractReader.ReadBody`.

### IMPACT
The migration is better guarded end to end: CI can exercise Scale, Windows runtime can find the restored extractor, partial scans no longer look clean, registered status no longer mixes target facts with current telemetry, and inspect no longer mislabels stale/missing bodies as no-span cases.
