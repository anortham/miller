## Found a live correctness bug while designing the resolution-scoping fix

### WHAT
User approved "fix the slow step first" (delta-scope resolution on whole-repo scans). The design investigation found the fix cannot come first: the incremental path is already unsound, and the slow whole-repo full pass is what silently repairs it.

**Reproduced myself with pinned julie-extract 2.25.0.** Fixture: a.ts has `import { realName as localName } from './b'; localName();` then b.ts gains `export function realName()`.
- `update --file src/b.ts` (the delta path, which is Miller's watcher path on every save): reference stays UNRESOLVED (resolved_pending=0, identifier target NULL).
- whole-repo `scan` (full path): RESOLVES it (resolved_pending=1, target 5714479fab41ca12...).

Cause: delta worklists match only pending_relationships.target_terminal_name / .target_receiver (resolution_store.rs:767, :811), but tier 2 gates on import.local_name and looks up by import.imported_name (resolution.rs:1045-1052), while touched_symbol_names carries only the changed file's own symbol names (writer.rs:1244). Three more defects of the same shape were confirmed by execution in the investigation: tier-3 receivers keyed via type_facts.resolved_type; NULL-target identifiers never retried (delta fill arms are never-attempted-only, resolution_store.rs:868/:892 vs full arm's r.target_symbol_id IS NULL at :960); module specifiers re-pointing when a file is added/removed.

### WHY THE ORDER IS FORCED
Miller's force scans build into a fresh symbols.db.rebuild where prior.is_none() forces Full anyway (JulieExtractRunner.cs:477-486), so the whole-repo incremental scan is the ONLY automatic pass that re-derives the overlay on a LIVE artifact. Scoping it first turns four self-healing defects into permanent ones while the artifact still reports partial/ready.

### HOW
Wrote julie-extractors/docs/plans/2026-08-05-delta-resolution-soundness-and-scoping-design.md. Phase A: widen delta reach via two WorkspaceCandidateIndex accessors (files_declaring_type_named, files_importing_names) unioned inside delta_scope_files, plus three missing by-files worklists. Phase B: split the overloaded is_full_scan into is_full_scan + whole_corpus, then scope conditionally at the single production site when no file was added/deleted, not Force, and under a measured crossover. T1 equivalence oracle (none exists in the repo) is the acceptance gate.

Also updated Miller docs: findings/2026-08-05-rebind-p1-cost-model.md, docs/README.md pointer, and resequenced the rebind program plan (new P1a; base+overlay removed as refuted).

### IMPACT
Phase A is a shippable correctness fix to live behaviour, independent of the perf work. Awaiting user review of the design before implementing.
