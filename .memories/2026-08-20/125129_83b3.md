## Defect A fixed; Defect C root cause pinned to a lost runsettings environment

### Defect A — FIXED (fix + tests, red-green proven)

`miller tests serve | anything` hung the pipeline because the detached daemon inherited the launcher's stdout pipe.

- **Mechanism**: Windows duplicates EVERY inheritable handle into a child created with handle inheritance on. `SetStdHandle` hides the original but never closes it or clears its inherit flag.
- **Measured, and it refuted the obvious fix**: a probe timed a pipeline whose child sleeps 20s. Current shape → 20s hang. NO redirection at all → still 20s hang. Clearing `HANDLE_FLAG_INHERIT` on the saved std handles → 0s. So dropping `RedirectStandardInput` would NOT have worked; .NET sets `bInheritHandles=TRUE` either way. A workflow agent measured the same four redirect shapes independently and added: with no redirection the swapped log handles never reach the child, so `RedirectStandardInput = true` is load-bearing for log capture and must stay.
- **Fix**: new `src/Miller.Indexing/StandardHandleInheritance.cs` — a scope that clears the inherit flag on the launcher's own standard handles and restores it. Taken BEFORE the swap in `CtDaemonLauncher.StartWithFileBackedStreams`.
- **Tests**: `StandardHandleInheritanceTests` (6, non-vacuous — proven red 2/6 with the guard neutered) plus `DetachedSpawnHandleConventionTests` (source scan: every production `SetStdHandle(` site must call the guard).

**Process lesson recorded**: my first test asserted on the runner's own std handles and PASSED with the fix removed — vacuous, because VSTest hands the test process handles whose inherit flag is already clear. Always neuter the fix and watch the test go red.

### Defect C — root cause is NOT what it looked like

CT does not run `dotnet test` for xunit projects. `DotnetTestProvider.cs:419-424` runs the built xunit v3 EXECUTABLE with only four environment variables. `tests/Miller.Tests/Miller.Tests.csproj:18` sets `RunSettingsFilePath`, and `test.runsettings` sets `MILLER_INDEX_STORE=off` — honored only by VSTest. So under CT store mode is default-on and hundreds of tests hit `FamilyStoreReadException`.

**Discriminating experiment** (4 classes, exe run directly, in-repo, matched filters):

- no env (what CT does today): **203 failed / 341**
- `MILLER_INDEX_STORE=off`: **0 failed / 341**

This corrects my own earlier note: the failures I attributed to test-order dependence were the lost runsettings environment. My `dotnet test` comparison was modeling the wrong runner.

Workflow taxonomy of all 366: ~292 lost runsettings env (CT bug, would break any repo with a runsettings environment block), ~50 repo-root walk, plus smaller buckets.

### Defect C env-var break — fix started

`ScaleTestSupport.cs` read the RETIRED `EROS_WORKSPACE_ROOT` while every provider sets `MILLER_CT_WORKSPACE_ROOT` (`DotnetTestProvider.cs:480`). Changed to read `CtEnvironment.WorkspaceRoot` through a new testable `RepoRootFrom(assemblyDir, cwd, readVariable)` seam. Test still to write.

### Other confirmed findings (not yet fixed)

- **B**: `Partial` is created BY the run (enqueue marks cases stale), so `--wait` exits immediately. No `Paused` arm either. `ReadStatus` hardcodes `Executing: false`, so no in-flight signal reaches a status reader — shared root with F2.
- **D**: double build confirmed — `DiscoverAsync` and `RunAsync` each allocate a generation with its own `OutDir`, so MSBuild cannot reuse.
- **E**: CT counts test METHODS, `dotnet test` counts theory ROWS (no `-preEnumerateTheories`). Numbers close exactly. Real hole downstream: delay-enumerated theory rows share one `TestCaseUniqueID`.
- **F1**: a stall kill truncates output, so the xunit parser never sees `test-assembly-finished` (the only place an end time is assigned), and the run takes the SUCCESS path.
- **G/H**: `tests failures` is capped at 5 (clamp max 20), has no paging, and is MCP-only; the CLI exits 0 on an unknown operation.
- Dashboard launcher has the same handle class of defect but no log-file swap, so it needs file-backed streams first. Not changed.
