## Three CT defects fixed and proven; fast suite green

Branch `main`, uncommitted. `dotnet test` (fast suite): **7513 passed, 0 failed, 27 skipped, 1m27s**. Release build of every changed project: 0 warnings, 0 errors.

### Defect A — `tests serve` hung any piped shell. FIXED, proven end-to-end.

- **New** `src/Miller.Indexing/StandardHandleInheritance.cs` — clears `HANDLE_FLAG_INHERIT` on the launcher's own standard handles for the length of a spawn, then restores. Taken BEFORE the `SetStdHandle` swap (after it, those handles are the log files the child must inherit).
- Wired into `CtDaemonLauncher.StartWithFileBackedStreams`.
- **End-to-end A/B**: pre-fix Release binary through `| cat` never returned (killed at 4 minutes); post-fix Debug binary returned in **0 seconds**. Same scratch workspace, same command.
- Two measurements refuted the obvious fix: dropping `RedirectStandardInput` does NOT help (.NET sets `bInheritHandles=TRUE` regardless), and with no redirection the swapped log handles never reach the child — so that flag is load-bearing for log capture and must stay.

### Defect C — the dominant cause was NOT the repo-root walk. FIXED.

CT runs the built xunit v3 executable, not `dotnet test`, so nothing applied the project's `RunSettingsFilePath` environment block. `MILLER_INDEX_STORE=off` never reached the test process.

- **Measured**: 4 classes from the executable, in-repo, matched filters — **203 failed / 341** without the variable, **0 failed / 341** with it.
- **New** `src/Miller.Testing/Providers/Shared/RunSettingsEnvironment.cs` reads `RunSettings/RunConfiguration/EnvironmentVariables` from the project's declared settings file. Silent-empty on any problem, matching `ParseDefaultFilterExclusions`. DTDs prohibited, no XmlResolver.
- Wired into `DotnetTestProvider.WorkspaceEnvironment`: project block first, CT's own variables (`MILLER_CT_WORKSPACE_ROOT`, `TMP`/`TEMP`/`TMPDIR`) overwrite it, because those are a containment guarantee.
- This affects ANY repo whose test project declares a runsettings environment block, not just Miller.

### Defect C — the env-var channel. FIXED.

`ScaleTestSupport.RepoRoot()` read the retired `EROS_WORKSPACE_ROOT` while every provider sets `MILLER_CT_WORKSPACE_ROOT`. New `RepoRootFrom(assemblyDir, cwd, readVariable)` seam so a test can drive the third fallback (it never fires in an ordinary in-repo run), and a test asserts the exact name read.

### Daemon-variable leak — FIXED across all four providers.

`MILLER_CT_DAEMON_WORKSPACE_ROOT` was inherited by every CT test process, so a `miller` CLI verb run inside a test would bind the daemon's workspace. Removed in the dotnet, Node, Python, and Rust providers. `CtDaemonLauncher` now also removes the provider-facing `MILLER_CT_WORKSPACE_ROOT` from the daemon's own environment.

### Tests added

`StandardHandleInheritanceTests` (6, red-green proven: 2 fail with the guard neutered), `DetachedSpawnHandleConventionTests` (source scan, non-vacuous site count), `RunSettingsEnvironmentTests` (11, including one pinned to Miller's real csproj), plus one provider wiring test and two `ScaleTestSupport` tests.

### Process lesson

My first Defect A test asserted on the test runner's own std handles and PASSED with the fix removed — vacuous, because VSTest hands the test process handles whose inherit flag is already clear. Neuter the fix and watch the test go red, every time.
