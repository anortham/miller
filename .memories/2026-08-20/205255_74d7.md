### Course correction: the worktree was abandoned
I created `.worktrees/ct-dogfood-defects` per the plan's sequencing note. Entering it **re-rooted the
Miller MCP server at the worktree path**, which had no view in the store family. Bootstrap threw
`StoreBindingMismatchException` and every read tool failed while `workspace status`/`health` kept
reporting the workspace healthy — exactly the host-lifecycle split CLAUDE.md documents.

My first hypothesis was WRONG and I want it recorded: I blamed the `\\?\` verbatim prefix on
`views.root`. `ArtifactRootIdentity.Matches` already strips that prefix on both operands, and its doc
comment names the exact Rust behaviour. The log record's `Root` property named the real cause.

Registering the worktree failed too (`workspace open` -> `state=failed failure=view_not_found`;
`workspace full` -> `ineligible_extractor`). So the branch moved to the main checkout and the
worktree was removed. Isolation is preserved by separate commits, which is what the plan actually
wanted.
