## Follow-up after the user rebuilt and restarted

### WHAT

**The Release build lock was a timestamp artifact, not stale code.**
Every DLL in `src/Miller.Server/bin/Release` is byte-identical to a fresh compile of the current
tree. .NET builds deterministically, so the user's pre-session build already produced exactly these
bytes. MSBuild still retried the copies because the SOURCE timestamps were newer, and the running
MCP servers hold the destination files. Aligning the destination timestamps — after byte-verifying
each file first — makes the in-place Release build succeed with the servers live.

Do NOT stamp a file without comparing it first. Stamping a file whose content differs would hide
real staleness, which is the failure mode `a-test-must-pin-the-binary-it-measures` records.

**Three more defects of the CT repo-root class, found by dogfooding the new `tests failures` verb.**
`miller tests failures` on this repo showed 366 red cases, nearly all
`InvalidOperationException: Could not locate repo root (Miller.slnx)`. `ScaleTestSupport.RepoRoot`
had already learned to fall back to `MILLER_CT_WORKSPACE_ROOT`, but two private copies survived that
repair:

- `TestProcessRunnerTests.FindRepoRoot` — deleted, now calls `ScaleTestSupport.RepoRoot()`.
- `DashboardFragmentCachingTests.RepoRoot` — now delegates to the shared helper.

Added `tests/Miller.Tests/Conventions/RepoRootResolutionConventionTests.cs`. It scans test sources
for the quoted literal `"Miller.slnx"` outside two exempt files, strips doc comments first, and
asserts the exempt files still carry the token so it cannot go vacuously green.

**One genuine test design defect fixed.**
`TestProcessStallTests.A_real_child_that_keeps_printing_keeps_its_stall_clock_near_zero` started its
sampling clock when `Start` returned, then required the stall clock to be under 1.4s. On a loaded
machine `cmd.exe` plus `ping` need longer than that just to reach their first line, so the test
measured process startup and reported it as a stalled clock. It now waits for the child's first
line before sampling. The wait cannot mask the defect it hunts: an unstamped clock only ever grows,
so the wait would time out instead.

### WHY the flakes matter

Three different tests failed across three consecutive full runs, one each, all passing in isolation.
That is suite-wide timing sensitivity under desktop load, not a regression.

### HOW I ruled out a regression in the daemon flake

`ContinuousTestDaemonHostHeartbeatTests` sets `AcquireLease = false`, and the pulse task is
`Task.CompletedTask` when the lease is null. The heartbeat republish I added is therefore never
reached by that test, and its `RunActivity` is null so every activity call is a no-op.

### IMPACT

The gate now runs in place. Two pre-existing load flakes remain open and are NOT from this work.
