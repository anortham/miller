## Branch `fix/ct-dogfood-defects` is complete: 6 tasks, both gates green, codex review done

**WHAT.** All five approved plan tasks plus Task 6 (added at the user's direction) landed as 10 commits.
Then the codex pre-merge review found 9 more defects after dedupe; 8 are fixed, 1 is deferred with a
reason, 2 halves are flagged for the user.

**Task 6 — the planned-view wedge.** A workspace whose store view is PLANNED in the registry but never
PUBLISHED in the family store could not index; the only escape was `workspace remove` + `workspace open`.
Two independent wedges: `StoreFamilyResolver.ReconcileCatalog` threw unless a caller passed a flag that
bootstrap could not pass, and `StoreArtifactVersionReader.ReadForLeadership` threw because the probe
followed the pointer to a view the catalog does not carry. Fixed by re-planning the view and reading the
FAMILY-scope `store_meta.binary_version`. `StoreViewReplan` distinguishes `NeverPublished` (warning, keeps
the legacy seed) from `VanishedFromCatalog` (error, barred from the seed because a seeded import does no
extraction).

**A regression I caused and caught.** The new bootstrap writer gate refused EVERY first import:
`PathCanonicalizer.CanonicalizeRoot` runs before the typed checks, so a never-written family raises a raw
`DirectoryNotFoundException`, which was wrapped as `Corrupt`. Four pre-existing store scale tests failed.
A baseline worktree at e726dd95 proved they were regressions (6/6 green there). Fixed in 6ab29c7a.

**Flaky fast suite, fixed.** `TestProcessStallTests` read the stall clock at two instants and required each
under 1.4s. Under the suite's own load one run read 2.59s then 0.53s — the clock FELL, so stamping was
healthy and the assertion was wrong. Now samples a 6s window and compares the highest read against half the
window, which is granularity-free.

**HOW the review findings were handled.** Every finding was verified against the code before it was fixed,
and every fix was watched failing first where a discriminating test exists — including breaking
`TestProcessRunner.StampOutput`, splitting the ct.db version stamps, and removing the disable guard.

**IMPACT.** The branch is ready for the user's decision on push/PR. Nothing is pushed. Two design questions
remain open for the user, and plan Decisions 1 and 2 were never answered.
