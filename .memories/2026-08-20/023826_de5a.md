## CT Windows hardening merged to main — ready for live dogfood

`main` fast-forwarded from `9322cfee` to `9f5066aa`. Three commits, working tree clean, NOT pushed.

```
9f5066aa  perf(ct): run the whole assembly once when a run covers every known case
0443732b  feat(ct): kill a test process that goes silent, and fail its run
7af0903a  fix(ct): harden the continuous-test daemon and providers on Windows
```

### WHAT shipped

**1. The 30-defect Windows CT fix set** (42 files). Process containment via Windows Job Objects with
membership proved by `IsProcessInJob`; diagnostics reaching `CtDaemonLog` (it was written, unit-tested,
and called from nowhere in `src/`); `CtDaemonJson.TryRead` retrying a refused open and confirming a
missing file across the `File.Replace` publish window, with jittered writer backoff; `workspace remove`
holding the CT daemon lease across the delete instead of half-deleting a workspace; `CtArgvChunking`
bounding every selection; paused runs reporting `verdict: unknown` rather than a stale green.

**2. Run stall guard.** 10 minutes of SILENCE (not total duration) kills the process tree and FAILS the
run. `MILLER_CT_STALL_TIMEOUT` overrides, `off` disables. Exit code is FORCED
(`TestProcessRunner.StallExitCode = -4109`) because a child exiting 0 as it is killed would read as
success.

**3. Whole-suite inversion.** A run covering every known case sends the provider an EMPTY selection, so
one assembly-level run replaces ~50 chunked vstest startups. Keyed on COVERAGE, not scope —
`DropCommittedFreshAt` can shrink a workspace-scope run to a few ids.

### Gate evidence

- Fast suite: 7492 passed / 0 failed / 27 skipped.
- Scale suite: 150 passed / 0 failed / 12 skipped (all 12 are julie-extract and semantic-sidecar tests
  that skip on unrestored tool packages; none is a CT test).
- CT scale alone: 8 passed / 0 failed / **0 skipped**.
- The whole-suite path was validated against a REAL dotnet provider by forcing `WholeSuite: true` and
  re-running `Change_selection_execution_reaches_green_on_a_real_dotnet_provider` — it reached green, so
  TRX ids are selection-independent in practice and not just in the code I read.
- Every new guard was red-proved by unwiring the thing it guards, then restored; no markers remain.

### Known follow-ups

- With an empty selection, a TRX parsing to zero results no longer throws. The run is still not green
  (the applier holds the full selected list, so cases stay unreported), but nothing says why.
  Distinguishing "no tests in this assembly" from "something broke" needs the whole-suite intent to
  reach the provider.
- The drain still blocks the daemon loop, so `stop` is not processed until a run ends. The stall bound
  caps how long that lasts but does not make stop responsive.
- CT test-role evidence gap: `CtSymbolFact` carries only `bool IsTest`. Verified present, written up in
  `docs/findings/2026-08-20-ct-test-evidence-gap-verification.md`. Separate workstream.
