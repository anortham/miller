## Whole-suite run inversion + stall guard landed; evidence gap verified

### WHAT

Three things since the last checkpoint.

**1. Commit `7af0903a`** — the 30-defect Windows CT hardening set (8,059 insertions, 42 files) on branch
`fix/ct-windows-hardening`. Gate: 7465 passed / 0 failed.

**2. Commit `0443732b`** — the run stall guard. `TestProcessRunnerOptions.OutputStallTimeout` defaults to
10 minutes of SILENCE (not total duration, so a slow suite survives and a wedged one does not).
`ITestBackgroundProcess.SinceLastOutput` is the signal, stamped by the drain loop and seeded at
construction. `MILLER_CT_STALL_TIMEOUT` overrides; `off` disables. The stall exit code is FORCED
(`TestProcessRunner.StallExitCode = -4109`), never read from the killed child — a child that exits 0 as it
is killed would otherwise report success. Gate: 7487 passed / 0 failed.

**3. Uncommitted: the workspace-scope inversion** the check-in note asked for.

### HOW the inversion differs from the recommendation

The note said "a workspace-scope run should send an empty selection". I keyed it on **coverage, not
scope**: `ContinuousTestDaemonQueue.CoversEveryKnownCase` compares the selection against the project's
known inventory as a SET, and only a run covering all of it sets
`ContinuousTestCoordinatorRunRequest.WholeSuite`. `DropCommittedFreshAt` can reduce a workspace-scope run
to a handful of ids, and running a whole assembly for three tests is the same mistake inverted. Backfill
is excluded — it takes a bounded batch on purpose.

The coordinator then passes `TestCaseIds: []` to the provider while STILL passing the full list to
`ContinuousTestStoreApplier.StartRun`, so verdict rows record every case covered and freshness at the
composite key stays honest. No provider changed, so cargo and pytest get the same benefit.

### Verification discipline that paid off

- The failing serve Scale test was a FALSE red: `RequireMillerBinary()` preferred Release, and the Release
  build was stale because a running MCP server blocks it (MSB3027). A first mtime comparison looked like
  proof and was not — `miller.exe` is the apphost and does not change when code changes.
- The stall wiring test caught my own bad premise twice (ping's 1s cadence made a 600ms sample ambiguous,
  then a phase-sensitive growth check). The final assertion is phase-independent, and removing the stamp
  fails it with 2.01s/4.02s.
- The whole-suite queue test caught a wrong premise too: two cases in the SAME test file are both selected,
  so that run genuinely IS whole-suite. The second case needed its own file.
- Every new guard was red-proved by unwiring the thing it guards, then restored.
