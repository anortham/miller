## False red closed: the CT serve scale test measured a stale binary

`CtDaemonLauncherServeScaleTests.ServeLauncherExitsFirst_AndTheDaemonStillWritesToTheCtLogFile` failed
with "the daemon wrote nothing ... daemon.out.log: `<absent>`". The message blamed production. Production
was already correct.

### Root cause

`RequireMillerBinary()` tried **Release first**, then Debug. The session builds and tests in **Debug**,
because a running miller MCP server holds `Miller.Testing.dll` open and `-c Release` fails MSB3027. So a
Debug test run spawned a **stale Release** `miller.exe` that predates the file-backed capture fix.

### How it was proved (not guessed)

- A manual `tests serve` with the **Debug** binary created `daemon.out.log` / `daemon.err.log` (0 bytes),
  and `tests stop` grew `daemon.out.log` to 52 bytes: `{"status":"stopped","reason":"stopped","pid":null}`.
  So the `SetStdHandle` capture works and the daemon is simply silent while running.
- The same manual run with the **Release** binary created **no log files at all**.
- A first mtime comparison LOOKED like it proved staleness and did not: `miller.exe` is the apphost and is
  rewritten only when project properties change, so its timestamp is meaningless for code changes. The
  managed assemblies beside it are the ones that carry the code.

### Fix

`RequireMillerBinary()` now resolves the configuration from the test assembly's own
`AssemblyConfigurationAttribute`, so a Debug run tests Debug and a Release run tests Release — neither can
silently measure the other. `RequireBinaryNotOlderThanSource` then fails loudly when the managed output
predates the newest `src/**/*.cs`, naming the offending file and mentioning the MSB3027 cause.

Result: 1 passed, 0 skipped, 738 ms.

## Other work in this batch

- **Coordinator diagnostic sink wired.** Both production `new ContinuousTestCoordinator(...)` sites in
  `TestsCore.cs` now pass `onDiagnostic: message => CtDaemonLog.Write(root, message)`. They were silent, the
  same defect already fixed for `ContinuousTestProviderFactory.CreateDefault`.
- **New guard `CtDiagnosticSinkConventionTests`** source-scans `src/` and fails when any production
  coordinator or provider-factory construction passes no `onDiagnostic:` sink. Asserts the site count so it
  cannot go vacuously green. Red-proved by unwiring one site (it failed, naming the file and offset), then
  restored.
- **Paused-run contract closed.** `docs/contracts/tests-cli-v1.md` gained the `paused` field row plus the
  rule (paused ⇒ `verdict: "unknown"`, `waited: false`, exit 0, because a run that executed nothing holds no
  results at the selected key). `TestsTool.cs` no longer tells an agent to "read the verdict" after a paused
  run; it points at a retry instead.
