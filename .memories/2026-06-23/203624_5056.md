## Hardened Miller Eros JSON contract discovery for 1.0

Validated the Eros readiness feedback and addressed the concrete Miller-side contract gap without adding Eros-specific workflow features.

- **WHAT:** Added first-class `json_contracts` entries for `workspace_status` (`workspace status --json`) and `refresh_wait` (`refresh --json --wait`) in `capabilities --json`.
- **WHY:** Eros CT depends on stable status/refresh fields such as `built_revision`, `latest_revision`, `freshness_status`, `queue_empty`, and `content_corpus.state`; these existed in output but were not named as versioned capability contracts.
- **HOW:** Added contract docs `docs/contracts/workspace-status-v1.md` and `docs/contracts/refresh-wait-v1.md`, linked them from `docs/contracts/cli-eros-v1.md` and `docs/README.md`, and extended `Capabilities_Json_ReportsErosContractSurface` test coverage.
- **IMPACT:** Miller now advertises the status/refresh JSON shapes as first-class v1 contracts. The possible future references/usage JSONL export is explicitly reserved in `cli-eros-v1.md` but not implemented as a 1.0 blocker.
