## Added telemetry-derived workspace onboarding

- **WHAT:** Implemented a read-only `workspace onboarding` report for Miller, exposed through MCP (`workspace(operation="onboarding")`) and CLI (`miller workspace onboarding [--json|--markdown]`). Added telemetry aggregation, target-hash recovery against the current index, compact/JSON rendering, capabilities advertisement, contract docs, README copy, GitHub Pages copy, and embedded agent instructions.
- **WHY:** The user wanted Miller to use its local telemetry to help any indexed repo provide useful startup/onboarding guidance for agents without moving semantic workflow ownership into Miller or auto-editing instruction files.
- **HOW:** Added `TelemetryOnboardingReader`, `WorkspaceTargetHashResolver`, `WorkspaceOnboardingFacts`, and `WorkspaceOnboardingAssembler`. The reader scopes the shared telemetry DB by workspace and summarizes tool mix, flows, misses, friction, and repeated target hashes. The resolver matches hashes only against current index identities (symbol id, `path:name`, file path, symbol name) and keeps unresolved hashes opaque.
- **IMPACT:** Agents can now ask Miller for privacy-safe starter guidance, hot current-index targets, common misses, and friction before starting work in any indexed repo. Docs and public site now advertise the feature.
