## Corrected the v1.5.1 Windows WAL-preservation test fix

- **WHAT:** Kept the WAL-resident corruption preservation test as POSIX coverage and added an explicit Windows skip explaining the live SQLite handle rename limitation. Retained the shared-byte helper so the POSIX test no longer relies on `File.ReadAllBytes`/`File.WriteAllBytes` defaults.
- **WHY:** The live pin connection is required to keep committed frames resident in `history.db-wal`; closing it lets SQLite remove/checkpoint the WAL before recovery can preserve it. But that same live handle blocks `File.Move(history.db, corrupt-*)` on Windows.
- **HOW:** Tried a copied main/WAL/SHM bundle, verified locally that SQLite deletes the restored WAL before `RenameAside` can move it, then restored the proven live-pin flow for POSIX and skipped only Windows for that invariant. Other public corruption recovery tests still cover Windows recovery without live WAL-resident frames.
- **IMPACT:** Avoids a false cross-platform assumption in the test while preserving meaningful WAL-bundle coverage where the setup is supported.
