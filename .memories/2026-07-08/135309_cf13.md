## Added Windows fast-suite hang diagnostics

- **WHAT:** Replaced the Windows `scripts/test.ps1 fast --no-build` workflow call with an inline bounded `dotnet test` invocation using `--blame-hang --blame-hang-timeout 120s --blame-hang-dump-type none`, and print any `Sequence*.xml` file on failure.
- **WHY:** The Windows suite now hangs or runs beyond both 10 and 15 minute job caps after v1.5.0 test growth. GitHub job timeout kills the process without identifying the active test.
- **HOW:** Preserve the same `Category!=Scale` filter and elapsed-time ceiling, but let VSTest terminate a per-test hang and write a blame sequence before the workflow exits.
- **IMPACT:** The next Windows CI run should provide the test sequence needed to identify the slow/hung test instead of requiring manual Windows debugging immediately.
