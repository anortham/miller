## CT `tests status` reported a dead daemon as running — found by dogfooding, fixed

Dogfooding the merged CT watermark work on main (`a75936b3`) surfaced a control-plane defect
that the branch gate could not catch, because no test covered a daemon that dies without a
clean shutdown.

### WHAT

`ContinuousTestDaemonHost.ReadStatus` returned the published `daemon.status.json` record
verbatim (`record?.State ?? Stopped`) with **no liveness probe** on the identity that record
names. A daemon that dies abruptly never rewrites the file, so its last `Running` record stays
on disk forever and every reader reports a watching daemon when nothing is watching.

The read is now split in two, mirroring the existing `CtDaemonLease.TryRead` / `TryReadLive` pair:

- `ReadStatus(root)` — unchanged, cheap, unprobed. The run-wait loop polls it every 50ms and runs
  its own probe on a slower clock; making every read probe would add ~12,000 process lookups to
  one full wait.
- `ReadLiveStatus(root, isLive = null)` — reads the record, then probes the identity it names
  (`record.Identity`, falling back to the lease for a record written before that field existed).
  A dead publisher yields `Stopped` / `"daemon gone"` / `activity: idle` / `run: null`.

`TestsCore.Status` — the reader behind MCP `tests`, the CLI, and the dashboard — now calls
`ReadLiveStatus`. The wait loop keeps the cheap read.

### WHY (observed live, not theorized)

The CT daemon (pid 30092) died when the old server was stopped to rebuild the Release binary.
Afterwards, against the very same files:

- `tests stop` returned `already_stopped` / `"no daemon"` — correct, it uses `TryReadLive`
- `tests status` returned `daemon: running, idle, running: true` — a lie, reproduced twice ~3 min apart
- `Get-CimInstance Win32_Process` showed no `miller.exe` except the server itself

An adopted worktree's record names the family daemon, so a dead family daemon read as running
from every worktree it served.

### HOW it was verified

Red-first: the new tests were run against a pass-through stub of `ReadLiveStatus` and failed
5 of 8 on assertions (not on compile), then passed 8 of 8 with the probe in place.

Live before/after on the identical on-disk files:

| reader | `daemon.state` | `reason` | `running` |
|---|---|---|---|
| running Release server (unfixed) | `running` | `idle` | `true` |
| Debug binary (fixed) | `stopped` | `daemon gone` | `false` |

The fixed reader still reports `running: true` for a genuinely live daemon, so the probe adds no
false negative.

### IMPACT

- The "honest status" invariant now holds across an abrupt daemon death — the common case on
  Windows, where the daemon runs from the build output and gets killed to free the locked binary.
- New file: `tests/Miller.Tests/Testing/Daemon/ControlPlane/CtDeadDaemonStatusTests.cs` (8 tests),
  including one that pins the cheap unprobed read so nobody "fixes" the wait loop's cost design.
- `docs/contracts/tests-cli-v1.md` documents that `daemon.state` is probed, not merely published.

### Second finding, NOT fixed

`CtDaemonLease` writes `miller_version` into `daemon.lease.json` and **nothing ever reads it for
a decision**. After a Miller upgrade the old daemon keeps running old code and status looks
healthy. The index leader has version-aware leadership as a documented load-bearing invariant;
CT has no equivalent. Left for a decision rather than fixed.

### Third finding, fixed separately

`WindowsKillOnCloseJobScaleTests` spawned real `powershell.exe` process trees with no window
suppression, so every scale run on Windows left visible console error boxes on the desktop
("the pipe is being closed", 0x800700e8 — teardown noise from the job-object kill the test
exists to prove). Added `CreateNoWindow` to the two `ProcessStartInfo` blocks and
`-WindowStyle Hidden` to the four `Start-Process` calls.
