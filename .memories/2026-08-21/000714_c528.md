## Fixed the broker host locator for CT's flat build layout — and the regression the first fix caused

**WHAT:** New `tests/Miller.Tests/Testing/SharedBrokerHostTestSupport.cs` replaces two copy-pasted `RequireBrokerHostExecutable()` locators (in `SharedSemanticBrokerConnectionFactoryTests` and `CliDispatchTests`).

**WHY:** First live CT run on merged main went red: 11 broker tests could not find `Miller.SharedBrokerTestHost` under `%TEMP%\miller-ct\build\...`. CT's dotnet provider builds with a global `-p:OutDir=`, flattening every project into one `out\` folder; the old locator only probed the repo-shaped tree four levels up.

**HOW:**
- `CandidatePaths` probes the test assembly's own folder first (flat layout), then the repo layout (`<config>`, Release, Debug).
- First fix caused 9 broker reds in the repo layout: the tests' output folder holds the host exe + deps.json + runtimeconfig **without the host dll** (ProjectReference has `ReferenceOutputAssembly=false`), and an apphost exe without its dll dies at launch — every handshake returned null at a uniform 10s timeout. Interference from concurrent suites was the first hypothesis; an isolated rerun refuted it.
- `Locate` therefore requires the companion dll beside the exe before accepting a candidate. Pure function, unit-tested for both layouts, the broken-sibling case, and trailing separators.

**IMPACT:** CT run on the merged tree: 0 failures (flat layout proven). Repo layout: 17/17 broker-side green, CliDispatchTests 225 passed / 7 skipped / 0 failed. Lesson repeated from memory: presence of an exe is not launchability — pin the binary you measure.
