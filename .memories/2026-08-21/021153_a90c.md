## Task 4: impacted/stale contract for CT selection

### WHAT
Landed the Task 4 contract of the CT watermark-freshness plan on `feat/ct-watermark-freshness`.

- `ContinuousTestSelectionContracts.cs`: new `ContinuousTestSelectionOutcome` enum (Unknown default / Impacted / KnownEmpty / WorkspaceScope) and `MayExecute` on `ContinuousTestSelectionResult`. Unknown is the enum default, so a caller cannot construct a runnable selection by accident.
- `ContinuousTestImpactSelector.cs`: path-scoped stale set = impacted IDs plus the already-owed backlog (store-stale rows and never-run cases). Known-empty impact stales nothing new. Truncated impact reads, unaccounted changed paths, and reachable-but-unrunnable evidence all fail closed to Unknown: stale everything, run nothing. Key-drifted greens are left to the Task 5 watermark.
- `ContinuousTestDaemonQueue.cs`: `_wholeSuiteEligible` keyed by pending key — WholeSuite collapse now requires workspace-scope origin AND full coverage; impact-derived all-known-ID selections travel as explicit ID lists. `!selection.MayExecute` returns before any foreground run or backfill. `EnqueueExplicit` trims committed-fresh cases with `DropCommittedFreshAt` before stale-marking, so an explicit run executes exactly the current stale set (this also fixes the daemon-host `run` command path).
- `TestsCore.cs`: comment only — the trim lives in the queue.

### WHY
The old selector fell back to workspace-wide staleness for any unmapped change, and the queue collapsed any full-coverage selection to `WholeSuite`. Both made an unknown impact indistinguishable from a deliberate full run, so a degraded index could silently trigger the whole suite.

### HOW
TDD: 11 new/updated selector tests red first, then implementation. Per-path accounting model decides Unknown: a changed path is accounted if it resolved to symbols, is project/config, is a harmless docs asset, matches a test-case file, or stem-matches; complete mapped hints also account for the delta. Unmappable-hint detection is name-scoped so project B does not stale on project A's edits.
