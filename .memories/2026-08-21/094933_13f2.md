## CT dogfood: watermark feature verified working; three defects found and fixed, two reported

Dogfooded the merged CT watermark work (main `a75936b3`) against the live repo with the
freshly built Release server, then had codex review the resulting fixes.

### The feature works

Measured on the real 7,835-case suite, one full identity migration and several edits:

- Baseline full run wrote **7,807 watermark rows**; green results then rode the watermark
  forward across revision advances without re-running.
- A one-line edit to a leaf test file produced a **debounced auto-run of 7 cases**, not 7,835 —
  about a 1,100x reduction — finishing in 30s.
- Freshness converged to `stale = 27 of 7,835`, and all 27 are `skipped` cases, which never
  advance by design.
- The "everything stale" readings seen mid-flight are the transient between a revision advance
  and the daemon applying the keep-set, not a defect.
- Legacy `ct.db` rows (pre-`ctgen1:` identity) read stale exactly once after the upgrade — the
  designed migration, pinned by `LegacyIdentityFreshnessTests`.

### Fixed

1. **`tests status` reported a dead daemon as running.** `ContinuousTestDaemonHost.ReadStatus`
   returned the published `daemon.status.json` record verbatim with no liveness probe. Split into
   `ReadStatus` (cheap, unprobed — the run-wait loop polls it every 50ms and probes on its own
   clock) and `ReadLiveStatus` (probes the identity the record names). `TestsCore.Status` now uses
   the probing read. Only an ACTIVE published state is probed, so a clean shutdown keeps its own
   `stopped` reason — that second half came from the codex review and was confirmed live.
2. **`CtCommandChannelTests`** had 2-second positive-wait bounds that went red under CT's own
   full-suite load while passing in 611ms alone. Replaced with a 30s `PositiveWait`.
3. **`ContinuousTestDaemonWorktreeAdoptionTests`** used attempt-count waits (400 x 10ms) whose real
   bound moved with thread-pool load, and `WaitForAsync` returned silently on timeout so every
   timeout surfaced as whichever assertion ran next ("Collection was empty"). Now wall-clock
   deadline based and throws a message naming what it waited for.
4. **`WindowsKillOnCloseJobScaleTests`** spawned real `powershell.exe` trees with no window
   suppression, leaving console error boxes ("the pipe is being closed", 0x800700e8) on the desktop
   on every Windows scale run. Added `CreateNoWindow` and `-WindowStyle Hidden`.

### Reported, NOT fixed (need a decision)

- **The CT daemon lease records `miller_version` and nothing ever reads it.** After a Miller
  upgrade the old daemon keeps running old code and status looks healthy. The index leader has
  version-aware leadership as a documented load-bearing invariant; CT has no equivalent.
- **The daemon recreates a deleted worktree root.** `TryWriteAdoptedStatus` guards only on
  `Directory.Exists(root)` while `CtDaemonJson.WriteAtomic` calls `Directory.CreateDirectory`, so
  writing the *detach* record recreates `<root>/.miller/ct/` under the root it just detached from.
  Observed live: it defeated `git worktree remove` cleanup twice.
- **codex finding 2 (medium, 0.92):** an adopted worktree can keep a dead predecessor family
  daemon's identity, because `TryWriteAdoptedStatus` marks `PublishedState` BEFORE writing, swallows
  write failures, and the adoption scan skips roots already in `_adopted` — so a failed write is
  never retried. `ReadLiveStatus` then probes the dead predecessor and reports stopped while a live
  replacement serves the worktree. Mechanism verified; closing it properly means resolving the
  family endpoint lease from the worktree, which is an adoption-design change.

### Suite flakiness (pre-existing, not from this change)

Four back-to-back full-suite runs each failed exactly one test, in a DIFFERENT subsystem each time
(worktree adoption, CT JSON sharing, semantic broker); every one passed in isolation. After
`dotnet build-server shutdown` and with CT stopped, the suite was fully green. Treat a single
moving failure across repeated runs as machine state, not as a regression.
