## Fix Antigravity Miller Tool Discovery & YAML Frontmatter

- **WHAT**:
  - Added `force_all_tools_eager: true` to Miller MCP server configuration in `~/.gemini/config/mcp_config.json`.
  - Updated `~/.gemini/config/hooks/miller-session-start.cjs` to dynamically resolve active workspace root from stdin, execute `miller workspace onboarding --workspace-id <workspacePath> --format compact`, and inject live telemetry, workspace guidance, and routing rules.
  - Quoted description frontmatter with `>-` in `miller-bridge-trace/SKILL.md` (.agents/skills and skills) to resolve Antigravity YAML parse errors.
- **WHY**:
  - Antigravity was rarely invoking Miller tools because they were lazily loaded behind `call_mcp_tool` while native tools (`grep_search`, `view_file`) were directly exposed.
  - The session start hook previously only read static guidance without providing the active workspace path or executing onboarding telemetry.
  - Antigravity failed to load the `miller-bridge-trace` skill due to unquoted colons in the description.
- **HOW**:
  - Configured eager loading for Miller in Antigravity.
  - Made the hook script robust against missing, relative, or multi-root workspace inputs, and gracefully fallback when telemetry is not yet available.
  - Validated with `/codex-cli` review and fixed edge cases identified during review.
- **IMPACT**:
  - Antigravity can now invoke Miller tools directly as eager tools.
  - Agents receive immediate workspace-specific onboarding telemetry and clear `workspace_id` guidance at session start.
  - All skill definitions load cleanly without YAML syntax errors.
