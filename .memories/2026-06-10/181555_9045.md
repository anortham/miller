## Fixed Cursor plugin-cache workspace fallback

Miller could silently use its own plugin/cache directory as the workspace root when Cursor started the shared MCP process without workspace folders.

- **WHAT:** Updated `bin/miller-plugin-launcher.cjs` so known plugin install/cache roots are treated as unsafe fallback cwd values, and added regression coverage in `tests/plugin/miller-plugin-launcher.test.cjs`.
- **WHY:** Cursor was open in `/Users/murphy/source/julie-extractors`, but its MCP process launched Miller from the Claude plugin cache with no workspace env. Miller then indexed the plugin/cache directory, so searches with `file_pattern=crates/julie-extractors/src/**` showed Miller/plugin-cache results.
- **HOW:** Added plugin/cache root detection for `~/.claude/plugins/cache`, `~/.codex/plugins/cache`, `~/.cursor/plugins/cache`, `~/.cursor/plugins/local`, and `~/.miller/plugin-cache`; preserved explicit workspace env precedence; changed no-workspace plugin-cache fallback into a clear startup error.
- **IMPACT:** Future Cursor reloads should fail with guidance instead of indexing Miller's own plugin cache. Synced the patched launcher into the local Cursor plugin copy and Claude Miller plugin caches after updating the installed Claude plugin to `0.3.6`.
