## Implemented gate-time stale self-heal + cross-process single-file converge (fixes 1 & 2)

**WHAT:** The `edit` freshness gate now self-heals instead of refusing immediately, and readers can hand the leader targeted single-file reindex requests.

**HOW (TDD, 11 new tests RED→GREEN, +2 helpers):**
- `IEditWriteThrough.TryRecoverStaleFile(path)` → `StaleRecoveryAttempt {None|Converged|Requested}`; default interface method returns None so test fakes keep old refuse-immediately behavior.
- `LeaderWriteThrough`: leader → `TryReindexAsLeader` inline (Converged); reader → writes a `.file-converge.json` request via `LeaderScanRequestQueue.RequestFileConverge` (Requested). `Converge` (post-apply) now also writes one batched request when not leader instead of a pure no-op.
- `LeaderScanRequestQueue`: new `RequestFileConverge`/`DrainFileConvergeRequests` (same atomic-write/dedupe/malformed-delete discipline as full-scan requests; suffixes keep the two kinds separate).
- `IndexerService` tick: `TryProcessFileConvergeRequests` drains and reindexes each path; non-leader never drains (would lose requests).
- `EditService.TryRecoverFreshness`: Converged → one immediate gate re-check; Requested → poll every 150ms within a 2.5s budget SHARED across all files of one Execute (rename loop can't stack waits). `RecoveryOptions` injectable for tests.
- Updated `edit` tool description + MILLER_AGENT_INSTRUCTIONS.md.

**VERIFIED:** fast suite 1874/1874 (~8s), scale suite 25/25 (real julie-extract), 0 warnings.

**IMPACT:** A Miller `edit` right after a file change no longer fails with "index stale for X" in the common case — leader sessions converge synchronously; reader sessions converge within ~1 leader tick (1s) + extract, inside the 2.5s gate budget. Read-tool (search/inspect) poll latency and timing tightening (fixes 3/4) intentionally not done yet.
