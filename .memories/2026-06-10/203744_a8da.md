## Task B: Sidecar converge corrupt-escalation (M5)

**WHAT:** `IndexerService.TryConvergeSidecar` now escalates a corruption-shaped converge failure (for either `search.db` or `content.db`) to delete-the-artifact + one full rebuild within the same converge call.

- New `TryRebuildCorruptSidecar(failure, artifactPath, rebuild)`: corruption-shaped ⇒ warn with the artifact path, `ClearAllPools`, delete the file, run a full `EnsureBuilt` once. Rebuild failure ⇒ warn and fall back to the existing warning path. One escalation per converge attempt, no loop.
- New `IsSidecarCorruption(ex)`: walks the exception chain for `SqliteException` with result code SQLITE_CORRUPT (11) or SQLITE_NOTADB (26) — primary or extended (low byte) — or the sidecar readers' MalformedMeta `InvalidOperationException` (matched on the "has malformed meta" marker; the sidecar layer has no bespoke exception type).

**WHY:** The one corruption shape that persists is *meta readable but FTS body corrupt*: `EnsureBuilt`'s revision gate sees a fresh revision and no-ops (or `EnsureCurrent`'s incremental `ApplyFileChanges` throws SQLITE_CORRUPT every 250ms converge), warning forever while every reader gets the stale-sidecar error. Fully-garbage artifacts already self-heal (temp-build + move never opens the old file).

**KEY DISCOVERY:** Deterministic corrupt fixture = `DELETE FROM symbols_fts_data` (FTS5 shadow table): meta stays readable at the old revision, any later FTS write throws "database disk image is malformed" (verified with sqlite3 CLI first). Non-corrupt control = `DROP TABLE symbols_trigram` ("no such table", SQLITE_ERROR 1) — must NOT trigger delete/rebuild.

**VERIFIED red/green:** with the fix stashed, the corrupt test fails and the non-corrupt test passes; with the fix, both pass. Fast suite 1929/1929 green.
