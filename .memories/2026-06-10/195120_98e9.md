## Multi-agent review of Miller post-freshness work — findings

Ran a 3-reviewer sweep (recent freshness commits, dogfood UX failures from TODO.md tail, broad risk sweep) after the v0.3.6 freshness/leader-identity work landed.

### Top finding (HIGH, verified by lead)
**Gate-time self-heal applies a stale-span edit plan.** `EditService.cs` pipeline: `ReadEditSpan` reads spans from the stale index (line 153) → plan spliced (line 206) → gate finds stale → `TryRecoverFreshness` converges the index (line 232) → **pre-recovery plan applied unchanged** (line 237). If drift shifted symbol offsets (lines added above the target), wrong bytes get rewritten silently. All existing recovery tests drift by *appending*, so spans never shift. Fix: re-resolve+re-plan after recovery, or refuse symbol ops with "index converged — retry now".

### Medium findings
- **LeaderIdentityFile.IsProcessAlive** (lines 75–86): `Process.HasExited` can throw `Win32Exception` on Windows pid reuse by elevated process → crashes `workspace health`; pid reuse also fakes "alive". Broaden catch + cross-check StartTime.
- **Converge requests undrainable by old leaders**: no TTL/cap on `.miller/requests/*.file-converge.json`; stale-binary leader never drains → every edit burns full 2.5s poll. Short-circuit via leader.json version/liveness check.
- **Double extract per reader edit**: converge request + FSW event for same file on same 250ms tick → two julie-extract runs. Route drained requests through the WatchEventQueue for coalescing.
- **Drain delete-failure retry storm**: `TryDelete` swallows IOException silently; Windows AV holding file → re-extract every 250ms (full scan per tick in the full-scan variant). Claim-by-rename before servicing.
- **Sidecar converge failure warns forever** (`IndexerService.TryConvergeSidecar` ~475–545): no corrupt→delete-and-rebuild escalation; refresh re-enters same failing path.
