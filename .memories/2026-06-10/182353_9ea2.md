## Widened Cursor launcher unsafe-cwd guard to whole plugin trees

**WHAT:** Reviewed the pending launcher fix (reject plugin/cache dirs as Miller workspace cwd, fail loudly when no workspace root is available) and found a gap: the unsafe-root list only covered `cache`/`local` subdirectories, but real installs also include full repo clones under `~/.claude/plugins/marketplaces/miller` and `~/.cursor/plugins/marketplaces` — Cursor's Claude-plugin import can launch from those and the old list let them through.

**HOW:** `pluginInstallRootCandidates` in `bin/miller-plugin-launcher.cjs` now treats the whole `~/.claude/plugins`, `~/.codex/plugins`, and `~/.cursor/plugins` trees (plus `~/.miller/plugin-cache`) as unsafe. Added a regression test for the marketplaces-clone path; updated the findings doc. Note: because every `resolveLaunchCwd` candidate (including env-provided ones) passes through the same guard, even an explicit `MILLER_WORKSPACE_ROOT` inside a plugin tree is refused — intentional.

**VERIFIED:** 13/13 launcher tests pass (`node --test tests/plugin/miller-plugin-launcher.test.cjs`); fast .NET suite 1861/1861 via `scripts/test.sh`. Synced the updated launcher into the installed copy at `~/.cursor/plugins/local/miller/bin/` so the fix is live on next Cursor reload.

**IMPACT:** Cursor empty/global-window launches can no longer silently index Miller's own plugin/cache/marketplace directories; they fail with guidance instead. Remaining manual step: reload Cursor, confirm the duplicate Claude-imported plugin source is removed, and verify a project window launches Miller with the correct workspace root.
