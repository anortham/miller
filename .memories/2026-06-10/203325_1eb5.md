## Task A: Request-queue hardening — TTL, claim-by-rename, leader short-circuit, coalesced drain (M2/M3/M4)

**WHAT:** Hardened the cross-process converge request machinery (`.miller/requests/*.json`) in `LeaderScanRequestQueue`, `LeaderWriteThrough`, and `IndexerService`.

- **TTL (M2-drain):** requests older than `RequestTtl` (10 min, stamp parsed from the file name, last-write fallback) are deleted without servicing; both full-scan and file-converge drains; leftover `.claimed` files swept too. Drains now return `FullScanDrainResult`/`FileConvergeDrainResult` records carrying expired/skip counts the leader logs.
- **Claim-by-rename (M4):** a drain claims each request via `File.Move(path, path + ".claimed")` before servicing; move failure ⇒ skip this tick (never service unclaimed). IndexerService logs the first claim-skip at Warning, repeats at Debug (`_requestClaimSkipWarned`).
- **Leader short-circuit (M2-writer):** `LeaderWriteThrough.TryRecoverStaleFile` now consults `LeaderIdentityFile.TryRead` + `IsProcessAlive(identity)` before writing a request: identity absent or leader dead ⇒ `StaleRecoveryAttempt.None` immediately (no fruitless 2.5s gate poll); probe-throw ⇒ assume capable. Internal ctor gains an injectable `Func<LeaderIdentity,bool>` probe (LeaderIdentityFile precedent).
- **Coalesced drain (M3):** `TryProcessFileConvergeRequests` now enqueues drained paths as synthetic `WatchEvent(path, Modified)` into the core's coalescing `WatchEventQueue` instead of calling `TryReindexAsLeader` directly — request + watcher event for the same file collapse into ONE extract on the same 250ms tick.

**WHY:** Readers' converge requests could rot forever under an old-build leader, undeletable requests were re-serviced (one julie subprocess) every 250ms, stale-gate edits burned the full recovery poll with no live leader, and each reader edit cost two extracts (request + watcher event).

**KEY JUDGMENT CALL:** No version-number capability check. `Directory.Build.props` is still `0.3.6`, so a pre-drain v0.3.6 release build and a post-drain dev build have identical numeric versions (only the git-SHA suffix differs). Instead: leader.json itself shipped in ea023cc, AFTER the file-converge drain (fa78c49) — verified via `git log -S` — so *any identity-writing leader can drain these requests*; identity presence IS the capability signal.

**M3 convergence guarantee preserved:** the debounce loop calls `TryProcessFileConvergeRequests` (enqueue) immediately before `_core.DrainAndProcess` on the SAME tick, so converge latency is unchanged; queue overflow (>1000 distinct paths) sets NeedsRescan which forces a whole-repo scan on that same drain — converge still lands, never dropped.

**IMPACT:** fast suite green 1927/1927 (~11s); 42 focused tests across LeaderScanRequestQueueTests/LeaderWriteThroughTests/IndexerServiceScanTests including new TTL, claim-skip, short-circuit, warn-once-then-debug, and one-extract-coalesce pins.
