## Implemented leader-served full-scan requests

The remaining `workspace full` lock-busy gap now has a Windows-safe request path instead of requiring users to kill the lock-holding server process.

- **WHAT:** Added a file-backed leader full-scan request queue under `.miller/requests/`, wired `CrossWorkspaceRefreshService` to write a request when `force=true` and `indexer.lock` is busy, and wired `IndexerService` to drain requests and run `Scan(force: true)` under the existing `_opsGate`.
- **WHY:** A one-shot CLI must not acquire a second writer or weaken `SingleWriterLock`, but users need a recovery path when a healthy MCP/server process owns the lock.
- **HOW:** The CLI atomically writes unique `*.full-scan.json` request files. The leader polls the request directory on its debounce tick, consumes valid requests, runs the existing force-scan path, converges sidecars, and the CLI polls for a readable revision advance. Delta refresh remains unchanged and does not request force scans.
- **IMPACT:** `miller workspace full` can now succeed while a new-enough server owns the writer lock; Windows users should not need task-kill workflows for this recovery path. The currently running leader still must be restarted onto this build before it can drain requests.
