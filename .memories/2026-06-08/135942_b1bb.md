## Fixed v0.3.0 package-only Native AOT release blocker

The first package-only release validation for `0.3.0` failed because the release workflow's Native AOT publish path caught reflection-based JSON serialization in `LeaderScanRequestQueue`.

- **WHAT:** Switched full-scan request file serialization/deserialization to source-generated `System.Text.Json` metadata and added `AotSerializationConventionTests` to keep this release-only failure from returning.
- **WHY:** Normal `dotnet build` and functional tests passed, but Native AOT publish fails on reflection-based JSON overloads when `JsonSerializerIsReflectionEnabledByDefault=false`.
- **HOW:** Added a red convention test for the problematic overloads, made `LeaderScanRequestQueue` partial, nested a source-generated JSON context beside its private request record, and updated the release-prep review with the failed run and root cause.
- **IMPACT:** Local AOT publish now succeeds and emits the expected `miller` binary, so the package-only workflow can be retried on the fixed commit.
