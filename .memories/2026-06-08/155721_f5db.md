## Added Windows release MCP smoke coverage

After pulling `v0.3.1`, the cross-platform sweep found the Windows release package verification only ran `julie-extract.exe --version` and `miller.exe version`, while Unix packages also exercised `miller serve` with an MCP `tools/list` smoke.

- **WHAT:** Added a PowerShell `miller.exe serve` smoke to `.github/workflows/release.yml` and pinned it in `MillerExtractContractTests`.
- **WHY:** Windows-specific release fixes need package validation that proves the packaged server can initialize and expose every MCP tool, not just print the version.
- **HOW:** Reused the Unix JSON-RPC initialize/initialized/tools-list pattern with a 20s stdin hold and stderr capture for useful failure logs.
- **IMPACT:** Future Windows releases should catch packaged MCP startup/tool-registration regressions before publication.
