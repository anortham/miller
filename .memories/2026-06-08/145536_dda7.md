## Fixed Windows MCP launch failure + drive-root safety bug (2 path-canonicalization bugs)

User's miller plugin (v0.3.0, installed at user level) failed in `/mcp` from `c:\source\AccessIQ` and failed to reconnect.

### Bug 1 (reported) — perpetual force-scan on Windows
- **Root cause:** julie-extract (Rust `std::fs::canonicalize`) records `artifact_metadata.root_path` WITH the Windows extended-length verbatim prefix (`\\?\C:\source\AccessIQ`); Miller's `PathCanonicalizer.CanonicalizeRoot` (`Path.GetFullPath`) produces it WITHOUT (`C:\source\AccessIQ`). `IndexBootstrapService.RootPathsEqual` compared them **ordinally** → never equal on Windows → `DecideBootstrapScan` returned `Force=true` every launch.
- **Why it failed hard:** timed `julie-extract 2.1.3` — cold scan **3.2s** vs `scan --force` **35.6s** (11x). Bootstrap blocks `StartAsync` until the scan finishes, so the server never answers `initialize`; Claude Code's MCP client times out at ~30s and kills the transport → "failed". First launch worked (no DB → cold scan).
- **Fix:** added `PathCanonicalizer.StripWindowsVerbatimPrefix` (strips `\\?\` and `\\?\UNC\`); `RootPathsEqual` now strips both operands and compares case-insensitively on Windows / case-sensitively on POSIX before equality.

### Bug 2 (found while running the suite, pre-existing — user approved fixing) — drive-root safety bypass
- **Root cause:** `PathCanonicalizer.ResolveExistingPrefix` trimmed `C:\` → `C:` (drive-RELATIVE) for a bare root with no path parts. `Path.GetFullPath("C:")` then re-resolves to the per-drive CWD, so `workspace open C:\` slipped past `WorkspaceRootSafety.IsSensitiveRoot` (exit 3 missing-tool instead of exit 2 refused). Bootstrap path was safe (checks raw cwd before canonicalizing).
- **Fix:** `ResolveExistingPrefix` early-returns the root verbatim when `parts.Length == 0`.
