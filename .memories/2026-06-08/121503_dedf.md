## Fixed incremental search sidecar doc_id collision

A live Miller leader was holding `.miller/indexer.lock`, but the actionable failure was that search sidecar convergence repeatedly crashed under that lock.

- **WHAT:** Added a regression test and fixed `SearchIndexWriter.AssignStableDocIds` so incremental file-change convergence reserves old `doc_id` values for symbols that still exist before assigning reusable IDs to new symbols.
- **WHY:** Logs showed repeated `SQLite Error 19: UNIQUE constraint failed: search_symbols.doc_id`, leaving `.miller/search.db` stale at revision 1363 while `symbols.db` reached revision 1453.
- **HOW:** Root cause was ordering-dependent allocation: a new earlier symbol could consume an old reusable `doc_id` before a later existing symbol reused its reserved old ID. Reusable IDs now come only from old symbols absent from the current changed-file symbol set.
- **IMPACT:** Incremental search sidecar convergence should stop failing with duplicate `doc_id`; Miller search/inspect tooling can recover once the running old leader process is restarted or replaced with the fixed binary.
