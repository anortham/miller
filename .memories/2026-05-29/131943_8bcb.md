## Miller toolbox design locked (7 tools) + day-1 telemetry mandate

Settled the agent-facing MCP tool surface for **Miller** (the .NET personal/local tier replacing julie). Persisted full spec to `docs/findings/miller-toolbox.md`.

**The 7 tools** (by area, mode-param only where sub-behaviors differ, most-common op defaulted):
- `search` (find code), `inspect` (file→symbols / symbol→deep-dive, absorbs julie get_symbols+deep_dive = ~44% of calls), `context` (task-anchored token-budgeted bundle), `trace` (refs + call paths + **cross-language bridge = the differentiator**), `impact` (blast radius), `edit` (preview-first, freshness-gated), `workspace` (admin).

**Key decisions:**
- **Smart-string targets, NOT JSON-object/dict selectors** — user confirmed from experience that object params cause agent confusion + wasted tool calls. Server infers path vs symbol-name vs id; optional `scope`/`as` override for rare collisions.
- **deep_dive folds into `inspect`, NOT into `context`** — julie telemetry showed deep_dive (symbol-anchored, fast, 2,695 calls) and get_context (task-anchored, 439ms/1.2s p95, 768 calls) are different intents with 6x latency gap.
- **Speed drives adoption** — julie's 2 slowest tools (get_context, blast_radius 5s p95) were its 2 least-used. So Miller's `context` and `impact` MUST be fast (precomputed transitive closure for impact) or they go vestigial.
- **Memory stays separate** (use goldfish); codesearch's `MemoryTool.cs` marked for removal from Miller scope.

**Telemetry = day-1 requirement** (user explicit): per-call ledger (tool, op, duration→p95 histogram, bytes_examined, bytes_returned + est_tokens = north-star KPI, index_fresh) in an append-only SQLite `tool_telemetry` table feeding a dashboard that reproduces julie's tool-breakdown screen. Build on existing Serilog (commit e208a0a). Verify MCP C# SDK has a tool-invocation filter hook for the central interceptor.
