## Decision: Miller commits NO fixture DBs or binaries — extraction is julie's to test

**WHAT:** Dropped the 64 MB `julie-snapshot/symbols.db` fixture (and its 12,964-line metadata.json manifest), purged the blob from all git history via `filter-branch`, and force-pushed. `.git` shrank 32M → 1.4M. Reversed the earlier "vendor/commit the julie-server binary (LFS)" plan.

**WHY (the principle):** Extraction correctness is **julie's responsibility** — julie owns the extractor tests. Miller consumes julie-server's SQLite output and trusts the *schema contract*. Miller must NOT re-test that julie extracts symbols correctly. Therefore Miller needs no large committed corpus.

**HOW (Miller's testing model, now canonical in docs/miller-mvp-plan.md):**
- `Miller.Core` (index/BM25/resolver): unit-tested against **in-memory contract objects** — no DB at all.
- `Miller.Indexing` (SQLite read layer): tested against a **tiny schema DB synthesized in test setup** (Microsoft.Data.Sqlite, ~a dozen known rows). Verifies "Miller maps julie's schema → Miller types correctly," and doubles as executable documentation of the schema contract.
- Scale/perf corpora (tagged `Category=Scale`, excluded by default): generated on demand, never committed.

**Binary sourcing:** julie-server is **fetched from julie's GitHub release** at restore time into a gitignored `.tools/` — never committed. No Git LFS anywhere; git stays lean.

**IMPACT:** Repo is small and stays small (a stated Miller value). No LFS dependency for cloners/CI. Shapes ALL of Miller's test design going forward.

**Verification:** blob unreachable post-gc; rewritten `main` references no symbols.db; remote `anortham/miller` main = 31ead7c, no large-file warning on push; working tree clean.
