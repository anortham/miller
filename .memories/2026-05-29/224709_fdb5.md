## M6 complete — `edit` tool (preview-first, freshness-gated)

Built the seventh Miller tool: byte-exact source edits with a preview-first, freshness-gated, all-or-nothing apply path. Built TDD by layer (Core pure logic -> Indexing read extension -> Server infra/surface), then a 5-lens adversarial review + verify + fix pass.

- **Surface:** `edit` with operations replace_text, replace_symbol_body, replace_symbol_signature, rename_symbol, insert_before/after, add_doc; dry_run default true (preview), apply default false, allow_stale default false, plus `scope` (matches the design-doc edit).
- **Core (pure, no I/O):** TextSplicer (byte-span splice), EditPlanner, RenamePlanner (workspace-wide name-based exact-span), UnifiedDiff.
- **Infra:** EditApplier (writer-locked, TOCTOU re-check, atomic, rollback), EditWriteLock (dedicated `edit.lock` so it never deadlocks the indexer leader), FreshnessGate (files.content vs disk via SHA256), LeaderWriteThrough -> IndexerService.TryReindexAsLeader (inline reindex if leader, watcher backstop otherwise).
- **Read extension:** ExtractReader gains edit-span + identifier-site reads; new `IdentifierSite` record (absolute UTF-8 byte tokens from julie's identifiers table, name-based because target_symbol_id is NULL at extract).

- **Review:** 6 findings, all 6 fixed with red-checked tests. Top one (high): RenamePlanner was leaking TextSplicer exceptions, breaking its pure-result contract -> now returns RenamePlan.Failure. Others: degenerate [0,0) span guards on insert/add_doc, multi-file rename failure now still reports the freshness verdict, scope param documented (not removed), misleading comments.

- **Verified green on the real tree:** build 0/0; 544 default tests (804ms, <10s budget); 7 live Scale tests against pinned julie-server v7.12.2.
