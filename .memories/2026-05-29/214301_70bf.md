## Miller M3 complete — freshness: watcher + revision-poll + index hot-swap + mutation-gate primitive

M3 built TDD via a 4-phase workflow (build-by-layer → 5-lens adversarial review → adversarial verify → fix+gate). Independently re-verified green.

### What shipped
- **Pure freshness logic (Miller.Core/Freshness):** `WatchEventQueue` (per-path coalescing merge state machine + bounded overflow→NeedsRescan, ported from julie queue.rs), `WatchEventRouter` (events + injected exists-predicate → ordered ExtractOp {Update|Delete|Scan}), `StalenessCheck` (hash + exact-text, mtime deliberately excluded — the M6 mutation-gate primitive). Zero I/O.
- **Indexing infra:** `PathCanonicalizer` (symlink-resolved paths — the verified delete-outside-root trap), `JulieExtractRunner.Update/Delete` + `ExtractReport` {Revision,FilesUpdated,FilesDeleted,WorkspaceId}, `FreshnessReader` (`SELECT MAX(revision) FROM canonical_revisions WHERE workspace_id`, no lingering txn), `IndexHolder` (volatile (index,revision) pair — atomic lock-free swap), `SingleWriterLock` (cross-process leader election), `SqliteReadOnlyAccess` (shared D4 read discipline).
- **Server hosting:** `IndexerService` (leader-gated FileSystemWatcher on canonical root + .git/HEAD watch + ~1s debounce drain → route → extract; FSW Error→rescan), `FreshnessService` (poll revision → rebuild → swap, ALL instances). Pure cores extracted (IndexerCore, FreshnessPoller, FreshnessState, JulieExtractOps, WatchPathFilter, WatcherEventMapper, IndexRebuilder, IndexFreshProbe) with thin untested BackgroundService shells. Tools repointed to IndexHolder.Current; index_fresh populated.

### Topology decision (user, 2026-05-29)
Leader-elected in-process watcher: each `miller` tries a cross-process lock; the holder runs the watcher, others are pure readers polling canonical_revisions + hot-swapping. julie-server subprocess is the actual DB writer (separate/optional — death degrades freshness not reads). Chosen for unknown-multi-user product reality over a separate indexer binary or uncoordinated per-server watchers.

### Adversarial review caught 6 real defects (3 high), all fixed root-cause + red-checked tests
- F1 (high): DB path used lexical Path.GetFullPath, not symlink-resolved — the exact verified-fact-4 trap. Canonicalize once at bootstrap; guard Update/Delete.
- F5 (high): ReadLatestRevisionOrZero swallowed InvalidOperationException + SqliteException — narrowed to FileNotFound only; propagate the rest (decision-10).
- F6 (high): IndexerCore not outcome-aware on extract exit-1 — now branches on error code (data_loss_guard/flock_timeout→Info keep-prior; else→Error loud).
- F2 (med): ExtractReader missing D4 writable-dir probe → shared SqliteReadOnlyAccess. F4: ledger-leak on partial bootstrap → try/dispose. F3: comment.

### Verified facts (live probe, pinned v7.12.2 schema 26)
canonical_revisions exists in schema 26; `update`(changed)/`delete` bump revision, no-op doesn't; revision_file_changes gives the changed-file delta. Symlink-resolved paths required for delete.
