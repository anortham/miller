## Completed Phase 2 content corpus routing

- **WHAT:** Routed `mode=content` through the content corpus sidecar while preserving the legacy content result shape. Docs and config files are now stored in `content.db` as `workspace_docs` and `workspace_config`, and source-body hits remain excluded from content mode.
- **WHY:** Content search needed to share the same FTS-backed corpus as source search so docs/config/source text all come from one durable raw-content store instead of the old in-memory docs projection.
- **HOW:** Added workspace content-kind classification, made `ContentCorpusWriter` index docs/config rows, added multi-kind text content search, introduced `SearchTool.RunContentCorpus`, switched MCP and CLI content mode to `ContentCorpusSidecar`, and expanded tests for routing, JSON compatibility, source exclusion, and sidecar-only CLI reads.
- **IMPACT:** Phase 2 of the content corpus plan is implemented and verified; this unblocks the later large-file/log and web/Eros semantic-search phases from using the unified corpus model.
