## Fixed post-push CI failures for search recovery work

The first pushed commit passed local checks but failed GitHub Actions in plugin metadata and Windows fast-suite jobs.

- **Root cause:** `bin/miller-plugin-launcher.cjs` was required by plugin distribution tests but the root `bin/` directory was globally ignored, so the launcher never reached CI.
- **Root cause:** `RestoreScriptPythonFallbackReadsArchiveInnerPathTemplate` exercised POSIX shell restore-script fallback code through `python3` on Windows, where the default suite timed out.
- **Fix:** Explicitly unignored and staged only the root plugin launcher, preserving the broad build-output ignore.
- **Fix:** Matched the adjacent restore-script regression test by skipping this POSIX shell fallback contract test on Windows.
- **Verification:** `scripts/test-plugin.sh`, `npx -y node@22 --test tests/plugin/*.test.cjs`, targeted .NET test, `scripts/test.sh`, `git diff --check`, and `dotnet build Miller.slnx -c Release --no-restore` all passed locally.

## Impact

The pushed search-quality/search-recovery work now carries the missing release launcher asset and should no longer fail the Windows fast job for a Unix-only restore-script contract.
