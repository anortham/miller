## Published Miller v0.2.0 and fixed the slow release path

Miller `v0.2.0` is now published as a stable GitHub release, and the release process no longer requires rebuilding the full platform matrix just to publish already-validated artifacts.

- **WHAT:** Published `v0.2.0` with all four platform archives and checksum sidecars, then committed/pushed a release workflow improvement.
- **WHY:** The previous release flow was too slow and frustrating because package validation and publication were tangled; publishing could require repeated full matrix work and manual promotion steps.
- **HOW:** Promoted artifacts from successful package-only run `27108158452`, added `scripts/release-promote.sh`, added `promote_run_id` support to `.github/workflows/release.yml`, documented the two-step validate/promote process in `docs/release-process.md`, updated plugin manifests to `0.2.0`, and removed stale release-candidate README wording.
- **IMPACT:** Future releases can validate packages once, then publish by promoting the successful run ID. This keeps release safety checks while reducing repeat release time and avoiding another 30-60 minute manual loop.
