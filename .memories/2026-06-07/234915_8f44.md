## Published v0.2.0 and streamlined release promotion

- **WHAT:** Published the Miller `v0.2.0` GitHub release from the successful package-only run artifacts and added a promote path for future releases.
- **WHY:** The release flow was taking too long because publishing required repeated manual steps and could rerun the full cross-platform package matrix.
- **HOW:** Created `scripts/release-promote.sh`, wired `.github/workflows/release.yml` to accept `promote_run_id`, added `docs/release-process.md`, updated plugin manifests to `0.2.0`, and replaced stale release-candidate README language.
- **IMPACT:** Future releases can validate packages once, then publish by promoting that successful run without rebuilding all target archives.
