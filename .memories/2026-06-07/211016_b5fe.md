## Completed content corpus Phase 5 Eros JSONL feed

- **WHAT:** Added `ContentCorpusExportReader` plus `content export` support through the MCP tool and CLI. The export emits deterministic JSONL chunk rows over `.miller/content.db` for Eros and other local consumers.
- **WHY:** Eros needs a stable, deterministic feed of source/docs/config/external/web chunks with freshness metadata without Miller adding embeddings, vector storage, or Eros-specific runtime dependencies.
- **HOW:** Implemented a read-only SQLite export over `content_chunks` joined to `content_sources` and `content_meta`, ordered by `content_kind`, `display_path`, `line_start`, and `chunk_id`. Rows include schema version, workspace id/revision, source/chunk ids, path/url/display path, spans, source hash/status/timestamp, raw chunk text, doc length, test flag, and containing-symbol metadata. Added `--kind` and `--content-workspace-id` filters, contract docs, README/instruction updates, and tests across reader/tool/CLI.
- **IMPACT:** Phase 5 provides the semantic-ingestion feed Eros can consume while preserving Miller's embedding-free boundary.
