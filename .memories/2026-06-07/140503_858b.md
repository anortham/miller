## Checkpointed search sidecar freshness work and dashboard status check

- **WHAT:** Captured the completed Miller search sidecar freshness changes plus the follow-up discovery that the dashboard already exposes sidecar status.
- **WHY:** Future sessions need the current architectural state: `search.db` is now maintained incrementally and enabled sidecar reads fail visibly instead of silently falling back to memory.
- **HOW:** The sidecar now uses explicit `doc_id`, `EnsureCurrent` consumes `revision_file_changes`, `IndexerService`/`CrossWorkspaceRefreshService` converge the sidecar after scans and single-file updates, `WorkspaceIndexProvider` requires a fresh disk sidecar when enabled, and `workspace status` renders structured sidecar facts. Dashboard already reads and displays `search_sidecar_status` through `DashboardIndexFactsReader` and `WorkspaceDetailPanel`.
- **IMPACT:** The stale-sidecar class is no longer hidden. Operators can see sidecar state in `workspace status` and a simpler label in the dashboard. Remaining possible follow-up: dashboard could be upgraded from a label-only status to the richer revision/expected-revision details now available in workspace status.
