## Fixed hidden search sidecar drift found during TODO architecture review

Closed the TODO architecture follow-up for hidden indexing/search issues by finding and fixing three concrete sidecar edge cases.

- **WHAT:** Made trigram-only candidate windowing deterministic by ordering FTS candidates by stored `search_symbols.doc_id`, not mutable FTS row order.
- **WHAT:** Preserved qualified parent-child trigram recall during incremental single-file sidecar updates by letting `SearchIndexWriter` load unchanged ancestor metadata from existing `search_symbols` before inserting changed symbols.
- **WHAT:** Tightened `FtsSymbolSearchIndex` metadata validation and `SymbolSearchSidecar` freshness peeking so duplicate/malformed `meta` rows fail closed and trigger a rebuild instead of being accepted at the same revision.
- **WHY:** The review started from the prior `doc_id`/rowid sync class. The old explicit `doc_id` fix was present, but adjacent hidden drift remained in FTS window ordering, incremental qualified trigram text, and metadata freshness checks.
- **HOW:** Added failing tests first for row-order churn, incremental unchanged-parent qualified trigram recall, duplicate meta rejection, and duplicate meta rebuild. Then patched the reader/writer paths with scoped changes.
- **IMPACT:** Search sidecar behavior now stays closer to full rebuild semantics after incremental updates, and corrupt same-revision sidecars self-heal instead of staying silently unusable.
