## Telemetry polish slice

- **WHAT:** Added a central per-tool-call diagnostic log line from `TelemetryCallToolFilter` so every MCP tool call has at least one JSONL log row carrying the same `cid` as `tool_telemetry.id`. Added a focused regression test using a silent tool body to prove the filter, not tool-body logging, creates the correlated log line.
- **WHAT:** Improved symbol-search empty output from bare `No results.` to a one-line hint pointing agents toward shorter symbol queries or explicit `mode=source` / `mode=content` searches.
- **WHAT:** Added `docs/findings/2026-06-16-tool-usage-telemetry-baseline.md` with the machine-global telemetry baseline, error groups, empty-result groups, storage-location caveats, and reproduction SQL.
- **WHY:** The telemetry review showed heavy `inspect`/`search` usage, many empty results, and historical error rows that could not be joined to logs. Live logs had no `cid` for normal tool calls unless a tool body logged inside the call.
- **HOW:** Used TDD: first observed `CorrelationFilterTests.ToolCall_WithNoToolBodyLogs_WritesOneJsonlLineWithTheTelemetryCid` fail because no JSONL line existed, then added the filter diagnostic line. Also observed `SearchToolTests.Run_Empty_ReturnsNoResultsSentinel` fail against the old terse output before adding the symbol-search hint.
- **IMPACT:** Future error triage can join telemetry rows to workspace-local logs by `cid`, and common search misses now give agents a practical next move without increasing server-instruction or tool-description text.
