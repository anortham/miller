## Tightened handoff skill drift contracts

### WHAT

Addressed external review findings in the Miller handoff skills on `main`. `handoff-out` now records the actual JSON workspace status fields `index_built_revision` and `index_latest_revision` from `index.built_revision` / `index.latest_revision`, and `handoff-in` now requires comparing the actual changed-file lists from `git status --short` and `git diff --name-only` before reporting `safe-to-resume`.

### WHY

The previous skill text used a synthetic `index_revision` field and treated `dirty_state` as enough to validate local changes. That could make receiving agents silently trust stale impact/context when the workspace was still dirty but the changed files differed.

### HOW

Added plugin regression assertions to reject the old `index_revision` literal, require the two real revision fields, and require changed-file list guidance. Updated canonical `.agents/skills/` docs, synced `skills/`, and refreshed the dogfood note to mention the tightened validation.

### IMPACT

The handoff packet contract is less ambiguous before release and better aligned with live `workspace(status, format="json")` output. `handoff-in` now treats dirty-state equality as insufficient without matching changed-file lists.
