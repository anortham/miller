### BLOCKER: trace refs paging is lossy
TraceTool.cs:815-823 builds the paging population with `ReferenceEvidenceBounds(limit, limit)` + `.Take(limit)`, so limit is BOTH page size AND total reachable universe. Continuation gated on `nextOffset < populationCount` (L953) while `exact_truncated` comes from `Coverage.ExactAvailable` (L948) — they disagree.

Proof (symbol CPU, DB truth = 39 refs): limit 20 (default) reaches 20/39 with exact_truncated=true and NO continuation token. reachable == min(limit, exact_available) exactly. Consumer paging to exhaustion silently gets a partial reference set. Documented Eros surface.

Test gap: 3 continuation tests exist but none assert full-population reachability; they run inside the capped population so they pass while the defect persists.
