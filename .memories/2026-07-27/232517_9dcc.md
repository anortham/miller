## Fixed the two dogfood defects left open after f38969aa

Follow-up to the rename-preview fix. Same root cause class, two different consumers.

### 1. Spanless duplicate rows double-counted every reference reader

`trace` reported `exact_available: 6` for `GenerationAgrees`' 3 real call sites. Confirmed against the live artifact: julie-extract emits a spanned `identifiers` row **and** a spanless `pending_resolutions` row per occurrence, under its own `reference_site_spanless-` identity. `ReferenceEvidenceReader.Deduplicate` keys on `(reference_site_id, target, kind)`, so the pair never collapsed.

- **Scope:** 8,365 spanless exact-arm rows workspace-wide, 8,159 (97.5%) redundant, only 206 genuine. Systemic, not a one-symbol quirk.
- **Fix:** new `WithoutRedundantSpanlessRows` folded into both `Deduplicate` and `DeduplicateOutgoing`. Drops a spanless row only when a spanned row covers the same `(file, containing symbol, target, kind)`. Uncovered spanless rows stay and still render `is_exact=false`.
- **Not a contract change:** `exact_observed` (raw rows) vs `exact_available` (deduplicated) was already the documented and tested semantic — `Read_DirectOverlayRelationshipAndPendingRowsAtOneSite_...` asserts observed=4/available=1. This was a bug against the spec, so no Eros decision was needed. Contract doc now states the rule explicitly.
- **Reported "contract contradiction" was not one.** `is_exact` (span attested) and `resolution_status` (target resolved) are deliberately independent axes, documented at trace-json-v1.md:132-136.

### 2. `context` said evidence=sufficient on a bundle without the answer

`DispositionFor` accepted any `query_rank_*` pivot with a non-null body. A shell variable (`SIDECAR_EXTRACT="${STAGING}/sidecar"`, body `{STAGING}`) ranked 1 and flipped the whole bundle to `sufficient`, suppressing `next_actions` — telling the agent to stop looking when `SymbolsArtifactIdentity` was only a neighbour.

- **Fix:** `CarriesImplementation` excludes `constant`/`variable`/`field`/`property` kinds. New partial reason `pivot_value_declaration_only`.
- **Also a spec repair, not a redesign:** context-json-v1 already required an *implementation body* for `sufficient`; a value declaration is not one.

### 3. Stranded doc comments

Fixed all three reported (`IndexBootstrapService:708`, `CanaryLedgerReader:56`, `SemanticEmbeddingSession:163`) and wrote a scanner for the stacked-`</summary>`+`<summary>` signature: exactly 3 at HEAD, 0 now.

### Deliberately NOT fixed

`context` **ranking** on overloaded terms — shell/eval-script symbols outranking source, and a class present only via its tests. That is a ranking-design task, not a located repair. The disposition fix makes the bad ranking honest (partial + next_actions) rather than hiding it.
