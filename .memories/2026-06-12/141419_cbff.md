## Dashboard: live activity feed + machine-wide telemetry + polish

**WHAT** — Added a julie-style live tool-call feed to the Miller dashboard plus a batch of review fixes, all TDD (10 new tests in `tests/Miller.Tests/Server/DashboardActivityFeedTests.cs`, 54 dashboard tests green, full fast suite 2196 green, Release build 0 warnings).

- **Live activity feed** (`ActivityFeedPanel.razor`): htmx `every 2s` polling of new `GET /fragments/activity` + `GET /activity.json`. Data from `DashboardData.ReadRecentActivity` reading `tool_telemetry` newest-first (UUIDv7 id tiebreak); machine-wide feed (landing page) annotates rows with registry display ids, scoped feed on the workspace page.
- **Machine-wide telemetry**: `workspace_id=all` sentinel in `ReadTelemetrySummary` (SQL `($all = 1 OR workspace_id IS $ws)` pattern); landing page now mounts an all-workspaces TelemetryPanel.
- **Relative timestamps**: `RelativeTimeScript.razor` rewrites `time.rel-ts[data-ts]` to "12s ago" on load/afterSwap/5s interval; applied to telemetry last-call/last-error/recent-errors and feed rows.
- **Refresh button wired**: `WorkspaceDetailPanel` button → `POST /fragments/refresh` → `RefreshStatusPanel` swap. Added `DashboardData.TryRefreshWorkspace` because `CrossWorkspaceRefreshService.Refresh` throws on unknown ids → 500 with empty body → htmx silently no-ops. `lock_busy` styled neutral (live leader owns the lock — not a failure).
- **Vendored fonts**: Archivo + JetBrains Mono variable woff2 latin subsets in `wwwroot/fonts/` (~66KB), `@font-face` + preload, explicit `/fonts/*` endpoints (Program.cs maps static assets one-by-one; no UseStaticFiles). No more Google Fonts CDN.
- **Dedup**: shared `DashboardFormat` static class via `@using static` in `_Imports.razor`.

**KEY CONSTRAINT discovered**: htmx config `allowEval:false` (DashboardHead) disables htmx trigger filters like `[document.visibilityState=='visible']` — visibility-gated polling intentionally dropped to keep the eval-free posture.

**WHY SSE wasn't needed**: telemetry rows are written synchronously at call completion to `~/.miller/telemetry.db` (WAL), so 2s DB polling gives a live feel without julie's in-process event bus. SSE (option B) can layer on later; the fragment markup would be reused as the SSE payload.

**VERIFIED live**: smoke on port 4990 — feed rendered 20 real rows, all-workspaces telemetry (4803 calls/9 tools), fonts 200 `font/woff2`, refresh fragment returns rendered failure for unknown ws and `lock_busy · rev 712` against the live miller workspace.
