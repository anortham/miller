## Fixed Cursor Miller install guidance and local config

### WHAT

Configured Cursor to use a global MCP entry at `C:\Users\CHS300372\.cursor\mcp.json` and documented that as the recommended Miller path.

- Created standalone launcher root: `C:\Users\CHS300372\.miller\plugin-cache\cursor-global-miller`
- Updated global Cursor MCP config to run `node .../miller-plugin-launcher.cjs`
- Set only `MILLER_WORKSPACE_ROOT` to `${workspaceFolder}` in Cursor env
- Moved broken Cursor-local plugin copy to `C:\Users\CHS300372\.cursor\plugin-backups\miller-local-20260612-101038`
- Updated `README.md`, `docs/site/index.html`, and the Cursor launcher finding doc

### WHY

Cursor was launching Miller from the home directory or an empty/global plugin context. Direct `miller.exe serve` failed Miller's sensitive-root guard, and Cursor plugin installs could become `plugin-miller-miller` with `Could not determine a Miller workspace root`.

### HOW

The global config now relies on Cursor's documented env interpolation:

```json
"env": {
  "MILLER_WORKSPACE_ROOT": "${workspaceFolder}"
}
```

The Miller Node launcher reads that env var and starts `miller serve` with the resolved workspace as cwd. The launcher root lives under `~/.miller/plugin-cache`, which the launcher treats as unsafe fallback territory, so unresolved `${workspaceFolder}` fails closed instead of indexing the launcher cache.

### IMPACT

Cursor has a single recommended user-wide Miller install path that should apply to all projects. README no longer tells users to install a local Cursor plugin copy as the normal path.
