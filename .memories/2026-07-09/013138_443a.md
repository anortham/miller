## Dashboard: remove button added to workspace detail page

Follow-up to the 2026-07-08 dashboard workspace remove + prune slice — the user looked for remove on the detail page first, so it now lives there too.

- **WHAT:** Extracted the per-row remove confirm form from `WorkspaceIndex.razor` into a shared `WorkspaceRemoveConfirm.razor` component (params: `WorkspaceId`, `CancelHref` default `/`) and rendered it in `WorkspaceDetailPanel.razor`'s heading actions with Cancel linking back to the workspace's own page.
- **WHY:** Detail page is the natural "manage this workspace" spot; ADR-0002 already permits dashboard registry-lifecycle mutations, and `POST /workspace/remove` works from anywhere (its post-redirect lands on `/`, correct after removal).
- **HOW:** TDD — RED render test `WorkspaceDetailPanel_RendersRemoveConfirmForm` in `DashboardRegistryReadTests.cs` (asserts form action, hidden workspace_id, confirm copy, cancel href, antiforgery token), then the shared component. Added the `FixedAntiforgeryStateProvider` stub to `DashboardActivityFeedTests`' render helper because the detail panel now embeds `<AntiforgeryToken/>`.
- **IMPACT:** Confirm copy/endpoint/antiforgery can no longer drift between list and detail views. Fast suite 3140/3140 green; live-verified on the rebuilt dashboard (detail page serves the form, all-workspaces rows unchanged, 39 rows = 39 registry entries).

Known nit (accepted): refusal notices still redirect to `/`, so a refused remove from the detail page bounces to the list to show the notice.
