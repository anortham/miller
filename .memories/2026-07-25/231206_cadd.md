## Completed the Workspace takeover slice

### WHAT

Implemented and documented the final Workspace-tool remediation required for Miller to replace Julie's local lifecycle workflows. The slice now has bounded MCP output, exact registry/onboarding totals, typed unavailable/refusal outcomes, cross-workspace leader facts, and one shared registered-only removal core across MCP, CLI, and dashboard.

### WHY

The audit showed Workspace was architecturally stronger than Julie but still had misleading success states, unbounded health/onboarding paths, incomplete registry facts, and unsafe removal edge cases. Those gaps prevented an honest Julie-retirement claim.

### HOW

- Enforced a universal 12 KiB MCP Workspace response ceiling and compact/summary-only MCP health.
- Reworked onboarding aggregation into one SQLite read transaction with exact section totals and omission counts.
- Made list use one registry snapshot, exact missing-root totals, correct retained-row telemetry, and surface-neutral cleanup guidance.
- Added typed diagnostics for missing/unreadable current and selected indexes, unavailable onboarding telemetry, unsupported/invalid parameters, and empty registries.
- Routed MCP, CLI, and dashboard removal through one core that requires a registered canonical root/index mapping, rejects live/sensitive/global/corrupt/symlinked/in-use targets, and preserves data on refusal.
- Added CLI status leader/version facts, dashboard refusal notices, and contract/release/migration evidence.
- Ran repeated Claude Opus read-only review/remediation rounds until the exact implementation returned `verdict=clean`; the doc-only verdict record was also verified clean.

### IMPACT

Workspace now preserves Miller's fixed-process and leadership advantages while porting Julie's useful root-existence inventory and registered-only deletion semantics. The last tool-specific implementation slice is ready to commit, enabling the final all-nine Claude reviews and broad branch review.
