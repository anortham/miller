## Implemented Registry-Backed Workspace Tool Behavior

- **WHAT:** Updated the Miller `workspace` MCP tool to target registry-backed workspaces by `workspace_id` or path, render registry list rows, route current workspace refresh/full through `IndexerService.TryScanAsLeader`, route registered non-current refresh/full through `CrossWorkspaceRefreshService`, register stable workspace ids from `open(path)`, and unregister/delete unlocked workspace indexes from `remove`.
- **WHY:** The workspace tool still behaved like a single-workspace admin surface while the integration branch already had central registry/provider/refresh services.
- **HOW:** Added TDD coverage in `WorkspaceToolTests`, `WorkspaceRenderTests`, and `CrossWorkspaceRefreshServiceTests`; extended renderer records for registry rows and target action metadata; added optional force support to `CrossWorkspaceRefreshService.Refresh`; injected `WorkspaceRegistry`, `IWorkspaceIndexProvider`, and `CrossWorkspaceRefreshService` into `WorkspaceTool`.
- **IMPACT:** `workspace list/status/refresh/full/open/remove` now uses the central registry path while preserving current-workspace leader behavior and writer-lock safety for deletes.
