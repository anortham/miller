## Corrected loaded_existing freshness reporting

- **WHAT:** Updated `WorkspaceIndexProvider.IndexFreshFor` so `WorkspaceRegistryState.LoadedExisting` without a refresh result reports `IndexFresh=false` while preserving `FreshnessStatus="loaded_existing"`.
- **WHY:** `loaded_existing` means the index is readable but startup/target refresh has not confirmed it is fresh, so presenting it as fresh would mislead cross-workspace reads and later telemetry.
- **HOW:** Removed `LoadedExisting` from the no-refresh fresh-state branch and added a provider regression test that resolves a registered readable DB with `ensureFresh:false`.
- **IMPACT:** Cross-workspace reads can still use the existing DB, but freshness is explicitly unconfirmed instead of incorrectly true.
