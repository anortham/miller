## Workspace Registry/Freshness Plan Approved

### WHAT
Created an implementation plan for Miller's workspace registry and freshness work after the user approved the design.

### WHY
Miller needs to replace Julie's useful multi-workspace and dashboard behavior without recreating Julie's daemon/resource problems. The plan converts the design into concrete worker tasks across Julie contract changes, Miller registry/storage, cross-workspace routing, startup freshness, BLAKE3 file hashing, telemetry, tools, dashboard, and docs.

### HOW
The plan uses local `<workspace>/.miller/symbols.db` indices plus a central `~/.miller/workspaces.db` metadata registry. It explicitly resolves the Julie UUID mismatch by passing stable full SHA-256 workspace IDs into Julie and adding a contract-3 `hash_algorithm=blake3` field. Read tools route through a snapshot provider so index/resolver/DB path stay consistent per call.

### IMPACT
Future implementation can be split into independent subagent tasks with clear file ownership and verification gates. The plan prevents accidental daemon revival, avoids dual workspace identities, and locks file freshness to Julie's BLAKE3 contract.
