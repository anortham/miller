## AccessIQ refresh hang traced to a stale 1.11.0 plugin process

- **What:** The AccessIQ Claude session was still running Miller `1.11.0+d1efbac593bd` after the `1.11.1` Windows fix had shipped.
- **Why:** That process repeatedly failed bootstrap in `BlazorProjectNamespaceResolver.TryReadXml` with `UriFormatException: Invalid URI: The hostname could not be parsed`; refresh calls triggered another failed bootstrap instead of recovering.
- **How:** Process inventory identified PID 62660 under the 1.11.0 plugin cache. AccessIQ logs showed repeated bootstrap failures. The plugin then updated/restarted as PID 59152 on released `1.11.1+f2a6507844fa`.
- **Impact:** AccessIQ now reports a fresh index at revision 1, current schema-v8 search sidecar, current schema-v2 content sidecar, an empty queue, and a live 1.11.1 leader. No code change was required in this session.
