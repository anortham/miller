## Fixed Windows CT compact-renderer newline drift

- **WHAT:** Updated the CT status, run-facts, and failure compact-rendering boundaries in `TestsCore` to normalize completed output to literal LF.
- **WHY:** Windows `StringBuilder.AppendLine` emits CRLF, while Miller's compact output contract and existing byte-stability assertions require platform-independent LF. The Windows fast suite exposed two failures; Linux hid the defect because its native newline is already LF.
- **HOW:** Preserved the existing builders and JSON paths, then applied `ReplaceLineEndings("\n")` only at the three completed compact-output boundaries. This is a three-line private implementation change with no API, schema, dependency, or persisted-data effect. Existing tests supplied the RED evidence on Windows.
- **IMPACT:** The exact two failing tests now pass on Linux, and all 34 `TestsToolTests` pass. The Windows fast suite must be rerun on the committed SHA before release readiness can be restored.
