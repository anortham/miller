## Aligned the broker sharing test's request and grace budgets with measured CPU fallback

- **WHAT:** The eight-process semantic broker Scale test now passes a shared 120-second budget for startup, request, grace, endpoint, and exit waits.
- **WHY:** A controlled Windows measurement showed one CPU-fallback query+batch iteration takes 29.319 seconds, already at the old 30-second request cap. Eight concurrent probes serialize query and batch operations through one session/pipe, so the old cap produced false hangs despite a healthy broker.
- **HOW:** Renamed the test constant to `BrokerTestTimeoutSeconds` and explicitly supplied it as `--request-timeout-seconds` and `--grace-seconds`, preserving process count, batch size, duration, and all production timeouts.
- **IMPACT:** This changes only the sharing Scale test; it does not mask production latency or alter Miller behavior. The exact broker test and owning class remain green on Linux. Windows Scale is the required after-measurement proof.
