## Alias-aware incremental search convergence

### WHAT

Implemented the bounded by-symbol-id reader and store-delta projection for search-sidecar alias convergence. Added focused FamilyStore regressions for alias additions, canonical/noncanonical deletion, canonical content replacement, region preservation, full-vs-delta parity, and candidate retrieval.

### WHY

Path-only replacement could delete or duplicate a logical symbol when aliases lived on unchanged paths. The search sidecar must retain one deterministic canonical row per logical symbol ID while preserving stable document IDs and avoiding a full rebuild.

### HOW

`SqliteSymbolReader.ReadForSymbolIds` reads all current visible candidates in bounded parameter chunks using the existing deterministic ordering. `ApplyStoreFileChanges` computes affected IDs from old sidecar rows plus changed-path store rows, reads all current candidates for those IDs, canonicalizes them, deletes/inserts by logical ID in one transaction, and keeps region updates path-based. Existing generic readers and schemas remain unchanged.

### IMPACT

The new delta path re-elects an earlier alias, preserves a surviving alias after canonical deletion, leaves noncanonical deletion as a search no-op, and keeps stable document IDs. The assigned FamilyStore test ceiling passes 62/62; the lead can now review and integrate this serial worker commit.
