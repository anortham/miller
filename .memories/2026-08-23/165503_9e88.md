## WHAT

The user approved the search symbol alias canonicalization implementation plan in `docs/plans/2026-08-23-search-symbol-alias-canonicalization.md`.

## WHY

Zod refresh at revision 1860 fails because legal alias rows share logical `symbol_id` values while the derived search schema and builders assume one row per ID.

## HOW

- Add a search-only canonicalization seam shared by disk and memory.
- Choose the lowest ordinal path for exact aliases and reject genuinely divergent collisions with an actionable health failure.
- Re-elect canonical aliases from a bounded affected-ID set during incremental updates while preserving `doc_id`.
- Keep source regions path-specific, since Zod has zero duplicate region IDs.
- Preserve all public, extractor, store, vector, and schema contracts.

## IMPACT

The branch is ready for two serialized TDD tasks. The final gates include Release build, fast and Scale suites, and a live fixed-binary Zod refresh/search replay.
