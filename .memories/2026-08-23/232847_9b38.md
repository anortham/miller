## Implemented Windows Scale contract separation

- **WHAT:** Added strict health-only broker probe mode, converted the eight-process sharing gate to use it, and hardened .NET provider PID readiness/cancellation cleanup.
- **WHY:** The sharing test overloaded the pinned sidecar's deliberate 30-second queue SLA on CPU-only Windows, conflating lifecycle correctness with accelerator throughput. A separate provider test also used a 10-second startup bound that failed only under loaded parallel Scale execution.
- **HOW:** Health-only probes handshake, hold the session for their requested duration, emit normal zero-traffic completion records, and never enqueue embeddings. Invalid Boolean values fail explicitly. The provider fixture now allows 30 seconds and always cancels/observes its run task before process cleanup. Batch-8 soak and every production timeout/protocol remain unchanged.
- **IMPACT:** Eight-process sharing still proves one endpoint, exactly one owner, zero failures, and zero hangs without asserting hardware throughput. Both owning Scale classes pass together: 10 passed, 2 expected soak skips.
