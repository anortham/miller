## Miller CLI + single-sourced build version (TODO #1, #2, #6)

Shipped the **dogfooding + CLI** track (the user's chosen next step after the search sidecar): the one `miller`
binary is now both the MCP stdio server and a one-shot CLI, and every build carries an identifiable version.

### What shipped
- **Build identity (single-sourced).** `Directory.Build.props` pins `<Version>0.1.0>` and a
  `_MillerStampInformationalVersion` target appends the git short SHA → `MillerVersion.Current` reads the
  assembly attribute. Surfaced in MCP `ServerInfo.Version`, `miller version`, and the `workspace status` header
  (new optional `WorkspaceFacts.ServerVersion`). Kills the "is my process stale?" ambiguity.
- **CLI dispatch layer.** `src/Miller.Server/Cli/{CliDispatch,CliOptions}.cs`. `Program.cs` branches on
  `CliDispatch.IsCliInvocation(args)` BEFORE any FS touch / host build: **no-args or `serve` → MCP host**
  (unchanged, stdio purity preserved); **any other verb → CLI**, which loads `<cwd>/.miller/symbols.db` via
  `RepositoryIndexLoader.Load` and calls the SAME pure tool cores the server exposes (`SearchTool.Run`,
  `InspectTool.Run`, `WorkspaceRender`, …) then exits. Verbs: version/help/search/inspect/context/impact/trace
  + workspace (list/status/refresh/full). `SearchTool.ParseMode` made internal for reuse.
- **Cross-platform launch (user constraint).** No bash-only script: `mcp-config.json` now launches with the
  explicit `-- serve` (pure `dotnet`, works everywhere). README documents the run/restart/version-signal loop.

### Adversarial review (5-dimension workflow) — 5 confirmed, 4 refuted, all fixed
1. **HIGH:** `workspace refresh/full` returned exit 0 on MissingRoot/MissingIndex/LockBusy (only `Failed`→3).
   Fixed with a `RefreshExitCode` status→code map (every non-success ⇒ non-zero) + a 6-case fast theory.
2. **MEDIUM:** no test spawned the real binary (TODO #6's actual goal). Added a Scale `CliBinarySubprocessTests`:
   in-process julie scan builds the index, then the built `miller` binary reads it from a separate CWD — proving
   the `Program.cs` entry branch + exit-code contract end to end.
3. **LOW:** git-failure path emitted MSB3073 (breaching 0-warnings). Fixed: `ContinueOnError`→`IgnoreExitCode`.
4. **LOW:** `CliOptions` `--` comment overstated GNU semantics → corrected.
5. **LOW:** README over-claimed `+<sha>` unconditionally → hedged for no-git builds.
