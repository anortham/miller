## Phase 5 complete — symbol-search sidecar default-ON, eval cleared, review fixes applied

Closed the on-disk FTS5 collapsed-trigram **search sidecar** (`<workspace>/.miller/search.db`): the recall eval cleared, the feature is now **default-ON** (opt out with `MILLER_SEARCH_SIDECAR=0/false/off/no`), and the four confirmed adversarial-review findings are fixed. Phases 0–5 are committed together.

### What shipped in Phase 5
- **Diacritics parity fix (Phase-5 prereq):** word arm tokenizer → `unicode61 remove_diacritics 0`; `SearchIndexWriter.SchemaVersion` 1→2 so the read gate rejects stale-tokenizer artifacts. Without this, BM25 scores diverged from the in-memory baseline (DF/score drift on non-ASCII identifiers).
- **Backend telemetry signal:** every symbol search stamps `metadata_json = {"search_backend":"disk"|"memory"}` (the observable "disk path taken" signal from the design risk list). Honest doc: recorded for diagnosis, queryable via `json_extract`, **no dashboard consumer yet**.
- **Recall eval harness:** `SearchRecallEval` (pure) + 7 fast tests; Scale eval on Miller's own committed `.miller/symbols.db` (OpenClaw/Hermes are pre-schema-2, can't feed it).
- **Flip default-ON:** `SymbolSearchSidecar.FromEnvironment()` opt-OUT semantics at the two env-reading composition roots (`MillerServiceRegistration`, `DashboardData`).

### Eval result (real corpus)
Interior-substring recall@5 **0.000 → 0.763**; word classes (Exact/Camel/Lasttok) **bit-identical**; **0 word-arm ranking parity violations**; disk path proven taken (`IsType<FtsSymbolSearchIndex>`).

### Four adversarial-review fixes applied this turn
1. **HIGH — schema-stale silent-disable:** `EnsureBuilt`'s freshness gate was revision-only; after a SchemaVersion bump a revision-matching stale-schema artifact would never rebuild while the read gate rejected it → sidecar self-heals to memory forever (the commit-5362b3d bug class). Fix: `ReadFreshArtifactRevision` now reads `revision, schema_version` and returns null (⇒rebuild) on any schema mismatch, keeping write/read gates in lockstep. New regression test pins it.
2. **HIGH — over-claimed consumer:** softened the `SearchTool` backend-metadata doc to stop asserting a dashboard aggregator that doesn't exist.
3. **MEDIUM — eval gate ordering:** moved the disk-path-taken proof (now Gate 3) ABOVE the interior-recall `Assert.SkipUnless` (now Gate 4) so an inconclusive sample can't abort the disk-path assertion.
4. **LOW — eval skip robustness:** broadened the corpus-read catch to `IncompatibleExtractException | InvalidOperationException | SqliteException` (skip, never fail).
