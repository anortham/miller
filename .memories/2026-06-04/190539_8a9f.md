## Phase 1 / leader build wiring complete — current-workspace `search.db` built by the indexer leader

Wired the on-disk FTS5 collapsed-trigram sidecar build for the CURRENT workspace into `IndexerService` (the writer-lock leader). This is the last build path; the external path (`CrossWorkspaceRefreshService`) was Phase 4.

- **WHAT:** `IndexerService` now injects `SymbolSearchSidecar` and best-effort (re)builds `<workspace>/.miller/search.db` after its two leader scans — `RunStartupDeltaScan` and `TryScanAsLeader` (the `workspace refresh`/`full` path) — both **under `_opsGate`** (serializes Miller's extract subprocesses, so the `symbols.db` read never races a file-replacing extract).
- **WHY:** Phase 3 routed reads to the disk sidecar when present + revision-fresh; without a leader build the current workspace's `search.db` was never written (only external workspaces got one). This closes that.
- **HOW:** `TryScanAsLeader` restructured so the build sits OUTSIDE the scan's `try/catch(⇒Failed)` (best-effort isolation — a build issue can't flip Scanned→Failed). Shared `TryBuildSidecar` helper swallows expected throwables behind a `when` filter, stamps `report.Revision`, no-ops when disabled/already-fresh/revision-less. OFF path never reads the `_bootstrap.Workspace` getter (byte-identical to pre-wiring).
- **Deliberate scope:** NOT built on the per-edit path (`TryReindexAsLeader`/debounce drain) — O(corpus) rebuild per save won't scale; reads self-heal to the always-fresh in-memory holder while the sidecar lags an incremental edit.
- **Intentional Phase-4 divergence:** null-`report.Revision` ⇒ skip (no freshness-read fallback like Phase 4) since a real scan always carries a revision and reads self-heal regardless.

**IMPACT:** Both writer paths now wired; feature still default-OFF (`MILLER_SEARCH_SIDECAR`). Only Phase 5 (recall eval + Scale disk-path assertion + telemetry counter, then flip default-on) remains. Work remains uncommitted per the user's workflow (Phases 0–4 + this all untracked).
