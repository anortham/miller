## CLI `workspace open` / `remove` implemented (TDD) — closes the CLI bootstrap gap

Added two CLI verbs to `CliDispatch` so the one-shot `miller` binary can bootstrap and tear down a workspace index from the command line — the gap flagged after the CLI/build-version work (`workspace full`/`refresh` only operated on an already-registered dir).

- **`workspace open [--path DIR] [--full]`** — canonicalize → sensitive-root guard on the canonical root → `Locate` julie BEFORE registering → `UpsertSeen` → `CrossWorkspaceRefreshService.Refresh(id, force)` (locks, scans/creates `symbols.db`, builds sidecar best-effort, marks scanned). Rendered as a `WorkspaceRender.Action("open", …)`, exit via shared `RefreshExitCode`. Default target = current dir.
- **`workspace remove (--id ID | --path DIR)`** — delete `.miller` + unregister, guarded by the cross-process `SingleWriterLock`; new `RemoveExitCode` (Removed/NotFound→0, Refused→3). Requires an explicit selector. `--path` on a gone dir best-effort prunes a stale registry row.

### How
- Reuses the tested refresh machinery rather than porting the server's direct-scan `Open` (which builds no sidecar and whose "not a live switch" copy is false in the CLI).
- Codex reviewed the spec first; all 5 findings folded in BEFORE coding: R1 Locate-before-register (no orphan `ready` row), R2 sidecar best-effort wording, R3 canonicalize-then-sensitive-check (catch symlink aliases), R4 stale-row prune, R5 `result.Result` call site.
- Scale E2E uses an isolated `HOME` so the real binary registers into a temp `~/.miller`, never the dev machine's.

### Impact
Only `CliDispatch.cs` changed in production. A true CLI-first / CI flow now works: `cd repo && miller workspace open && miller search …`.
