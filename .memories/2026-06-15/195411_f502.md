## Addressed Miller dashboard QOL findings

### WHAT
Implemented the dashboard quality-of-life fixes from the review pass:

- Added explicit agent/workspace guidance for dashboard launch requests: use Miller `workspace` with `operation=dashboard` instead of searching plugin cache directories.
- Captured local exception message/detail in telemetry and surfaced copyable issue bundles in dashboard activity/recent-error views.
- Added dashboard diagnostics JSON with resolved paths, version, logs, registry/telemetry state, and schema availability warnings.
- Added favicon route, JSON/debug links, workspace filtering, and full detail-panel refresh behavior.

### WHY
The dashboard should make it easy for users and agents to start the right local UI and copy useful issue details when a tool failure appears. Recent errors without stack/message details were not enough for issue reports, and dashboard startup/debugging needed stronger self-diagnostics.

### HOW
- Extended telemetry schema additively with `error_message` and `error_detail`, including migration of existing telemetry DBs and bounded exception text.
- Updated dashboard read models and Razor components to tolerate old telemetry schemas while rendering richer issue details when available.
- Added `/diagnostics.json`, `/favicon.ico`, JSON links, workspace filter UI, and refresh fragment replacement for the full workspace detail panel.
- Updated `MILLER_AGENT_INSTRUCTIONS.md`, `WorkspaceTool` description, `CLAUDE.md`, and regenerated `AGENTS.md`.

### IMPACT
Users now get copyable issue details with correlation IDs from the dashboard, agents get clearer dashboard-launch routing, and dashboard diagnostics can identify old telemetry schemas or wrong launch paths without spelunking the plugin cache.
