## Implemented deterministic search no-results recall fix

- **WHAT:** Implemented the search no-results recall plan through phase 1. Added `TextSearchQueryPlan` in `Miller.Core`, refactored `ContentSearchIndex` to use it, and updated `FtsTextContentSearchIndex` to retrieve strict AND candidates first then bounded OR candidates with final C# BM25, coverage, best-line, and token-phrase filtering. Added FTS tests for high-coverage long-query recall, short-query precision, code-like phrase precision, and content-kind/test filtering.
- **WHY:** Telemetry showed search empties concentrated in content-backed modes (`source`, `content`, `all-text`) while symbol/auto misses were low. The disk FTS path was stricter than the in-memory content index and returned false empties when useful chunks matched the existing high-coverage threshold but not every query term.
- **HOW:** Shared the existing lexical query plan from `ContentSearchIndex`; FTS uses coverage terms for candidate retrieval, deduplicates strict/widened candidate IDs, scores distinct query terms with existing BM25, requires shared coverage threshold, checks token phrase for code-like queries, and applies the same phrase boost. No schema change, semantic search, vector dependency, new MCP tool, or `julie-extractors` change.
- **IMPACT:** Deterministic text-content recall is improved without crossing the Eros semantic-search boundary. S2 symbol fallback and S3 content trigrams remain deferred pending post-deployment measurement.
