## Corrected Miller-vs-Julie effectiveness frame

### WHAT
Updated the gap analysis focus away from `metrics` and toward `search`/`inspect`, which dominate real agent usage.

### WHY
The previous analysis treated CLI-only metrics as a possible MCP gap. The user clarified this was intentional: the metrics tool was added without approval, then removed from MCP and made CLI-only because AI coding agents are unlikely to use it substantially.

### HOW
Live follow-up inspection showed:
- Miller telemetry confirms `inspect` and `search` dominate calls: `inspect` 777 calls, `inspect:full` 450, `search` 360, while misses remain meaningful (`search` 88 empty, `inspect` 71 empty in the observed window).
- Miller `SearchTool` is route/mode based: symbols by default, explicit `mode=source`, `mode=content`, regions, etc. Empty hints tell agents what route to try next.
- Miller `InspectTool` uses `SmartTargetResolver`: exact name/path/id resolution, candidates for ambiguity, near-miss suggestions capped at three, and no pick-first behavior.
- Julie `FastSearchTool` was a more integrated search product: unified mixed file+symbol hits, lexical/semantic/hybrid backend options, semantic fallback candidates, relaxed-match notes, line-mode enrichment, zero-hit reasons, scoped rescue headers, and locations/full return formats.
- Julie `DeepDiveTool` made inspect-like work task-shaped: overview/context/full depths and a single-call replacement for fast_search -> get_symbols -> fast_refs -> Read.

### IMPACT
The key effectiveness gap is not missing metrics. It is that Miller's two heavily used primitives are more deterministic and safer but less self-recovering and less task-shaped than Julie's integrated `fast_search`/`deep_dive` experience.
