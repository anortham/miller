## Built Julie vs Miller search/inspect benchmark matrix

### WHAT
Created a repeatable benchmark runner and captured real numbers comparing Miller `search`/`inspect` against Julie `fast_search`/`deep_dive` across nine local repos: Miller, Julie, Eros, Express, Flask, Gson, Newtonsoft.Json, Zod, and jq.

### WHY
The prior discussion identified that only `search` and `inspect` get substantial agent usage, so the comparison needed to focus on those surfaces and produce evidence instead of impressions.

### HOW
- Added `scripts/bench-julie-miller-search-inspect.py`.
- The runner prepares each workspace with Miller `refresh --wait --json` and Julie `manage_workspace open`.
- It measures warm MCP calls for both tools, with Miller measured reads using `ensure_fresh=false` after prep.
- It scores each task by expected-file evidence: expected file first, expected file present, empty response, latency, and output size.
- Wrote findings to `docs/findings/2026-06-27-julie-miller-search-inspect-benchmark.md`.
- Stored raw CSV evidence under `docs/findings/benchmarks/2026-06-27-search-inspect/`.

### IMPACT
The benchmark shows Miller is not broadly behind on exact symbol/file lookup. The main gap is `search auto` route recovery for source-body intent: Miller `search auto` scored 5/9 top and 6/9 present for source-intent tasks, while explicit `mode=source` scored 8/9 top and 9/9 present. `inspect full` found all expected targets but is much larger than Julie `deep_dive overview` and still has ambiguity issues for Flask/Zod-style repeated names.
