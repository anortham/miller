## Reviewed Miller search no-result telemetry and call path

- **WHAT:** Traced `search` from route planning through MCP tool dispatch, workspace providers, symbol/content/region backends, renderers, and telemetry empty-reason recording.
- **WHY:** Telemetry showed too many empty `search` results and raised concern that Miller may need a semantic fallback like Julie/Eros.
- **HOW:** Checked live workspace health, global `~/.miller/telemetry.db`, Miller onboarding telemetry, code paths in `SearchTool`, `SearchRoutePlanner`, `WorkspaceIndexProvider`, `FtsSymbolSearchIndex`, `FtsTextContentSearchIndex`, and relevant tests. Ran the existing search-quality runner for Miller.
- **IMPACT:** Main finding is not symbol-search failure. Since 2026-06-16, global search empties are dominated by explicit `source`, `content`, `all-text`, and `file` modes; `auto` and `symbol` empties are rare. Disk text-content search currently requires every distinct query token to match in the same chunk, unlike the older in-memory `ContentSearchIndex` coverage/stopword logic, which likely drives many prose-query misses. `mode=file` is symbol-backed and can miss docs/content files. Telemetry also collapses file-mode misses into `no_symbol_hits` and cannot distinguish filtered-scope misses from true misses.
