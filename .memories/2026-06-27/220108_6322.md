## Investigated Miller vs Julie effectiveness gaps

### WHAT
Compared current Miller 1.1.2 surfaces against the live `~/source/julie` product surface and docs, plus Eros integration state and Miller's recent five-gap/search-recall work.

### WHY
The user observed that Miller still feels less effective than Julie and wanted a gap analysis grounded in current code and contracts, not assumptions.

### HOW
Key discoveries:
- Miller current MCP surface is exactly nine tools: `content`, `context`, `edit`, `impact`, `inspect`, `patterns`, `search`, `trace`, `workspace`.
- Miller `MetricsTool` exists and CLI exposes `metrics churn|clones|complexity --json`, but there is no public MCP `metrics` tool despite the five-gap plan/docs saying one was added. That makes churn/clone/complexity facts unavailable to agents except through CLI/skill routing.
- Julie's public surface still has task-shaped tools and affordances Miller collapsed into generic primitives: `deep_dive`, `fast_refs`, `blast_radius`, `call_path`, `spillover_get`, fuzzy `edit_file`, and semantic/hybrid `fast_search`.
- Miller search/content recall improved in v1.1.2 and source regions are enabled, but telemetry still shows many no-result searches and deferred work remains around compact fallback, route recovery, content trigram, and semantic handoff.
- Eros owns semantic/vector retrieval, guidance, confidence/evidence views, history, signals, dead-code/hotspot/clone workflows; live Eros code has Miller import/eval plumbing but productized semantic retrieval is still deferred pending eval proof.

### IMPACT
The likely effectiveness gap is not freshness or core deterministic indexing. It is the integrated agent experience: task-shaped investigation/editing, no-result recovery, semantic/guidance layers, and one concrete Miller-owned mismatch where metrics are CLI-only instead of MCP-accessible.
