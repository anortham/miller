## Built the pure token-saving replace matcher

- **WHAT:** Added the first implementation slice for Miller edit redesign: a pure `TextReplaceMatcher` contract in `Miller.Core`, match-mode records/enums, and focused tests for exact, normalized, fuzzy, occurrence, and UTF-8 byte-span behavior.
- **WHY:** Miller edit needs to earn its tool surface by enabling localized edits without requiring agents to read full files first. The matcher is the pure foundation for indexed-content-assisted `replace_text`.
- **HOW:** Kept historical exact matching as the compatibility path by routing `EditPlanner.ReplaceText` through exact `TextReplaceMatcher.Plan`; added normalized line matching that ignores indentation/trailing whitespace/line-ending differences while preserving byte spans over original content; added bounded fuzzy matching for short snippets with a 160-char cap and local Levenshtein thresholding.
- **IMPACT:** Task 1 behavior is implemented and the focused Core edit tests are green. Next slice should add read-only indexed candidate discovery over `content.db`, then wire `EditService` to combine indexed candidates with disk verification and preview metadata.
