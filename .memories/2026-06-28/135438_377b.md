## Workspace Remove Stale Registry Cleanup Fix

- **WHAT:** Changed `workspace remove` MCP and CLI behavior so registered stale rows whose `.miller` index dir is already missing render as a successful registry cleanup instead of a no-op not-found.
- **WHY:** After deleting the foundation matrix worktree, `workspace list` still showed the old registered workspace. Running `workspace remove` cleared the row, but the message said there was nothing to remove, which made the successful registry cleanup look like a no-op.
- **HOW:** Added `WorkspaceRemoveResult.IndexDirDeleted`, render `removed workspace registry entry ... (no index dir at ...)` for stale registered rows, and wired both `WorkspaceTool.RemoveResolvedTarget` and `CliDispatch.RemoveMillerDir` / gone-path cleanup to use that state.
- **IMPACT:** Agents and CLI users can tell the difference between a true no-op and successful stale registry cleanup. JSON output now includes `index_dir_deleted` so automation can distinguish index deletion from registry-only removal.
