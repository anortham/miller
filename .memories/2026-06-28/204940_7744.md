## Wired token-saving replace_text through EditService

- **WHAT:** Implemented Tasks 3 and 4 for the Miller edit redesign: `EditRequest`/`EditTool` now accept `match_mode`, `query`, `anchor`, and `line`; `EditService` uses `IndexedEditCandidateReader` when selectors are present, verifies all accepted spans against current disk text, falls back honestly when `content.db` is unavailable, and renders compact/JSON match proof.
- **WHY:** Miller edit needs to save tokens by accepting small selectors while still proving edits are safe enough to apply without a full-file read.
- **HOW:** Plain replace_text calls continue disk-wide planning for compatibility. Selector-bearing calls use content-db candidates only as line-window hints, then run `TextReplaceMatcher` over current disk text. Preview/apply/no-op JSON and compact output now include match mode, source, line range, match count, occurrence, disk verification, and content index state. Telemetry metadata records only mode and selector presence booleans, not raw selector text.
- **IMPACT:** Existing exact apply/preview behavior remains covered, while new normalized/fuzzy/selector-scoped behavior has service tests. Next slice is prompt-facing docs/skills/README/GitHub Pages updates plus agent instruction budget tests.
