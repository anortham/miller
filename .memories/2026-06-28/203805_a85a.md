## Added indexed edit candidate discovery

- **WHAT:** Implemented Task 2 for the Miller edit redesign: `IndexedEditCandidateReader` reads bounded candidate chunks from `content.db` and returns a typed `Current`, `NoMatch`, or `Unavailable` result.
- **WHY:** `edit replace_text` needs to use Miller's indexed content to narrow localized edits without returning full file content, while still treating `content.db` as advisory rather than an edit buffer.
- **HOW:** The reader opens `content.db` read-only with `Pooling=false`, verifies `content_meta` schema/revision before querying, requires an active workspace content source for the target path, applies optional `old_text`, `query`, `anchor`, and `line` narrowing, and caps returned chunks with `MaxCandidates`.
- **IMPACT:** Missing, stale, corrupt, or skipped content corpus states are now explicit `Unavailable` results, so the server can fall back to verified disk matching honestly instead of confusing unavailability with no-match.
