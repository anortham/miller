## Fixed stale workspace remove by path

Live testing found a gap in the workspace-remove fix: removing a stale registry row by `workspace_id` worked, but removing by `path` returned `not_found` once the workspace root was gone.

- **Root cause:** `WorkspaceTool.ResolveTarget` rejected missing paths before `workspace remove` could consult the registry, then the path fallback treated the missing `.miller` directory as final.
- **Fix:** Added `WorkspaceRegistryRootMatcher` and wired MCP + CLI remove paths through it. It first matches the full selector path, then canonicalizes a possibly missing path by resolving existing symlink ancestors and appending the missing tail.
- **Tests:** Added MCP regressions for deleted registered root by path and deleted registered root selected through a symlinked parent.
- **Impact:** `workspace remove --path` and MCP `workspace(operation="remove", path=...)` now prune stale registry rows after repo deletion, including `/tmp` -> `/private/tmp` style alias cases.
