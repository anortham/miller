## Added Miller handoff skill workflows

### WHAT

Implemented the approved handoff-skills slice in the `codex/handoff-skills` worktree. The branch adds user-invocable `handoff-out` and `handoff-in` skills under `.agents/skills/`, syncs the generated `skills/` mirror, updates `miller-orientation`, adds plugin regression coverage, updates README/site/docs-map guidance, and records dogfood evidence.

### WHY

The user decided handoff should live in Miller as skills, not a new MCP tool, CLI command, Goldfish workflow, or Razorback-only workflow. The value is combining existing Miller `workspace`, `impact`, and `context` facts with explicit session notes to move work between harnesses/models.

### HOW

The implementation keeps `.agents/skills/` canonical and uses `scripts/sync-plugin-skills.sh` for the plugin mirror. `handoff-out` writes timestamped markdown packets plus `.miller/handoffs/latest.md`; `handoff-in` validates root, branch, HEAD, dirty state, and Miller freshness before summarizing. Plugin tests assert the skills exist, are user-invocable, mention `.miller/handoffs/`, avoid the `miller-` prefix, and do not add a handoff MCP surface.

### IMPACT

Miller plugin users now have a documented skill-only workflow for moving active work between Codex, Cursor, Claude, and other harnesses. Dogfood produced a local ignored packet and showed one report-only limitation: `impact(git=true)` covers tracked diffs, so untracked new files are represented by `git status --short` until staged/tracked.
