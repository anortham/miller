## Fixed trace same-file ambiguity recovery

### WHAT

Follow-up smoke testing after the trace recovery guidance merge found that `trace target="ZodObject" scope="packages/zod/src/v3/types.ts" mode="refs"` still stopped at same-file ambiguity when `julie-extract` emitted both a class and export symbol on the same line.

### WHY

The previous recovery guidance only suggested `scope=<file>` reruns. Once scope narrowed candidates to a single file, compact output returned only `Multiple candidates — pass a more specific target`, and JSON returned an empty `next_actions` array.

### HOW

- Added same-file ambiguity tests for compact and JSON trace output.
- Changed `AmbiguousTargetNextActions` to fall back to symbol-id reruns when all ambiguous candidates share one file.
- Forwarded resolution `nextActions` into compact output for auto, path, refs, and bridge target-resolution failures so compact and JSON behavior stay aligned.

### IMPACT

Agents now get a concrete copyable next step even when file scope is insufficient. The suggested symbol-id rerun resolves the ambiguity and returns refs on the zod smoke case.
