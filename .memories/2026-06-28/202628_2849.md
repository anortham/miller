## Token-saving edit redesign plan written

### WHAT
Created `docs/plans/2026-06-28-token-saving-edit-redesign-plan.md`.

### WHY
The current Miller `edit` tool is mostly a safe exact patch applier and does not yet clearly earn adoption over harness-native editing. The user wanted a plan for making it useful by leveraging Miller's current indexed content and safety model.

### HOW
The plan keeps one `edit` MCP tool, deepens `replace_text`, and avoids adding `edit_file`. It adds a pure text matcher, an indexed-content candidate reader over `content.db`, request parameters `match_mode`, `query`, `anchor`, and `line`, disk verification before preview/apply, richer preview/JSON match proof, docs/skill guidance, and foundation matrix evidence. The plan explicitly rejects deleting edit now, adding a new MCP tool now, and only adding fuzzy matching without indexed-content selectors.

### IMPACT
This plan can drive the next approved implementation goal. It should make Miller edit prove value through localized token-saving edits while preserving preview, freshness, TOCTOU, rollback, and convergence.
