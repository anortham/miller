## Completed trace/content/patterns quality slice

### WHAT
Implemented the approved Miller quality slice for `trace`, `content`, and `patterns` without adding MCP tools.

- `trace` empty states now expose structured next actions for no-path, empty refs, no-neighbour, and bridge unsupported/no-link outcomes.
- `content` no-result and read-error paths now return recoverable compact output and parseable JSON with `diagnostic_code` and `next_actions`.
- `patterns` list/no-match flows now return concrete next actions, near matches, and filtered-out guidance.
- Onboarding, server instructions, skills, README, GitHub Pages, and JSON/CLI contract docs were updated.
- Focused matrix evidence and a baseline finding were generated under `docs/findings/`.

### WHY
Local telemetry showed `trace` was frequently empty, `content read` had avoidable errors, and `patterns` had low adoption. The goal was to make existing deterministic Miller tools more useful and more naturally adopted by agents while preserving Miller's boundary: no semantic retrieval, no parser ownership, and no new MCP tool surface.

### HOW
Used the existing tool boundaries and added caller-facing recovery behavior:

- Reused `TraceNextAction` style recovery for more trace empty states and added JSON parity.
- Added content diagnostic classification and recovery action helpers while preserving successful output shape.
- Added generic patterns next-action helpers over observed `pattern_id` values rather than special-casing parser facts.
- Extended the foundation matrix runner for focused `content`/`patterns` MCP rows and JSON parseability checks.
- Updated `.agents/skills/` canonical docs, regenerated `skills/`, and kept guidance short and task-specific.

### IMPACT
The focused replay matrix moved from RED to GREEN:

- Before: `/tmp/miller-red-matrix` failed 12 focused recovery rows.
- After: `docs/findings/benchmarks/2026-06-28-trace-content-patterns-quality/summary.md` passes all focused gates: `trace` 6/6, `content` 4/4, `patterns` 4/4.

This gives Miller stronger deterministic recovery workflows and better agent guidance without expanding the MCP surface.
