## Fixed context render trimming after Claude review

The context render boundary could re-render and recount thousands of shrinking prefixes one item at a time, producing quadratic allocation and latency. Positive budgets smaller than the canonical empty response envelope also needed an explicit contract.

- **Fix:** Replaced tail-at-a-time trimming with a monotonic binary search for the largest retained priority prefix.
- **Behavior:** Preserved the initial full-render byte path, selected-count semantics, compact/JSON rendering, and ordinary/reference-aware callers.
- **Contract:** A too-small positive budget returns the canonical valid empty envelope with `selectedCount=0`; the MCP `token_budget` description now documents this exception.
- **Tests:** Added caller-facing coverage through `Run` and `RunReferenceAware`, including all four format/mode tiny-budget cases and a fixed 668-item prefix regression.
- **Impact:** The measured reference-aware JSON case fell from a deterministic 1,626,385,624-byte RED allocation to below the 32 MB bound while retaining the identical priority prefix.
