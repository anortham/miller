## Bound benchmark identity to the actual .NET code artifact

The post-repair build changed `miller.dll` and `miller version`, but the framework-dependent `miller` apphost SHA stayed byte-identical.

- **Problem:** Runtime preflight hashed only command element 0, so a .NET code change could pass with the same recorded binary SHA.
- **Fix:** Runtime identity now requires `binary_path`; preflight hashes that explicit artifact while independently resolving and probing the command executable.
- **Miller usage:** Set `binary_path` to `miller.dll`; keep `command` as the `miller serve` apphost.
- **Julie usage:** Set both `binary_path` and command element 0 to the standalone `julie-server` executable.
- **Verification:** A real fixture now uses different command and artifact files; all 55 Python harness tests pass.
- **Impact:** The sealed evidence manifest can detect framework-dependent product-code drift instead of only launcher drift.
