## Cursor MCP roots binding hardened

### WHAT
- Hardened the MCP roots workspace binding implementation so plugin/cache install directories are not accepted as fallback workspaces.
- Made current-workspace services rebind-safe across roots/list_changed by resolving holder/resolver/workspace/index providers per call instead of caching the first root.
- Kept telemetry as a singleton but added explicit workspace rebinding so default row attribution follows the active primary workspace.
- Made indexer leadership sessions generation-aware so reader/leader loops stop and restart when the primary workspace changes.
- Added an extra regression after final review: failed rebinds keep the previous workspace live until the replacement bootstrap fully succeeds.

### WHY
Cursor can launch MCP servers from plugin/cache directories while sending the real project root through MCP roots. Miller must defer or rebind to that root without indexing the plugin install path, and it must not keep using stale first-root singletons after roots/list_changed.

### HOW
- `WorkspaceBindingResolver` now refuses sensitive roots and known plugin/cache roots only when cwd is the last fallback; env override and MCP roots still have precedence.
- `Program` uses the resolved startup root for cwd safety/log setup, so `MILLER_WORKSPACE_ROOT` works even when process cwd is `$HOME` or a plugin root.
- `MillerServiceRegistration` changed root-bound services to transients; `TelemetryLedger.RebindWorkspace` handles the long-lived ledger case.
- `IndexBootstrapService` publishes new workspace state only after successful bootstrap, and `IndexerService` compares `BindingGeneration` through leadership loops.
- Tests cover plugin/cache cwd refusal, latest-state DI after rebind, failed-rebind preservation, and indexer restart attempts after rebind.

### IMPACT
Cursor project roots should now bind through MCP roots instead of requiring project-local config, while plugin/cache roots fail closed and roots/list_changed does not leave stale state behind.
