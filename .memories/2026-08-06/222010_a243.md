## Fixed MarkBootstrapFailed root resurrection

**WHAT:** `IndexBootstrapService.MarkBootstrapFailed` no longer recreates `<root>/.miller` when the workspace root is gone. The `Directory.CreateDirectory` call is now guarded by `Directory.Exists(canonicalRoot)`.

**WHY:** `CreateDirectory` creates every missing parent, so a bootstrap that failed *because the root vanished* (e.g. a removed worktree) resurrected the root as an empty directory holding only `.miller`. That is disk litter and can read as "root returned" to `WorkspaceRootPresenceMonitor`. Filed as a follow-up from the P4 findings-fixes run (2026-08-06).

**HOW:** TDD quick-fix on main. New regression test `MarkBootstrapFailed_WhenRootDisappeared_DoesNotRecreateRootDirectory` in `WorkspaceBindingServiceTests` deletes the root inside `TestRunBootstrapOverride`, then asserts the root stays absent AND the registry error row still lands (registry writes go to `~/.miller/workspaces.db`, which never needed the local dir). Verified `WorkspaceContext.Create` is pure path composition, so line ~916 was the only directory write in the failure path.

**IMPACT:** Vanished roots stay vanished after bootstrap failure; registry error reporting is unchanged. Fast suite green (6,149 passed).
