## Fixed doubled workspace/freshness banner in MCP inspect

The MCP `inspect` tool printed the `workspace:`/`freshness:` header twice whenever a banner applied (explicit `workspace_id`, or non-current freshness). Reported from a Grok session against the eros workspace; reproduced identically from Claude Code.

- **Root cause:** `InspectTool.RunCore` prefixes the compact banner in every resolution branch (file, symbol, candidates, not-found), and the MCP entry `InspectTool.Inspect` prefixed the same banner a second time after `RunLookupWithDiagnostics` returned (`InspectTool.cs:98`).
- **Fix:** removed the second `PrefixCompact` call in the MCP entry. The prefix inside `RunCore` stays because the CLI path (`CliDispatch` → `RunLookup`/`RunSummary`) relies on it.
- **Why the old test missed it:** `Inspect_ExplicitWorkspaceId_UsesTargetIndexResolverAndDbPath_AndPrefixesFreshness` used `StartsWith`/`Contains`, which a doubled banner still satisfies. Added `Inspect_ExplicitWorkspaceId_EmitsWorkspaceBannerOnce` asserting exactly one occurrence for both symbol and file targets.
- **Audit:** grepped all other `PrefixCompact` call sites (search, trace, context, impact, patterns, markers) — each prefixes once per branch; live trace call confirmed a single banner. The double was inspect-only.
- **Impact:** compact inspect output with a banner is one header again; JSON output was never affected (banner is compact-only).
