## CT sidecar direction set

Strategy session outcome for Miller's slice (business-specific context recorded in the private eros repo).

- **WHAT:** New active brief `ct-sidecar-direction`. Continuous testing will join Miller as an opt-in sidecar binary, packaged like the dashboard executable.
- **WHY:** CT's hard problems are already solved in Miller: test selection is the `impact` engine, triggering is the watcher/freshness machinery, throttling is the supervision discipline. An external CT daemon polling Miller is what caused the Eros 2026-07-28 refresh-storm incident.
- **HOW:** Safety spec derives from that incident: default off per workspace, global budget, degraded-index backoff, no full-suite cold-start fallback. Surfaces start as CLI verb + JSON export; any new MCP tool needs explicit approval.
- **IMPACT:** Next task is the CT sidecar brainstorm/design doc in this repo. Miller's export contracts (`docs/contracts/cli-eros-v1.md`) gain a consumer again as the push feed for an external human-facing console.
