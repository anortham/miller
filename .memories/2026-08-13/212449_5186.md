## Coordinator connection reuse fixed; julie-extractors workspace green on Windows

### The root cause, finally proven

`SQLITE_PROTOCOL` (FileLockingProtocolFailed, code 15) came from
`StoreCoordinator` holding **no connection**: all 27 methods called
`open_coordinator()` and re-ran the full writer pragma set. The claim
heartbeat did it 4x/second.

SQLite raises that code from the WAL read-retry ladder after WAL-index
recovery. Recovery is driven by the open-connection count reaching
**zero** — the last connection out unlinks `-wal`/`-shm`, the next open
rebuilds them under live readers.

**Decisive evidence:** the failure got WORSE as tests became more serial
(24 threads passed 2/2; 2-4 threads failed most; serial failed 3/3).
Fewer overlapping connections = more moments at zero.

### Three hypotheses I refuted (do not retry these)

1. open/close storm, 6 threads, one process → 0 errors
2. open/close storm, 6 separate processes → 0 errors
3. 50 hard-killed writers leaving a WAL mid-write → 0 errors

All three kept the connection count above zero, so the trigger never fired.
The standalone A/B harness is in the scratchpad (`sqliterepro`).
