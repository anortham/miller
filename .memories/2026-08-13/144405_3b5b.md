## Fixed all three pre-existing julie-extract product bugs (upstream asks 8-10)

WHAT: three product bugs found during the 2.33.0 prep are now fixed, each with a regression test that fails at pristine HEAD f8f5ea5d on Windows and passes after.

- Ask 10, Windows process liveness. coordinator.rs returned PidStatus::Unknown for every PID on non-Unix. Added a windows-cfg tasklist probe, made process_status public, re-exported it from store/mod.rs, and collapsed the two duplicate copies (watchdog.rs process_status_other, export.rs process_is_alive) onto it. Test: process_status_separates_a_live_process_from_an_exited_one.
- Ask 9, store import never retried the drain. import.rs called drain once, then fell into a passive observer loop that only watched for someone else to finish. Replaced with a retry loop that keeps the deadline check and the request_timeout report. Test: import_drains_as_soon_as_a_blocking_lease_is_released went from 30.17s exit 1 to 1.14s exit 0.
- Ask 8, leaked scratch DB. ResolutionBaseWriter and ResolutionScratchWriter unlinked inside the Drop body while their Connection field was still open. Windows SQLite omits FILE_SHARE_DELETE so every delete failed silently. Both now swap in an in-memory placeholder first. Tests: dropping_an_unfinished_base_writer_removes_every_scratch_file and its scratch-writer twin.

WHY: found and verified in the 2026-08-12 triage but left unfixed as out of scope. The user rejected that: we do not find bugs and then ignore them.

HOW: one shared liveness probe instead of three copies. export.rs now treats Unknown as alive, which is safer than the old code that read no-kill-no-ps as dead and could steal a live writer's lock.

IMPACT: store_resolution_contract SERIALIZED improved from 6 failures to 4. The two newly passing tests are the crash-resume pair, hard_kill_boundaries_resume and rebase_crash_boundaries_retry, which is exactly what the Windows liveness probe unblocks. That suite is parallel-unstable at pristine HEAD on Windows (5, 10 and 6 failures across three pristine parallel runs), so only the serialized run is evidence. All three fixes fold into the unreleased 2.33.0; the release notes and README now cover them.
