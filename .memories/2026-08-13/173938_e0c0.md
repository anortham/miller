## v1.19.0 release prep: reverted the semantic-broker layout change, release docs corrected

### WHAT

Prepared Miller v1.19.0 for release. The last open blocker was a change I had made to
`SemanticBrokerEndpoint` that home-scoped the Windows pipe name. **I reverted it.**

- Reverted `src/Miller.Indexing/Semantic/SemanticBrokerEndpoint.cs` and
  `tests/Miller.Tests/Indexing/SemanticBrokerEndpointTests.cs` to HEAD.
- Added `SkipWhenAForeignBrokerOwnsTheRendezvous(millerHome)` + `WindowsPipeExists` to
  `CliDispatchTests`, and applied it to the 3 tests that were failing.
- Wrote `docs/findings/2026-08-13-windows-broker-pipe-scope.md` recording the open question.
- Wrote `docs/findings/2026-08-13-julie-extract-2.33.0-adoption.md` with live GitHub API facts.
- Rewrote `docs/release-notes/v1.19.0.md` with 6 verified corrections.
- Added `.claude/worktrees/` to `.gitignore`.
- Added the v1.19.0 pointer + both findings to `docs/README.md`.

### WHY the revert

`docs/contracts/semantic-broker-v1.md` is marked **Frozen** and fixes the exact flat layout:
`broker-<identity>.lock`, `broker-<identity>.sock`, `miller-semantic-<identity>`. My change
rewrote all three, so it changed the Unix names too — not a Windows-only fix.

A prior session had already weighed this exact change and rejected it. The reasoning is recorded
in the `SemanticBrokerScaleTests.SkipWhenAForeignBrokerOwnsTheRendezvous` remark: splitting
mixed-version processes onto different pipes gives two brokers, two model loads, and one
accelerator lease — against the CLAUDE.md same-identity-shares-one-broker invariant.

The gate for any broker change is `scripts/semantic-broker-soak.ps1`, run by hand. CI never
exercises the broker. Shipping a frozen-contract layout change with no soak run is not defensible.

Reverting also resolved the three "stale statement" findings for free: after the revert, the
remarks in `SemanticBrokerScaleTests`, `semantic-broker-soak.ps1`, and the contract are all
accurate again.

### The 6 release-note corrections (each verified against code, not assumed)

1. **C1** — Dropped the false claim that a non-terminal store result keeps the latch armed
   "without inflating the failure streak". `StoreWorkspaceCoordinator.RequireCommitted` throws for
   `Queued`/`Claimed`, and `ScanFailurePolicy.RecordFailure` increments the streak.
2. **C2** — Rewrote the watcher section. The root event reached `julie-extract` and came back
   `invalid_file_path`; it did not "force a rescan". Added the separate cross-process
   file-converge filter change.
3. **C3** — The sidecar revision mismatch **throws**. `SymbolSearchSidecar.OpenRequired` /
   `OpenStoreRequired` reject it by design, so symbol search returns an explicit stale-sidecar
   error until reconverge. Also dropped "strictly lower" (a store with no non-terminal chunk
   events is unaffected).
4. **C4** — Deleted the whole broker section; replaced with a Windows caveat under `MILLER_HOME`
   pointing at the finding.
5. **C5** — Wrote the 2.33.0 adoption finding instead of deleting the verification sentence.
6. **C6** — Added the `JulieStoreClient.ParseResolutionState` `"converging"` fix, which was
   missing from the notes entirely.

### IMPACT

The release is now internally consistent: no note claims a behavior the code does not have, and
no frozen contract is amended without its gate. The Windows broker-pipe question is documented as
open with a concrete 4-step close plan rather than silently fixed or silently dropped.
