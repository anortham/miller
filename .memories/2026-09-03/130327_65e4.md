## Root-caused the v1.27.0 CT foreign-key retry loop

- **WHAT:** The daemon used an old method-level xUnit inventory while the current provider emitted pre-enumerated parameterized theory IDs.
- **WHY:** `EnqueueCore` sets `RefreshInventory` false for idle drains. The idle drain therefore ran 9,368 stored cases without rediscovering the current assembly.
- **HOW:** Parsed all 141 result shards from a failed cycle and compared raw provider IDs against `test_cases`. A disposable coordinator test reproduced the exact FK at the `test_results.test_case_id` insert with one missing case ID.
- **IMPACT:** Each run rolls back, leaves its artifact unlinked, retries the whole suite, and grows the CT build cache. The daemon was stopped. The preferred fix is to refresh inventory before workspace-scope idle drains; filtering unknown results would silently discard real tests.
