## Miller plugin v1.18.3 tool smoke test — 2 hard bugs found

Ran all 9 MCP tools against `C:\source\miller` on the released plugin binary
(`~/.miller/plugin-cache/1.18.3/x86_64-pc-windows-msvc/package/miller.exe`, pid 29792).

### Bug 1 — every git-backed `impact` path times out in the MCP server (blocking)

`impact` with no args, `base=`, `staged=`, and `git=true` all block exactly 30s, then fail
`git_diff_failed: git diff timed out`. Reproducible on every call.

- The **CLI** runs the same `ProcessGitDiffReader` code and SUCCEEDS (`miller impact --base HEAD~1`, 14.8s).
- Miller's exact argv (`git --no-pager diff --no-ext-diff HEAD~1 --`) runs in 0.2s from a shell.
- Diff is 12,251 bytes — under the 64KB Windows pipe buffer, so this is NOT an output-drain deadlock.
- Both spawned processes (cmd shim pid + real git pid) stay alive the full 30s and are killed by the timeout.
- `src/Miller.Server/Git/GitDiffReader.cs:30-37` sets `RedirectStandardOutput/Error` but **not**
  `RedirectStandardInput`, so the child git inherits the MCP server's JSON-RPC stdin pipe, which never EOFs.
  The CLI works because its stdin is an ordinary console.
- Suspected fix: `RedirectStandardInput = true` plus an immediate `process.StandardInput.Close()`.

### Bug 2 — dashboard workspace detail page never responds

`workspace operation=dashboard` starts fine and returns
`http://127.0.0.1:4977/workspace?workspace_id=<id>`, but that URL — the one the tool hands back — never
returns. Observed >90s and still spinning; dashboard CPU climbed 344s → 561s while blocked.
`/` (0.68s), `/healthz`, `/dashboard.css`, and `/fragments/workspaces` (0.67s) are all 200/fast.
Looks like the detail view hydrates the full index, which ADR-0002 / CLAUDE.md forbid.

### Lower severity

- `content operation=import` cannot open a file another process holds (`.miller/logs/miller-*.log` →
  "being used by another process"), yet live logs are its headline use case. `cp` of the same file works,
  so a `FileShare.ReadWrite` open would fix it.
- `content operation=shape` severity classifier does not understand Serilog `[WRN]`/`[INF]`/`[ERR]`:
  reported `warning=0 info=0 other=1123` on a log with 21 `[WRN]` and 1095 `[INF]` lines.
- `trace mode=refs` on a static CLASS reports `exact=0 fallback=40`, while `impact` resolves those same
  sites as `edge=call source=identifier_target`. Method-level targets resolve exactly (tier=3).
- `search mode=source` mislabels the enclosing symbol (`FullRebuildPromotion.cs:56` → "Diagnostics";
  `regions=doc_comment` labels it correctly).
- `workspace list` shows 2 broken registry rows: `SlicerDicerChallenge` → "Unknown resolution state
  'converging'", `claude` → "capacity_probe_failed:PowerShell failed to read filesystem capacity".
