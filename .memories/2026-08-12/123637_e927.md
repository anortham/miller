## WHAT

Closed the Miller family-store interactive-read recovery on final code commit `e46e72e2` and updated `PERF.md`, the recovery design/plan, and the active brief with honest remaining boundaries.

## WHY

The original default family-store path took 6.9–7.0 seconds and retained roughly 1–2 GB per host. The release gate required exact output plus sub-2-second context/impact/trace, sub-500-ms inspect, and bounded memory before release preparation could resume.

## HOW

The completed branch combines disk-backed family reads, lazy repository hydration, batched graph reads below compatibility-view barriers, request-local search reuse, bounded FTS hydration, deferred content hydration/mapping, and one-pass allocation-bounded multi-term scoring. One rebuilt final candidate ran each acceptance lane once. The project fast and scale suites then ran on the final source tree. The plan leaves registry/open isolation unchecked because Miller has no registry-path override and safe testing cannot repurpose HOME/USERPROFILE or mutate the shared registry.
