## WHAT

Reviewed the Windows-authored commit `f681e54f` after merging it locally as `39501895`. The core change correctly reports a persisted vector pause before falling back to generic completeness-stamp refresh advice.

## WHY

The incoming change was intended to stop misleading users when semantic vectors are paused because the model is not prepared. Review needed to verify that the new remediation guidance remained accurate for every vector failure classification.

## HOW

- Used Miller structural inspection and trace/impact evidence; the live MCP path repeatedly stalled while derived sidecars converged, so inspection used the documented one-shot lexical fallback with `MILLER_SEARCH_SIDECAR=0` and `MILLER_SEMANTIC=off`.
- Confirmed `VectorSidecarFacts.State == "unavailable"` is broad: it also represents unreadable/corrupt artifacts, family-store failures, and completeness-stamp refusal.
- Confirmed health/onboarding now suggest `miller semantic prepare` for every unavailable state. Onboarding states this unconditionally, so it can give the same kind of false remediation this commit intended to remove.
- Confirmed `SemanticPrepareCli` attempts `ActivateExistingBroker` and emits `activated`, `no_live_broker`, or `still_not_ready`, so documentation requiring a restart in every case is too strong; restart is needed only when activation did not succeed.
- Independent Codex reviewer reached the same two findings. Focused tests passed 53/53; Release build passed with zero warnings/errors; `git diff --check` passed.

## IMPACT

The incoming commit is not ready to push as-is. Fix guidance should use an explicit absence/model-preparation cause rather than broad `unavailable`, with negative tests for corrupt/read/stamp failure states. README/install guidance should make restart conditional on the activation result. No source files were changed during review, and the user-owned `TODO.md` remains untouched.
