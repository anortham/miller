## Fixed the semantic-model discoverability gap: pause-aware vector diagnostics, health/onboarding hints, README + install docs

Implemented fixes 1, 3, and 4 from the earlier gap analysis, all TDD (RED verified for the right reason before each implementation).

### Fix 1 — `VectorSidecar.InspectStore` now reports the recorded convergence pause
**Root cause was ordering, not wording.** `AddVectorWarnings` in `WorkspaceHealthFacts.cs:380` *already* had a `model-not-prepared` branch recommending `miller semantic prepare` — it simply never fired. `InspectStore` checked the completeness stamp FIRST and returned the generic "Run `miller workspace refresh` to converge it" message, so the `converge_pause_state` recorded on the artifact (read by `ClassifyGeneration` via `PauseState`) was never consulted on the unstamped path.

Added a `RecordedPause(path)` helper that probes existence → `TryReadMeta` → `PauseState`, and consults it before the stamp refusal. This means a missing model now surfaces as `model-not-prepared` with its real reason, which automatically lights up the correct existing recommendation. Much better than editing a string that couldn't know the cause.

Tests in `VectorSidecarClassificationTests`: the pause case, plus a boundary test that an unstamped artifact with NO recorded pause still refuses with the stamp reason (guards the pre-existing `InspectStore_RefusesAnUnstampedVectorArtifact`). Had to give the class a real temp `_storeRoot` — `PathForStore` canonicalizes against a live directory, so the original `/ws` const errored rather than failed.

### Fix 3 — actionable hints on both surfaces
- `WorkspaceHealthFacts.AddVectorWarnings`: the generic degraded fallback now also recommends installing the model, stating explicitly that "a refresh alone cannot download it". The existing "resident Miller leader" advice is kept, so the prior test still passes.
- `WorkspaceOnboardingFacts.Create`: new instruction note when semantic is enabled but not serving, gated by a `SemanticNeedsPreparing` local that excludes `disabled`/`ready`/`building`/`downloading` so it never nags mid-build. Guard test asserts no note when `ready`.

### Fix 4 — docs
`README.md`: corrected two claims this incident disproved — the intro's unqualified "semantic retrieval is on by default", and the quickstart's "there is nothing else to install". Added a `### Enable semantic retrieval` section (command, encoder sizes, per-platform cache paths, restart requirement, how to verify, `MILLER_SEMANTIC=off`). `docs/install.md`: qualified the "self-contained" framing and added a fuller `## Enable semantic retrieval` section with a facts table. Verified both `#enable-semantic-retrieval` anchors resolve.

### The 3 fast-suite failures are NOT from this change — proven, not assumed
`CliDispatchTests.WorkspaceStatus_UnsetSemanticReportsNotStartedWithoutCreatingBrokerState` (expected `not_started`, got `ready`) and `WorkspaceStatus_DefaultOnAndShadowPassivelyObserveAnExistingSharedBroker` ×2 (expected `cpu`, got `vulkan`).

I initially suspected environment and verified it properly: created a detached worktree at HEAD, copied in the gitignored `.tools/` (its absence tripped `VerifyPinnedJulieExtractVersion` first), and ran those three tests with **zero of my edits present** — identical three failures, same values.

Cause: these tests spawn a real broker and hard-assert `backend == "cpu"` / `state == "not_started"`, but the shared semantic broker is **user-global**, so they observe the live Miller server that now owns a Vulkan-backed broker. They passed before only because no model existed on this machine, making a ready broker impossible. **This will now bite any developer whose semantic arm actually works** — the fast suite is supposed to be pure per CLAUDE.md, and these three are not isolated from user-global broker state. Worth a separate fix (force CPU in-test, or isolate the broker endpoint per test run).
