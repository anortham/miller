## WHAT

Fixed a clean-worktree-only Scale harness failure in `SemanticBrokerScaleTests.StartProbe`. The test now resolves and launches the already-built probe apphost from the current configuration, Release, or Debug rather than hardcoding `dotnet run -c Release --no-build`.

## WHY

A normal Release solution/test build emits the probe helper under `scripts/Miller.SemanticBrokerProbe/bin/Debug/net10.0` because it is referenced as test support. The Scale test demanded the absent Release apphost, so the child exited immediately and the parent waited 30 seconds for a socket that could never appear. Developer machines with stale Release outputs masked the defect.

## HOW

- Reproduced the exact launch failure outside xUnit: the Release apphost path did not exist.
- Used the existing shared-broker host resolver pattern, including Windows `.exe` naming and an actionable missing-build assertion.
- Kept all changes in one Scale test file plus the release plan; no production or script parity changes.
- The focused eight-process test then passed, and the full Scale suite passed 138/138 with five optional-runtime skips.

## IMPACT

Clean release worktrees now run the broker Scale test deterministically without stale build outputs. Release build remains zero-warning/zero-error, fast suite remains 6,463 passed / 4 skipped, and v1.18.3 can continue through its long broker soak and package gates.
