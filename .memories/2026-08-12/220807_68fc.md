## Scale gate is red at pristine HEAD 3c68ba4e — 11 pre-existing Windows failures, NOT from the fix branch

Ran the opt-in Scale suite as the branch gate for the impact/dashboard/log-noise fixes. It failed. Re-ran the SAME 11 tests at pristine `main` HEAD `3c68ba4e` (the v1.18.3 release commit, zero local edits): **identical 11 failures**. The fixes are not the cause.

CI never caught it — run 31633472346 on that HEAD had `scale-test` and `windows-scale-smoke` **skipped**; the only red job was `sqlite-vec-aot-spike (win-x64)`.

- Branch run: Failed 11, Passed 127, Skipped 5, Total 143 (7m09s)
- Pristine-HEAD run of just those 11: Failed 11, Passed 0 (28s)
- Fast suite on the branch: 6466 passed / 3 failed / 22 skipped — those 3 are separate broker-environment failures, also reproduced at pristine HEAD

### Group 1 — extended-path prefix (2)

Expected root `C:/Users/.../Temp/miller-rebind...`, actual has the Win32 extended-length prefix (`//?/` form, real separators are backslashes). Something on the rebind path canonicalizes to the extended form. Decide whether the test expectation or the production canonicalization is right before changing either.

- `Indexing.RebindVerbScaleTests.Rebind_OnAnArtifactCopy_RetargetsTheRootAndLeavesTheFollowUpScanWithNothingToDo`
- `Server.RebindBootstrapScaleTests.Bootstrap_OfAFreshLinkedWorktree_RebindsTheMainCheckoutArtifactAndLeavesTheSourceUntouched`

### Group 2 — scan-governor timing races (5), all `Indexing.ScanGovernorContentionScaleTests`

The spawned scan finishes before the observer can witness admission held — failure payload shows `scan_duration_ms: 2392, duration_ms: 4097` on the `wt-large` fixture. Messages: "the probe never saw admission held, so nothing was actually governed" and a missing "Machine-wide scan admission is busy" substring. Fix by making the holder observable (a gate the test releases), not by widening a sleep.

- `ObserverProcess_WhileAScanHoldsAdmission_ReportsTheMachineWideHolder`
- `TwoSiblingWorktrees_ConcurrentFullOpen_NeverHoldScanAdmissionAtTheSameTime`
- `BlockedProcess_OnASeededRoot_ReportsLockBusy_AndKeepsServingTheExistingIndex`
- `BlockedProcess_OnAColdRoot_GivesUpInsideItsBudget_AndReportsAnUnusableIndex`
- `KilledHolder_FreesScanAdmission_WithoutManualCleanup`

### Group 3 — the rest (4)

- `Indexing.SemanticBrokerScaleTests.EightSameModelProcesses_LoadOneBrokerAndCompleteWithoutHangs` — expected 3, actual 0 brokers/completions
- `Server.VectorConvergePortScaleTests.Converge_ArtifactReplacementFromAnOlderMillerBuild_StillReusesStoredVectors` — expected version `1.18.3+3c68ba4ed4df`, actual `0.0.1+olderbuild`; the fixture pins a literal version the real build no longer produces
- `Server.StoreWorkspaceIndexProviderScaleTests.MissingFamilyStoreRootRebindsFromPartialLegacyResolution` — `IOException`, `workspaces.db` held by another process
- `Server.StoreWorkspaceIndexProviderScaleTests.ExplicitDowngradeOverrideRecoversAnUnreadableUnpublishedStore` — `IOException`, a `base-*.db` held by another process

Also seen once and NOT in the 11: `KeyNotFoundException` and `FormatException: The input string '' was not in a correct format` in the same output — attach them to a group when triaging.

### Why this matters

The v1.18.4 version bump was reverted and no release was cut. The Scale gate cannot certify a release until these are triaged, and CI skipping the Scale jobs means the next release would ship on a green-looking-but-unrun gate. Two separate problems: the 11 failures, and CI not running the jobs that would surface them.
