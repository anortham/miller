## Replaced family-store full-index hydration on interactive reads

- **WHAT:** `WorkspaceReadContext` now carries separate `ISymbolLookupIndex` and `ISymbolGraphReachability` surfaces. Family-store `Resolve`, context, impact, trace, and inspect-oriented symbol reads use generation-pinned disk-backed lookup/graph paths instead of building a complete `MillerRepositoryIndex`.
- **WHY:** Measured Miller MCP hosts retained 1–2 GB each because every family-store read hydrated and cached the full symbol graph. Default-on symbol reads also rebuilt an in-memory projection instead of using the generation-checked search sidecar.
- **HOW:** Reused `SymbolSearchSidecar.OpenStoreRequired`/`FtsSymbolSearchIndex` for default lookup, retained the explicit sidecar-off projection fallback, and taught `SqliteSymbolGraphIndex` to execute a complete traversal inside an existing `IWorkspaceReadSession.Read` without owning the session. Legacy repository-index behavior and bridge tracing remain intact.
- **IMPACT:** Removes the dominant per-host full graph allocation from family-store context/impact/trace and routes current plus registered symbol reads through the on-disk sidecar. Focused tests prove no full session-index load, one pinned graph read, non-ownership, and sidecar routing.
