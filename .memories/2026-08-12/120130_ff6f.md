## WHAT

Removed eager whole-corpus chunk and symbol-span hydration from content-index Open.

## WHY

Provider-stage telemetry proved the first context call spent 230 ms loading the content index. Inspection showed Open read every `content_chunks` and `content_symbol_spans` row before Search.

## HOW

Open now reads one metadata/chunk-count row plus schema/revision checks. Search joins candidate FTS rows to indexed chunk metadata, computes exact global average doc length once, hydrates full chunks in 400-ID batches, and loads spans only for hydrated source IDs in original stable order. Materialize likewise filters requested IDs/kinds/tests in bounded SQL before raw hydration.

## IMPACT

High-fanout Open reads one metadata row and zero eager chunks/spans; bounded Search hydrates one chunk/span with exact score/path/line/snippet/symbol parity. Public APIs/schema remain unchanged.
