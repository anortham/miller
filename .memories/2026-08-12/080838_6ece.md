## Split graph frontier SQL after exact composed-query reproduction

Every individual remaining graph arm was bounded, but the exact post-resolution four-arm production SQL still exceeded the interactive budget when composed.

- **Root cause:** Under `Direction.Both`, SQLite planned the relationship and unresolved-name arms as one compound query and materialized `identifier_resolutions` twice, scanning the base twice.
- **RED:** One real family query recorded 2,052.165 ms/0 rows, then the caller-facing family `Reach` test failed because fixed per-family statement telemetry and plan evidence did not exist.
- **Fix:** `BatchNeighbourEvidence` now executes relationship and unresolved-name forward/reverse statements separately and merges edges in memory. Family resolution capability remains unchanged; legacy resolution edges execute in separate fixed statements.
- **Parity:** The caller-facing test returns the hand-derived six neighbours across relationship, unresolved-name, identifier-resolution, and pending-resolution families.
- **Impact:** Removes compound-query materialization interaction without public API changes, temp indexes, attached-table graph SQL, or graph hydration.
