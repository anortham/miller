## Freshness log spam moved to Debug, wording corrected, per-file size cap added

Follow-up to the v1.18.3 bug fixes. The `Freshness: rebuilt + swapped index to revision N` line was 41% of
one day's log (774 of 1871 lines, peak 110/minute across 7 pids).

### Level — `FreshnessService.cs` + `FreshnessPoller.cs`

Added `FreshnessSwapReason { None, RevisionAdvanced, ArtifactReplaced }` and `out reason` overloads on
`PollOnce`/`PollOnceLazy`, keeping the existing `bool` signatures as delegating wrappers so the ~20 test call
sites are untouched. The reason rule stays in the poller — it is load-bearing (Eros field report #2: a
promoted rebuild restarts the revision counter, so artifact identity is the only signal).

- `RevisionAdvanced` → **Debug** (routine converge, twice a second per process, nothing actionable).
- `ArtifactReplaced` → **Information** (a full rebuild was promoted underneath this reader).

### Wording

Old text claimed a rebuild. In default store mode `PollOnceLazy` calls `IndexHolder.SwapLazy`, which swaps a
deferred factory and materializes on the next read — nothing was rebuilt. New text: "swapped index view to
revision N" / "artifact replaced; swapped index view to revision N".

### Retention — `MillerLoggingSetup.cs`

**Correction: I told the user retention was missing. It was not.** `retainedFileCountLimit: 14` was already
set on both sinks with a daily roll — the 28 files on disk are 14 days x 2 sinks, working as configured.
I had over-read CLAUDE.md's note about the removed per-pid startup reaper.

The real remaining gap was no per-file size cap: one busy day on a multi-process fleet is unbounded. Added
`FileSizeLimitBytes = 32MB` + `rollOnFileSizeLimit: true` to both sinks. Verified empirically that Serilog
accepts `shared: true` together with size rolling and actually rolls, rather than assuming it.

### Verification

- Build: 0 warnings, 0 errors.
- New tests: `FreshnessSwapLoggingTests` (4, capturing ILogger against the real service) asserts Debug for a
  routine swap, Information for a replaced artifact even when the revision did NOT advance, nothing on a
  no-op, and that no message contains "rebuilt". Plus 2 in `MillerLoggingSetupTests` for size rolling.
- Live A/B on the same shared log, same file churn: patched server (pid 49236) logged **zero** FreshnessService
  lines at default level; the unpatched plugin server (pid 29792) kept emitting Info swaps at revisions
  9581/9582.
- `MILLER_LOG_LEVEL=Debug` run produced 70 FreshnessService Debug lines, so the diagnostics survive. That
  window had no revision advance (observed == built == 9582), so the Debug SWAP line itself is covered by unit
  test, not live observation.
- Fast suite: **6466 passed, 3 failed, 22 skipped** (6491 total, up 6 from my new tests).

### The 3 remaining failures are environmental, not mine

All three are broker-observation tests failing because this machine has a live accelerated broker:
`WorkspaceStatus_UnsetSemanticReportsNotStartedWithoutCreatingBrokerState` expects `not_started`, gets
`ready`; `WorkspaceStatus_DefaultOnAndShadowPassivelyObserveAnExistingSharedBroker` (x2) expects
`backend=cpu`, gets `vulkan`. Verified earlier at pristine HEAD 3c68ba4e. CLAUDE.md already notes CI never
exercises semantic and the shared-broker gate is the manual soak script.

A fourth, `BootstrapAdmissionRetryTests.ADeterministicBootstrapFailureStaysTerminal`, failed only while my
probe servers were competing for the machine-wide scan governor; it PASSES once they exit. Worth knowing:
running Miller servers make parts of the suite flaky.
