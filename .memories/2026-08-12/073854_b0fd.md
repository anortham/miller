## Fixed family-store reverse graph read amplification

Real `context` acceptance stalled in the first frontier batch because reverse identifier and pending-resolution reads discarded candidate version identity and queried through overlay `UNION ALL` views.

- **Root cause:** SQLite could not push the target predicate through the compatibility union, so the base branch used an automatic index or full scan instead of Julie's target-leading indexes.
- **Fix:** Added an internal optional family graph-resolution capability below the union barrier. Base and delta branches execute separately with pinned `(target_version_id, target_symbol_id)` candidates; the graph index merges returned edges and preserves its standalone legacy path.
- **Semantics:** Identifier replacement and pending replacement/tombstone rules remain owned by `FamilyStoreReadSession`; public read-session, MCP, CLI, and producer schema contracts are unchanged.
- **Impact:** Reverse base arms now use `idx_read_resolution_identifiers_target` and `idx_read_resolution_pending_target` with automatic indexes disabled, eliminating the proven workspace-scale scan shape.
