## Miller 1.18.2 dogfood and performance audit

### WHAT

Dogfooded the rebuilt Miller 1.18.2+00f9a8a82a83 MCP server and CLI on the Miller workspace (225,808 indexed documents). Exercised workspace, search, inspect, context, trace, impact, patterns, content, edit preview, onboarding, health, metrics, and reference/report CLI paths.

### WHY

The user asked for a post-rebuild restart check covering tool correctness, timing, unexpected results, errors, and performance.

### HOW

- Initial health showed current index revision 9495 but stale search/content sidecars, unavailable vectors, semantic broker not started, queue non-empty, and a leader-startup scan-governor hold.
- Repeated MCP reads failed visibly in 14–37 ms with the stale-sidecar diagnostic; patterns list remained available.
- CLI refresh --json --wait returned status refreshed in 60 ms while still reporting stale sidecars; resident MCP refresh queued work.
- After several minutes the resident leader converged revision 9718, exact store resolution, current search/content sidecars, 100% vectors, and a ready Vulkan semantic broker.
- Three warm MCP runs then succeeded: lexical search 57–58 ms, semantic search 124–133 ms, inspect 153–154 ms, trace 78–79 ms, context 1.37–1.50 s, impact 1.69–1.70 s, patterns list 135–137 ms, patterns search 16 ms warm, content search 33–34 ms. Edit preview was 23–24 ms warm after a 6.8 s cold run and remained applied=false/disk_verified=true.
- Semantic conceptual search returned relevant ScanGovernor symbols; semantic-off and sidecar-off lexical outputs were byte-identical.
- CLI one-shot read paths with search sidecar disabled cost about 7.4–8.1 s and 571–577 MB RSS. Metrics churn was 9.2 s/711 MB and complexity 8.4 s/571 MB. Clones ran 144.7 s/575 MB before interruption; reference candidates ran 105.9 s/615 MB before interruption; report ran 98.5 s/578 MB before interruption, with no buffered output.
- Current logs showed no unhandled exceptions or internal_failure after convergence. Health still reports 12 parse diagnostics, 111 open capability gaps, and 131 recent telemetry errors, the latter including the intentional stale-sidecar calls and prior session history.
- The resident leader peaked near 2.0 GB HWM and settled around 964 MB RSS; semantic broker was about 145 MB RSS.

### IMPACT

MCP read tools are healthy and fast once sidecars are converged. The main findings are slow/heavy one-shot analysis/report surfaces, high resident memory after convergence, and a multi-minute post-restart leader-startup/sidecar convergence window. No source files were changed; the pre-existing TODO.md modification remains untouched.
