## Codex review of the semantic-diagnostics change: 2 of 3 findings were real bugs, now fixed

Ran `codex exec` adversarial review (codex-cli 0.147.0, read-only, structured JSON schema) against the 7-file working-tree diff. Verdict `needs-attention`, three medium findings. I verified each against the real code rather than accepting them.

### Accepted — finding 2: onboarding used a negative allowlist
`SemanticNeedsPreparing` excluded only `disabled`/`ready`/`building`/`downloading`, so **every other state emitted the "run `miller semantic prepare`" note** — including `incompatible` (encoder mismatch), `circuit-open` (sidecar restarts exhausted), and `disk-blocked`. Telling someone whose disk is full to download 134 MB is actively harmful, and none of those states are fixed by a download.

### Accepted — finding 3: the health recommendation was unconditional
`AddVectorWarnings` returns early for `disabled`, `ready`, and `model-not-prepared`; **everything else falls through to the generic block**, which I had made add the prepare recommendation unconditionally. So `building` and `downloading` — active convergence and an in-flight model download — both told the operator to go download the model. I had correctly gated onboarding against these states and then failed to apply the same gate to health. Codex caught the inconsistency I introduced.

**Fix for both:** replaced the negative allowlist with a positive one. Prepare is now recommended only for `model-not-prepared` (definitive) and `unavailable` (plausible fresh install, hedged with "if vectors have never converged here"). Proven by 8 new `[Theory]` cases across health and onboarding covering `building`/`downloading`/`disk-blocked`/`incompatible`, plus a positive `model-not-prepared` onboarding case. All 6 relevant cases went RED first.

### Rejected — finding 1: "RecordedPause accepts stale pause metadata"
Codex claimed `RecordedPause` never validates the pause against the current attempt, so a persisted `model-not-prepared` could mask a genuinely stale-but-converging artifact. **`VectorConvergeService.ResolvePause` (line 1217) disproves this**: it runs on every drain and writes an empty pause value whenever the embedding session is healthy and disk is not blocked, and `VectorSidecar.PauseState` treats empty as absent. The pause is bound to the live convergence attempt by construction. Codex also asserted a persisted `disabled` state could leak through — false; `PauseState` recognizes only the three pause values, and `disabled` is never one.

The residual truth in that finding: a brand-new artifact that no leader has drained yet carries no pause, so it still falls through to the stamp message. That is precisely the fresh-install case the health/onboarding hints were added to cover, so the design is coherent.
