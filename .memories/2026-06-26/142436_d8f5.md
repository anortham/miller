## Dogfooded five-gap Miller surfaces

- **WHAT:** Exercised the freshly built five-gap worktree through the live MCP server, the worktree CLI binary, and the dashboard.
- **WHY:** The user rebuilt/restarted and asked for practical dogfood coverage across the tools before continuing.
- **HOW:** Used the registered workspace selector `five-gap-implementation-b04437b16dc3` for MCP read tools; used the worktree Release binary for new CLI-only surfaces; launched the dashboard and verified both detached and foreground behavior.
- **IMPACT:** Confirmed the new `metrics` and `workspace leader` CLI commands are visible in `capabilities --json`, metrics churn/complexity/clones execute, inspect near-miss suggestions work in the new CLI, and the dashboard renders the new health/onboarding panels in foreground mode. Captured several follow-up defects/frictions: active MCP process is still the main checkout binary and does not expose `metrics` or `workspace leader`; `content read` cannot read workspace-doc source ids returned by `content search`; detached dashboard launch reports `started` but the process exits immediately; clone metrics can return huge groups despite small group limits; `edit` cannot route by `workspace_id` though absolute paths work; search miss recovery is weaker than inspect and JSON returns bare arrays/empties without hint metadata.
