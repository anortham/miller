## Prepared Miller v1.1.1 tool-surface release

### WHAT

Removed the `metrics` MCP tool while preserving the deterministic metrics workflows through CLI, skills, and dashboard.

- MCP server registration now exposes nine tools again: `search`, `inspect`, `context`, `trace`, `impact`, `edit`, `content`, `patterns`, and `workspace`.
- `miller metrics churn|clones|complexity` remains the CLI/export contract path.
- Dashboard selected-workspace details now show complexity hotspots and body-hash clone groups.
- Added `miller-metrics-audit` and `miller-patterns-audit` skills; tightened `miller-editing` exact-match guidance.
- Added CLAUDE/AGENTS rule: adding a new MCP tool requires explicit user approval.
- Bumped release/plugin versions to `1.1.1` and added `docs/release-notes/v1.1.1.md`.

### WHY

User wanted the 1.1.0 metrics work shipped without expanding the agent-facing MCP surface. Metrics are useful local facts, but not valuable enough as a default MCP tool to justify increasing tool count.

### HOW

- Converted `MetricsTool` to a static CLI-only core and removed `.WithTools<MetricsTool>()`.
- Kept `metrics-json-v1` as a CLI-only contract.
- Rendered artifact-backed complexity/clone summaries in the dashboard; left git churn CLI-only because it depends on explicit git revision ranges.
- Improved `patterns` compact empty-state recovery and filtered metadata display.
- Regenerated `AGENTS.md` from `CLAUDE.md` and synced plugin skills.

### IMPACT

Release `v1.1.1` is ready for commit/push/package validation. The key release objective is verified locally: fresh MCP `tools/list` returns exactly nine tools and no `metrics`.
