## Investigated AccessIQ scoped CSS search miss

Miller did not miss the CSS result; `file_pattern=wwwroot/css/**` is repo-relative and AccessIQ indexes the file as `src/AccessIQ/wwwroot/css/site.css`.

- **What:** Reproduced the Cursor-reported `.iq-card` search against `/Users/murphy/source/AccessIQ`, confirmed `wwwroot/css/**` returns a filtered miss while `src/AccessIQ/wwwroot/css/**` and `**/wwwroot/css/**` return the CSS hit.
- **Why:** The compact empty state was technically correct but misleading: it showed the CSS file under `Outside scope` without explaining that slash-containing patterns are matched against repo-relative paths.
- **How:** Added a shared filtered-miss hint that detects outside-scope hits which would match if the user prefixed the pattern with `**/`, then suggests that nested glob. Added symbol and source-text regression tests for the AccessIQ-shaped `wwwroot/css/**` case.
- **Impact:** Agents should recover from this class of scoped search miss without falling back to raw grep/read; search matching semantics remain unchanged.
