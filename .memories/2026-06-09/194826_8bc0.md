## Patterns tool deep-review follow-up

### WHAT
- Fixed `miller patterns --json` so a flags-first call defaults to `list`, matching the advertised capabilities/Eros contract.
- Added CLI regression tests for `patterns --json` and `patterns --help` not requiring an index.
- Changed pattern search to stream structural-fact matches and apply the result limit after path/language filtering instead of materializing every row for common pattern ids.
- Updated README examples, GitHub Pages `docs/site/index.html`, `patterns-json-v1`, and the synced `CLAUDE.md`/`AGENTS.md` harness notes.
- Improved MCP `patterns` tool descriptions so agents know to call with no args first, then search by `pattern_id` plus filters.

### WHY
The deep review found the public contract was not directly callable, the search path had unnecessary allocation risk on large workspaces, and public/harness docs did not expose the new tool surface.

### HOW
- Treated a leading CLI flag as the default `list` operation while preserving explicit `search`/`summary` behavior.
- Added `PatternFactsReader.EnumerateMatches` and used it in `PatternsTool.Search` to stop after filtered matches.
- Edited `CLAUDE.md` first and regenerated `AGENTS.md` with `scripts/sync-agents.sh`.

### IMPACT
The patterns tool is easier for agents and Eros to discover, the default advertised CLI call now works, and large pattern searches avoid unnecessary list materialization.
