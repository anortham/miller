## Patterns implementation plan written

### WHAT
Created the implementation plan for the future Miller `patterns` MCP/CLI surface over `structural_facts`.

### WHY
The approved design needed an executable plan with exact file ownership, task breakdown, TDD gates, verification scope, and architecture guardrails before implementation begins.

### HOW
The plan decomposes the feature into reader, cheap workspace artifact routing, shared path/language filters, MCP tool rendering, CLI command, contracts/capabilities, and final verification. It also updates the design to clarify that `patterns` is a normal read tool with `workspace_id`/`--workspace-id`, and that first-slice metadata filtering uses one `where` string in `key=value` form.

### IMPACT
Implementation can proceed without guessing module boundaries. The plan explicitly avoids raw AST query execution, per-pattern switches, private SQLite coupling for Eros, and full-index hydration when only the extract DB path is needed.
