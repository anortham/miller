## Implemented Miller patterns tool

### WHAT
- Added `PatternFactsReader` over `structural_facts` with list, summary, search, metadata parsing, and malformed-metadata tolerance.
- Added cheap workspace artifact routing via `IWorkspaceArtifactProvider` / `WorkspaceArtifactContext` so DB-path-only tools do not hydrate the full symbol index.
- Added MCP `patterns` tool and CLI `miller patterns` with `list`, `summary`, and `search` operations.
- Added `patterns-json-v1` docs, Eros CLI contract discovery, capabilities entries, and MCP agent guidance.

### WHY
Agents and Eros need a stable way to consume extractor-recognized code-shape facts without raw AST queries or private SQLite coupling.

### HOW
- Kept pattern recognition in `julie-extractors`; Miller only reads generic `pattern_id` facts, filters by path/language/metadata, groups, and renders.
- Reused existing read-tool workspace selector semantics and extracted shared path/language glob filtering from `SearchTool`.
- Used TDD for reader, tool, routing, CLI, and agent-guidance behavior.

### IMPACT
Miller can now expose known structural patterns through both MCP and CLI JSON. Eros can consume `patterns --json` as a documented commercial-facing integration surface instead of reaching into Miller internals.
