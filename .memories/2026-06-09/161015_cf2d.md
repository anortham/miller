## Implemented reference-aware context usage mode

### WHAT

Added an opt-in `context` usage mode for Miller that enriches context bundles with reason/confidence-labeled usage evidence.

- Added `reference_mode=usage`, `reference_depth`, and `exclude_tests` to the MCP `context` tool.
- Added CLI support for `miller context <query> --reference-mode usage`.
- Added `ContentCorpusContextReader` to read source chunks attached by `containing_symbol_id`/`containing_symbol_name` from `content.db`.
- Added JSON/compact rendering for mixed bundle items: `symbol`, `identifier`, and `content_chunk`.
- Updated Miller agent instructions, CLI help, Eros CLI contract docs, capabilities feature discovery, and the reference-aware design doc with dogfood evidence.

### WHY

The existing `context` tool mostly returned definitions and graph neighbors. The new usage mode lets an agent see how selected symbols are used without embeddings or extractor changes, while preserving exact/default behavior for existing callers.

### HOW

- Reused the existing seed and graph candidate path by factoring it into a shared candidate builder.
- Kept `Miller.Core` pure; SQLite reads stay in `Miller.Indexing` and server/CLI seams.
- Treated identifier rows as `possible_reference` with `confidence=name_based`, because current identifier reference data is name-based rather than resolved target-symbol edges.
- Used `ContextPacker` to keep enriched bundles token-budgeted.

### IMPACT

Agents can now request usage-aware context and get explicit evidence labels for definitions, possible name references, call identifiers, and containing source chunks. Eros can discover the feature via `capabilities --json` and can consume the structured `context --json` bundle without parsing compact text.
