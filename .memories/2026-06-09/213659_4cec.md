## Fixed watcher registry revision drift

- **WHAT:** Verified the live file watcher/incremental update pipeline with a real temp MCP server workspace, found a false-stale status bug, and fixed `IndexerService` so successful index convergence marks the workspace registry at the latest revision.
- **WHY:** After a watched file edit, `symbols.db`, `search.db`, and `content.db` advanced correctly, but one-shot `workspace status --json` compared sidecars against the stale registry revision and reported them stale. That could also affect registry-backed/cross-workspace views.
- **HOW:** Removed the search-sidecar-enabled early return from watcher convergence so content corpus and registry updates still run, added `TryMarkRegistryScanned`, and updated the watcher drain test seam to run the same post-drain convergence as production. Added regression tests for watcher drain and inline edit write-through registry revision updates.
- **IMPACT:** The watcher path now keeps `symbols.db`, search sidecar, content corpus, freshness status, and registry revision aligned after incremental edits. Live smoke confirmed a file edit moved status from revision 2 to 3 with both sidecars current and updated source text searchable.
