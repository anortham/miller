## Wired Structural Facts Into Bridge Trace

- **WHAT:** Miller now reads relevant `structural_facts` rows and feeds them into the dotnet-web bridge graph. The provider converts `htmx.attribute.v1`, `vue.route_reference.v1`, and `aspnet.minimal_api.route.v1` facts into bridge candidates.
- **WHY:** The patterns tool proved julie-extractors was emitting useful web-stack facts, but `trace mode=bridge` ignored them, so htmx/Vue frontend routes did not resolve to ASP.NET minimal API handlers.
- **HOW:** Added `StructuralFactRecord`, extended `BridgeProviderContext` and `BridgeGraphBuilder`, taught `SqliteBridgeReader` to read bridge-relevant structural facts, and updated `DotnetWebBridgeProvider` to derive client calls and endpoints from those facts. Added a conservative `MapGroup` source-region fallback so AccessIQ route group prefixes compose without another extractor release.
- **IMPACT:** AccessIQ htmx traces now produce high-confidence hits from `ConnectorForm` to minimal API handlers such as `SaveAsync` and `PreviewEmailAsync`; Vue route-reference facts are covered by core graph tests. The bridge no longer emits noisy structural endpoint `Consumes` edges for minimal API service parameters.
