## Completed Task 3 htmx and ASP.NET minimal API bridge review

### WHAT

Task 3 is implemented and lead-reviewed clean in the Miller web-stack structural facts bridge worktree.

- Added `WebStackStructuralFactReducer` in Miller Core.
- Reduced `aspnet.minimal_api.route.v1` facts into `ControllerEndpoint` inputs.
- Reduced route-bearing `htmx.attribute.v1` facts into `TsClientCall` inputs with carriers like `htmx.get` and `htmx.post`.
- Merged structural routes/calls into `DotnetWebBridgeProvider` before `RouteBridge.Resolve`.
- Added htmx/minimal API bridge graph tests.

### WHY

This is the first real bridge consumer of parser-backed structural facts: `hx-get="/todos"` can now link to ASP.NET `MapGet("/todos", ...)` through existing bridge scoring instead of raw text parsing.

### HOW

The reducer consumes only `StructuralFactRecord.MetadataJson` and contract fields. It requires `route_template` plus verb for minimal API endpoints, requires `target_path` plus a route-bearing `hx-*` attribute for htmx calls, and ignores non-route attributes such as `hx-target`.

### IMPACT

Task 4 can now add Vue route facts by extending the same reducer/provider path. Task 3 did not add MCP tools, modify `PatternsTool`, or parse source text in Miller.
