## Miller consumes julie-extractors v2.5.6 route facts

- **WHAT:** Updated Miller's `julie-extract` pin to `2.5.6`, restored the local `.tools/julie-extract`, and expanded dotnet-web bridge consumption of parser-backed structural route facts.
- **WHY:** v2.5.6 emits the extractor facts Miller needed: ASP.NET Minimal API `route_group` plus `effective_route_template`, Vue route definitions, React Router route references/definitions, and Next.js route references/file routes. Miller should use those facts directly for trace instead of source-text `MapGroup` scraping.
- **HOW:** `SqliteBridgeReader` now reads the v2.5.6 route fact IDs, no longer scrapes `source_regions` for `MapGroup` string literals, and `DotnetWebBridgeProvider` prefers `effective_route_template`, reduces frontend route facts from `target_path`, `attribute_value`, `normalized_route_template`, or `route_path`, defaults static frontend route facts to GET, and filters structural frontend facts from test paths.
- **IMPACT:** Release CLI dogfood now resolves AccessIQ `/admin/connectors/save` from `ConnectorForm` to `SaveAsync` using htmx + effective ASP.NET facts, while Tycho diagnostics correctly report `/calendar` as frontend-only and `/keep-alive.html` as backend-only without Next test-file route noise.
