## Improved Framework Bridge Trace Pattern

- **WHAT:** Made `trace mode=bridge` route targets precise, retained unmatched framework route facts as observation nodes, added actionable route diagnostics, and supported synthetic ASP.NET minimal API endpoints for lambda/unresolved handlers.
- **WHY:** The initial htmx/Vue structural-facts bridge worked for matched AccessIQ routes, but URL route targets emitted every edge from the owning component and Tycho Vue routes looked broken when there was no matching backend endpoint. This needed to become the reusable pattern for future framework bridges.
- **HOW:** Added route-filtered bridge walks in `TraceTool`, exposed read-only bridge nodes on `BridgeGraph`, extended `BridgeProviderResult` with provider observation nodes, merged those nodes in `BridgeGraphBuilder`, made `ControllerEndpoint.SymbolId` nullable for non-symbol structural endpoints, and refactored `DotnetWebBridgeProvider` into private frontend-route/backend-endpoint fact adapter helpers.
- **IMPACT:** AccessIQ `/admin/connectors/save` now emits only `ConnectorForm -> SaveAsync`. Tycho `/calendar` now reports the frontend route fact exists and shows `/keep-alive.html` as the observed backend route. Tycho `/keep-alive.html` now reports the backend route fact exists and shows `/calendar` as the observed frontend route. Lambda minimal API facts can become synthetic endpoint nodes without fake code symbols.
