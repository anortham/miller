## Brainstorm outcome: store-path incremental resolution (design brief written)

**WHAT:** A Miller-session brainstorm about deferring relationship data ended in an approved design brief for julie-extractors: `docs/plans/2026-08-11-store-incremental-resolution-brief.md` (written, not yet committed there).

**WHY:** The user asked whether relationship data could be computed on demand per query instead of up front. Research verdict: sound for point queries (~50–300 ms cold) but unusable for graph tools (`impact`/`trace path`/`context`: 5–60+ s cold). The decisive discovery: row-level delta resolution SHIPPED in julie-extract v2.26–v2.28 but only for the legacy artifact path — the family store (Miller's default since 1.18.0) hard-codes full-corpus resolution at both `store/resolve.rs` call sites (`:313` base build, `:419` per-request, both `run_resolution_session(session, true, true)`). A 98-file store resolve costs 2m24s even after the v2.31.4 repair.

**HOW (approved design):** Scope the resolution, not the diff/publish. New `resolution_scope_journal` additive store table (write-time capture of changed paths + touched names incl. OLD names), `store_delta_scope` (ported name-set expansions + 0.7 crossover), `StorePriorOverlay` (base+bound-delta prior state so `resolve_delta` runs unmodified), `materialize_overlay_exact` (carry-forward makes the exact file byte-identical to a full pass; `catalog_hash` is the free oracle). Diff/publish/Miller read contract untouched. T7 base-rebase slice fixes the 151.7 MB `exact_gap_json` growth (71 rows, repeated identical 7.4 MB payloads — previously unreported anomaly).

**User decisions:** (1) rebase slice in scope; (2) NO shadow/trial period — ship after the equivalence hazard suite + Miller-store 98-file replay gate pass, off-switch env only; (3) journal table from the start so the fast path never falls back due to retention.

**IMPACT:** Task breakdown T1–T7 in the brief (~5–7 agent tasks in julie-extractors). Miller stays untouched; the other active Miller session owns this tree. Also recorded process feedback to memory: plain-language questions only; "I don't understand" means re-explain, never decide-and-proceed.
