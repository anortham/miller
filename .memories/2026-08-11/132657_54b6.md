## Diagnosed post-1.18.1 dogfood failures

### WHAT

- Added the requested active `TODO.md` entry for JSON `inspect`/`trace`/`impact` diagnostics returning `invalid_json_output` during resolution convergence.
- Isolated `context` latency to outgoing-reference enrichment over family-store compatibility views.
- Isolated the Windows `capacity_probe_failed` bootstrap report to the pinned `julie-extract` PowerShell capacity probe.

### WHY

The new family-store default exposed two expensive/fragile producer and consumer paths that fast local dogfood did not make obvious.

### HOW

- Controlled `context` runs remained slow with `reference_mode=off`, `max_hops=0`, and 200-token budgets, proving the budget is applied after candidate enrichment.
- Semantic search measured 122ms and content search 330ms; reference-rich `inspect`/`trace` took seconds.
- `BuildCandidates` calls `PromoteTermRescueTestSubjects`, which searches up to six test candidates per query term and reads outgoing evidence for each unique hit before selecting pivots.
- Family-store `identifier_resolutions`/`pending_resolutions` compatibility views discard `version_id`; `ReferenceEvidenceReader` then joins/correlates on local IDs only. On the live 415,975-row base, one method's exact arm took 1.32s and fallback arm 4.86s. A composite `(version_id, local_id)` query pushed through the containing-symbol filter returned the same 301 exact and 130 fallback rows in under 10ms.
- Producer v2.31.4 invokes `powershell.exe -Command "(Get-Volume -FilePath $args[0]).SizeRemaining" <path>`. Windows PowerShell treats arguments after a string `-Command` as more command text, so `$args[0]` is not populated as assumed. Miller only propagates the failed producer result.
- Scheduled Windows Scale CI reproduced store failures, but the Windows store scale suite is not a PR/release gate.

### IMPACT

- Context needs a store-aware targeted/composite reference query and a bounded/cached term-rescue policy; token budget alone cannot cap current compute.
- `julie-extract` should replace the shell probe with `GetDiskFreeSpaceExW` (or a correctly parameterized subprocess), add Windows argv/integration coverage, and preserve stderr in failures.
- Miller should improve Scale failure assertions and promote Windows store Scale coverage into release gating.
