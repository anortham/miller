## Wrote the user-relief bugfix program

### WHAT

Created `docs/plans/2026-08-11-user-relief-bugfix-program.md`, a six-task cross-repository plan covering all confirmed bugs and the actionable semantic item from `TODO.md`.

### WHY

Users need immediate relief from invalid JSON diagnostics, 30-second context calls, semantic prepare requiring restart, and Windows family-store bootstrap failure. Product backlog work was intentionally kept out so the batch remains verifiable and releaseable.

### HOW

- Keep `ReferenceEvidenceReader` public callers stable and add a partial family-store implementation using targeted composite `(version_id, local_id)` SQL.
- Bound optional context term-rescue evidence reads at eight and memoize them.
- Make the existing sidecar broker loader health-recoverable without process respawn.
- Park Miller sessions on `model_not_prepared`, probe only from converge/prepare paths, and correct health guidance.
- Replace extractor `df`/PowerShell probes with safe `fs4 1.1.0`; direct `windows-sys` was rejected because the workspace forbids unsafe code.
- Promote existing Windows live-store Scale coverage to pull requests and preserve producer failure details.
- Finish with from-source cross-repo integration; publication remains explicitly approval-gated.

### IMPACT

The plan is ready for implementation and targets a locally verified sidecar 0.1.1, extractor 2.31.5, and Miller 1.18.2 candidate. It records hard query-shape/state-transition gates and report-only dogfood timing comparisons.
