## WHAT

Implemented cooperative cancellation for Miller's `context` MCP request in `ContextTool`.

- Added a framework-bound cancellation-aware MCP handler while preserving the existing direct `Context` wrapper.
- Propagated cancellation through candidate discovery, term rescue, body enrichment, usage/reference assembly, packing, and bounded rendering.
- Added regressions for mid-enrichment cancellation, handler cancellation propagation, and omission of the token from the generated JSON schema.
- Marked the approved design implemented and its acceptance criteria complete.

## WHY

A client-abandoned reference-aware context request kept one .NET thread at 100% CPU and prevented graceful shutdown because the synchronous pipeline never observed request cancellation.

## HOW

The installed MCP/AI binding contract automatically supplies `CancellationToken` and excludes it from JSON schema. Existing non-MCP callers continue through the no-token wrapper. `OperationCanceledException` is rethrown instead of converted into a tool diagnostic. Cancellation checks occur at phase boundaries, after external callbacks, and inside candidate/reference loops.

## IMPACT

Canceled context work now stops cooperatively instead of becoming an orphaned CPU loop. Uncanceled output remains covered by the existing ContextTool suite, and the published tool schema remains unchanged.
