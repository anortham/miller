## WHAT

Implemented Miller-side recovery after a semantic model is prepared while a broker/session is already live.

- Added a parked `ModelNotPrepared` session state with explicit readiness probing.
- Propagated that state through convergence, vector classification/opening, semantic-search fallback, workspace status, and health guidance.
- Added passive post-prepare broker probing with `activated`, `no_live_broker`, and `still_not_ready` outcomes while preserving prepare exit code 0.
- Corrected the plan’s ownership omission by including `VectorSidecar` and its narrow classification/open tests.

## WHY

The previous client treated `model_not_prepared` as a terminal circuit state. Even after successful model preparation, the live Miller process could not recover without restart and operator guidance suggested the wrong action.

## HOW

Only the exact valid protocol refusal parks the session; transport failures retain fatal/backoff behavior. Embed calls fail fast while parked, while convergence and explicit prepare use the cold-load initialization timeout to probe. Activation observes an existing broker only and never enters spawn/owner election.

## IMPACT

Miller can recover the same live semantic session after preparation, reports a distinct actionable state, and tells the user to run `miller semantic prepare`. Frozen protocol-v1 fields, methods, error codes, and off-switch behavior remain unchanged.
