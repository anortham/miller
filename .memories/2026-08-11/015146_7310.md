## WHAT

Added a conservative zero-change fast-forward for Miller's family-store search and content sidecars.

- `StoreSidecarCatalog.TryFastForwardEmptyDelta` advances an existing sidecar only when its serving identity is unchanged and the complete store revision delta contains no changed or deleted paths.
- Search updates its internal revision plus store stamp atomically.
- Content updates workspace revisions for corpus metadata and workspace sources plus the store stamp atomically.
- Non-empty, incomplete, schema-incompatible, identity-changing, or level-changing cases retain the existing full rebuild.
- Tests prove search/content fast-forward, sentinel preservation, transaction rollback, and non-empty fallback.

## WHY

The first default family-store dogfood run advanced store sequence 6168 to 6385 with a reused manifest and zero changed paths, but Miller replaced the 359 MB search sidecar and 129 MB content sidecar anyway. That unnecessary rewrite added roughly 1.5 minutes after producer convergence.

## HOW

The fast path compares the prior and expected store sidecar stamps while permitting only sequence and resolution-stamp advancement, reads the bounded revision delta, and opens the sidecar read-write only after proving that delta complete and empty. It rechecks the stamp and commits sidecar-native metadata plus the shared stamp in one SQLite transaction. Any uncertainty returns false and invokes the established rebuild path.

## IMPACT

No-change store journal advances no longer rewrite large search/content databases. Non-empty A8 cursor-incremental convergence remains separate work; this repair closes the measured zero-delta case without weakening freshness or fallback behavior.
