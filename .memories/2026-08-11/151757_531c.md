## WHAT

Reworked family-store reference reads to use targeted composite-key SQL and bounded Context rescue enrichment.

- Added a family-store partial with version-scoped base/delta resolution queries.
- Routed session-based inbound, outgoing, bundled, and kind reads through the store-aware path while leaving legacy DB-path SQL unchanged.
- Deterministically ranks, memoizes, and caps optional term-rescue outgoing reads at eight.
- Added collision, composite query-plan, eight-read-cap, and byte-for-byte legacy/family parity coverage.

## WHY

Family-store reference reads scanned large base resolution tables repeatedly. Context and inspect calls could exceed 30–60 seconds, and local IDs could only be interpreted safely when paired with `version_id`.

## HOW

Targeted queries first resolve visible `(version_id, local_id)` keys, probe base/delta tables through their composite indexes, apply replacement/tombstone rules, then reuse existing parsers, deduplication, bounds, ordering, coverage, and fallback logic. Context optional promotion work is capped before reads.

## IMPACT

Warm inbound reads on the real store fell from about 1.21 seconds to about 0.001 seconds. Cold usage Context fell from timeout to 12.23 seconds, versus a 9.35-second reference-off startup baseline. Returned evidence remains byte-identical to the equivalent legacy projection.
