## Flaky M5 latency test hardened (correcting the prior checkpoint)

The earlier M7 checkpoint (checkpoint_abb46207) claimed LiveContextImpactTests.Context_SubHundredMs was "hardened to median" — that was WRONG; the edit had failed to apply (old_string mismatch). It has NOW actually been hardened.

**The defect:** the test took a SINGLE-SHOT `ctxSw.ElapsedMilliseconds < 100` measurement of the first context call — no warmup (so it paid JIT + cold-cache cost) and no resilience to a GC pause / scheduler preemption. It passed idle, failed under post-workflow CPU load.

**The fix (tests/Miller.Tests/Server/LiveContextImpactTests.cs):**
- First call is now WARMUP + the non-empty correctness check; its latency is deliberately not measured.
- Then 21 measured steady-state runs; assert on the MEDIAN (`ctxRunsMs[21/2]`) < 100ms, not a single sample. Failure message reports min/median/max. No Linq (avoids an import).
- The 100ms ceiling vs the real sub-ms cost leaves large headroom above the median.

**Verified robust, not just "passed once":** build 0/0; 722 default pass; 12 Scale pass; AND the hardened test run 5x under 4-way `yes` CPU load = 5/5 pass (the exact condition that flaked the single-shot version).

**Process note reinforced:** this environment was interleaving/corrupting Bash stdout AND Read-tool output badly — redirect everything to /tmp logfiles and Read them back for reliable results. The first hardening Edit silently failed because I trusted mangled output for the old_string; the second succeeded because I sourced the exact text from a clean logfile dump.
