## WHAT

Validated v1.19.2 end to end and implemented four corrections across Miller and julie-extractors:

- Miller retries a failed seeded store import once as a fresh import.
- `IndexerCore.HasPendingWork` no longer blocks status/tool calls behind a synchronous scan.
- Miller holds read transactions on both family `coord.db` and serving generation `store.db` for every store mutation child process, preventing SQLite WAL shared-memory teardown races.
- Julie resolve waiters return immediately when their durable request becomes committed/acknowledged/failed.
- Julie ordinary writer-open now runs the idempotent schema ensure, repairing missing read indexes such as `idx_read_symbols_symbol` on upgraded stores.

## WHY

The live upgraded workspace initially hung status for minutes, resolve waiters slept until their ten-minute deadline, and concurrent store mutations produced repeatable SIGBUS cores in SQLite `walFindFrame`. The live store also lacked the shipped symbol-id lookup index, making default impact take 16.5–17.0 seconds.

## HOW

Used live MCP/CLI timing, request journals, phase logs, SQLite schema/plan evidence, and coredump stacks. A held read transaction proved the WAL lifecycle cause. The schema repair was placed after writer lease/fencing and reuses existing idempotent DDL. Tests cover fresh/replayed seed fallback, nonblocking pending-work telemetry, both WAL anchors, terminal resolve waiters, and writer-open schema repair.

## IMPACT

Fresh reader startup is ~281 ms and status 132 ms median. Healthy tool medians: lexical search 66 ms, hybrid 230 ms, inspect 103 ms, trace 51 ms, patterns 50 ms, content 256 ms, impact 1.07 s, context 1.88 s. Default CLI impact is 1.35–1.39 s with byte-identical output across three runs after the live index repair. Miller fast gate: 6,572 passed/4 skipped; Scale: 138 passed/10 skipped; zero failures. Julie connection contracts: 28 passed; resolve contracts: 32 passed.

One producer performance gap remains: after 79 files accumulated against an old resolution base, a nominal one-file change reprocessed 227,249 scoped rows and took 100.3 s. Existing bounded children batching is already present; this needs a separate cumulative-delta/rebase design correction rather than a superficial limit change.
