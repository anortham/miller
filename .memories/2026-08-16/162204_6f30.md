## Located the accumulated-resolution-delta failure mode

### WHAT

Traced the 79-file / 227,249-row / 100.3-second case to `julie-extractors` scope reconstruction and rebase policy. Miller is only the caller and reporter; no Miller API or MCP change is required.

### WHY

The latest request can inherit the entire validated transition chain since its exact predecessor. Name, alias, receiver, and module expansion widened 79 changed paths to 227,249 admitted rows, but the 70% full-scope crossover did not fire.

### HOW

- `build_store_delta_scope` reconstructs every valid batch through `validated_scope_changes`.
- `scope_crosses_over` promotes only at 70% of corpus identifier cost.
- `exact_rebase_required_inner` rebases only after resolution and only above 25% replacement/tombstone rows or 64 MiB cumulative gap JSON.
- Neither policy measures accumulated transition age or the actual base-plus-delta overlay work that made the scoped path slow.

### IMPACT

The recommended correction is producer-local: add a deterministic accumulated-work rebase budget so an exact publication compacts before the next small request inherits an oversized overlay. Keep full resolution as a correctness fallback, not the primary speed fix. Add a realistic multi-transition fixture with row-count assertions and identical full/scoped digest; profile phase costs before changing the scoped processor.
