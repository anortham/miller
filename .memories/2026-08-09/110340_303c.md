## Added the typed julie store process boundary

Miller can now invoke every released family-store verb without exposing raw argv or JSON to later lifecycle code.

- **What:** Added typed import, update, delete, resolve, and export requests; typed report, manifest, resolution, failure, and coordinator results; and one supervised subprocess client.
- **Why:** Ph3 needs a stable process boundary before registry, reader, sidecar, or bootstrap code can depend on the store.
- **How:** Built exact argv from operation-specific records, parsed report schema 1 with source generation and invariant checks, bounded cancellation and process time, and attached Windows kill-on-close containment.
- **Impact:** Later tasks can use `IJulieStoreClient` without opening `store.db` or `coord.db` writable or duplicating Julie's queue/retry rules.
