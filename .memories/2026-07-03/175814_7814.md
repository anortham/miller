## Fixed Eros-facing Miller review findings

- **WHAT:** Added artifact-generation validation to `impact --from-index-revision`, surfaced `index.artifact_id` in workspace status JSON, aligned plugin manifests to 1.4.1, and updated the Eros-facing docs/release notes.
- **WHY:** Numeric revision watermarks are unsafe across full rebuilds because julie-extract revision counters can restart. Eros needs a revision plus artifact id to distinguish a real empty delta from an unreconstructable generation boundary.
- **HOW:** `RevisionDeltaReader.Read` now accepts `fromArtifactId`, reads current `artifact_metadata.artifact_id`, and returns `unavailable` for missing/mismatched artifact ids. CLI delta JSON now includes `artifact_id`, `from_artifact_id`, and `delta_reason`; negative `--from-index-revision` is a usage error. `WorkspaceFacts` now carries `ArtifactId` at the end of the optional record tail, and dashboard construction uses named args to avoid positional drift.
- **IMPACT:** Eros can persist `{revision, artifact_id}` watermarks and fall back conservatively on rebuilds. Manifest/version drift is closed for Claude, Cursor, Codex, and Claude marketplace surfaces. The dashboard health regression caused by the parameter insertion was fixed at the root.
