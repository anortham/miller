## v1.4.0 release recovery: AOT publish failure fixed

The first v1.4.0 tag build (run 28633117793) failed on all four platforms.

- **Root cause:** new backend-http code `BackendHttpBridgeProvider.ParseActionList` used reflection-based `JsonSerializer.Deserialize<List<string>>`, which is an IL2026/IL3050 **error** under the release workflow's Native AOT publish. Normal CI never AOT-publishes, so the branch was green everywhere until the tag build.
- **Why the step looked green:** the workflow's Publish step runs pwsh where a failing `dotnet publish` doesn't abort; the step passed and the "Verify packaged extractor" step then failed instantly on `test -x $publish_dir/miller`.
- **Fix:** parse with `JsonDocument` (AOT-safe, same semantics — JSON array → parsed, valid-but-not-array or invalid JSON → tolerant ruby bracket/comma split).
- **Verified:** Release build 0/0, `scripts/test.sh all` 2766+45 green, and a local `dotnet publish -r osx-arm64 -p:PublishAot=true -p:Version=1.4.0` mirroring the workflow: clean, binary runs `1.4.0+<sha>`.
- **Watch out:** no project sets `IsAotCompatible`/AOT analyzers, so reflection-JSON regressions stay invisible until a release tag build. Candidate hardening: enable AOT analyzers on Miller.Core/Indexing/Server, or add a single-platform AOT publish to CI.
