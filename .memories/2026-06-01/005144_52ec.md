## Reviewed and Hardened Large Workspace Dogfood Fixes

### WHAT

Reviewed the uncommitted large-workspace dogfood fixes and added one additional cache-race fix before committing.

- External registered-workspace status uses cheap DB facts instead of hydrating the full index.
- Identifier fallback resolution is capped to prevent explosive graph fan-out.
- Registered workspace index caching uses single-flight loads, failure eviction, and same-workspace stale-entry eviction.
- Added a regression test for stale in-flight loads racing newer cache keys.

### WHY

The existing dogfood fix handled ordinary stale cache eviction, but review found a completion-order race: an older in-flight load could finish after a newer registry entry was inserted and remove the newer cache entry. That would leave the next read to reload unnecessarily and could keep stale cache behavior alive under concurrent refresh/read timing.

### HOW

Moved same-workspace cache eviction to the point where a new cache key is inserted under `_cacheGate`, rather than after `Lazy.Value` completes. The stale in-flight load can still return to its original caller, but it no longer decides which key survives in the provider cache. The new async regression test forces the stale load to finish before the fresh load and asserts the fresh index remains cached.

### IMPACT

The dogfood performance fixes now cover both the large-repo runaway path and the provider cache concurrency edge case. Verification passed across focused provider tests, Release build, fast suite, scale suite, whitespace check, and external review.
