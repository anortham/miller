## WHAT

Validated Task 14 with both upgrade-state and indexed-serving-store production replays.

## WHY

The store schema lacked the exact type-facts lookup index. The first replay showed no speedup because direct read-only resolve does not run schema repair on an old copied store; an indexed clone was required to isolate steady-state value.

## HOW

- Added `idx_read_type_facts_symbol(version_id,symbol_id,type_fact_id)` with fresh inventory, dropped-index repair/idempotence, exact EXPLAIN proof, schema catalog/hash update, and 24 green schema contracts.
- Upgrade-state replay without prior writer ensure stayed at 103.692 s wall / 6.901 s type-facts.
- On a byte-faithful disposable clone with only the index added to the serving `gen-001/store.db`, EXPLAIN used the new index; wall fell to 98.667 s, resolution to 88.576 s, and type-facts to 2.459 s. Query count/output/memory stayed fixed.
- One-time index creation on this corpus took about 28 seconds; that repair cost is separate from steady-state timing.

## IMPACT

Task14 is a real 5-second steady-state win and should ship. The 60-second gate remains 38.7 seconds away. Children (27.661 s) and prime (16.517 s) now dominate, so the next design must batch unique ancestor scope keys rather than chase smaller families.
