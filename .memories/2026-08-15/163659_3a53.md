## WHAT

Completed three independent Task 12 read-only diagnoses: Luna child-cache churn, Luna non-child query families, and a bounded Grok 4.6 review.

## WHY

Task 11B was a safe 6.4-second win but left the 60-second full-resolution gate red. A new behavior change without attribution could optimize the wrong query family or violate completeness.

## HOW

- Non-child families consume 45.646 seconds: prime-window 16.736, top-level 11.707, type-facts 9.207, filtered-name 7.997.
- Prime executes exactly once per 300-item identifier/pending chunk and reads 490,865 rows, so its cost is volume/cutoff behavior rather than duplicate calls.
- Top-level/type-facts/filtered-name return only 0.229/0.307/0.247 rows per execution; execution and empty/trailing-page overhead dominate.
- Child cache has no individual eviction; the whole phase window resets 1,732 times. Tier1/tier3 scope chains still own 175,764 child pages.
- Grok independently identified missing receiver/resolved-type names from the prime input and an estimated trailing-empty-page tax. Lead correction: resolved-type-name omission affects filtered-name; type-facts itself is a by-symbol query with no cache/index.
- Chosen next step is default-off fixed-cardinality attribution: prime completeness/cutoff/admission, caller/cache state, SQL page shapes, and capped same-window fingerprints. No behavior change.

## IMPACT

The next exact replay will distinguish missing priming, global cutoff, same-window repeats, capacity refusal, and trailing empty pages. Only then will one bounded TDD optimization be selected.
