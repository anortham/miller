## Fixed all three v0.4.0 pre-release review findings

**WHAT:** Resolved the release-blocking review findings before the v0.4.0 release.

- **Marketplace version drift (P1):** `.claude-plugin/marketplace.json` bumped 0.3.6 → 0.4.0 in both `metadata.version` and `plugins[0].version`.
- **workspace remove writer-lock race (P1):** The acquire-release-delete pattern (introduced in `6b3de0c` for Windows) let another writer acquire the lock between release and `Directory.Delete`. Restructured so index data is deleted **while holding the lock** via new `SingleWriterLock.DeleteContentsExceptLock` (skips only the held `indexer.lock` — the file Windows cannot delete while open), then the lease is released and `SingleWriterLock.TryDeleteEmptiedDir` best-effort removes the lock file + empty dir (swallows IOException/UnauthorizedAccessException — a sneaking-in writer finds an already-empty index and cleanly rebuilds). Applied at all three call sites: `CliDispatch.RemoveMillerDir`, `WorkspaceTool.Remove` path branch, `WorkspaceTool.RemoveResolvedTarget`. Three new tests in `SingleWriterLockTests`.
- **Missing release notes (P2):** Authored `docs/release-notes/v0.4.0.md` from `git log v0.3.6..HEAD` (35 commits): version-aware leadership, julie-extract 2.4.0 pin, index hygiene, search pipeline fixes, freshness hardening.

**Also cleaned:** a stray Miller index inside `skills/` (`skills/.miller` + `skills/.julieignore`, left by a pre-"refuse plugin dirs as launcher cwd" launch) was failing the plugin skills-mirror test; removed via `miller workspace remove --path skills` so it is also unregistered.

**WHY:** Review findings blocked the v0.4.0 release; the lock race was a regression introduced this cycle.

**IMPACT:** All release verification green — ready to commit and proceed with the release.
