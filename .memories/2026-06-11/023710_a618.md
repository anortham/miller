## Task 2: leader.json ExtractorVersion + yield request transport (version-aware leadership D4/D5)

**WHAT**
- `LeaderIdentity` gained `string? ExtractorVersion = null` as last positional param (`src/Miller.Server/Hosting/LeaderIdentityFile.cs`); legacy leader.json without the field deserializes to null (back-compat pinned by test parsing a raw JSON literal).
- New `yield` queue operation on `LeaderScanRequestQueue` (`src/Miller.Server/Workspaces/LeaderScanRequestQueue.cs`): `YieldRequest` record, `.yield.json` suffix, `RequestYield(...)` atomic temp→move write, `DrainYieldRequests(...)` returning `YieldDrainResult(Requested, MaxRequesterVersion, RequesterPid, ExpiredDiscarded, ClaimSkipped)` reusing the existing TTL/claim-by-rename/sweep helpers verbatim.

**WHY**
A newer-extractor reader enqueues a yield; the older live leader drains it and abdicates (orchestration is Task 3 — this is transport + identity field only).

**HOW / decisions**
- `MaxRequesterVersion` uses numeric major.minor.patch compare; pinned with "2.10.1" > "2.3.0" (lexically smaller) test.
- **Judgment call (resolved):** version compare started as a local private static because Task 1's parallel agent was mid-flight in the same tree; once Task 1 committed, the drain was consolidated onto `LeadershipEligibility.CompareVersions` (Miller.Indexing) via an `IsStrongerChallenger` wrapper. The wrapper catches its `ArgumentException` so a yield carrying an uncomparable version is dropped like malformed JSON (pinned by test) instead of crashing the leader's drain tick.
- **Judgment call:** `ExtractorVersion` got a `= null` default so all 6 existing construction sites (IndexerService + 5 tests) compile unchanged; Task 3 populates it at the live write site.

**IMPACT / verification**
- 8 new yield tests + 2 identity tests; worker-scope filter run 36/36 green; full fast suite 1972/1972 green, 0 warnings Release build.
