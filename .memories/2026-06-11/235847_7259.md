## Added scan/total duration telemetry to workspace action JSON (cli-eros-v1)

Follow-up to the openclaw timeout triage: the 7x slowdown under fleet-sweep load is attributed but unproven because Miller never recorded scan durations. Now every refresh/full/open action reports them, so Eros's next fleet sweep measures extract durations for free.

- **`WorkspaceRefreshResult`**: new `ScanDuration` (julie-extract attempt wall time — KEPT on a failed/killed scan so a timeout kill ≈ the timeout is distinguishable from an instant hard failure) and `TotalDuration` (whole refresh attempt incl. lock wait + sidecar convergence).
- **`CrossWorkspaceRefreshService.Refresh`**: stopwatches around the scan and the whole attempt; threaded through all result paths (scanned, failed, lock_busy, missing_root/index, ineligible).
- **`WorkspaceActionResult` + `WorkspaceRender.Action`**: `scan_duration_ms` / `duration_ms` in JSON (null when unmeasured) and compact output (omitted when unmeasured). Mapped in CLI `refresh`/`full`/`open` and MCP cross-workspace `RenderTargetAction`; the MCP current-workspace leader path leaves them null.
- **Contract doc**: fields documented in docs/contracts/cli-eros-v1.md refresh response section.
- **Verified**: fast suite 2163 passed (+3: durations service test, JSON render, compact render); Scale 27 passed; live `workspace refresh` on cobra → `"scan_duration_ms":90,"duration_ms":144`, exit 0.

**Perf question status**: no proven perf bug — monitored, not investigated. Next Eros fleet sweep yields real per-repo extract durations; openclaw ~2min under load → embedding-churn theory confirmed; 10+min while quiet → real SQLite/IO contention to investigate.
