## Task 1 (version-aware leadership): pure eligibility verdict + binary_version reader

**WHAT:** Implemented the D1/D2 decision core for version-aware indexer leadership.

- `src/Miller.Indexing/LeadershipEligibility.cs` — `Evaluate(own, artifact, allowDowngrade)` returns `LeadershipVerdict(Eligible, ArtifactOlderThanOwn, Reason)`; plus numeric `CompareVersions` over major.minor.patch (prerelease/build ignored, same lenient first-token regex as `JulieExtractVersionProbe.ParseVersion`).
- `src/Miller.Indexing/ExtractBinaryVersionReader.cs` — tolerant read-only `TryRead(dbPath)` of `artifact_metadata.binary_version`; null (never throws) on missing file/table/key/not-a-db, mirroring `ExtractReader.ReadRootPath`.

**WHY:** Invariant — artifact `binary_version` never goes backwards. An older extractor never claims leadership (permanent reader); unknown artifact version stays eligible (cannot prove a downgrade); unknown own version is ineligible (cannot index anyway); `allowDowngrade` is the explicit escape hatch and wins over everything, but never alters `ArtifactOlderThanOwn` (the auto-upgrade-rescan signal).

**HOW:** Pure statics, zero I/O in LeadershipEligibility; reader uses `SqliteReadOnlyAccess.Open` with enumerated catch set. `JulieDbFixture` already seeds `binary_version` = `MillerExtractContract.PinnedJulieExtractVersion`, so reader tests use `CreateDefault()` and delete the key via raw SQL for the missing-key case.

**IMPACT:** Unblocks Task 3 (IndexerService claim gate) and Task 4 (CLI gate + health rendering) — both consume `LeadershipEligibility.Evaluate` + `ExtractBinaryVersionReader.TryRead`. 27 new tests; full fast suite 1971 green.
