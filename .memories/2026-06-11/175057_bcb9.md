## Shipped Eros bulk export feeds: `symbols export --jsonl` + `complexity export --jsonl` (0.4.1)

**WHAT:** Two new CLI JSONL export feeds for fleet rollups, per the Eros H1 contract asks in TODO.md:

- `miller symbols export --jsonl [--workspace-id SELECTOR] [--workspace DIR]` — one deterministic row per symbol (symbol_id, name, kind, language, path, line+byte span, visibility, parent_symbol_id, signature, `has_doc`, `body_hash`, `is_test`), ordered `(path, start_line, symbol_id)` so an unchanged artifact re-exports byte-identically.
- `miller complexity export --jsonl` — one row per `complexity_metrics` row (file- and symbol-scope), ordered `(path, start_byte, complexity_metric_id)`.

**HOW:**
- New readers `SymbolExportReader` / `ComplexityExportReader` in Miller.Indexing follow the `TelemetryExportReader` pattern: `SqliteReadOnlyAccess.Open` (pooling off), `JulieSchemaGate.Verify` before the read (incompatible artifact → CLI exit 3), `Utf8JsonWriter` + UnsafeRelaxedJsonEscaping, `schema_version: 1` per row. Shared `ExportJson` nullable-column helpers.
- Span columns written null-tolerantly — an export must report what the artifact holds, not throw mid-feed (JulieDbFixture exposed this: GetInt64 on NULL → exit 1).
- `CliDispatch` gained `symbols`/`complexity` verbs via a shared `ArtifactExport` helper (selector resolution → exit 2, missing index → exit 3).
- Advertised in `capabilities` (compact + JSON `supported_export_formats`, `json_commands`).
- Documented field-level guarantees in `docs/contracts/cli-eros-v1.md`; release notes `docs/release-notes/v0.4.1.md` "What Is New".

**IMPACT:** Eros can build per-repo symbol/doc-coverage/clone rollups and fleet-wide complexity hotspot ranking from stable JSONL instead of per-file `inspect` fan-out or reading Miller-private SQLite. Ships in 0.4.1 alongside the cross-workspace fixes.

**Verification:** 9 new export tests + full fast suite 2147 green; scale suite 27 green; Release build 0 warnings; real-artifact smoke test of both feeds + capabilities output.
