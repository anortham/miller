## Hardened WorkspaceIndexProvider in-flight cache tests after CI failure

The post-release evidence commit triggered CI run `28728554091`, and Linux `build-test` failed in `WorkspaceIndexProviderTests.ResolveContentSearch_RegisteredWorkspace_InFlightStaleLoadCannotEvictNewerCacheEntry` with `Assert.Same` timing out before `startedB.Task` completed.

- **What:** Replaced blocking `Task.Run` calls in the provider single-flight and stale in-flight eviction tests with a `RunBlockingResolve` helper that uses `TaskCreationOptions.LongRunning`.
- **Why:** These tests intentionally block inside loader callbacks. Under CI parallelism, using threadpool `Task.Run` made the assertions depend on threadpool scheduling rather than cache behavior.
- **How:** Kept production code unchanged and moved only the intentionally blocking test calls onto dedicated long-running tasks.
- **Impact:** The tests still verify that concurrent cache misses share one load and stale in-flight loads cannot evict newer cache entries, but no longer fail when the CI threadpool is busy.
