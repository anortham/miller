## Registry accumulation: prune now clears the worktree backlog

Implemented all four steps of `docs/plans/2026-08-29-registry-accumulation-design.md` on
`worktree-dashboard-smoothness`. Build 0/0, fast suite 9298 passed / 0 failed / 9 skipped (was
9263), plugin hooks 16/16.

### Verified against the real 59-row registry with `miller workspace prune --dry-run`

| | Before | After |
|---|---|---|
| would prune | 4 | **9** |
| kept | 55 | 50 |
| "linked-worktree removal is not confirmed" | **25** | **1** |
| "deferred by the per-run prune limit" | 0 | 19 |

The one remaining refusal is `nonmiller-repo`, a `git_is_linked = 0` plain checkout — correct.
23 rows moved from permanently-blocked to confirmed-but-queued. Draining needs ~5 runs at the
default cap of 5; the deferral message says "rerun prune to advance".

### What changed

- **`WorkspaceRegistryPrune`** — `HasConfirmedLinkedWorktreeRemoval` falls back to
  `store_members.root_git_dir` / `store_families.canonical_common_dir` when the `workspaces` lineage
  columns are NULL (38 of 59 rows). Tests the repo's **common dir** present + this worktree's admin
  dir gone, instead of the old admin-**parent** test — git deletes `<repo>/.git/worktrees` when the
  last worktree goes, so tidy cleanup was what made a row unprunable. Refuses when common == admin
  (plain checkout) and when `git_is_linked = 0`. `producerRetirements++` moved after a *successful*
  retirement so a failure no longer burns the slot. Cap is a `Run()` parameter, default 5.
- **Lineage capture** on both `workspace open` paths and on live-root `UpsertSeen`, so future rows
  are prunable and old rows heal.
- **Selector tie-break** — an ambiguous selector matching one live and one dead root resolves to the
  live one. `miller workspace status --workspace-id miller` failed before this.
- **Dashboard** — no facts read for a gone root; the prune notice no longer reports an error just
  because rows were kept.
- **Guidance** — routing-block rule 7 now covers deletion by any means and names
  `workspace remove path=<exact old path>`, which works after the directory is gone.

### Defects the review caught, and what I fixed as lead

- **Lane 3, high, safety.** The tie-break sat in the shared resolver, which `WorkspaceRemoval` also
  uses — `miller workspace remove --id miller` would have stopped refusing and deleted the LIVE main
  repo's index and store view. Fixed with `WorkspaceSelectorIntent`: `Read` breaks ties, `Mutate`
  never does. `WorkspaceRemoval` passes `Mutate`. Test pins it.
- **Lane 5, high.** `tests/plugin/hooks-session-hook.test.cjs:16` pinned the old rule-7 text; two
  tests failed. Updated the constant.
- **Lane 4, medium.** `DashboardEndpoints.PruneRedirect` returned "remove-error" whenever any row
  was kept — which is every registry that needs pruning. Now reports success when rows were pruned.
- **Lane 2, medium** (fixed by its own reviewer). `MarkRegistryError` was rewriting lineage on the
  failure path, overwriting the stored checkout generation that `DisqualifiesRebind` uses to force a
  rebuild after a root is replaced.

### Deliberately not done

No automatic sweeper. `docs/plans/2026-08-28-worktree-view-retirement-design.md:108-109` rejects
automatic startup pruning; prune destroys a store view and its per-view sidecars, and
`Directory.Exists` returns false on any error, not only on absence.
