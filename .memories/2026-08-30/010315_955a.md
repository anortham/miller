## Dashboard smoothness fixes landed and measured

Implemented the five lanes from `docs/plans/2026-08-29-dashboard-smoothness-design.md` on
`worktree-dashboard-smoothness`. Build 0 warnings / 0 errors, fast suite 9263 passed / 0 failed / 9
skipped (baseline was 9233, so 30 new tests).

### Measured on the real 59-workspace registry, same script before and after

| Endpoint | Before | After |
|---|---|---|
| `/fragments/workspaces` cold | 3.049 s | 3.191 s (one miss per TTL window) |
| `/fragments/workspaces` warm | 3.029 / 3.039 s | **0.021 – 0.031 s** |
| `/fragments/workspaces` 304 | 3.029 s | 0.021 s |
| `/index.json` | 3.046 s | 0.035 s |
| `GET /` | 3.078 s | 0.088 s |
| `/fragments/refresh-status` | 4.510 s, 40,222 B, 200 | **0.002 s, 57 B, 286** |
| `GET /workspace` | 4.515 s | 4.670 s (unchanged, out of scope) |

The honest shape: the cache turns "3 s on every poll" into "3 s once per 90-120 s window", ~120x on
the warm path. It is NOT 3 s → 0.013 s; that figure was the store-mode-**off** code path.

### What changed

- **`DashboardIndexFactsCache`** — caches in both modes. Key is identity only (`mode|workspaceId`),
  so entries no longer leak per revision. Store mode is witnessed by
  `WorkspaceReadSessionFactory.Probe` (generation identity, manifest generation, manifest hash,
  store-log sequence); the legacy `symbols.db` timestamp is never consulted as a witness, which is
  what the original bypass was protecting. Stamp also folds in registry row + sidecar file state,
  because the facts copy both and neither moves the store sequence. `last_seen_at` deliberately
  excluded. TTL 30 s → 120 s (equal to the poll interval it would never hit), with FNV-1a
  per-workspace jitter up to 25% so 59 entries do not expire into one poll.
- **`RefreshStatusPanel`** — `hx-target` `#workspace-detail-stack` → `"this"`. This is the whole
  poll-leak fix: htmx re-inits the swapped-in node and clears its timer only when the swap target IS
  the polling element. `/fragments/refresh-status` now returns the span alone, plus HTTP 286 and an
  `HX-Trigger: miller:refresh-finished` header. `#workspace-detail-stack` listens for that on `body`
  and refetches the ten panels once via a new `/fragments/detail-stack` route.
  `DashboardRefreshJobs.PeekLastOutcome` (60 s retention, non-consuming) keeps the outcome readable
  across that refetch — `Peek` stays exactly-once. Also fixes the second-tab case.
- **`dashboard.css`** — deleted the unscoped `.htmx-request { opacity: .5; pointer-events: none }`.
  Replaced with a cue scoped to `.refresh-button.htmx-request` / `:disabled` plus their `:hover`
  forms (without `:hover` the accent rule at :283 repaints an inert button). Added
  `hx-disabled-elt="this"` to the Open-folder and Telemetry Refresh buttons to restore the
  double-submit guard `pointer-events: none` was silently providing. New
  `DashboardStylesheetGuardTests` fails if an unscoped rule returns.
- **`dashboard-site.js`** — `updateRelativeTimes` compares before writing; the 5 s interval returns
  early while `document.hidden`; `rehydrateSortableTables` is scoped to the swapped subtree so a 5 s
  activity poll no longer re-appends all 59 workspace rows; `Idiomorph.defaults.ignoreActiveValue`
  stops the filter input being wiped mid-typing.
- **Stable ids** on every repeated row: activity, workspace index (live and stale), tests projects
  and failures, pattern families, trend series, and telemetry tool rows plus recent errors. The
  telemetry ones reuse the existing `IssueId` helper, which already backed an HTML id via
  `IssueCopyId`.

### Verified over HTTP, not just by unit test

`/fragments/refresh-status` → `286`, `HX-Trigger: miller:refresh-finished`, 57 bytes, zero
detail-stack markup. `/fragments/detail-stack` → 200, ten panels, no poll trigger. Row ids present
in the live fragments. `.htmx-request` appears in the served stylesheet only under `.refresh-button`.
