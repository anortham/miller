## WHAT

Closed the post-v1.25.3 review campaign and prepared Miller v1.25.4. The release tree now includes atomic dashboard refresh state, ordered htmx refresh/refetch requests, negative store-maintenance count rejection, aligned 1.25.4 plugin/build metadata, release notes, and the release plan.

## WHY

Claude's final fixes still left dashboard races: concurrent terminal readers could emit the same outcome twice, an older retained write could overwrite a newer outcome, current/retained detail reads were split, and immediate completion could leave no polling response. The store parser also accepted negative `pruned_request_rows`, which `HasReport` silently hid.

## HOW

- Replaced split `ConcurrentDictionary` transitions with one lock guarding current jobs and retained outcomes.
- `Start` always returns Running for new async work so the response installs a poll.
- `Peek` and `PeekDetail` claim completed jobs atomically and retain one terminal outcome.
- The detail endpoint uses one `PeekDetail` decision.
- Added htmx `hx-sync` drop/replace ordering on the shared detail-stack target, verified against official htmx docs.
- Added red-green concurrency/detail/immediate-completion/markup guards and the negative-count parser guard.
- Kept documented prune candidacy and four audit items as deliberate policy or coverage-only gaps.
