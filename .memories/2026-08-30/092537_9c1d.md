## Codex review round: 5 findings, all fixed

Second external reviewer (codex, after grok) on branch `worktree-dashboard-smoothness`. Verdict `needs-attention`, 5 findings. I verified every one against the code; all were real.

### The destructive prune gate had two open holes (high)

`WorkspaceRegistryPrune.HasConfirmedLinkedWorktreeRemoval` retires a family-store view and deletes the per-view sidecar set. Both holes were **reproduced as failing tests before the fix** — the prune really retired a live view in each:

- **The lineage pair was never proved to be a pair.** Admin dir and common dir can come from different sources (row lineage vs `store_members`/`store_families`), and "unequal" does not mean "linked" — a submodule and a `--separate-git-dir` checkout both read as unequal. Now requires the admin dir to sit directly in `<common>/worktrees`.
- **A missing pathname is not a removal.** A RENAMED admin directory leaves the recorded path absent while git still registers the worktree. `ConfirmedAbsent` now reads each surviving entry's `<admin>/gitdir` backlink and refuses when one names this workspace's root. An unreadable backlink answers "still registered".

### `WorkspaceSelectorIntent` had a default (medium)

Grok found ONE destructive caller reaching the live-root tie-break. Codex found the general case: `Read` was the parameter default, so every caller inherited it silently. Removed the default; all 15 call sites now state intent. A reflection guard in `WorkspaceRegistrySelectorTests` blocks re-adding it.

### The dashboard facts cache served stale store-wide facts (medium)

Worse than codex stated. `StoreMemberSummaryReader` runs `SELECT COUNT(*) FROM views` — the WHOLE store, not this view's rows. Registering or retiring any workspace changed what every other workspace rendered, and `Probe` only reads a per-view stamp file. New `DashboardStoreViewsWitness` reads the views table identity once per store root per 2s (memoized so a 59-workspace page pays one store read, not 59). Stamp also gained `probe.BinaryVersion`. Red-to-green proven.

### The detail-stack refetch could erase a newer refresh (medium)

The refetch is triggered by refresh A finishing but lands a round trip later, rendering `PeekLastOutcome` unconditionally. A refresh B started inside that window had its running panel morphed away, poll attributes and all. New non-consuming `DashboardRefreshJobs.PeekRunning` now outranks the retained outcome.

### The cache had no bound (low)

Entries are replaced only when their own workspace is read again, so a removed workspace held its fact graph for the process lifetime. `TrimToCapacity` drops the least recently cached past 256.

## Impact

Branch is now cross-model reviewed (grok + codex), 9309 fast tests green, build 0/0. Still local and unmerged; `workspace prune` still NOT run — it is destructive and the user's call.
