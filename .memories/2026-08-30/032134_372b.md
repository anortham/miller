## Grok review caught a critical half-fix: MCP `workspace remove` could delete a live repo

An outside review by grok-4.6 (19 turns, $0.31) found that my earlier `WorkspaceSelectorIntent` fix
covered only the CLI removal path.

### The bug

`WorkspaceTool.Remove` (`src/Miller.Server/Tools/WorkspaceTool.cs:1472`) calls `ResolveTarget`,
which calls `WorkspaceRegistrySelector.Resolve` with the DEFAULT `Read` intent. `Read` breaks an
ambiguous match toward whichever root `Directory.Exists` reports present. `Remove` then hands
`RemoveById` an already-resolved full workspace id, so the `Mutate` guard inside
`WorkspaceRemoval.RemoveByIdCore` — the fix I added — never fires.

On the author's real registry, `workspace remove workspace_id="miller"` would have resolved
`miller` to the LIVE `/home/murphy/source/miller`, deleted its `.miller` index dir, retired its
family-store view and reclaimed its sidecars. The CLI path was safe; the MCP path was not.

**Reproduced before fixing:** with the intent reverted, the new test fails on
`Assert.True(Directory.Exists(liveMiller))` — the live workspace's `.miller` was really deleted.

### Second finding, also real

`ConfirmedAbsent` did not exist; the gate used `!Directory.Exists(adminDir)`. That returns false on
a permission or I/O fault as well as on absence. The OLD gate required the admin PARENT
(`<common>/worktrees`) to exist, so a fault there refused. The new common-dir proof dropped that,
so a fault confined to `<common>/worktrees` read as a removal — a narrowing of safety the code
comment wrongly claimed was equivalent.

### Fixes

- `ResolveTarget` takes a `WorkspaceSelectorIntent` (default `Read`); `Remove` passes `Mutate`.
  Test: `Remove_AmbiguousSelectorMatchingALiveAndADeadRoot_RefusesAndDeletesNothing`.
- `ConfirmedAbsent(adminDir, commonDir)` proves absence from a listing that SUCCEEDED: enumerate
  `<common>/worktrees` while git keeps it, else enumerate the common dir and require the parent to
  be gone. Any `IOException`/`UnauthorizedAccessException` refuses. Test:
  `Run_AdminDirParentUnreadable_RefusesTheRemoval` (POSIX-only, skips as root).

Build 0/0, fast suite 9300 passed / 0 failed / 9 skipped.
