## WHAT

Implemented the shared `CtWorkspaceMirror` reconciler, the Godot project-shadow adapter, and the thin behavior-compatible sbt adapter. Added focused tests and ADR-0008.

## WHY

Godot imports and project code must run outside the user project, while the existing sbt filesystem safety contract must remain unchanged. A shared internal mirror keeps traversal, manifest, link, metadata, budget, and path safety rules authoritative.

## HOW

The mirror uses closed data policies with `StrictHash` and `MetadataFastPath` integrity modes, serialized sync per candidate, atomic manifests, no-follow candidate measurement, stable metadata digests, path containment, and candidate reparse-point guards. Godot owns project/home candidate paths, exact source-to-mirror mapping, import-stamp validity/publication, atomic activity markers, project-local `.gdignore`, and an over-budget marker outside the reapable candidate. The sbt adapter keeps `SbtWorkspaceShadowResult`, `sbt-workspace`/`sbt-deps`, strict repair, Git barrier, and dependency creation after validation.

## IMPACT

The Task 2 GUT tooling/provider can consume stable Godot shadow contracts. Focused verification is green: shared mirror 6 passed, sbt shadow 31 passed, and Godot shadow 7 passed. No broader suite or release gate was run in this worker packet.
