## Trace no-path traversal regression fixed

### WHAT

Removed the automatic reverse `ShortestPathWithEvidence` probe from `TraceTool.RunPath`. No-path results now always offer an explicit swapped-endpoint retry without claiming a reverse path was discovered. Added a caller-facing test with a counting graph and updated no-path expectations/release notes. The pre-existing ambiguous-destination retry test/fix was preserved.

### WHY

The release candidate performed two graph traversals for a single no-path request, causing the measured p95 regression. Reverse discovery belongs to the explicit retry action.

### HOW

TDD red test failed with 2 traversal calls; the minimal production change removed the reverse call and reverse-only render branch. The swapped retry is emitted unconditionally, and the no-path action bound increased from five to six to retain the existing source-search fallback. A mutation removing the swapped action failed the regression test; the mutation was reverted.

### IMPACT

Forward no-path requests perform one traversal, retain directional diagnostics, and provide a non-speculative reverse-direction next action. Focused verification: new test green (1/1), full TraceToolTests green (103/103), mutation caught, git diff --check clean.
