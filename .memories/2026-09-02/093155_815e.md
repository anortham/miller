## WHAT

Task 7 reached a confirmed architecture blocker before implementation: sbt 1.x writes build products inside the source workspace during build loading.

## WHY

Miller CT requires every provider write to stay under the supervised generation root. Cache redirection appeared promising but does not relocate sbt's application-base or meta-build outputs.

## HOW

A disposable official sbt 1.13.0 fixture was run with boot, global, Ivy, and Coursier paths redirected; server autostart and build-property generation disabled; and a session target override. The run still created both `target/` and `project/target/`. Official sbt source was checked and confirms the canonical working directory becomes the application base and `target/out` is allocated before session settings. The finding and SDD ledger now record this evidence, and the active brief names the required product decision.

## IMPACT

A normal in-place sbt backend would violate a load-bearing safety invariant. Continuing safely requires either a generation-owned build/source shadow with explicit performance and compatibility costs, or removal of runnable sbt from this release plan. Release remains held; Tasks 8–9 were not started because the plan is serialized.
