## WHAT

Implemented Task 3's Ruby/RSpec continuous-testing vertical slice on `feature/ct-providers-jvm-ruby-php-gdscript`: RSpec discovery and artifact-backed runs, stable workspace/project-owned case IDs, per-example location selection, whole-suite execution, provider registration, Gemfile inventory detection, minitest refusal text, Ruby language-family mapping, and Scale runner guards.

## WHY

The held release depends on the approved CT provider plan. Ruby projects need a real machine-readable RSpec path while minitest projects must be named and refused rather than silently scheduled.

## HOW

Discovery runs `rspec --dry-run --format json`, using `bundle exec` when `Gemfile.lock` exists. Runs use `--format json --out <artifact>` and parse only the report file; stdout truncation is refused on discovery and irrelevant to artifact parsing. Case IDs encode workspace, project, spec path, example id, and selector; decode validates ownership and path containment. Location selectors use `file_path:line_number`, switching to the raw hierarchical RSpec id for line collisions. Inventory recognizes `rspec` before `minitest`; the latter is unsupported with the documented reason and remedy. Commands share `ITestProcessRunner` and generation handoff paths.
