## Windows directory metadata fix

### WHAT

Changed `CtWorkspaceMirror.ApplyMetadata` to call `Directory.SetLastWriteTimeUtc` for directory entries and retain `File.SetLastWriteTimeUtc` for file entries. The test-only regression is already committed in `4d44e0ec`.

### WHY

The focused Windows RED reproduced `UnauthorizedAccessException` from `File.SetLastWriteTimeUtc` on a mirrored directory. The same API works on Linux, which is why the prior Linux mirror class did not expose the defect.

### HOW

Miller tracing showed `SyncCore` invokes `ApplyMetadata` for all non-symbolic-link entries and `CaptureEntry` distinguishes `EntryKind.Directory`. The minimal branch now selects the directory-specific timestamp API before applying existing Unix mode and read-only attributes. No other failure groups or metadata behavior changed.

### IMPACT

This addresses the 38 Windows failures sharing the `ApplyMetadata` stack. Linux focused regression passes 1/1 after the fix. The next verification is the exact regression test on the Windows guest, followed by the full shared mirror class on Linux; the broader Windows gate remains the lead's responsibility.
