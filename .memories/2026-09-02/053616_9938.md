## WHAT

Corrected the Task 3 Ruby/RSpec provider after lead review. `MapResults` now builds path/example and path/selector indexes once and maps report rows without scanning every selected case. Partial runs reject report examples not present in the requested selection; whole-suite runs retain their intentional extra-report mapping. Added regression coverage for partial attribution and same-location RSpec selector collisions, including selected-run ID round trips.

## WHY

The first implementation could become quadratic for large reports and could commit verdicts for examples a partial invocation did not select. Same-line examples also exposed a lookup ambiguity when location fallback was evaluated before exact example identity.

## HOW

The tests were changed first and the focused Ruby run was observed red: the old implementation returned an unselected third row and mapped both same-line examples to the first location selector. The provider now uses precomputed nested dictionaries with platform-aware path comparers, exact example-id lookup before location-selector fallback, fail-closed partial attribution, and raw RSpec IDs for duplicate locations. Whole-suite behavior remains artifact-driven and reports selected plus extra artifact cases.

## IMPACT

The correction is ready for the lead's inline review and a serial follow-up commit. No Task 4+ files were touched. The focused Ruby and whole-suite tests pass, the Release build is clean, and no release or push action was taken.
