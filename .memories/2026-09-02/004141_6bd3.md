## CT selector fix exposed by julie-extract 2.39.0 local-variable facts; both gates green

### WHAT
Scale gate failed on `Real_vb_fixture_discovers_runs_and_selects_with_julie_identity`: selection Unknown, `Adds` stale, nothing selected. Two selector defects in `ContinuousTestImpactSelector`:
1. `AddIdentifierReferenceEvidence`: a reference from a test symbol the store does not know fell back to the single case in that file by PATH ONLY, then `CanUseProviderCase` saw the symbol-id mismatch and set `unmappable`. Fix: when the source symbol is known, filter fallback candidates with `TestNameMatches(source.Name, row)` (mirrors the graph-evidence path).
2. `ResolveProviderIdentity`: a resolved typed identity kept `FileRole` null; `HasTestBackingFile` then fell to `IsTestPath`, which rejects a root-level `UnitTests.vb`, and the identifier branch reported the case unrunnable. Production discovery never writes `file_role` (only the reader exists), so any root-level test project would hit this. Fix: on a unique match, `FileRole = testCase.FileRole ?? (match.IsTest ? "test" : null)`.

### WHY
2.39.0 emits locals/parameters as `variable` symbols inside test methods, so a changed test file now yields `variable_ref` identifiers from each test to its own locals. Before, no identifiers targeted symbols in that file and neither branch ran.

### HOW
Diagnosed by temporarily instrumenting the Scale test with `Assert.Fail(JsonSerializer...)` dumps of selection, symbols, impact, identifier evidence, and store cases (restored from a scratchpad backup afterwards). Two TDD unit tests in `ContinuousTestImpactSelectorTests` (`Select_ignores_identifier_references_from_an_unstored_sibling_test_symbol`, `Select_trusts_a_resolved_test_symbol_as_the_backing_file_when_the_path_looks_plain`), each watched failing (Unknown) then green.

### VERIFIED
Fast suite 9,448 passed / 0 failed; Scale 204 passed / 0 failed / 18 skipped (full logs in scratchpad `fast2.log`, `scale2.log`). The earlier single fast-suite failure did not recur in two captured runs.
