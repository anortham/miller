## Completed Phase 9 BGE versus CodeRank decision lane

Miller now has a bounded evaluator-only CodeRank adapter that drives the exact current-Julie producer through real vector convergence, sqlite-vec storage, semantic search, fusion, `search`, and `context` without adding a production model option or MCP tool.

- **Why:** The prior comparison could not isolate model identity through final Miller behavior.
- **How:** Added a strict frozen CodeRank pin/config, injected expected-pin handshake, 768-d shadow generation support, separate nine-tool evaluator host, exclusive writer lease, and read-only mutation filter.
- **Evidence:** All five frozen snapshots had identical workspace/index identities across arms. The five-task visible subset tied correctness and relevance; CodeRank used fewer calls and lower wall time only on the one jointly correct task, so the scorer returned `not_decisional`.
- **Decision:** Keep BGE-small as production default. Do not spend sealed tasks or add a production CodeRank runtime on this evidence.
- **Review:** Fresh Claude review findings were validated and accepted fixes received a clean narrow rereview.
- **Verification:** Release build 0 warnings/errors; fast suite 4,812 passed with 2 expected skips; scale suite 92/92 passed with the actual CodeRank MPS config; live BGE/CodeRank lease replay and semantic-off missing-config proof passed.
- **Impact:** Phase 9 closes with an honest reusable comparison lane and no production-default regression.
