## WHAT

Completed Phase 5 of the Miller Julie-takeover remediation: redesigned `context` around ranked pivots, bounded implementation bodies, evidence-aware neighbours, aligned schemas, explicit disposition, and hard output budgets.

## WHY

The prior context surface routinely consumed its full budget but still forced follow-up inspections. Visible takeover trajectories failed call and token budgets because the first bundle did not contain implementation evidence or say whether it was sufficient.

## HOW

- Added pure `ContextPivotRanker` and allocation-tier packing.
- Routed full-task and bounded task-term candidates through the shared Phase 4 retrieval pipeline.
- Added entry-symbol, edited-file, failing-test, colon/Python stack-frame, and optional semantic signals.
- Preserved explicit entry order while diversifying duplicate names, files, and test pivots.
- Added inspect-grade freshness-guarded pivot bodies plus two task-ranked same-file neighbours per pivot.
- Removed the hidden twelve-neighbour rendering cap; selected and rendered sets are identical.
- Added aligned `item_type`, `role`, `reason`, and `confidence` fields in normal and usage JSON.
- Added typed ignored-anchor recovery, evidence sufficiency, and conditional next actions.
- Made CLI and MCP share guarded body reads.
- Kept `MILLER_SEMANTIC=off` deterministic and zero-work.
- Claude raised four findings: three valid issues were fixed; its claimed lambda-shadowing compile blocker was rejected with live compilation evidence.

## IMPACT

The four public context-loss tasks now return required implementation evidence in one call. Estimated outputs are 1,727, 2,296, 3,983, and 1,724 tokens versus prior 2,973-3,991-token signature bundles that still required follow-up calls. Real registered-artifact p95 is 290 ms across 21 fresh CLI processes, including startup.
