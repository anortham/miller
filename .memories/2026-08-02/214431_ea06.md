## W7 complete — worktree ignore propagation + seeder rework

### WHAT
Landed W7 on `fleet-safety`: a Miller-owned invariant ignore file, in-tree seeding of the main checkout's `.julieignore` for linked worktrees, a reworked seeder detection cap, and root-relative segment matching in the watcher filter.

### WHY / the two findings that mattered
1. **W7 as first built broke live indexing in this very worktree.** `WatchPathFilter.ShouldProcess` matched `SkipSegments` against the **absolute** path and never relativized against `root`. Adding `.worktrees` therefore rejected every file in any workspace whose own root sits under a `.worktrees/` pool — this repo's convention. Proved against the built binary: `impact` returned `"changed_paths":[]` with `"delta_status":"complete"` for a diff with six real changes, and every watcher event was dropped. The flaw was latent for `.claude/worktrees`, `.miller`, `bin`, `obj`; `.worktrees` is what made it fire. Fixed at the segment source via `HasSkippedSegment(root, path)` over the root-relative remainder, with whole-path fallback for out-of-root paths.
2. **The `--ignore-file` propagation design was replaced, not patched.** Passing the main checkout's `.julieignore` via `--ignore-file` created a scan/watcher split: `WorkspaceIgnorePolicy` only reads ignore files at or under the workspace root, so the watcher applied zero rules and `julie-extract update` re-inserted on first touch exactly what the scan excluded. Retrying on malformed input couldn't fix that, and made a permanently-broken file spawn the extractor twice per scan forever, silently.

### HOW — the replacement
Seed an **in-tree copy** of the main checkout's `.julieignore` into the worktree. It is then read by both the watcher and the scan, and a malformed pattern only **warns** (in-tree) instead of hard-failing (`--ignore-file`). That deleted `WithoutPropagatedFile`, `NamesIgnoreFile`, the exception filter, and the `RunScan` split together with the hazard.

### Extractor facts established empirically (julie-extract 2.21.0)
- Malformed in-tree `.julieignore` → `status=partial`, exit 0, artifact written. Same content as `--ignore-file` → hard failure, no artifact.
- `delete` does **not** accept `--ignore-file` (`error: unexpected argument`, exit 2) — only `scan` and `update` do. The plan was wrong about this.
- `update` without the invariant file wrote 2 symbols for a `.worktrees/` file; with it, `unsupported`, 0 symbols. That was a live defect, now closed.

### IMPACT
9 confirmed findings across 3 adversarial lenses, all closed with holding mutation proofs. Fast suite 5509 passed / 0 failed; **full Scale suite 119 passed / 0 failed**. Also removed the dead `GitWorktreeLayout.Root` and added the missing Scale test for a workspace rooted *inside* a `.worktrees` pool — the one acceptance claim that had rested on a manual run.

### Known, deliberately not fixed
- `.gitignore:24` is `.tools/` (directory-only), so this worktree's `.tools` **symlink** is untracked and a `git add -A` would commit a machine-specific absolute path. Every commit stages explicit paths instead. Needs a one-character fix the user should approve.
- `bin/` is in neither the seeder's walk-skip set nor `VendorDirectoryNames`, so the detection walk still enumerates `bin/` trees. Efficiency only; changing it would alter seeded `.julieignore` output for every repo.
