## Multi-worktree fleet-safety triage + cross-model consensus plan

**WHAT:** Triaged a user field report (installed Miller ~2026-07-30, multi-worktree agent fleet: indexes never converged, exit 137, ~130 GB leaked spools) into `docs/findings/2026-08-01-multi-worktree-fleet-triage.md` (feedback verbatim + claim-by-claim verdicts) and a unanimous cross-model fix plan in `docs/plans/2026-08-01-multi-worktree-fleet-safety-plan.md`. Docs map updated. Nothing implemented — plan awaits user approval.

**WHY:** The GPT triage in the report was directionally right (control plane unsafe under fleets) but wrong on mechanisms; every claim needed code-level verification before spending on fixes.

**HOW:** Lead verification across miller@7220c15d + julie-extractors@173ae45, then two-round convergence with Codex and Grok (`codex exec` / `grok -p`, read-only): independent reviews → synthesized 10-item plan vote → one amendment. Key verified findings:
- **Bootstrap lease hole (Codex, most severe):** `RunBootstrap` calls `runner.Scan` (incl. force rebind) with NO `SingleWriterLock` (IndexBootstrapService.cs:391); only the auto-rebuild closure locks. Original complaint partially vindicated.
- **Progress-stamp blindness:** `ProgressStamp` samples only db/wal/shm + output lines; julie-extract's long spool phase looks stalled → healthy big scans killed at 10-min window, spool leaked.
- No `--jobs` ever passed (all-core default); no machine-wide scan governor; N worktrees = N leaders.
- `.julieignore` is untracked so fresh worktrees never inherit it; seeder detection caps at 25k files; nothing excludes `.worktrees/`.
- Spools leak on SIGKILL (Drop-only cleanup, no reaper, shared temp_dir).
- Stale doc comment: NO julie-side flock exists anymore — Miller's lock is the only serialization.
- Linked-worktree `.git`-file → no HEAD watcher → branch-switch rescan storms.
- Child-death ≠ leader-death: dead child keeps lock, nothing retries; dead process → 5s failover restarts force scan from zero (PrepareRebuildTarget deletes partial .rebuild).

**Consensus (unanimous after amendment):** P0 = bootstrap lock, `--jobs min(4,cores/2)` + MILLER_EXTRACT_JOBS + jobs-1-after-137, capacity-1 user-global scan governor (covers sidecar converge too), julie flags `--spool-dir`/`--progress-file`/`--parent-pid` + dead-PID reaper (julie ships first, pin bump). P1 = ignore propagation via `--ignore-file` + invariant ignore file, persisted backoff + scan-intent enum (downgrade rules), worktree HEAD watcher + path-reuse epoch. P2 = 74k-file scale repro before WAL chunking; shared-artifact worktree bootstrap deferred. Codex's amendment: Unix process groups do NOT kill children on parent death; portable fix is extractor-side parent-liveness watchdog (PDEATHSIG is Linux-only).

**IMPACT:** ~9–12 agent sessions estimated across both repos; candidate 1.16 theme "safe under agent fleets". Findings partially vindicate the reporter — no version excuse, all reproducible on current code.
