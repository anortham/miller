## Real-repo scale baseline: dotnet/runtime crashes julie-extract 2.21.0

**WHAT:** Ran the first-ever real-repo scale test (dotnet/runtime @ a2f953fe266, 58,500 files)
against the pinned julie-extract 2.21.0 directly (jobs=4, no Miller orchestration). Documented in
`docs/findings/2026-08-02-dotnet-runtime-scale-baseline.md`; delta-rebind plan P0 updated with the
real-repo tier + crash gate; new "progressive indexing levels" candidate follow-on section added to
the plan.

**WHY:** User challenged the 25–40 min cold-start extrapolation and asked where to find a
reporter-scale (~74k files) real repo to test against. W10's synthetic fixture cannot contain
real-world pathologies — proven on the first run.

**Findings (all live-verified on this machine, 24-core/64 GB):**
- **Stack-overflow crash:** worker thread blew its 2 MB stack at 186 s / 60% through the repo.
  Likely deep recursion on generated JIT test files (thousands-long operator chains in
  `src/tests/JIT/Directed/cmov/*`). No DB existed at death (W5 progress-blindness confirmed at
  scale); the abort skipped Drop and leaked a **15.4 GB spool** (W4 confirmed; temp dir already
  held 10 older dead spools from normal local use).
- **Spool amplification:** 982 KB source → 66.6 MB spool entry (**68×**); ~10× aggregate
  (projected ~25 GB spool for a sub-2 GB checkout). Hypothesis: per-reference-site JSON with
  multiple long hash IDs; explains the reporter's mystery "14 GB" and 130 GB spool accumulation.
- **Throughput reframe:** ~190 files/s sustained at scale (healthy 58k extract ≈ 5–6 min, NOT
  25–40 min); small repos pay ~44 s fixed/serial overhead (miller repo: 1,330 files in 51 s,
  parallelism ≈0.93) — its own first-impression bug.
- **Attempt 2 (32 MB stacks):** different, graceful failure — no spool leaked, DB initialized with
  schema+metadata but ZERO files. Error text lost to a `time | tail` pipeline mistake; attempt 3
  with RUST_BACKTRACE=full running in background.

**IMPACT:** Two new julie-extractors bugs with one-command repros — recommend bundling fixes into
the same release as fleet-safety W4–W6 flags. dotnet/runtime pinned commit is now the standing
scale target in P0 (ladder: roslyn ~15k, openjdk ~70k, linux ~85k, llvm ~150k). Progressive-levels
idea recorded as candidate follow-on (L1 symbols → L2 references → L3 regions/facts → L4
embeddings-already-progressive), deliberately sequenced after the extractor fixes + re-measure
since the bloat fix may erase much of the need.
