## W1 — bootstrap scan now holds the writer lock (fleet-safety)

### WHAT
`IndexBootstrapService.RunBootstrap` decided from an unlocked artifact probe and then called `runner.Scan` with **no `SingleWriterLock` held** — including the force-rebind path, which *promotes* over the live artifact. Two fresh Miller processes on the same worktree therefore scanned and promoted the same `symbols.db` concurrently. That is the root of the 2026-08-01 multi-worktree field report's non-convergence.

Now every bootstrap scan runs under a lease obtained by `AcquireBootstrapScanLease`, and the scan decision is **re-read after** the outcome is known so the caller never acts on the stale pre-lock probe.

### HOW
- `AcquireBootstrapScanLease<TLease>` — generic over the lease type (sealed in production) so the fast suite drives the whole control flow with fakes, same shape as `LoadIndexWithAutoRebuild<T>`.
- A loser **never waits for release** — a live `IndexerService` leader holds the lock for its entire process lifetime, so a release-wait could not terminate. It waits for the winner's *artifact* instead, then loads that.
- `WinnerArtifactProbe.IsFinished` is the stand-down gate. Four conjuncts: root matches, `artifact_id` stable across polls, **committed revision > 0**, and this build can read the schema.
- `MILLER_BOOTSTRAP_SCAN_LOCK_WAIT_SECONDS` overrides the 10-minute default; `DescribeBootstrapLockHolder` names the holder from the leader identity sidecar.
- Also fixed `RebuildAndRetry` reporting `Rebuilt: true` when `forceRescan()` returned null on a busy lock, and the auto-rebuild closure re-acquiring a lock this bootstrap already holds (`FileShare.None` denies the *same* process a second handle).

### The regression the adversarial review caught (do not lose this)
The first implementation accepted a winner on **root match + stable `artifact_id` alone**. Verified in `julie-extract-artifact/src/writer.rs`: `open_path` runs `create_schema` + `initialize_metadata` in **autocommit**, so `artifact_id` and `root_path` are visible the instant the writer opens; every symbol row then goes into one long `unchecked_transaction`. And a *first* scan is `force: false`, writing **in place** — no `.rebuild` staging, so no rename ever moves the id.

Result: the loser saw a stable id ~1s into the winner's scan, stood down, and bound a schema-valid **zero-symbol** artifact, serving empty search/inspect/context for the winner's entire write. Pre-W1 that same interleaving caused a redundant scan — wasteful but correct. **W1 as first written turned it into a silent empty index.** The committed-revision conjunct is the fix: uncommitted rows are invisible across connections, so a visible revision is exactly the proof the write landed.

### Why the tests missed it
`BootstrapScanLockScaleTests` re-implemented `ReadDecision` and `WinnerArtifactUsable` as fixture-local copies and asserted against *those*. Mutating the production `RootPathsEqual` conjunct to a bare `File.Exists` left the suite green, and no test executed `RunBootstrap` at all — so deleting `bootstrapLease?.Dispose()` from the `finally` also passed 5299 tests.

Rewritten to drive production: `ReadDecision` extracted to `ReadBootstrapScanDecision`, the gate is the real `WinnerArtifactProbe`, and the tests run the actual `RunBootstrap` through `BootstrapForRoot` with a real lock held by the test and a real `julie-extract` subprocess. Scan counting uses a new `internal Action? TestScanObserver` seam (`JulieExtractRunner` is sealed with a non-virtual `Scan`, so a wrapper was not available without unsealing a shared type).

**Lesson worth carrying:** a test that re-implements the logic it guards is worse than no test — it reports confidence it has not earned.

### Other fixes in this round
- **Lease leak (critical):** `decide()` throwing after `tryAcquire()` won orphaned the lease — `bootstrapLease` was still null, so the `finally` disposed nothing and the `FileShare.None` handle survived to process exit, making *every* later bootstrap on that workspace wait out the full timeout and fail. Reachable: `SqliteReadOnlyAccess` throws `InvalidOperationException` for `SQLITE_READONLY_RECOVERY`, exactly what a SIGKILLed prior writer leaves. All three outcomes now construct through a `Resolve` helper that disposes and rethrows.
- **Unloadable winner:** standing down on a schema-incompatible artifact turned a self-heal into a hard bootstrap failure (auto-rebuild cannot take the lock the winner still holds). Added `SqliteSymbolReader.VerifyCompatible` — a public, row-free schema-gate entry point — rather than widening `InternalsVisibleTo`.
- **`ParseBootstrapScanLockWait`** was documented "never throws" but passed an unbounded double to `TimeSpan.FromSeconds`; `Infinity` and `1e400` both parse. Now guarded like `FullRebuildPromotion.ReadTimeout`.
- `SingleWriterLock`'s doc comment claimed julie's `<db>.julie-extract.lock` was a cross-process backstop. It is not — julie-extract runs no lock of its own. Corrected: this lock is Miller's **only** serialization, and it is strictly per-workspace.

### IMPACT
Closes the P0 concurrent-promote hole. The per-workspace scope is the limitation W3 addresses: N workspaces are still N independent leaders with nothing machine-wide above them, which is how a worktree fleet still ends up running N concurrent extraction pools.
