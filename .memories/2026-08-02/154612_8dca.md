## Worktree delta-rebind successor program plan authored

**WHAT:** Wrote `docs/plans/2026-08-02-worktree-delta-rebind-program.md` — the approved successor
program to the fleet-safety plan — plus a `docs/README.md` map pointer and a strategy-brief addendum.
Docs only; no code.

**WHY:** The 2026-08-01 field report exposed two problems. The in-flight safety plan fixes crashes
(OOM cascades, spool leaks, crash loops). The second problem remains: every fresh worktree pays a
full extraction (~25–40 min at 74k files), serialized by the new governor — an 8-worktree fleet
converges in hours, and worktree-per-task agent workflows pay it constantly. An architecture review
this session (user-approved) concluded: safety makes fleets *not die*; delta-rebind makes them
*usable*.

**HOW (key decisions from the architecture discussion):**
- **Swarm stays.** The incident validated the per-workspace-process + lease architecture — every fix
  fit inside it. No central daemon: version-skew is the killer (Gradle/Bazel lesson), and the
  escalation continuum (lease → small elected broker → daemon) is already precedented in-tree by the
  semantic broker. Trigger documented: sustained 20+ heavy-churn worktrees.
- **SQLite stays.** Single-writer was never the bottleneck (write contention never occurred); the
  artifact-as-copyable-file property is load-bearing for rebind AND any Eros/CI future. LanceDB
  trigger: ~100× embedding growth.
- **Rebind contract is julie-extractors-owned** (Miller never rewrites extractor metadata privately).
  v1 lean: copy-and-rebind (APFS clonefile makes the copy ~free) with base+overlay (SQLite ATTACH
  read-through) documented as the future shape. Identity lean: keep `WorkspaceId.FromCanonicalRoot`,
  add registry lineage columns (git common dir + generation) instead of a breaking re-derivation.
- **Eros reframed:** runtime (Miller) vs artifact supply chain (Eros), not addon vs replacement. The
  worktree rebind contract IS the future CI/team artifact-consumption seam — zero-regret.
- **P0 measurement riders on W10** capture the gaps the review found in the safety plan: RSS per
  jobs level (memory-aware admission data), embedding convergence running OUTSIDE the governor,
  Linux inotify consumption across N worktrees, per-platform artifact clone cost.

**IMPACT:** The "what's next after fleet safety" question is settled and written down with standing
triggers, so daemon/LanceDB/Eros stop being open questions. Program gated on the safety plan
landing + per-phase approvals; ~5–7 agent sessions across both repos, two approval points
(julie-extract release/pin bump, Miller release).
