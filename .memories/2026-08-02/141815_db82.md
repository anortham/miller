## Fleet-safety P0: W2 landed, seam scope settled by cross-model doubt pass

Executing the approved `docs/plans/2026-08-01-multi-worktree-fleet-safety-plan.md` on worktree

### W2 — extraction parallelism cap (DONE, green)

- New `src/Miller.Indexing/ExtractJobsPolicy.cs` — pure, mirrors the `SemanticActivation`/`SymbolSearchSidecar`
  `EnvVar` + `FromEnvironment()` + pure `FromEnvValue()` triple. Default `min(4, max(1, ProcessorCount/2))`,
  `MILLER_EXTRACT_JOBS` honored verbatim (including above the cap), `0` = rayon auto, invalid falls back silently.
- `BuildScanArgs` now takes `jobs` and always emits `--jobs` before the conditional `--force`;
  `ArgumentOutOfRangeException` on negative (julie types it `usize`, so a negative would surface as an opaque
  clap usage failure).
- `Scan(root, db, force, int? jobs = null)` — explicit `jobs` BEATS the env var, because W8's post-OOM retry
  passes `jobs: 1` as a safety response a stale operator override must not undo.
- Build 0 warnings; fast suite 5282 passed (+24). CLAUDE.md documented, AGENTS.md synced (`cmp` clean).

### Doubt pass on the P0 seam scope (round 1 complete, both reviewers substantive)

Four recon agents disagreed about how much of the scan-coordination seam belongs in P0. Ran the Doubt Pass
with Codex and Grok independently. **My re-entrancy claim was wrong and both killed it.**

Verified in code myself before adopting:
- `WatchEventRouter.Route` returns ONLY `ScanOp` when `needsRescanOrHead` — the W3 recon agent's "mixed batch"
  premise was false.
- `IndexerService` `RunStartupDeltaScan` (:382) and the extractor-upgrade rescan (:396) are SEQUENTIAL, so the
  nesting that motivated re-entrancy does not exist; meanwhile one process CAN refresh two different registered
  workspaces concurrently via `WorkspaceIndexProvider._refresh`, which a process-counter lease would wrongly admit.
- `TryReindexAsLeader` (:581) holds `_opsGate`, so a governor wait inside that gate would block the exempt
  per-file path — admission must be acquired BEFORE `_opsGate`.
- `IndexerCore` clears `NeedsRescan`/`_overflowSignaled` (:122-125) before `ExecuteIsolated`, which swallows
  `JulieExtractFailedException` — so success, not admission, is the commit point. Pre-existing defect W3 worsens.
- `RebuildAndRetry` (:773-778) reports `Rebuilt: true` even when `forceRescan()` returned null because the lock
  was busy and the rebuild was SKIPPED. Real defect, found by Grok.

### Impact

P0 shape is now settled except one open dispute (below). W1 gained four correctness requirements it did not
have in the plan: full `RepositoryIndexLoader.Load` + artifact-id stability as the accept condition (not bare
`ReadRootPath`), retry on SQLITE_CORRUPT/NOTADB/FileNotFound, an honest `LoadedWinner` outcome, and no lock
acquisition on the healthy reuse path.
