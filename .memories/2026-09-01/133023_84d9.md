## Trace path fixes 1–3 implemented and proved live

### WHAT
Three fixes to `trace mode=path` (all TDD, fast suite 9,433 green, uncommitted on main):
1. **Overload-set name-fallback edges** (`QueryTimeResolutionReader`): an unresolved call into a set of same-name symbols sharing one non-null declaring parent now gets an edge per member (site confidence × 0.4, reason `identifier_name`); globally unique names keep × 0.5. Critical discovery: julie emits a `pending_relationship` for these call sites, and a pending SUPPRESSES its site's identifier — so the fallback had to cover unresolved PENDINGS too (`PendingsByFrom`/`PendingsNamed` arms), or the fix never fires on real extracts. Contract updated: `docs/contracts/resolution-policy-v6.md`.
2. **Reverse probe on miss** (`TraceTool.RunPath`): a forward miss now runs the reverse BFS; on a hit the message names the reverse path and the first next-action is the swapped retry.
3. **Honest empty handoff + destination handling**: no-path text states the search walks caller -> callee only and that unresolved call sites can hide a real path; an unresolved/ambiguous `to` is named ("trace path destination 'X': ..."), gets diagnostic code `unresolved_destination`, next-actions keep target/mode/to with candidate symbol ids, and `to` retries resolution with the caller's scope.
