## Fresh family-store repair gate and performance position

### WHAT

Reverified the staged family-store dogfood repairs and measured the rebuilt server from startup through exact resolution and sidecar readiness.

### WHY

The repair commit needs evidence for both correctness and the user-visible performance tradeoff, not only passing unit tests.

### HOW

- Release build: 0 warnings, 0 errors.
- Fast suite: 6,332 passed, 4 skipped, 0 failed.
- Scale suite: 135 passed, 5 optional-runtime skips, 0 failed.
- Live store reached exact resolution with search, content, vectors, and the Vulkan semantic broker current.
- Warm lexical searches measured 107–129 ms (median 123 ms); explicit semantic searches measured 104–128 ms (median 111 ms).
- This Miller checkout took about 7m44s from server start to startup delta completion and roughly 9m to full sidecar readiness after a large accumulated change set. The family directory occupies 1.60 GB while the preserved local `.miller` directory occupies 1.55 GB.

### IMPACT

The family-store read path and repaired semantics are operational and fast once converged. Startup resolution/full-view sidecar convergence and duplicate migration-era storage remain the performance gaps; A8 cursor-incremental sidecars, family-shared vectors, A7 durable reader pins, and multi-view live storage validation remain follow-up work.
