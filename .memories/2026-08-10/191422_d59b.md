## Isolated legacy test fixtures from the new product default

- **WHAT:** Added project-level VSTest run settings that set `MILLER_INDEX_STORE=off` inside the test host, while the dedicated environment/CLI tests explicitly unset it to prove default-on behavior. Hardened the bounded progress-stamp test so whichever 512 nested entries are sampled must observe a size change.
- **WHY:** The first unset full-fast run correctly exposed that hundreds of synthetic standalone fixtures left storage mode implicit and were being routed into family-store pointer validation. A separate bounded-directory test depended on unspecified filesystem enumeration order and failed locally.
- **HOW:** Used the supported `RunSettingsFilePath` project property and `RunConfiguration/EnvironmentVariables` contract. Production binaries and shell environments remain default-on. The progress test appends every bounded fixture file instead of guessing that `part-0000` is in the unspecified first 512 entries.
- **IMPACT:** A real unset shell run now passes 6,324 fast tests with 4 skips; Scale passes 135 with 5 optional-runtime skips. Default-on remains covered explicitly rather than accidentally through legacy fixtures.
