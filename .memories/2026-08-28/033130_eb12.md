## qmake Qt Quick Test backend implemented

### WHAT

Added qmake project inventory and the qmake-backed Qt Quick Test adapter, including bounded .pro/.pri evidence, Qt 5/6 logger selection, QTest result parsing, generated-path isolation, qmake/make probing, and target-level normalization. Added provider routing, shared Scale-toolchain guards, convention coverage, unit tests, and a real qmake fixture.

### WHY

Miller needed qmake coverage without changing the public `qt-quick-test` framework identity or writing build/results into source trees. Qmake projects must prove a usable `check` target before they can run.

### HOW

Inventory accepts `CONFIG += qmltestcase`, or `QT += qmltest` together with `CONFIG += testcase`, and reads only literal included `.pri` files within the bounded evidence limit. The backend probes qmake version, `QT_VERSION`, and the make tool, configures/builds under `CtGenerationPaths`, verifies the generated Makefile check target, runs `make check` with version-correct XML logger arguments, and aggregates QML function results to one stable qmake target case. Unsupported native Qt Test-only projects remain refused.

### IMPACT

The qmake path is now available behind the existing QML provider and is fail-closed on unsupported Qt versions, missing check targets, incomplete output, missing/malformed reports, nonzero runs, and out-of-generation artifacts. Focused fast verification is green; the real Scale test skips honestly when qmake is unavailable in this environment.
