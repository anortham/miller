## Windows release gate exposed a platform-specific qmake assertion bug

The Windows fast suite failed only `BuildCheckArguments_neutralizes_make_and_shell_expansion_in_result_paths`.

- **What:** The test rejected the substring backslash+backtick on every OS.
- **Why:** On Windows that backslash is the native directory separator before the legal directory name `` `echo``; NMAKE/cmd treats the backtick as inert. The production `TESTARGS` output preserved the exact path and was correct.
- **How:** Kept the POSIX no-backslash-escape assertions, while the Windows branch now checks the exact make-safe native path with `$` doubled.
- **Evidence:** Initial Windows fast: 9,153 passed, 25 skipped, 1 failed. Focused Linux qmake tooling after the test correction: 17 passed.
- **Impact:** The release gate must rerun the focused Windows class and then the complete Windows fast suite on the correction commit. No production code changed.
