## Stabilized daemon-launcher Scale output capture

### WHAT

Updated `tests/Miller.Tests/Testing/Daemon/ControlPlane/CtDaemonLauncherTests.cs` so `RunMiller` waits for the first asynchronous stdout/stderr line after launcher exit under the existing sink lock, with a five-second bound. `AppendLine` pulses the sink monitor after appending. Empty output now fails with an actionable assertion before callers parse JSON. Updated Task 5 in the v1.25.0 release-prep plan.

### WHY

The exact-SHA Scale gate once observed launcher exit code 0 with an empty async output sink, while the same test passed alone. The detached daemon inherits the launcher's pipe handles, so waiting for parameterless process exit or pipe EOF is unsafe.

### HOW

Kept the existing timed `WaitForExit(120_000)`. After it returns, `RunMiller` locks the `StringBuilder`, waits only if no output has arrived using `Monitor.Wait(..., TimeSpan.FromSeconds(5))`, snapshots the output, and asserts it is nonblank. The handler pulses the monitor while holding the same lock. No production code changed.

### IMPACT

The focused Scale test is resilient to the async-handler race without waiting on daemon-owned pipe closure. The focused test passed once after the build and three consecutive times with `--no-build`; `git diff --check` passed. The complete Scale gate remains for the lead-owned release gate.
