## WHAT

Completed Task 2 of the CT provider expansion plan. Miller now has one exact language-family mapper, trailing provider `SymbolName`/`SymbolPath` identity, current-snapshot name/path joins, detailed role precedence, and fail-closed file completeness rules.

## WHY

Selection previously relied on partial extension logic, fileless .NET assumptions, and legacy symbol IDs. Missing or stale evidence could be mistaken for `KnownEmpty`, and provider identity could not be safely rejoined after index revisions.

## HOW

- Centralized raw extension labels and execution-family comparison, including VB.NET, JS/TS dialects, QML, Go, and existing Python/Rust compatibility.
- Persisted provider symbol name/path without treating any unversioned Julie ID as durable.
- Resolved typed identity only when the provider path has current indexed file evidence and one exact current symbol match.
- Kept containers/lifecycle roles as reachability-only and preserved legacy `IsTest` behavior.
- Forced ordinary missing, unavailable, diagnostic, non-indexed, stale, ambiguous, or unresolved evidence to `Unknown`.
- Lead inline review found unavailable-file and stale-identity gaps plus duplicate mapping; a bounded Luna correction closed them.

## IMPACT

The shared CT contract is stable for provider work. JavaScript and QML corrections can run in parallel, followed by qmake, VB.NET/MTP, and Go.
