## Go continuous-testing provider slice is ready for commit

### WHAT

Added Go project inventory and provider support for one project per `go.mod`, top-level test discovery, package-grouped runs, generation-scoped artifacts, and structured verdict parsing. Added guarded single-module and in-root multi-module fixtures.

### WHY

The approved CT expansion requires Go support without inheriting an ambient external `GOWORK`, writing outside Miller-owned cache/temp/result paths, or treating malformed/incomplete test output as green.

### HOW

`go version` gates Go 1.24+, `go env -json` records effective toolchain and environment, `go list -json ./...` is parsed as a multi-value pretty JSON stream, and `go test -list` supplies top-level `TestXxx` names. Runs use explicit `GOWORK`, sanitized `GOFLAGS`, project-stable `GOCACHE`, generation-owned `GOTMPDIR`/results, anchored escaped `-run`, and `-count=1`. `go test -json` parser separates test/build events, rolls subtests to parent cases, maps package build failures to all selected cases, and refuses malformed/truncated/missing-terminal evidence.

### IMPACT

The provider is registered as framework `go`; nested modules stay distinct while root `go.work` is execution context. Focused provider/inventory/factory/convention tests and both real Go Scale fixtures are green. The next session should review the owned diff and commit it with this checkpoint and the task report.
