## WHAT

Completed the reviewed parallel provider-correction batch: Task 3 JavaScript discovery and Task 4 QML CMake/CTest.

## WHY

JavaScript discovery could silently change suites through unsafe config fallback, wrong defaults/exclusions, runner-version ambiguity, and incorrect negative/glob semantics. QML inventory missed supported macros, accepted projects without CTest evidence, collapsed independent nested projects, and lacked a backend seam suitable for qmake.

## HOW

- JavaScript now reads bounded literal Jest/Vitest/Vite config without execution, supports documented defaults and runner-specific negatives, validates installed/dependency runner versions, and refuses unsupported/truncated/interpolated/spread/testRegex/glob shapes.
- QML now recognizes the full supported macro family, scopes evidence to resolvable CMake inclusion graphs, requires local/included CTest registration, preserves independent projects, and fills bounded reads.
- Added an internal backend contract whose adapters own build, discovery, run validation, and result parsing; the CMake adapter preserves current CTest/JUnit behavior.
- Lead review caught unknown-version and unsupported-glob gaps in JavaScript plus nested evidence contamination and hard-coded CTest parsing in QML; bounded Luna corrections closed all findings.

## IMPACT

JavaScript CT discovery is fail-closed and QML CMake support is ready for a separate qmake backend without changing the public `qt-quick-test` identity.
