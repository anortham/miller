## Task 7 MTP contract evidence

### WHAT
Verified the current Miller Task 7 baseline and official Microsoft documentation needed for the internal Microsoft.Testing.Platform adapter.

### WHY
MTP routing must be version- and evidence-aware; hidden fallback to VSTest would violate CT fail-closed behavior.

### HOW
The approved brief owns DotnetTestProvider, DotnetTestBackend, new MTP adapter/tooling/list-parser files, focused provider tests, and a guarded VB fixture. Official Microsoft docs establish .NET 10 global.json `test.runner` selection, MTP support from 1.7, text `--list-tests` before 2.3, JSON listing from 2.3, and TRX via the `Microsoft.Testing.Extensions.TrxReport` extension with `--report-trx`/`--report-trx-filename`. MSTest.Sdk defaults to MTP and `UseVSTest=true` opts into VSTest. Existing Miller currently refuses MTP after Resolve and uses VSTest generic commands for MSTest/NUnit.

### IMPACT
Implementation can add an internal MTP executable adapter while preserving public `mstest`/`nunit` framework identities and existing VSTest/xUnit command paths.
