## WHAT

Completed wrapper-safe batched context hydration. `ISymbolLookupIndex` now has a default `ResolveMany` fallback; FTS resolves document IDs in bounded 500-ID statements on one connection; every production wrapper forwards batching while retaining live validation and resolve telemetry; `SearchTool` hydrates each fetch window once.

## WHY

Warm context requests performed roughly 2,500 per-hit SQLite resolves and commonly took 13–18 seconds, with lagging-sidecar cases reaching 40–65 seconds. The cursor delay came from repeated lookup work rather than result rendering.

## HOW

The interface fallback preserves existing implementations. FTS de-duplicates requested IDs, executes `[500,500,200]` statements for 1,200 IDs, and maps rows back to requested identity. Search still iterates original hit order and uses its prior single-resolve fallback for an omitted row. Measured, context-cache, and lagging wrappers retain their policies. TDD captured the per-hit production-chain failure, live-validation bypass, and incorrect batch bound before GREEN.

## IMPACT

The exact MCP context workload now runs with a cold 2,927 ms call and warm telemetry rows of 2,817/2,767/2,760/2,787/2,754 ms: nearest-rank warm p95/max 2,817 ms, below the 3,000/5,000 ms hard gates. Output, diagnostics, relaxation, and memoization remain unchanged.
