## WHAT

Task 7 now routes supported .NET test projects through an internal Microsoft Testing Platform backend while retaining the existing public .NET framework identities. It adds version-aware list handling, fail-closed filter/report/result validation, and a guarded real VB MTP fixture.

## WHY

The provider previously refused MTP projects. The implementation needs to distinguish MTP from VSTest using global.json and evaluated project evidence, preserve selected-case semantics, and avoid silently running or accepting an unverified whole suite.

## HOW

- Preflight uses the built test module's `--info` output and requires MTP 1.7 or newer.
- MTP 2.3 or newer uses the documented JSON list shape; older supported versions use the documented text list shape.
- Runs use generation-scoped TRX output only when the TRX report extension is proven; malformed, truncated, incomplete, missing, or nonzero-without-results paths refuse.
- Direct MTP executable invocation uses its documented app-option contract; the `dotnet test` driver delimiter is not passed to `dotnet exec` because the live MTP executable rejects it.
- Existing VSTest and xUnit-v3 paths remain outside the MTP route.

## IMPACT

MSTest.Sdk projects default to MTP unless evaluated `UseVSTest=true`; conflicting or unknown runner evidence remains refused. The VB fixture proves discovery, selected execution, TRX parsing, and source immutability against MTP 2.3.3.
