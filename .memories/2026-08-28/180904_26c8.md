## Tool latency and health design approved and adversarially corrected

### WHAT

Wrote `docs/plans/2026-08-28-tool-latency-and-health-design.md` for edit, context, impact, and workspace-health fixes. A one-call Claude doubt pass found two high and five medium design gaps; all seven were verified and folded into the spec.

### WHY

The fixes cross workspace read routing, SQLite symbol identity, search wrapper policy, graph evidence semantics, and telemetry aggregation. A local speed patch could silently drop search hits, bypass live-row validation, break stale edit recovery, or produce contradictory health counts.

### HOW

- Store edits use the pinned symbol provider; legacy mode reuses its eager index.
- Store stale recovery reopens the read context after convergence.
- Lagging live rows keep sidecar DocIds when path filtering moves inside the CTE.
- `ISymbolLookupIndex` gains wrapper-safe batch resolution with a default fallback.
- Impact optimization follows measured graph phases rather than assuming a generic cache helps.
- Health uses seven-day summary and outcome aggregates.
- Performance targets remain context p95 <=3s/max <=5s and impact p95 <=5s on fixed warm workloads.

### IMPACT

The written spec is ready for user review. No production code or tests have changed. After approval, move the spec and Goldfish checkpoints into an isolated worktree, commit the design there, write the executable TDD plan, and run Luna-owned implementation packets.
