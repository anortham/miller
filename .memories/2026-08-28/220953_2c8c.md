## WHAT

Designed worktree view retirement for Miller's family store. The existing removal path cleans registry rows and Miller sidecars but leaves julie-extract producer views and manifests alive. The design adds a producer retirement adapter to existing `workspace remove/prune`, a session-hook lifecycle reminder, and a compact missing-root hint.

## WHY

The live Miller family has 12 producer views, only two active Git worktrees, and nine views whose roots are missing. Those views pin old manifests and file versions, increasing disk use and family-wide identifier lookup work.

## HOW

Capture the exact store root and view id from `store_members`, preview and apply the pinned extractor's `store maintain retire-view`, then delete registry membership and reclaim per-view sidecars. Producer failure leaves the registry mapping intact for retry. Dry-run stays read-only. The one-time cleanup targets the nine missing views only.

## IMPACT

Future worktree removal will retire producer data through existing workspace lifecycle commands. Existing stale views can be removed without a new MCP tool or direct store writes. The present `ct-dogfood-round2` directory remains outside automatic cleanup because its root exists.
