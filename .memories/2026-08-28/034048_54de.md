## qmake correction regressions resolved

### WHAT

The qmake packet correction now leaves no completion marker after a failed build, retries a failed generation, rejects independent nested qmake evidence borrowing, and uses one bounded effective root-plus-literal-in-root-pri project model for backend target/import parsing. New regressions cover dynamic, out-of-root, and oversized includes.

### WHY

The prior implementation could reuse a failed build, classify an outer project from a nested independent project, and ignore TARGET/IMPORTPATH declared in a literal included pri file.

### HOW

Tests were added first. The focused gate now passes 112 tests. EnsureBuildAsync writes the Qt-version marker only after successful make; inventory uses the shared qmake model and excludes files under nested pro roots except explicitly included pri files; backend discovery and run parse the model's effective text. Miller context/search/inspect/impact/trace/workspace refresh evidence was collected before and after the edits.

### IMPACT

The qmake backend is fail-closed for stale partial generations, nested-project ownership, and unsupported project-model evidence. The report was corrected to use prior commit d8d98921 as the base; the correction commit is pending.
