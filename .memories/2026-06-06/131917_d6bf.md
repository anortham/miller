## Routed graph-only CLI reads through SQLite reachability

The remaining TODO #5 one-shot CLI paths no longer need full repository graph/bridge hydration for non-bridge reads.

- **WHAT:** Added `SqliteSymbolGraphIndex` for on-demand graph reachability over `symbols.db`, plus batched FTS sidecar symbol-id hydration via `FtsSymbolSearchIndex.FindBySymbolIds` / `SymbolLookupBatch`.
- **WHY:** OpenClaw dogfood showed `context`, `impact`, and `trace auto` still took 6-8s and ~1.5 GB RSS because CLI loaded the full repository projection and bridge graph.
- **HOW:** CLI `context`, `impact`, and `trace mode=auto|path` now use symbol lookup + SQLite graph reachability. `trace mode=bridge` still loads the full bridge graph. Tool cores gained graph-reachability overloads while preserving the existing full-index path.
- **IMPACT:** OpenClaw broad `context` dropped to `real=0.77s` / ~119 MB RSS, `impact` to `real=0.31s` / ~69 MB, and `trace auto` to `real=0.32s` / ~69 MB. TODO #5 is now closed for the beta CLI path; no symbol-search widening or incremental patching is justified by current evidence.
