## Avoided full graph load for ambiguous full inspect

Started TODO #5 with a targeted read-path performance fix.

- **WHAT:** `inspect depth=full` now preflights target resolution through the symbol lookup projection. If the target resolves to candidates, file listing, or not-found, it renders through the cheap summary path and avoids full repository graph hydration. Only a unique symbol proceeds to the full `RepositoryIndexLoader` path.
- **WHY:** OpenClaw showed `miller inspect noteWorkspaceStatus --workspace-id openclaw --depth full` returned only an ambiguity candidate list but still paid the full graph load first.
- **HOW:** Updated both MCP `InspectTool` and CLI `CliDispatch` inspect routing. Added regressions for MCP and CLI ambiguous full inspect; CLI regression drops `relationships` to prove the full graph loader is not touched for the ambiguity branch.
- **IMPACT:** OpenClaw ambiguous full inspect dropped from `real=8.75s` and ~1.45G max RSS to `real=0.60s` and ~69M max RSS. Unique-symbol full inspect, `context`, `impact`, and `trace` remain the graph-heavy TODO #5 follow-up surface.
- **VERIFICATION:** `scripts/test.sh` passed 1622 tests; `dotnet build Miller.slnx -c Release` passed with 0 warnings/0 errors; `git diff --check` passed.
