## Added MCP restart verification to workspace status

- **WHAT:** Added optional server process id rendering to `workspace status` compact and JSON output, and wired live status producers to populate it with `Environment.ProcessId`.
- **WHY:** The stdio MCP server cannot hot-swap while running, and rebuilt uncommitted changes keep the same git SHA suffix. Dogfood sessions needed a cheap way to confirm a client restart actually loaded a new Miller subprocess.
- **HOW:** Extended `WorkspaceFacts` with `ServerProcessId`, rendered `pid <n>` in compact status and `server_pid` in JSON, populated it from `WorkspaceTool` and CLI status paths, and updated README/TODO/beta checklist to document the restart constraint honestly.
- **IMPACT:** `workspace status` now answers both which build and which process is live. This closes the MCP rebuild/restart ergonomics TODO without pretending hot reload exists for stdio MCP.
