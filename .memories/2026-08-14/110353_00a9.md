## Split-root producer harness correction

### WHAT

Completed the bounded Task 1B-C correction in the performance-recovery harness. Producer retry rows now resolve the source pointer's view and use disposable spool/progress/parent-pid controls; source-changing resolution setup clones the source root into a temporary workspace and establishes a fresh view through public import/resolve commands before changing one file.

### WHY

The previous harness mixed the staged Miller pointer/view with the Julie source root and edited or resolved against a root whose pointer/workspace identity could not agree. It also treated Julie's nested numeric `manifest.generation` as if it were the `CURRENT` directory name (`gen-*`).

### HOW

- Added source-view, disposable supervision, and fresh-view runtime placeholders with strict producer flag validation.
- Validated source pointer family/store identity against the explicit live store.
- Added baseline import -> baseline resolve -> temporary pointer adoption -> changed import -> measured resolve ordering, with subprocess completion/JSON identity gates and abort-on-setup-failure behavior.
- Added a read-only selected-view `views.current_generation` check, with setup-generation fallback when test/public reports do not expose a readable catalog.
- Added tests for source/staged view divergence, pointer/store mismatches, temporary-root transitions, setup ordering/failure, unchanged source bytes, and nested numeric manifest generations.

### IMPACT

Julie rows can be measured against copied stores and disposable roots without touching the original source pointer/files or comparing a public numeric manifest generation to a `gen-*` directory name. Miller CLI/MCP rows retain the staged workspace binding.

### NEXT

Commit only the owned harness files and this checkpoint; leave unrelated worktree changes untouched.
