## Project startup phases into MCP replay rows

The performance-recovery harness now preserves the runtime startup phase records for the MCP child that produced them instead of projecting only `startup_total`.

- **WHAT:** Added bounded phase collection for bind, import, resolve, coordinator_total, content, search, metrics, vector, sidecar_total, and startup_total. Collection starts at the session log offsets, filters the child PID, stops optional-phase collection at the first startup_total, and caches records before result serialization.
- **WHY:** The baseline JSONL exposed only startup_total even though the staged JSONL logs contained the detailed phase records needed for Task 5B attribution.
- **HOW:** Reused `_phase_records` and per-file offsets; retained existing startup_total wait/completion behavior, including completed/failed selection and absent optional phases. The row schema remains `phase_timings` with startup_total still present.
- **IMPACT:** Startup/replay rows can carry all observed child phases without including pre-offset records, another PID, or post-startup duplicate bind records. The change is harness-only and uses no Unix-specific process behavior.
