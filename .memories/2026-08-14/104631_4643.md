## Preserve registry-first store resolution

### WHAT

The memberless store resolver now checks for an already-registered, usable lineage before attempting workspace-pointer adoption. Added a regression covering a malformed pointer alongside a valid registered family/view.

### WHY

A malformed or conflicting pointer must not block the established registry-backed workspace path. Pointer adoption is only appropriate when no usable registered family can serve the current root.

### HOW

- Added `HasUsableRegisteredLineage`, which reads the existing lineage/family catalog and opens a read-only family session without minting a family or mutating registry state.
- The memberless branch attempts pointer adoption only when that gate is false.
- Kept unknown-lineage promotion, root-replacement rejection, and empty-registry pointer adoption paths unchanged.
- Did not change `WorkspaceRegistry`; no test or evidence demonstrated partial mutation requiring a transaction refactor.

### IMPACT

The malformed-pointer regression passes while the existing resolver, coordinator, and bootstrap contracts remain green. The correction is limited to the resolver and its focused test.
