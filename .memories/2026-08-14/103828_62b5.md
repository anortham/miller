## Implemented validated store-pointer adoption

A lock-winning Miller leader can recover an empty isolated registry from a valid root-matching family-store pointer without minting a new family.

- **WHAT:** Added memberless pointer adoption in `StoreFamilyResolver`, an internal explicit family/store-root registration seam in `WorkspaceRegistry`, and focused resolver coverage.
- **WHY:** Direct CLI and warm-reader paths already trusted validated pointers, while leader resolution ignored them and created unrelated lineage.
- **HOW:** Read the pointer only after normal registry member lookup finds no binding; validate catalog family/view root and `FamilyStoreReadSession.Open` (CURRENT, generation/manifest, coordinator, resolution/read identity), then validate lineage and view uniqueness before registering family/member rows. Invalid or root-replaced pointers fail closed without registry or pointer mutation.
- **IMPACT:** Leader, direct-read, and warm-reader paths select the same family/view for a staged root; normal registered workspaces remain registry-first.
