## WHY

The first harness version could run refresh/full against the workspace's real absolute family-store pointer while merely recording `--store-copy` in an unused environment variable. A benchmark harness must never mutate the live store, and subsequent tasks need a stable evidence contract.

## HOW

The CLI now requires explicit `--live-store` and `--store-copy`. Before `Popen`, it validates `.miller/store.json`, `CURRENT`, generation `store.db`, and `coord.db`, checks the workspace root and view, rejects canonical/symlink/hardlink aliases to the live store, and requires the supplied copy to identify the exact active family root/generation database or legacy `symbols.db`. `MILLER_INDEX_STORE` is set to the proven mode. Lead review found and corrected both the unused-copy path and an overbroad sibling-file authorization rule.

Tasks 2-8 can consume a safe, deterministic replay schema. No real performance workload or live-store mutation has run yet. The implementation branch remains local and unpushed.
