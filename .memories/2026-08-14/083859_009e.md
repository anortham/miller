## Cycle-5 recovery harness corrections

### WHAT

Implemented the cycle-5 harness corrections in `scripts/perf-recovery.py` with focused regression coverage in `scripts/tests/test_perf_recovery.py`.

### WHY

Windows tree cleanup could stop retrying after a successful parent wait; a leader session could be retained before its result proved success; a live failed startup phase was ignored until timeout; and depth-pair ordering was not a hard gate and rejected valid inserted neighbors.

### HOW

- Retry bounded Windows `taskkill /T /F` tree cleanup whenever the initial tree command fails, even if the parent wait succeeds.
- Probe the final leader session result before retention, close failed candidates, and recheck the retained leader PID immediately before reader dispatch.
- Return the newest same-PID terminal phase record (`completed` or `failed`) immediately, including a failed record while the host remains alive.
- Compare relative order of common `symbol_order` IDs, allow depth1-only neighbors, and include ordering in depth-pair hard-gate evaluation.

### IMPACT

Leader/reader measurements cannot proceed from an unproven or exited leader, failed startup evidence is preserved without waiting for timeout, Windows descendant cleanup has a retry after parent reaping, and context ordering regressions are surfaced as hard-gate failures.
