## WHAT

Implemented Task 3: `ReferenceEvidenceReader.ReadMany` for legacy and family-store sessions plus budget-aware batched context enrichment. Added legacy exact/fallback/offset/truncation parity, 1,001-ID chunking, family 129-ID chunking, and real resolution-base rotation parity tests.

## WHY

Default context depth 1 took about 11 seconds because `BuildReferenceItems` performed singular inbound and outgoing SQLite reads for each candidate even when the final token budget could not admit identifier evidence.

## HOW

IDs are validated and deduplicated in first-seen order, then target info and four evidence arms are read in bounded 128-ID chunks inside one pinned `IWorkspaceReadSession.Read` snapshot. Existing per-symbol builders retain ordering, offsets, limits, fallback suppression, coverage, and snapshots. Context estimates fixed tier-0/1 output plus a minimum tier-2 identifier with the existing `TokenEstimator`; it skips all evidence work if the identifier cannot fit, otherwise invokes one `ReadMany` batch. `MILLER_CONTEXT_REFERENCE_BATCH=off` preserves the singular fallback.

## IMPACT

The measured N+1 structure is removed without changing output contracts. The family read follows rotated bases and large requests remain below SQLite parameter limits. Real copied-store timing remains for the later replay gate.
