## Preserve WAL-free identity and producer WAL mode

- **WHAT:** Added WAL-aware snapshot routing and focused regressions. Zero-byte WAL files are treated as nondurable; WAL-free databases are streamed byte-for-byte, while nonempty-WAL databases use the existing private-shadow/SQLite-backup path and retain WAL mode.
- **WHY:** Regenerated copied stores exposed two replay blockers: DELETE-journaled destinations were rejected by Julie, and SQLite backup changed referenced resolution-base bytes when the source WAL was empty.
- **HOW:** Raw copies capture source facts before/after, verify exact size and SHA-256 equality, and run immutable quick checks when a valid SQLite header is present. WAL backups set WAL mode, checkpoint/truncate, close, remove destination WAL/SHM sidecars, and validate without reopening mutably.
- **IMPACT:** WAL-free resolution bases retain identity, zero-byte partial files survive unchanged, and nonempty-WAL snapshots satisfy Julie's WAL contract without sidecars at rest. Cleanup and source-mutation gates remain intact.
