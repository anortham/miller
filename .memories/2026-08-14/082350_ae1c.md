## Cycle-4 recovery harness corrections

### WHAT

Implemented the bounded harness cycle-4 fixes in `scripts/perf-recovery.py` with regression coverage in `scripts/tests/test_perf_recovery.py`.

### WHY

Normal parent exit could leave descendants holding inherited MCP/CLI pipes; reader warm-up could execute without a live leader; MCP close could report synthetic success after an unknown/failed reap; initialize JSON-RPC errors were ignored; and phase-log polling could retain oversized/incomplete lines or advance past an incomplete tail.

### HOW

- Run process-group/tree teardown in normal and timeout paths, with bounded POSIX SIGTERM/SIGKILL handling and Windows `taskkill /T /F` retry behavior.
- Return and enforce MCP close/reap success; only retained live sessions may synthesize exit 0 for an unknown return code.
- Validate selected reader/leader order and reject reader execution without a successfully retained leader session.
- Stop bootstrap immediately on a top-level initialize JSON-RPC error.
- Read phase logs as bounded binary chunks, preserve the last incomplete line offset, and skip oversized records without unbounded buffering.

### IMPACT

The cycle-4 harness contracts are explicit and tested. The reader cannot be recorded as a standalone warm run, failed MCP teardown cannot become a completed attempt, and normal-exit descendants are cleaned up before pipe capture is finalized.
