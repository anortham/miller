## WHAT

Added a Linux/macOS-safe fallback for semantic broker Unix sockets when `<miller-home>/semantic/broker-<identity>.sock` exceeds the platform byte limit.

- Working short Unix paths remain byte-identical.
- Windows named-pipe names and behavior remain byte-identical.
- Service and accelerator locks remain under `<miller-home>/semantic`.
- Long Unix homes use `/tmp/miller-semantic-u<user-hash>/broker-<home-hash>-<identity>.sock`.

## WHY

Task 1B found default-on semantic status failing before broker startup when a long `MILLER_HOME` produced a 128-byte socket path. Linux `sun_path` allows 107 pathname bytes and macOS exposes 103 usable bytes through the conventional API.

## HOW

`SemanticBrokerEndpoint.Create` measures the legacy path in UTF-8 bytes, keeps it when valid, and otherwise derives deterministic 16-hex SHA-256 hashes from `Environment.UserName` and the absolute normalized `Path.GetFullPath(millerHome)`. The pinned sidecar already creates the dedicated fallback parent, sets it to `0700`, sets the socket to `0600`, and removes the endpoint on owner exit. The contract now records this narrow v1 exception and its mixed-version rationale.

## IMPACT

Long Unix homes no longer disable default semantic behavior. Same-user/same-home/model sharing, lock election, short-home compatibility, and all Windows paths are preserved. No sidecar or producer change is required.
