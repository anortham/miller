## Task 1B-A snapshot review cycle 2

- **WHAT** - Reworked the disposable store snapshot helper to read source SQLite files directly and added cycle-2 safety regressions.
- **WHY** - The previous implementation shadow-copied database/WAL/SHM inputs, used metadata-only source coherence, allowed an absent live root, hashed after promotion, and hid cleanup failures.
- **HOW** - Direct percent-encoded `mode=ro` connections use the backup API; an existing WAL `-shm` sidecar is temporarily made read-only and restored so the stopped WAL row is read without changing source bytes. Source metadata and streamed content are checked before/after reads and around each database backup. Live aliases, complete pre-promotion destination digesting, cleanup verification, and partial-connection closes are covered by focused tests.
- **IMPACT** - The disposable WAL fixture includes its committed row and preserves source DB/WAL/SHM bytes; all focused snapshot tests are green. The lead plan remains unstaged.
