## WHAT

Extended the performance-recovery harness with separate, fail-closed process-tree peak and retained-idle memory gates.

- Added a 350 MiB retained-idle budget only for startup leader and warm-reader hosts; the existing 600 MiB peak budget remains separate for all workloads.
- Added Linux PSS and Windows PrivateUsage idle fields, three-second sample duration, process count, and strict report output.
- Peak/idle samples aggregate the root and descendants; Linux enumerates children across every thread and Windows uses Toolhelp32 with explicit EOF/error handling.
- Added optional `--verification-report` so the final replay writes a pass report only after the complete strict ledger validates.

## WHY

The original harness could enforce only peak memory and sampled only the root process. It could undercount children, accept missing metrics, retain stale-good idle evidence after a reader run, or write a failing full ledger with a successful process exit.

## HOW

Measured startup attempts sample retained memory for a fixed three-second window after readiness without adding that window to `wall_ms`. The retained leader is sampled again after the warm-reader sequence; peak and idle maxima, liveness, actual exit status, and close success are merged into its final record. Missing/partial samples, process exit during the window, wrong metric identity, short duration, fractional process counts, or over-budget values fail closed. The strict report independently checks exit, timeout, parity, semantic, resolver, timing, peak, and idle evidence.

## IMPACT

Task 8 now has authoritative Linux and Windows memory contracts rather than root-only estimates. Full replay can be invoked in strict mode and cannot leave a stale pass report after failure.
