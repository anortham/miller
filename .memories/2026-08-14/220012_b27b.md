## WHAT

Added the strict, manifest-driven Task 8 replay ledger validator and compact verification report in `scripts/perf-recovery.py`, with complete regression coverage in `scripts/tests/test_perf_recovery.py`.

The validator now requires every fixed manifest workload, at least three distinct measured attempts, one platform, successful per-row hard gates, timing and platform-specific memory metrics, same-depth parity evidence, cross-depth semantic evidence, and exact resolver state/digest evidence.

## WHY

A JSONL replay alone could look complete while omitting workloads, duplicating attempts, lacking parity fields, missing Windows PrivateUsage/Linux PSS, or silently dropping resolver exactness. Task 8 needs a false-pass-resistant acceptance gate before performance recovery can be declared complete.

## HOW

The checked-in workload manifest is the sole source of required IDs and budgets. The report rejects caller-defined subsets, missing or mismatched platform identities, duplicate attempts, missing evidence, invalid truncation relationships, failed semantic/parity/resolver invariants, and timing or memory overages. Valid cross-depth truncation changes remain accepted when the shape and changed/match relationship are truthful.

## IMPACT

Full Linux and Windows replays can now be reconciled deterministically instead of manually eyeballing records. Independent review found and closed two false passes and one false failure before commit. The separate 350 MiB retained-idle memory contract remains the next harness slice; this validator currently enforces the existing 600 MiB peak fields.
