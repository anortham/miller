## Snapshot private-shadow correction

- **WHAT:** Replaced direct source SQLite opens with bounded private shadow inputs and expanded source stability tests.
- **WHY:** SQLite's WAL reader mutates the source shared-memory read marks even in mode=ro; chmod also changes ctime. The snapshot contract requires committed WAL preservation with no source mutation.
- **HOW:** Stream-copy the source main/WAL/SHM triplet into a tempfile, compare content plus device/inode/size/mtime/ctime/mode before opening the shadow, use SQLite backup only from the shadow, and recheck source state around the operation. Claims use the same shadow path before family copying; destination quick-check, WAL/SHM-free validation, digest, cleanup, and atomic promotion remain.
- **IMPACT:** The focused snapshot suite is green with 30 tests; direct-source mutation is removed. Native Windows execution remains unverified locally.
