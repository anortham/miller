## WHAT

Task 4B now persists bounded continuous-test activity facts. `CtRunActivityCell` carries provider source, Task 3 selection facts, monotonic elapsed seconds, and capped chunk progress into `CtDaemonRunProgress`; the queue wires provider-resolution and chunk callbacks into the cell. Activity tests cover live status progression, bounded names, and old/new JSON compatibility.

## WHY

The daemon status previously exposed only the run identity and stall state, so an operator could not tell which provider or selection was executing or which chunk was active. New status fields must remain additive and must not leak argv or unbounded case IDs.

## HOW

The cell captures the run start tick once, stores selection at `BeginRun`, accepts provider and chunk updates under its gate, caps activity names to eight samples, and clears all metadata at run end. New nullable protocol properties use `JsonIgnore(WhenWritingNull)`; the queue passes provider and progress callbacks already supplied by the coordinator contract. Focused tests were written first and failed on the missing API, then passed after implementation.

## IMPACT

Task 4 activity persistence is ready for serialization into the daemon status stream and for Task 5 rendering. The owned source, tests, and Task 4 plan checkboxes are ready for one serial worker commit.
