## Typed CT wait classifier

### WHAT
Implemented the Task 5A2A slice in `src/Miller.Server/Tools/TestsCore.cs` and added `tests/Miller.Tests/Server/TestsWaitOutcomeTests.cs`. The run result now carries an optional typed wait fact; the start result carries optional launcher publication readiness.

### WHY
The old `--wait` path returned only the requested workspace status, so queued, not-picked-up, timed-out, stopped, and lease-lost exits were indistinguishable and a standing verdict could look like completion.

### HOW
Added a narrow internal `TestsWaitProbe` seam for status reads, lease liveness, monotonic time, and bounded delay. The classifier records exactly six states, requires observed execution plus a live lease before `completed`, propagates the accepted acknowledgement command ID and observed run ID, and preserves the requested workspace status. The default timeout remains ten minutes. Optional facts are ignored when absent so no-wait payloads retain their old shape.

### IMPACT
The next CT contract/rendering task can expose honest wait state and correlation without reworking the daemon host or command channel. Deterministic tests cover all six states, the ten-minute default, correlation, and no-wait compatibility.
