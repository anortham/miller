## WHAT

Implemented generated ignore-policy Task 1 across storage, scan/update argv, store mode, watcher filtering, watcher lifecycle, focused tests, and ADR-0006.

## WHY

Ordinary newly registered workspaces received a top-level generated `.julieignore`, dirtying user checkouts. Moving only the file would have broken parity: scan, direct update, and watcher decisions must consume the same effective rules.

## HOW

- Added `EffectiveIgnorePolicy` with user-root, inherited-root-copy, and generated-global sources, content hash, path, and write outcome.
- Fresh ordinary roots atomically materialize deterministic baseline/vendor rules under `MillerHome.ResolveMillerDirectory()/ignore-policies/<workspace-id>.julieignore`; no generated root file is written.
- User root policy remains authoritative and byte-identical. Linked worktrees retain the exclusive in-tree inherited snapshot so malformed policy remains warning-only.
- Full scans detect/materialize; direct updates use a bounded resolver that never walks vendor trees or writes generated-global policy, though it may establish the required inherited snapshot.
- Scan/update order is generated policy first and invariant policy last. Watcher matching loads global patterns relative to the workspace root and attaches a policy watcher only for generated-eligible roots.
- Root/inherited races are rechecked, workspace ID must match the canonical root, and atomic publication exposes only complete snapshots.

## IMPACT

Fresh workspaces stay free of generated top-level `.julieignore` files while exclusions remain consistent across scan, update, store, and watcher paths. Task 2 can now safely delete only the validated global policy on workspace removal. The real extractor vendor/update acceptance remains intentionally pending for Task 3.
