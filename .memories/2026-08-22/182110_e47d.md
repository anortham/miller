## WHAT

Stabilized `A_routed_run_reaches_only_the_worktrees_own_store` by waiting for and capturing both a nonempty worktree status snapshot and the routed command's acknowledged `run` response. Final assertions use those captured values while retaining the main-store and primary-enqueue isolation checks.

## WHY

The original test waited until one read returned nonempty, then immediately performed a second read for `Assert.NotEmpty`. Under full-suite load that time-of-check/time-of-use pattern failed once even though the routed run had landed. The isolated test subsequently passed 30 times, confirming the failure was synchronization-sensitive rather than routing logic loss.

## HOW

The wait predicate now captures the evidence only when both the worktree status and command ack are present. Adjacent narration comments were removed per repository test-comment policy. No production code changed.

## IMPACT

The test now proves routed completion and storage isolation from one consistent observation. This unblocks an honest rerun of the exact-tree branch gate.
