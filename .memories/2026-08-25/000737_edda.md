## Windows Scale launcher-grace test correction

### WHAT

Adjusted `CtDaemonLauncherServeScaleTests.ServeLauncherExitsFirst_AndTheDaemonStillWritesToTheCtLogFile` to accept both documented successful publication readiness values: `ready` and `not_published_within_grace`.

### WHY

The launcher contract permits a successful spawn when the daemon takes the lease after the fixed two-second publication probe. The test independently waits for the live daemon, so requiring `ready` imposed an unrelated readiness SLA and failed on exact Windows suite runs.

### HOW

Kept the live-daemon lease proof, reported PID equality, stop command, and post-launcher log-growth assertion unchanged. The test now rejects every other readiness value, including `daemon_exited_before_publish`. No production grace or sleep was changed.

### IMPACT

The Scale test checks launcher exit and daemon log ownership without conflating them with publication timing. The focused test passes locally; the containing launcher class is itself tagged Scale, so there are no non-Scale launcher tests in that file to run.
