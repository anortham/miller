## QML continuous-test selection correction

### WHAT

Added regression coverage for project-scoped QML selection and conventional Qt Quick Test harness files. The selector now checks that each changed QML/CMake/runner path is inside the selected project root even when production supplies `ProjectPath`, and recognizes `tst_*` C/C++ sources plus common headers.

### WHY

The daemon queue always populated `ProjectPath`, so sibling changes could incorrectly select every QML project case. Typical `tst_foo.cpp` and header edits were not classified as QML project changes, which could leave the selection unknown without the required project run.

### HOW

Tests were written first and failed on the old behavior. The selector now preserves project identity matching, derives the selected project root, and applies path containment before adding QML project-scope evidence. C/C++/header extensions and `tst_` stems are treated as QuickTest harness changes. Added a production-shaped queue regression for sibling CMake/runner paths.

### IMPACT

Focused selector and daemon queue tests pass. This packet prevents false green/false project selection while retaining fail-closed behavior; the parent agent still needs to run the branch-wide verification and reconcile the other QML packets.
