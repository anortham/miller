## QML CTest result handling fixed

### WHAT

Added a focused provider test proving a parseable JUnit report with a failed test case is returned as a failed provider result even when CTest exits 8. Updated `QtQuickTestProvider.RunInGenerationAsync` to parse a produced JUnit artifact before treating a nonzero CTest exit as infrastructure failure.

### WHY

CTest uses exit code 8 for ordinary test failures. The provider previously threw before parsing the report, so red QML tests appeared as provider infrastructure failures and continuous testing lost the actual test result.

### HOW

Missing artifacts still fail immediately with the existing exit-context error. Parse errors and empty reports remain infrastructure failures. A nonzero exit is accepted only when the parsed report contains at least one `failed` or `errored` case; normal mapping, selected-case validation, whole-suite behavior, and argument-array process launching remain unchanged. A temporary non-Qt CTest project empirically confirmed CTest 4.3 emits exit 8 and a JUnit report containing a `<failure>` case.

### IMPACT

QML continuous testing now preserves ordinary red test outcomes while continuing to reject missing, malformed, empty, or non-failing reports from failed CTest invocations.
