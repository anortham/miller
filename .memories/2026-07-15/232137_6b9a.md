## Documented Node.js requirement for plugin installs

The Miller plugin launcher (`bin/miller-plugin-launcher.cjs`) runs under Node.js (`command: "node"` in the plugin manifests), but this requirement was undocumented. Users without Node — common with Claude Code's native installer, which doesn't need Node itself — hit an opaque MCP `-32000` error with no Miller log written, because the client can't spawn the launcher at all.

- **What:** Docs-only change across all three plugin manifests (`.claude-plugin/`, `.cursor-plugin/`, `.codex-plugin/`) plus marketplace.json — descriptions now state "Requires Node.js on PATH". README gained a callout in the plugin quickstart, a note in the plugin-distribution section, and a troubleshooting entry (symptom: `/mcp` shows `failed` with `-32000`, no log; fix: install Node LTS and fully restart the agent — in-session reconnect keeps the old PATH).
- **Why:** The `-32000` failure mode gives zero diagnostic signal; documenting it saves users a dead-end debugging session.
- **Impact:** Version stays 1.9.0 (no release-prep semantics — marketplace serves manifests from origin/main, but description-only changes are safe to push without a new release).
