## Brainstorm: content-addressed index store + views ("Ceres" candidate)

**WHAT:** Design brainstorm converged on replacing copy-per-worktree indexing with one content-addressed index store per repo family plus per-checkout views (manifests). User-driven rethink after 1.17.0 shipped; motivated by disk explosion (~19 GB of `.miller` across main checkouts, 21.9 GB dotnet/runtime artifact **per worktree**, 512 GB work SSD, 30 projects) and the square-peg feel of multi-agent/multi-worktree workflows.

**WHY:** The shipped rebind program (validated 2026-08-06) fixed worktree *time*, not *bytes* — its page-stepped copy is a full physical copy, and the in-flight FTS5 sidecar-copy work adds more copied bytes. Base+overlay was refuted (cost-model findings §5: span-folded symbol IDs), but that refutation kills naive artifact-union only — NOT content-addressed versioning, because ~85–88% of artifact bytes are a pure function of (relative path, file content); only the resolution layer (~12%) is global and must be per-view.

**HOW — decisions settled in discussion (all user-confirmed):**
- **Model:** git-object-store analogy. Store = version-keyed rows keyed by blake3 content hash; view = manifest (path → version) + per-view resolution overlay. Branch switch/new worktree = manifest repoint + delta, not rescan/copy. Dedup is across worktrees AND time.
- **Ownership is performance-driven, not law** (user explicitly retired the julie/Miller ownership rules as hard constraints). julie-extract writes the store — the tuned Rust bulk writer lives there (artifact write = 90% of cold start; savepoint/memory-journal tricks proven at 21.9 GB). Miller writes derived sidecars (FTS/vectors/content) re-keyed to the same version key.
- **Multiple files, shared version key, ATTACH for reads.** SQLite write locks are per-file → separate files give parallel writers; ATTACH joins are ~free for reads; no cross-WAL atomicity, which Miller's revision-keyed converge already tolerates.
- **Store location:** `~/.miller/stores/<family-id>` (family = git common-dir lineage; non-git = family of one). In-checkout store rejected: dies with the folder and `git clean -xdf` deletes ignored files — one command would vaporize the whole family's store.
- **Retention:** window + user-initiated pruning via dashboard (ADR-0002 POST-endpoint pattern; no new MCP tools). GC = manifest refcount + policy.
- **Naming:** "branch versioning" undersells it (content-keyed, not branch-keyed). Working name: index store + views; codename candidate **Ceres**.
- **Prerequisite:** P1a delta-scoped resolution (julie-extractors) is load-bearing for cheap per-view resolution overlays.

**IMPACT:** Reframes the 2026-08 program line: fleet-safety, lineage columns, governor, and P1a all carry forward as foundations; rebind's copy path becomes compat/fallback; copy choreography (including the in-flight sidecar-copy session's approach) retires when this ships. Design is FS-agnostic — Windows/Linux users from the multi-worktree feedback report get the same wins as APFS.
