## julie-extract v2.28.0 crossover fix shipped; audit's save-win prediction refuted; Ph1 docs corrected

**WHAT:** Shipped julie-extract v2.28.0 (commit 525679f, tag pushed, Release Binaries run 31185274991 in flight). The `DELTA_SCOPE_CROSSOVER` guard is now denominated in identifier rows, single-changed-file scopes are exempt from promotion entirely, and `corpus_current = whole_corpus` only. Corrected the Ph1 branch's evidence docs to the measured truth.

**WHY:** User approved the crossover fix ("do the julie crossover fix now, performance is very important"). But the paired A/B (probe3/probe4, committed as probes/out/results3.json + results4.json) REFUTED the audit's predicted save win: on the save shape (1 changed file, 90–93% identifier scope) Full measured equal or slower than the widened delta — promotion sheds only per-changed-file worklist overhead, and one file has none. The scan shape held: 737 changed .cs files (99.7% identifiers) measured 25,972 ms scoped vs 22,569 ms Full (−13%).

**HOW:** Shape-aware fix instead of shipping a regression: identifier denomination for multi-file deltas + single-file exemption (saves byte-identical to 2.27.0). Corrected four Ph1 docs that carried the refuted "~11 s Full path / improves shipped Miller immediately" claim: julie-path-audit results.md §2.1, binding-proof findings doc shipped-cost section, v4 contract §16.3 (marked DONE with measured correction), run report next-steps item 3.

**IMPACT:** The 16–18 s per-save cost STANDS — no crossover variant fixes it; only row-level scoping (audit §2.1 tier 3, a redesign) or the store program's background converge reaches delta-sized save cost. This validates the user's "our approach is wrong" read and sharpens the store program's motivation. Next: pin bump to 2.28.0 on miller main (local commit only, NO push) once release assets publish.
