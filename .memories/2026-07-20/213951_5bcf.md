## Initial-converge scale fix + sidecar Metal/batching fix — 27 min broken → 3.5 min clean

### WHAT
Two fixes in one day, driven by the first real shadow-converge benchmark on the Miller corpus (48,804 symbols / 9,490 eligible cards / 868 docs-config chunks, M2 Ultra):

1. **Miller** (`97f2b80`, merged to local main `d9b65e5`): `BuildShadowAsync` had promoted an EMPTY generation for any >2000-unit corpus (incremental planner's `BatchTooLarge` escalation returns empty ReEmbed; 0==0 completeness passed). Fixed with `VectorConvergePlanner.RebuildWorkList` (hash-gated, uncapped) + bounded ≤2000-unit slice commits + flagged-unit tolerance + refuse-empty-promote + chunk cursor never escalates (holds or bounded batches via `BoundedBatchHoldReason` loop) + post-promote same-wake chunk continuation (`DrainAsync` reopen hook). Gates: VectorConverge 51/51 red→green, fast 4168/0, scale 86/86, Release 0W/0E.

2. **julie-semantic-sidecar** (`bcfe965`, branch `metal-backend`, pushed): RC 0.1.0-rc.1 ran ~6 units/s vs the 52.3 P0 design floor. TWO causes: (a) CPU-only by design — `default-features = false`, `backend_select` always resolved cpu → `n_gpu_layers=0`; added `metal` cargo feature + MetalMachine identity + metal resolution. (b) **`n_seq_max` never set** — llama.cpp default 1 rejected every multi-seq group and `isolate()` silently bisected to one-context-per-text (~500 contexts/probe, flat ~46ms/text on EVERY backend). Fixed with `n_seq_max=count`, `n_ctx=longest×count`, `group_by_cell_budget`. Also ubatch 256→2048, package.sh metal leg.

### WHY
User asked for real indexing-time numbers; the benchmark exposed the empty-promote bug (zero CPU/GPU), then the fix exposed the throughput regression, then the user's "we needed MPS support" push exposed the CPU-only design.

### HOW (key evidence)
- 1,497 llama contexts in stderr for 750 texts = the bisection smoking gun; `n_ctx_seq = n_ctx / n_seq_max` partitioning is why the context must be sized longest×count.
- Probe on real binary: 6.6 → 25 (metal alone) → **78.9 units/s** (n_seq_max fix); contexts 500→4; conformance 9/9 ignored rows incl. golden vectors; 53/53 unit tests.
- End-to-end reruns: Run 2 (RC sidecar) 27 min symbols + chunk cursor DEAD (64-chunk batch > 30s timeout); Run 3 (fixed sidecar) **3.5 min total**, promote 16:10:11 "9490 embedded (0 flagged)", 864/868 chunks same-wake, zero errors.

### IMPACT
- Miller-sized repo initial semantic index: ~3.5 min (extract 20s + ~2m50s cards + ~15s chunks). Full details in `docs/findings/2026-07-20-first-real-shadow-converge-benchmark.md`.
- Local `.tools/julie-semantic-sidecar` (main checkout + Release output) = FIXED binary, same reported version as RC, different bits — pending release decision.
- Process memory saved: `validate-hardware-perf-on-real-artifact` (harness numbers ≠ engine numbers; RC gates need throughput floors).
