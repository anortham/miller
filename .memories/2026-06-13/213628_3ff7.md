## Evaluated and patched watcher extension-gate feedback

External review claimed the supported-extension watcher gate was the likely culprit because it drops extensionless files and dotfiles when active.

- **What:** Verified current code did drop extensionless paths (`Dockerfile`, `Makefile`, `.env`, trailing-dot paths) when the supported-extension gate was active.
- **Correction:** This is unlikely to explain a stale `.cs` DTO/validator because the live `julie-extract languages --json` catalog includes `cs`, and a local forced scan showed current julie-extract does not index Dockerfile/Makefile/.env as symbol files.
- **Fix:** Changed `WatchPathFilter.HasUnsupportedExtension` to drop only explicit unclaimed extensions; extensionless/dotfile/trailing-dot paths now remain fail-soft and reach julie, while `.gitignore`/`.julieignore` still stay off per-file dispatch because they go through the force-rescan path first.
- **Tests:** Added `ExtensionGate_KeepsExtensionlessPathsFailSoft` and hosted wiring coverage `GateActive_ExtensionlessFiles_RemainFailSoftAndReachExtractOps`.
- **Impact:** Restores pre-gate fail-soft behavior for extensionless paths without disabling useful filtering for explicit unsupported extensions like `.log`, `.png`, and `.lock`.
