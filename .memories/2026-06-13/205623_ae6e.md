## Fixed file watcher directory-event and pending-scan gaps

A crawl of Miller's watcher pipeline found two correctness issues in the hosted watcher/freshness path.

- **What:** Split directory-name notifications onto a dedicated `FileSystemWatcher`; directory create/delete/rename events now signal a delta scan instead of being routed as single-file operations or dropped by the extension gate.
- **Why:** `julie-extract delete --file` removes one file's rows, not a subtree. Directory moves/deletes can carry many indexed files, so they need scan reconciliation.
- **What:** Added `IndexerCore.HasPendingWork` and changed `IndexerService.QueueEmpty` to include forced-rescan signals, not just queued per-file events.
- **Why:** `SignalRescan()` previously left the per-file queue empty, so `index_fresh`/status could briefly report fresh while an overflow/ignore-policy/directory scan was pending.
- **How:** Added focused regression coverage in `IndexerServiceScanTests` for directory delete/change/rename scan scheduling, and in `IndexerCoreTests` for pending rescan visibility.
- **Impact:** Watcher-driven subtree changes and pending forced scans are now surfaced and reconciled through the same scan/sidecar/freshness path as HEAD and overflow events.
