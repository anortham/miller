## WHAT

Implemented direction-aware graph scratch construction in `src/Miller.Indexing/Reads/QueryTimeResolutionReader.cs` and added caller-facing coverage in `tests/Miller.Tests/Indexing/Reads/QueryTimeResolutionReaderTests.cs`.

- `ResolveGraphQuery` now passes its requested `Direction` into a new private overload of `ResolveQuery`.
- The existing two-argument `ResolveQuery` remains the full-read path and delegates with `Direction.Both` for inbound/outbound exact and fallback readers.
- Forward graph reads execute only within/by-source identifier and pending arms; reverse reads execute only named/by-name arms; `Both` retains all four.
- Skipped arms report `GraphResolutionMeasurement(TimeSpan.Zero, 0, 0)`.
- Added tests for forward/reverse zero measurements and either consumer order scratch reuse with literal serialized edge parity.

## WHY

Reverse impact calls were paying for unused forward reads and vice versa. The change must reduce that work without changing query-time resolution policy, details, pending overrides, relationship reads, ordering, or public graph outputs.

## HOW

Strict TDD was followed. New tests first produced RED because forward still reported named rows (4) and reverse still reported within rows (5). The smallest branch was then added inside `ResolveQuery`; no storage, cache, public interface, or `GraphReadKind` changes were introduced. Controlled mutations forcing a reverse within arm or omitting the named arm failed focused tests, then were reverted. Existing graph/evidence/export behavior was re-run through the assigned focused union.

## IMPACT

The focused reader class passes 24/24; the assigned four-class union passes 137/137; Miller.Indexing and Miller.Tests Release builds pass with zero warnings/errors. The branch is ready for lead review and Task 2's Release replay. No product performance claim is made until the separate measurement task runs the committed binary.
