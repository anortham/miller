## WHAT

Completed the measurement-only impact read-path spike docs. The fixed one-shot replay used the exact six changed paths at depth 2 and limit 200: cold 10.92s, warm 10.89/10.76/10.80/10.90/10.79s, with byte-identical output (53 impacted, 147 tests) and warm p95/max 10.90s, below the 11.30s instrumentation gate. A matching branch MCP replay emitted six correlation IDs and seven complete resolution breakdowns per call; warm tool p95/max was 8.296s.

## WHY

The task needed phase-level evidence to decide whether SQL visibility, direction-blind reads, unused details, resolver CPU, proof traversal, or a new reference sidecar owns the remaining impact latency.

## HOW

Correlated all 42 breakdown records from the shared JSONL log. Warm median phase totals were: candidate 557ms; identifier within 1,893ms; identifier named 248ms; pending within 1,710ms; pending named 250ms; identifier details 1,014ms; identifier resolution 1,351ms; pending resolution 493ms; relationships 337ms. On one URI mode=ro SQLite connection, created only the connection-local `_miller_visible_entries` TEMP table/indexes and compared current manifest visibility, TEMP visibility, and no-visibility upper bounds for Run, Path, Equal, and Assert. Current/TEMP rows matched; the live `idx_read_manifest_entries_version(version_id,view_id,generation)` exists and SQLite selects it. TEMP was 34–44% faster for isolated named reads, but named arms total only 498ms of the 7,853ms breakdown.

## IMPACT

The owned finding and docs map now reject the sidecar as the next change and recommend direction/consumer-aware reads with lazy detail hydration, preserving query-time policy and output parity. No production/test code or producer schema changed. The next implementation requires a separate approved plan and replay. The docs-only commit must include this checkpoint.
