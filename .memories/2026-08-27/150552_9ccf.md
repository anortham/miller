## Codex review response + edit-crash root cause closed

### WHAT
Two things landed in one slice:

1. **Edit-crash mystery (telemetry audit priority 1) RESOLVED without waiting for a new field occurrence.** The local `~/.miller/telemetry.db` stores `error_message`/`error_detail` (only the JSONL export omits them). All 107 edit errors are ONE cause: `FreshnessService.LoadPinnedStoreIndex` throwing "generation changed before its lazy repository was loaded" when `EditTool.Edit` forces `IndexHolder.Current` mid-swap. Already fixed in v1.24.1 (550dc679); zero occurrences on 1.24.1+ builds. TODO.md item 1 and the audit doc now record the resolution.

2. **Codex review findings addressed** (review of the 4 unpushed commits; verdict was "not ready to merge, two important perf/concurrency issues"):
   - `RevisionFactCacheStore.WarmInBackground` — store-owned, single-flight-per-scope background warm. Concurrent cold callers share one task; a faulted warm removes itself so the next call retries; a warm scope returns `Task.CompletedTask`. Replaces the per-call `Task.Run` in `FamilyStoreReadSession.WarmResolutionFactsInBackground`, which now delegates.
   - `ContextTool` ReferenceMode.Off — the warm/skip decision is gated on `termRescueCanRun = !IsNullOrWhiteSpace(query) && !HasTestOrDefIntent(query)`; a call whose promotion can never run neither probes, stamps, nor warms.
   - `EditTool` backstop comment corrected: the telemetry EXPORT is type-only; message/stack live in local-only telemetry.db columns plus the shared log.
   - `IsWarm` doc comment now states the advisory check-then-use race and why it is a bounded latency fallback (accepted, not fixed — the race costs one blocking load, the pre-A1 behavior).
   - Skipped Codex's minor #5 (extra ReadEvidence malformed-files tests) as contrived: the julie schema gate guards real artifacts and the minimal-DB fallback is already tested.

### WHY
User asked for a Codex review + a second performance eval pass before the v1.24.2 release. The review's two "important" findings were real (thread-pool pile-up risk, wasted warms); the root-cause discovery came from validating Codex's minor finding #4 about the comment wording.

### HOW
Single-flight via a `Dictionary<string, Task>` beside `_scopes` under the same `_gate`; removal in the task's `finally` needs no identity check because entries are only inserted while no entry exists for the scope. Tests: 2 new store tests (shared in-flight task + faulted-warm retry), all 255 focused tests pass, fast suite 8,939/0.

### IMPACT
Release-blocking review findings closed. Remaining before v1.24.2: user approval to push + publish. The performance eval pass was already recorded in docs/plans/2026-08-27-context-latency-diagnosis.md (no new offenders; impact git_diff tail is the freshness contract; leader-triggered warm recorded as a follow-up candidate).
