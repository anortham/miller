## Removed windows-fast from CI; Windows proof is now a pre-release gate on the win-test guest

### WHAT
Deleted the per-push `windows-fast` job from ci.yml (replaced by a comment naming the new home). Added "Windows Verification (required before every release)" as step 0 in docs/release-process.md (win-test sync + fast suite, 0 failures on the release commit, recorded in the verification finding) and the matching load-bearing rule in CLAUDE.md's Release section. AGENTS.md regenerated.

### WHY
User decision after the flake history: even fixed, hosted windows-2025 runners cost ~14 min per push and keep finding new flake modes (the 1-in-300 antivirus file-hold). The local KVM guest runs the same suite in ~9 min, deterministically, and releases are the moment Windows correctness actually gates anything.

### HOW
windows-scale-smoke (schedule/dispatch only) and the win-x64 sqlite-vec AOT spike leg stay — neither is per-push flake tax. The six real Windows bugs the job caught this week are already fixed and keep their tests.

### IMPACT
Pushes no longer wait on or fail from hosted Windows. Every release now REQUIRES the win-test guest run before package validation.
