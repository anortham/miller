## Telemetry audit: what to work on next (2026-08-27)

Analyzed all 36,130 telemetry rows (`miller telemetry export --jsonl --workspace-id all`, 2026-08-02..08-27) with duckdb.

### Finding 1 — LIVE BUG: `edit replace_text` fails ~53% of recent calls
- 102 errors in the last 7 days, ALL `edit_failure_reason=unhandled_InvalidOperationException`.
- Happens on every version 1.20.1 → 1.24.0 (current), in 4 workspaces (miller, julie-extractors, Tycho, gesso).
- Fast failures (4–24ms), both apply=true and apply=false, match_mode=auto, no query/anchor/line selectors.
- **Diagnosability gap:** the EditTool catch backstop (src/Miller.Server/Tools/EditTool.cs:166) records only the exception TYPE in telemetry (privacy rule: never the message) and logs NOTHING — the shared log shows only "tool edit completed with error". The message went to the calling agent once and is lost.
- No explicit `throw new InvalidOperationException` in EditService — it is BCL-thrown (LINQ First/Single, Nullable.Value; candidates at EditService.cs:2002-2004 `reference.StartByte!.Value`).
- Fix path: (a) log the full exception + stack to the shared workspace log in the edit backstop (local logs already carry stacks for indexer exceptions — no new privacy exposure), (b) then catch the next occurrence and fix the root cause.

### Finding 2 — `context` tool is slow everywhere: p50 ~7s, p95 ~20–37s
- Telemetry metadata shows the cause: 1,300–2,000 `read_lookup_count` per call.
- Backend comparison (last 7 days): `search_sidecar` lookup_p50 3.5s; `lagging_sidecar` 24s; `session_projection` **54ms** for the same work.
- The fast `session_projection` path exists but served only 8 of ~270 calls. Direction: batch the lookups or route them through the session projection.

### Finding 3 — a file deleted mid-scan fails the whole store delta
- Tycho 8/26: 3× `StoreWorkspaceOperationException: source file could not be read: No such file or directory (os error 2)` at StoreWorkspaceCoordinator.RequireCommitted (line 846), each triggering scan-failure backoff during watcher-overflow churn.
- Direction: treat a vanished file as a delete instead of failing the delta (fix may belong in julie-extract).

### Lesser signals
- `search file` 52% empty, `search source` 32% empty last 7 days — possible handoff/recall gap, or normal agent probing.
- `content import` 16% error, all `missing_file` — agents pass bad paths; minor.
- The 1,250+ `search symbol` internal failures were 1.18–1.19.x era (8/14–16 spike); current versions are clean. Already fixed.

### Impact
Priority order for next work: (1) edit-tool exception logging + bug fix, (2) context lookup latency, (3) mid-scan file-deletion robustness.
