## Fixed two trace route-diagnostic attribution defects (provenance-scoped rows)

Adversarial review confirmed two diagnostic-attribution lies in `trace mode=bridge` route diagnostics, both reproduced through `TraceTool.Run`:

- **F-A (wrong-noun shadowing):** client-request observation nodes and navigation route-reference nodes share `BridgeNodeKind.TsType`; `TryBuildRouteDiagnostic` pooled one `frontendPresent` set, and the first provider row (nextjs before nextjs-api) won. A normal Next.js repo (a `/dashboard` page + GET handler + attested-POST fetch to `/api/messages`) emitted `nextjs_route_no_file_match` "route reference exists" for a fetch that is not a navigation reference, shadowing the honest `nextjs-api_route_no_bridge_link`.
- **F-B (foreign-endpoint claim):** API rows used pooled `backendRoutes` (ALL Endpoint nodes including dotnet-web's ASP.NET endpoints), so a monorepo with a Next handler at `/api/health` claimed "Next.js client request and route handler facts exist for /api/orders" when only ASP.NET serves `/api/orders`.

### Fix: real observation-node provenance (no file-path guessing)

- `BridgeGraphBuilder.Build` accumulates `nodeId -> sorted provider ids` while merging `BridgeProviderResult.ObservationNodes` (a shared node, e.g. one client request observed by dotnet-web + nextjs-api + nuxt-api, carries all of them).
- `BridgeGraph.Build` gains an additive optional `observationProviders` param; read accessors `ObservationProviders(id)` + `HasObservationProvenance`. Provenance is diagnostics-only — edges/scoring/walk untouched.
- `TraceTool.TryBuildFileRouteDiagnostic` scopes each provider row's reference/definition sets to that provider's provenance, collects claims from ALL participating rows (row order never decides), then: a single definition-matching claim wins; a single reference-only claim wins only when NO pooled definition fact matches the target (otherwise another frame owns the definition — fall back to the pooled generic diagnostics); zero/conflicting claims fall back to generics. Graphs without provenance (hand-built test node maps) keep pooled per-row inputs, so all shipped diagnostics tests stay green unchanged.
