## Task 4 shipped: nextjs-api / nuxt-api client→handler bridge providers

**WHAT:** Two new descriptor-driven verb-aware bridge providers that resolve `http.client_request.v1` fetch/axios call sites to server route-handler facts, emitting `BridgeKind.Hits` edges:
- `nextjs-api`: `http.client_request.v1` → `nextjs.route_handler.v1`
- `nuxt-api`: `http.client_request.v1` → `nuxt.server_route.v1`

**WHY:** Miller-side consumption of julie-extractors 2.6.0 HTTP boundary facts (plan `docs/plans/2026-07-01-http-boundary-bridge-consumption.md`, Task 4) — `trace mode=bridge` can now follow `fetch("/api/users/42")` to the exported Next.js `GET` handler symbol or a Nuxt server route file.

**HOW:**
- `FileRouteBridge.ResolveClientRequests` (new verb-aware arm in `src/Miller.Core/Resolver/FileRouteBridge.cs`) beside the verb-blind navigation `Resolve`; `BestMatch`/`CompareSpecificity` generalized to route-string selectors so both arms share segment specificity — navigation behavior byte-identical.
- Verb-honesty rules: handler verb known+equal → `RouteVerbMatch` (High); known+different → no edge; handler verb NULL (suffix-less Nuxt = answers every method) → `RouteOnlyMatch` (Medium + `verb_unknown` flag) — the accepted verb set is not source-attested, never assumed GET.
- Exact-specificity ties → `ambiguousMatches` count, no edge. Verb filtering happens at candidate selection (before specificity), so a GET+POST handler pair on one Next route resolves cleanly instead of tying ambiguous.
- Edge target binds `containing_symbol_id` (Next.js exported handler) when present, else a synthesized `Endpoint` node (`"VERB /route"` dotnet-web shape; route-only display for verb-less handlers via `FileRouteBridge.HandlerDisplay`).
- `ApiRouteBridgeProvider` + `ApiRouteBridgeDescriptor` + `NextJsApiBridgeProvider`/`NuxtApiBridgeProvider` accessors in `src/Miller.Core/Graph/FileRouteBridgeProvider.cs`; registered in BOTH `BridgeGraphBuilder.DefaultProviders` and `BridgeProviderSelection.DefaultProviders` + `CreateProvider` (order: dotnet-web, nextjs, nextjs-api, nuxt, nuxt-api, vue, react — matches the Task 7 doc list). `miller.json` `bridge.providers` selects them.
- Evidence keys: `nextjs-api.clientRequests|routeHandlers|candidates|ambiguousMatches`, `nuxt-api.clientRequests|serverRoutes|candidates|ambiguousMatches`; skip reason `no <id> bridge evidence` when both sides empty.
