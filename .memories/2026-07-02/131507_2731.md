## Incident: v1.3.2 marketplace 404 — release prep pushed without publishing the release

A Miller user reported the marketplace update to v1.3.2 failed: version bumped but no zip to download, forcing rollback to v1.3.1.

- **Root cause:** Commit `07232c0` ("release: prepare Miller 1.3.2") was pushed to `origin/main` on 2026-07-01 17:29 CDT, bumping all plugin manifests (including `.claude-plugin/marketplace.json`) to 1.3.2 — but no `v1.3.2` tag was pushed and no `workflow_dispatch publish:true` ran, so the GitHub release (and its 8 assets) never existed. The launcher's download URL `releases/download/v1.3.2/…` 404'd.
- **Why it happened:** Marketplaces serve manifests from `origin/main` HEAD while binaries come from GitHub releases — pushing the prep commit alone desyncs the two. The 2026-07-01 session pushed the prep commit, then moved on to HTTP boundary work without publishing.
- **Fix:** Pushed tag `v1.3.2` at `07232c0` on 2026-07-02; tag-triggered release run 28592841424 builds exactly the prepared state (julie-extract 2.5.10 pin) independent of the 12 newer local commits (2.6.0-era HTTP boundary work).
- **Prevention:** Added a load-bearing CLAUDE.md Release-packaging bullet: a pushed release-prep commit IS a live marketplace release — publish the tag/release in the same session and verify assets. AGENTS.md regenerated in sync.
- **Impact:** Marketplace installs/updates of 1.3.2 recover once the run publishes; newer HTTP-boundary work ships later as 1.3.3/1.4.0.
