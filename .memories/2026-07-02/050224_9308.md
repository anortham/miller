## Fixed four confirmed HTTP-boundary bridge defects (adversarial review follow-up)

Adversarial review of the 2026-07-01 HTTP-boundary bridge consumption work confirmed four core defects by execution; all four fixed TDD (every repro was a failing test first, verified against pre-fix HEAD in a throwaway worktree: 9 failing → all green post-fix).

- **F4 (HIGH) — legacy url-literal leg bypassed verb discrimination.** `DotnetWebBridgeProvider.BuildCandidates` concatenated legacy url-literal client calls with structural `http.client_request.v1` calls; live extracts emit BOTH for the same fetch call site, so the verb-unknown literal fabricated a false Medium `[verb-unknown]` RouteOnlyMatch edge to a different-verb endpoint (different target ⇒ different edge signature ⇒ graph dedupe can't help). **Fix:** new `DedupeClientCalls` (mirrors `DedupeEndpoints` placement/style) suppresses a literal covered by a structural request at the same site — same canonical route + same containing symbol id, falling back to file path + canonical route when either side is symbol-less. Uncovered literals (ky/got/$fetch wrappers) survive; suppression is per-site, never global.
- **F1 — carrier round-trip degraded non-whitelist attested verbs.** `ToClientCall(request)` synthesized carrier `fetch.purge`; `VerbFromCarrier`'s whitelist can't carry PURGE ⇒ verb-unknown ⇒ false Medium edge. **Fix:** `TsClientCall` gains optional `AttestedVerb` (default null, legacy call sites untouched); `RouteBridge.NormalizeClientCall` prefers it over the carrier-derived verb. Carrier kept for display; `VerbFromCarrier` whitelist NOT widened (library-name tails stay verb-unknown).
- **F2 — verb-exact match dropped as ambiguous on verb-null route tie.** Nuxt `notes.get.ts` (GET) + suffix-less `notes.ts` (verb null) tie on specificity ⇒ `BestMatch` returned null ⇒ legit High edge silently dropped. **Fix:** `FileRouteBridge.ResolveClientRequests` partitions matches; when verb-exact candidates exist, specificity runs over those only (verb-null handlers are fallbacks). Verb-null-only sets keep prior behavior.
- **F3 — divergent symbol-less source node ids across providers.** `FileRouteBridge.BuildClientRequestEdge` used raw `/api/x` as the symbol-less source display while dotnet-web's `RouteBridge` route node uses canonical `api/x` ⇒ two node ids for one module-scope fetch ⇒ `trace` found 2 starts and bailed. **Fix:** symbol-less source display now uses `CanonicalClientRoute` (canonical, no leading slash — byte-identical to RouteBridge's route-node form). Core-only fix; no TraceTool changes.
