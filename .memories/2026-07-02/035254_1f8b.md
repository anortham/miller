## Task 5 (HTTP boundary bridge consumption): TraceTool trace surface wired for nextjs-api / nuxt-api / dotnet-web boundary evidence

**WHAT** — `src/Miller.Server/Tools/TraceTool.cs` + `tests/Miller.Tests/Tools/TraceToolTests.cs`:

- **Route diagnostics:** `FileRouteDiagnosticProviders` extended with `("nextjs-api", "Next.js", "route handler")` and `("nuxt-api", "Nuxt", "server route")` rows. The record grew beyond the plan's 3-field hint (allowed by its "sibling-table equivalent" clause) because code reality differs: API providers' definition observation nodes are `Endpoint` kind (not `FileRoute`), and both API providers share the `http.client_request.v1` reference family. New fields: `ReferenceNoun` ("client request" vs "route reference"), `DefinitionNodeKind`, `DefinitionEvidenceName` (`routeHandlers`/`serverRoutes`), `EdgeNoun` ("route edge" vs "navigation edge").
- **Participation rule (key decision):** an API provider joins route diagnostics only when its *definition-side* evidence is non-zero. Client requests alone can't attribute a repo to Next.js vs Nuxt (both providers activate on the shared fact family, and dotnet-web repos also carry client requests) — handler facts can. Without this gate a dotnet-web repo with fetch() calls would get a bogus "Next.js … no matching route handler" diagnostic instead of the honest generic `route_no_backend_match`.
- **Gate extension:** `TryBuildRouteDiagnostic` now also enters the framework loop when a participating API provider has Endpoint routes (`nuxt-api_route_no_reference_match` for handler-only cases).
- **Evidence keys:** `HasRouteFactEvidence` + `BridgeFallbackNextActions` gained `dotnet-web.clientRequests|attributeRoutes`, `nextjs-api.clientRequests|routeHandlers`, `nuxt-api.clientRequests|serverRoutes`; new pattern audits suggest `pattern_id=http.client_request.v1` and `pattern_id=aspnet.attribute_route.v1`; nextjs/nuxt query audits extended with the handler keys.
- **Prose:** class doc header provider list + stale MCP `[Description]` ("currently dotnet-web") now name dotnet-web, nextjs, nextjs-api, nuxt, nuxt-api, vue, react.
