## Authored backend HTTP boundary consumption plan (v2.7.0 companion)

**WHAT:** `docs/plans/2026-07-02-backend-http-boundary-consumption.md` — 8-task light plan consuming julie-extractors v2.7.0's 16 backend route/mount fact families + 5-language `http.client_request.v1` extension.

**WHY:** Companion to upstream's shipped backend-http-boundary lane, per the v2.7.0 release-notes "Miller Handoff": client `target_path` joins `normalized_route_template` across all server families; four mount/include facts are cross-file prefix-join inputs; `rails.resource_route.v1` needs Miller-side Rails expansion.

**HOW — key decided shapes (from live code orientation):**
- ONE generic `backend-http` provider (new `BackendHttpBridgeProvider`), generic over the 10 route-template families, reusing `FileRouteBridge.ResolveClientRequests` by having `TryReadBackendRoute` return the existing `StructuralRouteHandler` record. Join precedence `effective_route_template` ?? `normalized_route_template`; `RouteNormalizer.Canonicalize` already folds `:param` → `{}`.
- Cross-file mount composition with deterministic anchors only: django `included_module` → file-path anchor; express/fastapi/flask → unambiguous mount_target identifier resolution; ambiguity poisons (no compose). Only facts WITHOUT effective_route_template compose.
- Rails expansion: deterministic RESTful set (only/except/scope_path honored, singular variant), verb-known High; `controller_action`/conventional `<Name>Controller#action` symbol binding, unambiguous-or-nothing.
- `RouteBridge.IsRealClientCall` csharp exclusion narrowed: structural-fact csharp client requests become real client calls (service-to-service C#→ASP.NET); legacy csharp url literals stay excluded.
- Task 7 is a language-parity hard gate: live fixtures across all 10 languages + a 16-family per-pattern emission assertion.

**IMPACT:** Ready for user review/approval, then subagent-driven execution. Pin bump to 2.7.0 already landed (2c5fcb5, fast 2634 / scale 38 green).
