## Closed: CT watcher-overflow storm traced to Tycho's npm build hooks

### WHAT
The Windows watcher-overflow storm after every CT run is fixed. Tycho's `Tycho.Api.csproj` and `Tycho.Client.csproj` ran `npm ci` + `npm run build` via MSBuild Exec hooks inside every CT generation build (test projects reference them), rewriting node_modules — measured 41,493 workspace file events per build. Both csprojs now default their skip switches to true when `MILLER_CT_WORKSPACE_ROOT` is present (Tycho commits 5dba115 + user's Razor fix 0753197, pushed to Tycho master). Verified on the buildable tree: 0 errors, 0 workspace events under the gate.

### HOW
CT's provider processes (builds included) carry `MILLER_CT_WORKSPACE_ROOT`; MSBuild reads env vars as properties, so a one-line property condition gates the hook. No Miller code change — the pattern is documented in `docs/continuous-testing.md` (Miller commit 4b275937), since ASP.NET+SPA hook repos will all hit this.

### IMPACT
Windows machine needs only `git pull` in C:\source\Tycho; the next CT run builds with the gate and the overflow storm ends. Miller's overflow handling itself was already correct (self-healing debounced reconciles, all DidWork=false).
