## Fixed: Run stale tests button reported failure while the daemon ran the tests

### WHAT
`DashboardTestsActions` now passes `--json` for the run action and `TranslateRunOutcome` rewrites the two known submit shapes: a daemon submit reads "run submitted to the test daemon — results appear here as they land" instead of the standing "verdict=unknown"; an unacked submit (`reason: "not acknowledged"`, exit 3 — the daemon holds the request but its loop was busy in a drain past the 5s ack window) reads as likely-busy with normal styling instead of a red error. Real refusals keep the error notice with the reason; non-JSON output passes through.

### WHY
Windows field report: user clicked Run stale tests, the panel reported failure, yet the daemon log showed the submit acknowledged (`ct enqueue selected=0/6/0/82` across the four projects) and the runs completing (`ct run complete status=failed/passed`). The button worked; its feedback lied — `tests run` without `--wait` returns the pre-run verdict, and a busy daemon trips the ack timeout.

### IMPACT
Verified: 4 new tests in DashboardTestsActionEndpointTests, fast suite 8772/0, Release build 0/0. Also confirmed the watcher-overflow bursts in the user's log are not CT dotnet builds (those use `--artifacts-path` away from the workspace) — likely vitest cache/coverage writes; the indexer's reconciles were all `DidWork=false`. Fix is committed to main, not yet released; rides the next release.
