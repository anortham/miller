## Dashboard version-aware lifecycle + CT UX slice (uncommitted, on main)

### WHAT
Five changes landed in one working-tree slice:
1. **Version-aware dashboard lifecycle** (Opus workflow, 6 agents, reviewed + fixed): `dashboard.json` now records `miller_version` and the process's own start time; `/healthz` body is `miller-dashboard ok <version>` (prefix-matched by the launcher); `EnsureRunning` reuses same-build, stops-and-replaces older/unversioned dashboards (identity-checked kill under `dashboard.lock`, re-read under the lock), reuses-with-mismatch for newer/unorderable; new `miller dashboard --stop [--json]`. New `DashboardVersionDecision` wraps `CtDaemonVersion.Evaluate` (missing recorded version = older, unlike the daemon).
2. **CT first-verdict nudges**: `tests serve started|replaced` compact output and `tests enable` compact output now end with `next:` lines pointing at `tests operation=run` (owed backlog = first verdict). JSON untouched.
3. **Dashboard tests-panel actions**: new POST `/workspaces/{id}/tests/{enable|start|run}` (X-Miller-Dashboard CSRF header), backed by `DashboardTestsActions` which runs the public `miller tests <verb>` CLI as a subprocess (in-process daemon spawn would resolve Miller.Dashboard.exe as the executable — wrong binary). Panel shows Enable (never-decided only), Start (enabled + daemon stopped), Run (daemon running) buttons and an outcome notice rendered in every panel state.
4. **Panel hover fix**: removed `transform: translate(-2px,-2px)` from `.panel:hover` (sections "danced"); kept the shadow. Row `translateX(4px)` kept.
5. **MillerVersionTests** now asserts version SHAPE (`^\d+\.\d+\.\d+`) instead of a hardcoded literal that broke on every release bump.

### WHY
Field report from Windows plugin-update testing: a 1.22.1 dashboard and 1.22.1 ct-daemon survived the 1.23.0 upgrade; the old dashboard would be reused forever (no version anywhere in metadata or healthz) and pins its plugin-cache dir against pruning. Separately, `enable CT` confused the user: the daemon is status-only at start by design, and nothing said "run for a first verdict".

### HOW
Mirrored the CT-daemon pattern (`CtDaemonVersion`, lease identity = pid + process start time). Dashboard actions deliberately go through the CLI contract subprocess, not in-process cores.
