## Bound prompt semantics into run identity

Before launching the next calibration, the evaluator still allowed a changed prompt contract to share a run identity with earlier exports.

- **What:** Added a deterministic `prompt_contract_sha256` derived from the exact static prompt prefix, generated typed-action guidance, and a task-prompt placeholder.
- **Why:** Task manifests bind individual task text and schemas bind output shape, but neither bound the behavioral instructions that explain typed action targets.
- **How:** `_prompt` and `prompt_contract_sha256` share `_prompt_prefix`, preventing the executed prompt and identity hash from drifting independently.
- **Gate:** `preflight_run` includes the hash before computing `run_identity_sha256`; completed-export reuse therefore invalidates automatically when prompt semantics change.
- **TDD:** Added a preflight identity assertion, observed the missing API failure, then implemented the shared hash path.
