## Fixed Codex structured-output schema incompatibility

The visible Miller-versus-Julie calibration could not produce product evidence because the model API rejected the answer schema before agent execution.

- **Root cause:** Codex structured outputs reject `oneOf`, `dependentRequired`, incomplete object `required` sets, untyped `const` branches, and regex lookaround in `pattern`.
- **Fix:** Reworked the model-facing schema into the accepted strict subset, requiring every object property and representing optional fields with nullable unions.
- **Compatibility:** Added normalization so legacy and sparse internal answer fixtures still parse into the strict model-facing shape.
- **Safety:** Moved repository-relative path and canonical symbol identity checks into Python semantic validation after removing unsupported regex patterns; paired reference-site columns must both be present or both null.
- **Evidence:** The focused path regression passes, all 32 answer-contract tests pass, all 95 Python benchmark/controller tests pass, and a real `codex exec --output-schema` smoke returns the required answer JSON successfully.
- **Interpretation:** The abandoned run remains a harness void and must not be counted as Julie or Miller quality evidence.
