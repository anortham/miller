## WHAT

Completed Phase 1 of the Miller-to-Julie takeover: introduced `ReferenceEvidence`, `ReferenceKind`, and `ReferenceEvidenceReader`; made materialized and on-demand graphs exact-first; recorded ADR-0004 and the Phase 1 evidence report.

## WHY

Legacy name-based reference projection attributed homonyms to the wrong definition, duplicated extractor sources, and made CLI/server graph results diverge. Agents need exact, bounded evidence to reduce calls, tokens, and unsafe actions.

## HOW

- Union direct identifier targets, resolution overlays, relationships, and resolved pending relationships by target symbol ID.
- Normalize source kinds and deduplicate stable sites with deterministic source precedence.
- Separate fallback rows, return them only for a unique definition, cap confidence, and expose ambiguity/truncation coverage.
- Preserve distinct line-only sites by caller and normalized start column.
- Make both graph implementations prefer exact targets and filter endpoints absent from the artifact.
- Remove inert fanout caps and stale claims that `target_symbol_id` is always null.
- Run two fresh Claude reviews plus a narrow closure pass; accept and fix every concrete finding.

## IMPACT

Phase 3 tool migrations now have one trustworthy reference seam instead of five divergent policies. CLI and server graph traversal agree on homonyms, pending resolutions, missing targets, and fallback. The live coverage matrix makes extractor gaps explicit; all-supported-language promotion remains a Phase 8 gate rather than an implied Phase 1 success.
