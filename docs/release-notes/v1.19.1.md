# Miller v1.19.1 Release Notes

- **Audience:** All users, especially Windows users of the family store.
- **Release shape:** Store-coordination latency and reliability patch release. The MCP surface remains nine tools.
- **Pinned extractor:** `julie-extract 2.33.2`, raised from `2.33.1`.
- **Pinned semantic sidecar:** `julie-semantic-sidecar 0.1.0`, unchanged.
- **Publication:** Stable coordinated Miller release.

## What changed

### A full import no longer submits a redundant resolve

When a full store import reports both `resolution=exact` and `exact_at_matches`, Miller now trusts that completed
resolution fence and skips the follow-up `store resolve`. Imports whose resolution is not exact, or whose fence does
not match the current manifest, still submit resolve. This removes the multi-minute whole-store resolve that could
follow an otherwise successful single-file update.

### Freshness reports the actual resolution fence

Workspace freshness now checks the resolution base, delta generation, and `exact_at` fence against the current
manifest. A state string of `exact` by itself no longer makes a view look current while its resolution layer is still
converging. An intentionally disabled search sidecar remains valid because Miller then uses its in-memory backend.

### Adopt julie-extract 2.33.2

The pinned producer release carries the related reliability and performance fixes:

- whole-operation retries for transient read-only SQLite locking-protocol failures;
- lease timestamps sampled after lock acquisition, plus bounded heartbeat renewal and fencing-token handling;
- preservation of scoped resolution for a one-file change with broad identifier collisions; and
- Windows root-relative path normalization.

The producer adoption evidence and live archive hashes are recorded in
[`docs/findings/2026-08-14-julie-extract-2.33.2-adoption.md`](../findings/2026-08-14-julie-extract-2.33.2-adoption.md).

## Upgrade notes

- Re-run `scripts/restore-julie-extract.ps1` on Windows or `scripts/restore-julie-extract.sh` on Unix after updating
  a source checkout. The build guard rejects a missing or stale 2.33.2 binary.
- Miller's schema and extract-contract gates are unchanged; the restored 2.33.2 binary must pass the release
  preflight before packaging.
- Existing workspaces may report resolution or sidecar convergence while the leader catches up. Run
  `miller workspace refresh` if status names a stale derived sidecar.
