# Miller v1.21.2 Release Notes

- **Audience:** All users, especially teams running continuous testing on large repositories or Windows.
- **Release shape:** Patch release. Continuous testing remains opt-in and off by default; existing MCP, CLI, and index contracts remain compatible.
- **Pinned extractor:** `julie-extract 2.35.0`, unchanged.
- **Pinned semantic sidecar:** `julie-semantic-sidecar 0.1.0`, unchanged.
- **Pinned sqlite-vec:** `0.1.9`, unchanged.

## What changed

### Whole-suite CT output stays bounded

The xUnit whole-suite provider path no longer emits an unbounded JSON event
stream into Miller's captured stdout. It uses bounded verbose progress together
with the existing JUnit artifact, so large suites do not overflow the capture
limit or make result import depend on a giant in-memory JSON document. Smaller
selected and chunked runs retain their bounded JSON path.

### CT idle work follows revisions

Continuous testing now publishes aggregate status from revision changes instead
of materializing every CT state on every 250 ms tick. Unchanged ticks avoid
reopening the compatibility projection; revision cursors, moving-cursor retry,
truncation, and identity mismatch handling keep publication fresh without
repeating full-state work.

Selection is project-filtered, terminal retry keys are evicted, disabled
lifecycle rows stay out of status, and completion uses bounded statement shapes
with a covering history index. Run, result, and artifact history now has a
transactional retention policy, and build-cache generations have enforcing TTL
and workspace/machine caps.

### General performance hot spots are closed

Provider generations no longer duplicate runtime trees. Context and Impact reuse
batched graph detail and indexed lazy slices while preserving output hashes.
Schema migration occurs before reads, adopted-family routing stays read-only,
and cache cleanup reports protected state and remaining debt instead of doing
unbounded work.

### Windows correctness and fixture performance

CT cache-debt paths use portable separators, janitor fixtures use zero-byte
control markers, and Windows-only symlink assumptions are isolated from the
cross-platform behavior. Structural-fact, bounded-fact, and failure-page
fixtures batch their SQLite setup; the deliberate snapshot lock probe fails
immediately instead of waiting for SQLite's default timeout.

Subprocess, allocation, broker, and daemon checks are classified in the Scale
suite, while pure contract tests remain in the fast suite. This keeps the fast
boundary honest without removing coverage.

## Upgrade notes

- No producer pin changed. Existing installations do not need a re-extract or
  forced rescan for this patch.
- Source checkouts should continue to restore the pinned `julie-extract 2.35.0`
  binary when the build guard requires it.
- Rebuild and restart a resident Miller server or CT daemon to load the new
  binary. `MILLER_SEMANTIC=off` remains a permanent zero-work guarantee, and
  lexical-only output remains byte-identical.

## Verification

- Linux and Windows Release builds passed with zero warnings and zero errors.
- Linux fast and Scale suites passed with no failures. Windows fast and Scale
  suites also passed locally through the NTFS VM using `win-test`; this note
  makes no claim about a post-fix GitHub Windows run.
- Plugin validation passed, and the secret and vulnerable-dependency scans
  found no issues.
