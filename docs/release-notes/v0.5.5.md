# Miller v0.5.5 Release Notes

- **Audience:** Agents and users running Miller in workspaces that also contain local agent state, logs, or Miller sidecar files.
- **Release shape:** Patch release for safer generated `.julieignore` defaults that prevent Miller from indexing its own sidecar directory.
- **Pinned extractor:** `julie-extract 2.5.1`.

## What Is New

- **Generated `.julieignore` files now exclude `.miller/`.** Miller's baseline ignore patterns include the workspace sidecar directory alongside `*.log`, so newly seeded workspaces do not feed Miller's own DBs, logs, and coordination files back into extraction.
- **Idle agent workspaces churn less.** This blocks a self-update loop where `.miller/logs/*.jsonl`, leader files, or derived sidecars could appear as source changes and trigger repeated refresh work even when no agent query was active.
- **Existing custom ignores are still respected.** Miller does not overwrite or append to a user-owned `.julieignore`; the new baseline applies when Miller creates the ignore file for an unmanaged workspace.
- **SQLite dependency vulnerability is cleared.** Miller now builds against `Microsoft.Data.Sqlite 10.0.9` with an explicit `SQLitePCLRaw.bundle_e_sqlite3 3.0.3` override, resolving the vulnerable `SQLitePCLRaw.lib.e_sqlite3 2.1.11` restore failure reported by NuGet audit.
- **GitHub Actions now use Node 24-based action releases.** CI, Pages, and release workflows were moved to current action majors (`checkout`, `setup-dotnet`, artifact actions, and Pages actions) so package validation is not relying on deprecated Node 20 action runtimes.
