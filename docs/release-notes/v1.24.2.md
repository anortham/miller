# Miller v1.24.2 Release Notes

- **Audience:** Every `context` user — the tool's two largest latency costs are
  removed, so cold and post-save calls answer in a fraction of the time. Store-mode
  users on churning repos gain the julie-extract 2.37.2 vanished-file delta fix.
- **Release shape:** Patch release. Performance fixes on the `context` read path, a
  pinned-extractor bump, and an edit-tool diagnosability backstop. No contract
  changes; telemetry metadata gains one additive stamp
  (`term_rescue: skipped_cold_facts`).
- **Pinned extractor:** `julie-extract 2.37.2` (was 2.37.1).
- **Pinned semantic sidecar:** `julie-semantic-sidecar 0.1.0`, unchanged.
- **Pinned sqlite-vec:** `0.1.9`, unchanged.

## What changed

### `context` no longer blocks on the cold fact-cache load

Term-rescue promotion — a ranking refinement that runs on every query-driven
`context` call — used to force the whole-generation reference fact-cache load on
the first reference-touching call of a server process (~5 s on a 1,785-file
repo). When the shared cache is cold, the call now skips the refinement, stamps
`term_rescue: skipped_cold_facts` in telemetry, and starts the load in the
background so the next call promotes warm. The background warm is single-flight
per workspace: concurrent cold calls share one load task, a failed load clears
itself for retry, and a call whose promotion cannot run (blank query, test/spec
intent) neither probes nor warms. Measured: anchor_resolution 4,813 ms → 6 ms on
the cold call; the second call promoted warm at 404 ms.

### `context` no longer scans the symbols table per save

The Blazor component graph reader selected every class/import symbol with
metadata from the session's symbols view — a full scan of the family store's
908k-row symbols table on every revision advance, spending 1,192 ms to find ~70
razor rows. The query is now bounded to razor files through the
version-id-leading index. Measured: supplemental edge reload 1,192 → 135 ms;
post-save graph_reach 1,285 → 223 ms; post-save `context` call 3.1 → 2.0 s; cold
first call 7.6 → 4.8 s. Full diagnosis and numbers:
`docs/plans/2026-08-27-context-latency-diagnosis.md`.

### julie-extract 2.37.2: a file deleted mid-scan no longer fails the delta

A source file that vanished between discovery and read (build churn, branch
switches) failed the whole store delta with `RequireCommitted` os error 2 —
observed three times in one field day. The pinned extractor now commits vanished
files as deletions; only genuine NotFound qualifies. Decision record in the
julie-extractors repo: `docs/decisions/2026-08-27-vanished-file-delta-semantics.md`.

### The edit backstop logs the real exception

An exception that escapes the edit pipeline now lands in the shared workspace
log at WRN with its full stack, next to the tool's other lines. The telemetry
export keeps its type-only privacy rule. The 2026-08-27 telemetry audit also
closed the standing edit-crash question: all 107 field errors were one already-
fixed cause (the v1.24.1 lazy-load generation retry), with zero occurrences on
any 1.24.1+ build.

## Upgrade notes

- No sidecar schema changes, no index artifact changes, no JSON contract changes.
- The extractor upgrade to 2.37.2 triggers the standard version-aware rescan on
  the leader's first claim; readers keep serving during it.
- Lexical-only output remains byte-identical; the cold-call promotion skip is a
  ranking refinement visible only in telemetry metadata.
