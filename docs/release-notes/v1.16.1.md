# Miller v1.16.1 Release Notes

- **Audience:** Everyone running v1.16.0. This is a correctness patch for progressive index levels, which
  shipped default-on in v1.16.0 without the diagnostics that tell you when you are reading a converging index.
- **Release shape:** Patch release. The MCP surface remains nine tools. No Miller artifact schema change and no
  semantic wire protocol change; the one output-contract change is an additive field on `references export`.
- **Pinned extractor:** `julie-extract 2.25.0`, unchanged from v1.16.0.
- **Pinned semantic sidecar:** `julie-semantic-sidecar 0.1.0`, unchanged from v1.16.0.

## Why this release exists

v1.16.0 made progressive levels the default: a fresh `workspace open` builds a symbols-level core first (fast
first query) and upgrades to the full index in the background. At symbols level the `identifiers`,
`identifier_resolutions`, `source_regions`, and `structural_facts` tables are **empty by design**.

v1.16.0 did not consistently say so. A read against a converging index could return an empty result that was
indistinguishable from a real, complete answer — a silent wrong answer rather than a visible gap. v1.16.1 closes
that across every affected surface.

## What Changed

### Reads against a converging index now say so

- `inspect` at `overview`/`full` depth and `context` now attach a `reference_layer_converging` diagnostic when
  the artifact they read evidence from is at symbols level, instead of rendering empty refs/callers/callees
  sections that read as "nothing references this symbol". `summary` depth is complete at symbols level and is
  unchanged.
- `search` region modes and `patterns` report the converging facts/regions layer across both MCP and CLI rather
  than returning an empty result set.
- `markers` reports the converging layer instead of "no markers found".
- `rename` refuses while the identifier layer is unextracted: an unproven rename is worse than a delayed one,
  because it would rewrite definitions and miss every usage site.

### Reports, health, and feeds stop recording absence as data

- `report` and metric history omit facts-derived rows at symbols level instead of recording `marker_total=0`,
  which otherwise entered trend history as a real measurement.
- `workspace health` reports its `StructuralFacts` section as unavailable at symbols level rather than as
  healthy zeros.
- `references export` keeps emitting its relationship-derived rows at symbols level — the degradation is
  **partial, not empty** — and now signals that both out-of-band (a diagnostic) and in-band: every row carries a
  new `index_level` field. See [`docs/contracts/references-export-v2.md`](../contracts/references-export-v2.md).

### A read context carries the level of the artifact it actually reads

Every workspace read context now carries the index level of the artifact its evidence comes from, so a
cross-workspace read served by a lean projection and a read taken across a full-rebuild promotion both guard on
the right generation. This is what makes the guards above correct during a repair rebuild, which extracts at
symbols level over a previously-full workspace.

### CLI diagnostics match the MCP tool

`miller inspect` on a path that is not in the index reported a bare `No indexed symbols in <path>`, which read
as "this file exists and is empty". It now answers `file_not_indexed` with a recovery action, exactly as the MCP
tool does. The CLI applies the same precedence rule: a tool diagnostic wins at every depth, and the
converging-level notice fills in only where there is none.

### Input mistakes classify correctly

Validation errors classify as `invalid_request` refusals instead of `internal_failure`, so a typo no longer
lands in telemetry as a Miller crash.

## Measured effect of progressive levels

Recorded in
[`docs/findings/2026-08-04-index-levels-indexing-benchmark.md`](../findings/2026-08-04-index-levels-indexing-benchmark.md):
on a 1,389-file / 121,044-symbol corpus, 5 repetitions per mode with alternating order,
`MILLER_SEMANTIC=off`:

| Mode | Wall median | Spread |
|---|---|---|
| symbols | 9,696 ms | 3.2% |
| full | 27,383 ms | 1.6% |

**2.82× faster time-to-first-usable-index.** This is not less total work — progressive still builds the full
index afterward in the background. Symbol count is identical in both modes: symbols level costs no definitions,
no search recall, and no relationship edges.

## Upgrade Notes

- Plugin manifests advertise version `1.16.1`.
- No manual `symbols.db` migration is required, and no rescan is needed. The guards read the level already
  recorded in existing artifacts.
- `MILLER_INDEX_LEVELS=full` remains the permanent zero-behavior-change escape hatch: every build runs at full
  level and no guard in this release can fire.
- The one output change at full level is the additive `index_level` field on `references export` rows. Every
  other surface in this release is byte-identical at full level.
