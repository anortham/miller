# Miller v1.24.1 Release Notes

- **Audience:** Continuous-testing users first — every finding from the 2026-08-26
  evening round-2 Tycho dogfood session is addressed, so CT converges to an honest
  green on repos whose own build hooks churn the source tree, with zero
  project-side settings. `edit` and `impact` users gain resilience and a staged-diff
  hint.
- **Release shape:** Patch release. CT behavior fixes, additive JSON contract fields
  on `tests` (`daemon.auto_runs_paused`, `daemon.pause_reason`), a ct.db sidecar
  schema bump (v6, automatic migration), and a flatter CT build layout. No breaking
  JSON changes; compact output gains lines.
- **Pinned extractor:** `julie-extract 2.37.1`, unchanged.
- **Pinned semantic sidecar:** `julie-semantic-sidecar 0.1.0`, unchanged.
- **Pinned sqlite-vec:** `0.1.9`, unchanged.

## What changed

### A red case can no longer retire without being executed

A run that selected a red case but whose provider output silently omitted it (a
filter term that matched nothing) used to retire that red to `stale` at run
commit — the dogfood session watched 3 standing reds vanish unexecuted. Run start
now captures the displaced state (`pre_run_state`, ct.db schema v6, migrated
automatically) and keeps a red row's committed key; requested-but-unreported
cases restore red with one owed rerun stamp, and a nonzero unreported count logs
one bounded `role:ct` line naming the run and count.

### CT converges under hostile build hooks

Two fixes close the self-sustaining stall observed when a repo's own build hooks
(`npm ci`, client asset builds) churn thousands of files per CT run:

- **A truncated impact read now resolves to Unknown instead of stalling.** It
  used to answer "unavailable": no staleness landed, the poll cursor stayed
  pinned, the interval grew every poll, and auto-runs paused into a permanent
  stall. The complete delta is now delivered and the selector fails it closed to
  Unknown — everything stale, nothing executes, and the cursor legally advances.
- **An idle daemon drains the owed backlog once the workspace settles.** When
  staleness exists, the queue is empty, no run is executing, the last poll was
  healthy with the cursor at the live index revision, auto-runs are not paused,
  the workspace has been quiet for a debounce window, and no drain ran in the
  last 5 minutes (fixed cooldown, also counted from daemon start), the daemon
  schedules one drain of the stale set — selected exactly as an explicit run
  selects it and executed as an explicit test-ID list, never as a whole-suite
  run. Byte-identical rebuilds re-stale nothing (julie-extract no-ops unchanged
  content; the store delta reader's content-hash gate is now pinned by test).

### `edit` survives background index promotions

Three consecutive `edit apply=true` calls used to fail with
`internal_failure: The family-store generation changed before its lazy repository
was loaded` while a CT build promoted index generations. The lazy index load now
retries onto the current generation (bounded), a failed load is no longer cached
until the next swap, and the residual failure classifies as
`unavailable`/`index_reloading` with a plain "retry the call" message.

### `tests failures` shows the real error

The persisted `failure_summary` now carries the first line plus the first
error-shaped line of the underlying output, bounded to 400 UTF-8 bytes — an NUnit
`OneTimeSetUp` failure now names its actual cause (for example a StaticWebAssets
asset error) instead of only "dotnet failed." TRX capture is widened from
StackTrace and sibling messages, and run-level `RunInfo` errors fold into each
failed case.

### The auto-run pause is visible

`tests status` now reports `daemon.auto_runs_paused` and `daemon.pause_reason`
in JSON, prints `auto-runs paused: <reason>` in compact output while paused, and
the daily log records each pause enter and clear. `daemon.paused` keeps its
lifecycle meaning, now documented.

### `impact` names `staged=true` when it would help

An empty unstaged diff now probes the staged diff once; when staged changes
exist, the empty-diff diagnostic says so and emits a JSON-visible retry action
(`staged=true` on the MCP path, `--staged` in the CLI note). Nothing-staged
output is byte-identical.

### CT build path flattened to five levels

The per-project CT build root moves from `.miller/ct/build/<proj12>` to
`.miller/ct-<proj12>`, so the deepest test-assembly directory sits exactly five
levels below the workspace root — repo-root walk-up helpers capped at eight
ascents clear it with margin even after losing one ascent to a trailing path
separator. The Windows MAX_PATH budget is recomputed (workspace-root budget 117
→ 123 characters), and coordinator maintenance reclaims the legacy
`.miller/ct/build` tree under the janitor's lease rules, so upgrades do not
strand old generations.

## Upgrade notes

- ct.db migrates to schema v6 automatically on first open. Older Miller builds
  refuse a v6 ct.db (designed advance-only protection); `tests disable` +
  re-enable is never needed.
- The first maintenance pass after upgrade sweeps the legacy CT build tree; a
  root held by a live lease is left alone.
- No index (`symbols.db`), search, content, or semantic artifact changes.
