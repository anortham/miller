# Miller v1.4.2 Release Notes

- **Audience:** Agents and local dashboards using Miller on larger workspaces, plus Eros consumers of
  content-corpus and telemetry export contracts.
- **Release shape:** Patch release focused on SQLite read/write performance hardening and JSONL export memory
  behavior. No extractor pin change.
- **Pinned extractor:** `julie-extract 2.8.1`.

## What Changed

### SQLite performance hardening

- **Search sidecar incremental refresh:** `.miller/search.db` schema version `7` adds path indexes for
  `search_symbols` and `search_regions`, so single-file refresh deletes and FTS cleanup no longer scan the
  whole sidecar metadata table.
- **Content corpus reads:** `.miller/content.db` schema version `2` adds source-line and containing-symbol
  indexes for bounded reads, source removal, and reference-aware context chunk lookup. Existing content sidecars
  rebuild through the normal schema-mismatch path.
- **Reference-aware context:** containing-symbol chunk lookup now uses separate indexed symbol-id and symbol-name
  fallback queries instead of one `OR` predicate that forced SQLite onto the broad `content_kind` index.
- **Dashboard telemetry:** recent activity, recent errors, latest tool status, and p95 latency queries now use
  composite indexes and scoped SQL shapes instead of `$all OR workspace_id` predicates. The superseded
  single-column telemetry indexes are dropped on open to reduce write amplification.

### JSONL export memory behavior

- CLI bulk exports for symbols, references, complexity metrics, structural facts, and telemetry now stream
  directly to the provided `TextWriter` instead of building one full JSONL string before writing.
- Public JSONL output shapes are unchanged except for the content-corpus `schema_version` value moving to `2`
  with the sidecar schema.

## Upgrade Notes

- Plugin manifests now advertise version `1.4.2`.
- No `julie-extract` restore is required if a checkout already has the `2.8.1` pin restored.
- Existing `.miller/search.db` files older than schema `7` and `.miller/content.db` files older than schema `2`
  rebuild through normal Miller freshness checks.
- Existing `~/.miller/telemetry.db` files drop the superseded single-column telemetry indexes on the next
  `TelemetryLedger.Open`; telemetry rows are preserved.
