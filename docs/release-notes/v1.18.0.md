# Miller v1.18.0 Release Notes

- **Audience:** Users evaluating the versioned family store for large repositories and restart-safe
  incremental indexing under controlled garbage-collection conditions.
- **Release shape:** Minor feature release. The MCP surface remains nine tools. The versioned family store
  is default-on; `MILLER_INDEX_STORE=off` selects the legacy standalone compatibility path.
- **Pinned extractor:** `julie-extract 2.31.2`, up from 2.31.0. The 2.31.x line carries the canonical
  migrated resolution-base identity required by Miller's restart path; 2.31.2 adds the published physical
  maintenance, capacity-preflight, rollback, parity, and resolution-adapter fixes used by this release.
- **Pinned semantic sidecar:** `julie-semantic-sidecar 0.1.0`, unchanged.

## Why this release exists

Miller historically consumed one mutable standalone extractor artifact. v1.18.0 adds the Ph3 consumer for
Julie's versioned family store: immutable file versions, coherent view manifests, durable queued writes,
exact resolution bases and deltas, and restart-safe generation changes.

The new path is default-on when `MILLER_INDEX_STORE` is unset or blank. Set `MILLER_INDEX_STORE=off` to use
the legacy standalone compatibility path, which exports the current view before rollback.

## What Changed

### View-scoped family-store reads

Miller opens one validated family, view, generation, and manifest snapshot for each read. Search, inspect,
context, references, trace, impact, patterns, metrics, dashboard queries, and sidecar convergence all consume
that same visible view rather than mixing retained versions or a newer current generation into one response.

### Durable migration and orchestration

The indexer can import an exact standalone artifact into a family store, bind the canonical resolution base,
and resume through Julie's public coordinator after process interruption. Requests remain durable across
timeouts and dead holders; Miller never writes producer-owned store tables directly.

Import and resolve requests use a producer request timeout that may raise Miller's four-hour default process hard
cap, while update/delete requests retain the five-minute default. `MILLER_STORE_REQUEST_TIMEOUT` applies only to
import/resolve and accepts either seconds or a `TimeSpan`; it cannot shorten Miller's process cap. From-artifact
waits use bounded recursive samples of producer spool, scratch, and resolution-base activity with deterministic
capped summaries, so nested activity is visible without a wall-clock progress signal.

Rollback export remains available through the public producer contract. Root, family, view, manifest-generation,
and store-log identity are validated before mutation; prepared/ready recovery markers and staged-artifact digests
prevent duplicate or stale exports, while an observed producer failure clears its marker for a clean retry. A
started or view-advanced marker never promotes a staged file and fails closed into source reconciliation. Pending
markers from pre-v4.6 builds lack the required view identity and are also source-rebuild-only; they cannot promote
a structurally valid but unrelated legacy artifact.

Store freshness polling uses a cheap store-log probe and caches exact resolution-base validation by file identity;
full compatibility projections are still built for actual read sessions. Imports from an existing artifact use the producer's `--from-artifact` contract, which rejects scan-only
supervision flags; Miller therefore uses coordinator, generation-database, and process-output activity for stall
detection on that path while retaining the generous absolute process backstop. Ordinary store scans additionally
count heartbeat activity. Store leadership also fails closed when a store pointer exists but its serving store
cannot be read; it never substitutes a legacy artifact version in that state.

Workspace onboarding resolves hot targets through the pinned read session in both MCP and CLI paths. Native store
workspaces do not require `symbols.db`, and a store-open failure renders unresolved target rows rather than mixing
legacy targets into store facts. Unknown sidecar stamp kinds are treated as stale metadata so the read surface
reports a rebuildable sidecar failure instead of crashing.

Leadership version checks and semantic vector path resolution use the same bounded metadata-only family-store probe;
they validate the serving generation without rebuilding the temporary compatibility projection or hashing every
manifest level stamp.

Store-sidecar failures are isolated from the producer scan result. A lease timeout or content/search sidecar error is
logged for retry, while history and vector freshness stamps still publish from the completed store view. If Miller
restarts with an orphaned import journal entry, it replays that request once and then submits a fresh import so source
changes made after the earlier terminal request are not hidden by idempotency-key replay.

Bootstrap rollback cleanup revalidates malformed pointers under the writer lock and retries if another process installs
a valid store pointer during source reconciliation. Store freshness rebuilds publish the complete identity from the
rebuilt family-store session, and interrupted artifact migrations never replay `--from-artifact` against an already
populated view.

The final rollback repair also covers well-formed interrupted export markers: store-off bootstrap revalidates the
rollback state under the writer lease, reconciles the legacy artifact from source, and removes the pointer plus
pending markers before binding. A valid pointer whose store cannot be opened remains preserved and not-ready under
the rollback contract. Resumed terminal `store resolve` requests now submit a fresh request after completing the
old journal entry, matching the import replay safety rule.

The follow-up recovery pass also keeps a valid pointer with a published generation but no `CURRENT` pointer
not-ready instead of replanning a stale import. Cross-workspace source reconciliation removes the pointer and
both rollback markers under the workspace writer lease before reporting the legacy artifact usable.

The final recovery pass validates the producer's extraction-identity epoch before exposing parser and capability
health views, applies the no-CURRENT guard to member-less family recovery, and adopts an existing catalog view
when it already names the workspace root. From-artifact imports no longer sample an unused legacy scan heartbeat,
and a cleanup failure leaves the registry in an error state instead of advertising a ready refresh.

### Sidecars follow store identity

Search, content, and semantic sidecars key freshness to the visible store generation, manifest hash, and
store-log sequence. A generation change with an unchanged legacy artifact timestamp still invalidates the
derived sidecars correctly. Reader transactions stay bounded and no database is attached across store or
sidecar boundaries.

### Store provenance is visible

`workspace status`, `workspace health`, and the dashboard now report family, view, generation, manifest,
store-log sequence, completed extraction level, exact-resolution state, migration state, rollback state, and
typed store failures. Dashboard health renders the exact sidecar facts captured by the same store read session.

## Upgrade Notes

- Plugin manifests advertise version `1.18.0`.
- Existing standalone workspaces migrate into the family store on default-on bootstrap.
- Set `MILLER_INDEX_STORE=off` to use the legacy standalone compatibility and rollback path.
- Source checkouts must rerun `scripts/restore-julie-extract.sh`. The build guard rejects a stale bundled
  extractor, and release archives include the matching 2.31.2 binary.
- The MCP tool count and public command vocabulary are unchanged.
- A7 durable reader pins/lock-order proof and A8 cursor-incremental store-sidecar convergence remain explicit
  Ph4/Ph5 follow-up work. Family-shared vector storage is likewise deferred; Ph3 ships per-view vector sidecars.
- A8 currently rewrites full store search/content sidecars under the family lease. Concurrent workspaces may leave
  a sidecar stale until convergence succeeds; Miller reports that state and never falls back to a legacy artifact.
  Cursor-incremental convergence and its local reproducible cost gate remain Ph5 work.
- Until A7 closes, do not run producer family-store GC concurrently with live Miller store readers: reader
  sessions do not yet publish durable coordinator pins, so a reclaimed non-current generation can make an
  active read fail. The explicit standalone compatibility path is unaffected.
