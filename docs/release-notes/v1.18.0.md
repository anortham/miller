# Miller v1.18.0 Release Notes

- **Audience:** Users evaluating the versioned family store for large repositories and restart-safe
  incremental indexing under controlled garbage-collection conditions.
- **Release shape:** Minor feature release. The MCP surface remains nine tools. The existing standalone
  `symbols.db` path remains the default; family-store mode is explicit and off by default.
- **Pinned extractor:** `julie-extract 2.31.2`, up from 2.31.0. The 2.31.x line carries the canonical
  migrated resolution-base identity required by Miller's restart path; 2.31.2 adds the published physical
  maintenance, capacity-preflight, rollback, parity, and resolution-adapter fixes used by this release.
- **Pinned semantic sidecar:** `julie-semantic-sidecar 0.1.0`, unchanged.

## Why this release exists

Miller historically consumed one mutable standalone extractor artifact. v1.18.0 adds the Ph3 consumer for
Julie's versioned family store: immutable file versions, coherent view manifests, durable queued writes,
exact resolution bases and deltas, and restart-safe generation changes.

The new path is deliberately opt-in. Set `MILLER_INDEX_STORE=1` to use it; leave the variable unset to retain
the existing standalone artifact behavior byte-for-byte. Default-on adoption remains a later scale decision.

## What Changed

### View-scoped family-store reads

Miller opens one validated family, view, generation, and manifest snapshot for each read. Search, inspect,
context, references, trace, impact, patterns, metrics, dashboard queries, and sidecar convergence all consume
that same visible view rather than mixing retained versions or a newer current generation into one response.

### Durable migration and orchestration

The indexer can import an exact standalone artifact into a family store, bind the canonical resolution base,
and resume through Julie's public coordinator after process interruption. Requests remain durable across
timeouts and dead holders; Miller never writes producer-owned store tables directly.

Import and resolve requests now use one effective timeout for the producer request and Miller's four-hour default
process hard cap. `MILLER_STORE_REQUEST_TIMEOUT` accepts either seconds or a `TimeSpan` for an explicit local
override; short update/delete requests retain the five-minute default. From-artifact waits use bounded shallow
samples of producer spool, scratch, and resolution-base activity, treating a capped sample as unknown activity
until the hard cap rather than recursively walking large trees on every poll.

Rollback export remains available through the public producer contract. Root, family, and view identity are
validated before mutation; prepared/ready recovery markers and staged-artifact digests prevent duplicate exports,
and an unreconcilable marker fails closed into source reconciliation. Incompatible store/schema/writer floors fail
with typed status instead of falling back to stale standalone data.

Imports from an existing artifact use the producer's `--from-artifact` contract, which rejects scan-only
supervision flags; Miller therefore uses coordinator, generation-database, and process-output activity for stall
detection on that path while retaining the generous absolute process backstop. Ordinary store scans additionally
count heartbeat activity. Store leadership also fails closed when a store pointer exists but its serving store
cannot be read; it never substitutes a legacy artifact version in that state.

### Sidecars follow store identity

Search, content, and semantic sidecars key freshness to the visible store generation, manifest hash, and
store-log sequence. A generation change with an unchanged legacy artifact timestamp still invalidates the
derived sidecars correctly. Reader transactions stay bounded and no database is attached across store or
sidecar boundaries.

### Store provenance is visible

`workspace status`, `workspace health`, and the dashboard now report family, view, generation, manifest,
store-log sequence, completed extraction level, exact-resolution state, migration state, rollback state, and
typed store failures. Dashboard health renders the exact sidecar facts captured by the same store read session.

## Upgrade Notes

- Plugin manifests advertise version `1.18.0`.
- Existing workspaces require no migration while store mode is off.
- To opt in, set `MILLER_INDEX_STORE=1`; unset it to return to the standalone path.
- Source checkouts must rerun `scripts/restore-julie-extract.sh`. The build guard rejects a stale bundled
  extractor, and release archives include the matching 2.31.2 binary.
- The MCP tool count and public command vocabulary are unchanged.
- A7 durable reader pins/lock-order proof and A8 cursor-incremental store-sidecar convergence remain explicit
  Ph4/Ph5 gates; store mode remains opt-in until those gates close. Family-shared vector storage is likewise
  deferred; Ph3 ships per-view vector sidecars.
- Until A7 closes, do not run producer family-store GC concurrently with live Miller store readers: reader
  sessions do not yet publish durable coordinator pins, so a reclaimed non-current generation can make an
  active read fail. The default remains store-off.
