# Miller v1.29.0 release notes

- Audience: agents using Miller through plugins, MCP, or the CLI.
- Release shape: agent workflow improvements, truthful search and freshness reporting, and shared-store recovery.
  No new MCP tools.
- Extractor pin: `julie-extract 2.42.0`.
- Semantic sidecar: `0.1.0`, unchanged.
- sqlite-vec: `0.1.9`, unchanged.

## What changed

### Agent guidance and workspace setup

- `workspace onboarding` gives repository-specific guidance from local telemetry without starting continuous
  testing or changing workspace state.
- Plugin session hooks, tool descriptions, next-step hints, and Miller skills use the same workspace ID,
  freshness, text-search, and continuous-testing rules.
- Search guidance now distinguishes ranked token-normalized discovery from exact literal audits. Empty results
  route to the appropriate symbol, source, content, pattern, or imported-text workflow.

### Navigation, context, and editing

- `inspect` member pagination stays within MCP output limits and can enumerate long Unicode signatures without
  missing or duplicating rows.
- Trace and impact results carry clearer path, confidence, truncation, and test-role evidence.
- Reference-aware `context` uses one shared implementation across CLI and MCP, with bounded evidence and
  explicit partial-result reporting.
- Edit preview, batch application, and rename checks cover stale hashes, homonyms, exclusions, overlapping
  changes, rollback, and spanless-reference refusal.
- Shared read projections now use generation-aware cache keys, coordinated eviction, a 512 MiB structural
  retention budget, and idle disposal.

### Continuous testing

- Selection stops once truncated or unavailable impact establishes an unknown result. Reverse-only fact reads
  avoid work that cannot change that conservative outcome.
- Explicit, automatic, and idle selections share one supervised worker. Status reports real selection phases,
  the daemon remains responsive to commands, and waits follow the submitted command instead of unrelated work.
- An MCP `tests run wait=true` call against a stopped daemon now returns `daemon_stopped` within its wait budget
  without reading facts, discovering projects, running tests, or starting CT.
- Discovery failures retain bounded command, output, and environment artifacts. State-based next steps and
  provider-owned direct-run recipes cover .NET, JavaScript, Python, Go, Rust, Ruby, PHP, JVM, Godot, and QML.

### Search and content truthfulness

- Content search preserves the FTS candidate-window saturation signal. `more_may_exist` remains true when
  post-filtering returns fewer rows than the requested limit but the candidate window was saturated.
- Tool and skill wording no longer describes ranked token-normalized results as exhaustive exact-text proof.
- Large imported content reads reconstruct bounded Unicode text without loss across continuation pages.

### Freshness and shared-store readers

- Explicit workspace reads for the process's own bound root use the resident leader scan and freshness poll,
  avoiding self-contention on the writer lock.
- Reader processes now send nonce-bound incremental reconcile requests to the live leader. A result counts as
  fresh only when the request nonce and independently read generation/revision witness match.
- Blocking calls always request a new reconciliation. Default background calls retain timed-out work for later
  pickup, then settle to `unchanged` or `refreshed` after the leader completes it.
- Queued, not-leader, failed, corrupt, expired, and mismatched completions remain unconfirmed. Reader processes
  can refresh directly after a leader exits.
- Deferred background work captures immutable host paths instead of a disposed dependency-injection scope.

### Extractor and SQLite

- The bundled `julie-extract 2.42.0` keeps artifact schema 7, extract contract 4, JSONL schema 5, report schema
  3, family-store schema 2, format epoch 1, and extraction identity epoch 10.
- The extractor carries the 2.41 line's parser facts: return-type usages across 25 native-applicable language
  probes, ASP.NET route facts for C#/Razor, htmx/component expression metadata across six applicable fixture
  languages, and Java single-segment namespace facts.
- Deep-chunk store imports may overlap extraction with writes. The additive `prefetched_files` progress field
  does not advance Miller's freshness cursor.
- Miller now bundles SQLitePCLRaw with SQLite 3.53.4, including the upstream multi-process WAL-reset corruption
  fix. The extractor's independently bundled SQLite remains separate.

## Upgrade notes

- Restart every resident Miller MCP server, dashboard, and CT process after upgrading.
- Reader and leader processes must both run v1.29.0 before they can use incremental reconcile receipts. A new
  reader cannot make an older live leader service the new operation, and Miller does not kill or force a
  handoff from user processes.
- The extractor upgrade can trigger an automatic rescan. Existing family stores retain their prior reader floor;
  newly created 2.42.0 families require reader capability 2.42.0.
- A default explicit-workspace read may briefly report queued or unconfirmed while background reconciliation is
  active. Repeated reads settle after the completed cycle; use `ensure_fresh=true` when the current call must
  wait for source reconciliation.
- `MILLER_SEMANTIC=off` remains the permanent zero-work switch for semantic retrieval.
