# Miller v1.26.0 Release Notes

- **Audience:** every MCP client, especially user-level GUI installs that launch Miller without a
  project working directory.
- **Release shape:** Feature release with a **breaking MCP contract change** (explicit workspace
  targeting). No MCP tools were added.
- **Pinned extractor:** `julie-extract 2.38.1` (was 2.37.2).
- **Pinned semantic sidecar:** `julie-semantic-sidecar 0.1.0`, unchanged.
- **Pinned sqlite-vec:** `0.1.9`, unchanged.

## What changed

### Breaking: MCP calls target workspaces explicitly

Workspace-bound MCP tool calls now require a registered `workspace_id` (display ID, prefix, full ID,
or root path). The `current` and `primary` selectors are refused at the MCP boundary; they remain
CLI-only. Discover workspaces with `workspace list`; register a missing project with
`workspace open path=/absolute/project`, then pass the returned ID on every workspace-bound call.
`workspace list/open/remove/prune/dashboard` stay unscoped.

This makes Miller work as a user-level GUI install: a server can now start, serve, and answer every
tool call with no primary workspace ever bound. The plugin skills and `docs/agent-guidance.md` teach
the new targeting.

### Fixes from the pre-release review

- Tool calls no longer throw when no primary workspace is bound — the exact GUI case this release
  serves.
- `workspace remove` can no longer delete the machine-global `~/.miller` directory (registry,
  telemetry, and logs), guarded by a regression test proven against the pre-fix code.
- Current-workspace telemetry summaries read the correct workspace instead of an empty ledger.
- MCP edits keep complete-recall symbol reads instead of the recall-limited search sidecar.
- The MCP target policy accepts `path=` as an explicit target, matching the tool schema.
- Cross-volume paths on Windows can no longer pass registered-workspace file containment.

### Behavior decisions

- The dashboard opened with no primary workspace now lands on the registry list view instead of a
  detail page for an unregistered synthetic workspace.
- `workspace refresh`/`full` with an explicit `workspace_id` that names the bound primary keep the
  in-process fast path instead of queueing a leader request.

### julie-extract 2.38.1

- **F# is the 40th extraction language** (`.fs`, `.fsx`, `.fsi`) at the full capability tier,
  including xUnit test detection and the `fsharp.attribute.v1` structural fact.
- Go literal `t.Run` subtests become their own test-case symbols, parented to the enclosing test.
- Rustdoc executable code blocks are recorded as `rust.doc_test.v1` structural facts.
- C# `internal` declarations report visibility `internal` instead of `private`.
- 2.38.1 fixes a family-store defect: stores created by julie-extract 2.37.1 through 2.38.0
  recorded the wrong extraction identity epoch, which made Miller's parser-inventory and
  language-capability projections read empty. A store heals on its next import that carries a
  capability snapshot.

## Upgrade notes

- **Agents and clients that call workspace-bound MCP tools must pass `workspace_id`.** Calls that
  relied on the implicit current workspace, or passed `current`/`primary` over MCP, are refused with
  guidance. The CLI is unchanged.
- Restart resident Miller and dashboard processes to load the new binary.
- The extractor upgrade forces one full rescan per workspace on the new leader's first claim
  (version-aware leadership). C# visibility values and the new F#, Go subtest, and Rust doc-test
  rows appear after that re-extract.

## Verification

The release verification finding will record the review fixes, Linux build/fast/Scale results
against the 2.38.1 binary, the local `win-test` fast-suite result on the release commit, exact-run
package promotion, checksum validation, and published-asset smoke.
