# Miller v1.19.0 Release Notes

- **Audience:** All users, and Windows users in particular.
- **Release shape:** Index-convergence and Windows-correctness release. The MCP surface remains nine tools.
- **Pinned extractor:** `julie-extract 2.33.0`, raised from `2.32.1`.
- **Pinned semantic sidecar:** `julie-semantic-sidecar 0.1.0`, unchanged.
- **Publication:** Stable coordinated Miller release.

Minor, not patch: this adds the `MILLER_HOME` override, which is observable behavior.

## What changed

### A store import no longer looks like a failure and gets re-submitted

`StoreWorkspaceCoordinator` decided success from the extractor's exit code. A request the coordinator had
already recorded as `Committed` could still carry a nonzero exit code, so Miller treated committed work as
failed, re-armed the latch, and submitted the same whole-repo import again. The result was duplicate imports
of an unchanged tree and a store that never settled.

Success is now decided by the request state first: `Committed` and `Acknowledged` are success whatever the exit
code says. A `Failed` state, a nonzero exit that did not commit, and a non-terminal `Queued` or `Claimed`
result all remain hard failures, so the retry throttle still counts them and no second retry timer was added.

### The revision cursor stopped counting work that had not happened yet

Miller's store-log cursor counted non-terminal import chunk events, so the revision it reported ran ahead of
the work actually committed. Two files carried byte-identical cursor SQL, and both had to agree or sidecar
convergence broke.

There is now one definition, `Miller.Indexing.Reads.StoreLogCursor`, which both readers consume, so they can no
longer drift. It excludes chunk event kinds while keeping the `*_l1_published` events, which are legitimately
non-terminal and would be lost by a bare `terminal = 1` filter.

**Expected on first run, and it is not silent.** For a store that holds such events, the corrected cursor
reports a LOWER sequence than the previous build did. A search, content, or vector sidecar stamped by that
build then reads as ahead-of-expected. `SymbolSearchSidecar.OpenRequired`/`OpenStoreRequired` reject a
revision mismatch by design rather than falling back, so **symbol search returns an error naming the stale
sidecar and telling you to run `miller workspace refresh`** until the leader reconverges it. `workspace status`
shows the sidecars `stale` or `unavailable` over the same window. A store with no such events is unaffected.
This is a one-time effect of the correction, not a regression.

### A converging store resolution is no longer a contract failure

`JulieStoreClient.ParseResolutionState` knew `unbound` and `exact` but not `converging`, which
`julie-extract` reports for a resolution base that is mid-flight. Any read that observed that state threw a
contract failure instead of reporting progress. `converging` now maps to `StoreResolutionState.Converging`.

### `MILLER_HOME` overrides Miller's user directory

New `Miller.Indexing.MillerHome` resolves `MILLER_HOME`, falling back to the user profile. It is honored
together by workspace context, the scan governor registration, deferred log-directory setup, and the dashboard
paths, so a process cannot split its home across the registry, telemetry, scan, semantic, and store locations.

Three lookups deliberately do **not** follow it: the sensitive-root safety guard, which must keep resolving the
real profile because making the forbidden set steerable would be a security regression; plugin-install-root
probing; and the shared `~/.cache` model directory, which is shared by design under ADR-0003.

`HOME` and `USERPROFILE` are not the switch, and a test asserts that.

**Windows caveat.** `MILLER_HOME` does not isolate the semantic broker on Windows. The broker rendezvous is a
machine-global named pipe whose name carries only the model identity, so two homes still share one broker
there while getting two on Unix. The fix is a change to a frozen contract and did not ship here; see
[`docs/findings/2026-08-13-windows-broker-pipe-scope.md`](../findings/2026-08-13-windows-broker-pipe-scope.md).

### Freshness swaps are cheaper

A freshness swap re-ran a streaming distinct-path scan costing 92-97 ms. That scan is now memoized on the
manifest hash and the symbol-bearing file count, so an unchanged manifest reuses it. The file count is part of
the key because a progressive level upgrade inside one manifest can add symbol-bearing paths.

### The bootstrap wait says what it is waiting for

A blocked first-run bootstrap logged nothing. It now logs one line naming what is awaited on the first failed
acquire, and one on completion with the outcome, elapsed milliseconds, and poll count.

### The watcher no longer sends the workspace root to the extractor

A `FileSystemWatcher` rename whose old-name record fell into a previous buffer read arrives with a null old
name, and the handler then stats only the new path — which resolves back to the workspace root. That root
reached `julie-extract` as a per-file op and came back `invalid_file_path` against Miller's own workspace.
`WatchPathFilter` now rejects a root-relative empty path or `.` before any other rule.

Separately, file-converge requests arriving from another Miller process had never passed through the watcher
filter at all, so a request naming the root, a build-output path, or an ignored file became an extract op the
watcher itself would have dropped. That path now runs the same filter and logs how many requests it dropped.
Directory-change handling deliberately keeps its conservative rescan: an empty-name event there means
information was lost.

### Benchmark JSON is out of the index

The in-tree `.julieignore` excludes benchmark and evaluation result JSON. **Tradeoff, stated plainly:** the
content corpus enumerates the same file set, so `search mode=content` over benchmark results stops working.
This removes roughly half the symbol count and most `structural_facts`, but only about 29% of stored text — it
will not halve `store.db` or the cold bootstrap time.

## Upgrade notes

- The pinned extractor moves to `julie-extract 2.33.0`. Re-run restore after upgrading a source checkout.
  Artifact contracts are unchanged and verified: schema 6, SQLite schema 6, extract contract 4, report schema
  3, `blake3`.
- Sidecars reconverge once on first run. Symbol search reports an explicit stale-sidecar error until they do.
- Default semantic retrieval remains enabled; `MILLER_SEMANTIC=off` remains the permanent opt-out.
- The family-store schema, semantic model identity, MCP tool count, and public commands are unchanged.

## Verification

The fast suite passes on Windows: 6,483 passed, 0 failed, 25 skipped. The `julie-extract 2.33.0` pin was
verified by scanning a scratch repository
with the restored binary and reading `artifact_metadata` directly, rather than by trusting the upstream release
notes: schema 6, SQLite schema 6, extract contract 4, report schema 3, `blake3`, `binary_version 2.33.0`.

Three semantic-broker tests skip on a machine that already runs a Miller plugin. Their probes would attach to
the live machine-global pipe as non-owners, so no broker starts under the test's own home. The finding above
records why that is a skip and not a fix.

Upstream, `julie-extract 2.33.0` carries three Windows repairs found while preparing this release: process
liveness was never known on Windows, `store import` never retried a blocked drain, and a failed resolve leaked
its scratch database. See the
[julie-extract v2.33.0 release notes](https://github.com/anortham/julie-extractors/releases/tag/v2.33.0).
