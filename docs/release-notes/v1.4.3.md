# Miller v1.4.3 Release Notes

- **Audience:** Eros continuous-testing consumers and anyone using `miller impact --from-index-revision`.
- **Release shape:** Patch release. Exposes `artifact_id` on workspace refresh JSON so Eros can pass
  `--from-artifact-id` on index-revision delta calls. Includes a test-stability fix for workspace provider
  cache races.
- **Pinned extractor:** `julie-extract 2.8.1` (unchanged).

## What Changed

### Refresh JSON exposes `artifact_id`

- `workspace refresh --json`, `refresh --json`, and the Eros-facing refresh action payload now include
  `artifact_id` when the workspace artifact is known.
- `miller impact --from-index-revision` requires a matching `from_artifact_id`; Eros CT revision-delta
  polling depends on this field (see Eros `docs/findings/2026-07-04-revision-delta-acceptance.md` F1).

### Test stability

- `CrossWorkspaceRefreshServiceTests` and related workspace provider cache coverage hardened against
  races observed under parallel test runs.

## Upgrade Notes

- Plugin manifests now advertise version `1.4.3`.
- No `julie-extract` restore change if a checkout already has the `2.8.1` pin restored.
- Eros should bump its Miller floor to `>=1.4.3` when packaging CT revision-delta builds.

## Verification

- Pre-release local verification:
  - `scripts/test.sh`
  - `git diff --check`
- Release build smoke:
  - `miller refresh --workspace <root> --json` includes non-null `artifact_id` when indexed
  - `miller impact --json --from-index-revision <N> --from-artifact-id <id>` returns `delta_status`
