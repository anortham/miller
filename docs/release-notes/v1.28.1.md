# Miller v1.28.1 release notes

- Audience: agents using Miller through plugins, MCP, or the CLI.
- Release shape: patch for shared-store read overhead.
- Extractor pin: `julie-extract 2.40.6`.
- Semantic sidecar: `0.1.0`, unchanged.
- sqlite-vec: `0.1.9`, unchanged.

## What changed

The bundled extractor skips a redundant SQLite `auto_vacuum` assignment when the database
already uses incremental vacuum. Reopening a shared store no longer commits that unchanged
setting, reducing the configuration overhead paid by reader-protection operations.

In the local follow-up measurement, short CLI inspect median fell from 347 ms to 313 ms,
about 10%, with identical results. Latency spikes remain; this patch does not eliminate the
full regression observed after v1.28.0.

Reader protection, durability settings, schemas, and extraction behavior are unchanged.
Miller accepts the newly qualified 2.40.6 reader floor and continues to reject unsupported
future floors.

## Upgrade notes

- Restart resident Miller, dashboard, and CT processes after upgrading.
- The extractor upgrade can trigger an automatic rescan.
- `MILLER_SEMANTIC=off` remains the permanent zero-work switch for semantic retrieval.
