# Miller v1.12.0 Release Notes

- **Audience:** Teams using Miller's extractor-backed patterns, cross-language bridge tracing, workspace
  refresh diagnostics, or Kotlin test evidence.
- **Release shape:** Feature release adopting `julie-extractors` v2.15.0. No MCP tool, artifact schema,
  contract-version, or index migration was added.
- **Pinned extractor:** `julie-extract 2.15.0`.

## What Changed

### New backend bridge families

- `trace --mode bridge` now composes client requests with Symfony and Ktor route facts emitted as
  `symfony.route.v1` and `ktor.route.v1`.
- Both families use Miller's existing normalized route-template and optional uppercase HTTP verb contract;
  no parser recognition or framework-specific extraction moved into Miller.

### Extractor warning visibility

- Successful scans that carry julie-extract warnings now surface concise operator-facing diagnostics instead
  of silently dropping them.
- Bootstrap, indexing, workspace refresh/open, and cross-workspace refresh paths report warning counts,
  diagnostic codes, and affected paths while preserving existing partial-artifact handling.

### Kotlin test-role evidence and pattern catalog

- Live Scale coverage proves Kotlin JUnit case, container, and lifecycle roles flow through the existing
  generic symbol and JSONL readers while ordinary Kotlin controls remain non-test.
- Current guidance now reflects the upstream catalog of 194 pattern IDs across 36 languages.

## Upgrade Notes

- Plugin manifests advertise version `1.12.0`.
- The bundled extractor upgrades from 2.14.0 to 2.15.0 on all four release targets.
- Existing artifacts remain compatible because artifact schema 4, SQLite schema 4, extract contract 3, and
  report schema 3 are unchanged. Version-aware leadership performs the normal extractor-upgrade rescan.

## Verification

- Pre-release gate: clean Release build with 0 warnings/errors, 3,598 fast tests passed with 1 skipped,
  53 Scale tests passed against the real julie-extract 2.15.0 binary, plugin suite 48/48, no vulnerable
  NuGet packages, and a clean `git diff --check`.
