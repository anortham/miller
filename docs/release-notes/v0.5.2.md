# Miller v0.5.2 Release Notes

- **Audience:** Agents indexing large or adversarial repositories, especially repositories with deeply nested
  syntax trees or workflows that inspect julie-extract JSON reports.
- **Release shape:** Patch release updating Miller's bundled extractor before the next package validation.
- **Pinned extractor:** `julie-extract 2.5.0`.

## What Is New

- **Updated pinned extractor to `julie-extract 2.5.0`.** The upstream release keeps SQLite schema version,
  artifact extract-contract version, JSONL schema version, and JSON report schema version at `3`, so Miller's
  runtime compatibility gates stay unchanged.
- **Extractor-side stack-safety hardening.** The bundled extractor includes depth-bounded traversal for covered
  tree-sitter paths so pathological nested syntax trees cannot overflow the Rust stack in the extraction passes.
- **Additive report attribution fields.** Successful `scan --json` reports can include `counts.file_rows` and
  `counts.file_rows_truncated`, and `info --json` includes persisted per-file row attribution. Miller treats
  these as additive upstream report data; existing Miller report parsing remains compatible.
