# Miller v1.3.2 Release Notes

- **Audience:** Agents and teams using Miller bridge traces for Next.js, Nuxt, Vue, React, htmx, and ASP.NET route evidence.
- **Release shape:** Patch release for the `julie-extract 2.5.10` pin plus the completed web bridge route-fact hardening plan.
- **Pinned extractor:** `julie-extract 2.5.10`.

## What Changed

- **Extractor pin update.** Miller now targets `julie-extract 2.5.10` and validates the restored binary through the build guard.
- **Dynamic file-route bridging.** Next.js and Nuxt route references now bridge to dynamic file routes such as `/users/42` -> `app/users/[id]/page.tsx` and `/blog/hello` -> `pages/blog/[slug].vue`.
- **Route normalization hardening.** Bracket, brace, colon, and template-literal route parameters canonicalize to the same route key, improving bridge dedupe and matching consistency.
- **File-route ambiguity handling.** File-route matches now prefer the most specific route instead of dropping resolvable dynamic-vs-catch-all matches.
- **Provider ownership cleanup.** The `dotnet-web` bridge no longer treats frontend file-route definitions as backend client calls, while pure frontend route bridges stay owned by the framework providers.
- **Honest navigation verbs.** Vue, React, Next.js, and Nuxt navigation references no longer synthesize `GET` evidence; route-only backend matches stay Medium with `verb_unknown`.
- **htmx attribute normalization.** `data-hx-*` and mixed-case htmx attribute facts normalize to the same verb evidence as canonical `hx-*` attributes.
- **Vue and React route-definition bridges.** Vue and React route references can now bridge to router definition facts using the same matching and diagnostic vocabulary as file-route providers.

## Upgrade Notes

- Plugin manifests now advertise version `1.3.2`.
- No Miller schema migration is required.
- Source checkouts should rerun `bash scripts/restore-julie-extract.sh` so `.tools/julie-extract` matches the `2.5.10` pin.
