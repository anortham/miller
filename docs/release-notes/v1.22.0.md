# Miller v1.22.0 Release Notes

- **Audience:** All users, especially teams indexing QML modules or running CMake/CTest Qt Quick Test projects.
- **Release shape:** Stable minor release. Continuous testing remains opt-in and off by default; existing MCP, CLI, and index contracts remain compatible.
- **Pinned extractor:** `julie-extract 2.35.1`, unchanged for this release.
- **Pinned semantic sidecar:** `julie-semantic-sidecar 0.1.0`, unchanged.
- **Pinned sqlite-vec:** `0.1.9`, unchanged.

## What changed

### First-class QML indexing and resolution

Miller now consumes the released Julie QML artifact contract for QML, `qmldir`, and
`.qmltypes` facts. The typed QML visibility catalog is parity-tested across the
store-backed reader, standalone artifact reader, and bounded one-shot reader, so
those paths expose the same evidence and resolution decisions.

QML component resolution now handles module and directory imports, same-file and
same-directory candidates, `qmldir` export aliases whose names differ from their
source file symbols, version constraints, and public versus internal visibility.
Ambiguous and unresolved references stay explicit and evidence-backed; Miller does
not fall back to a globally unique component name.

The existing user-facing `search`, `inspect`, `trace`, `patterns`, and `edit`
surfaces have QML evidence and integration coverage without adding an MCP tool.

### CMake/CTest Qt Quick Test continuous testing

Continuous testing now inventories strict CMake Qt Quick Test projects, collapses
nested build files to one configure root, and provides a dedicated CMake/CTest
provider. It supports project preflight, selected-target and whole-suite
selection, CTest discovery, JUnit result mapping including failed-test artifacts,
and generation-scoped build/output directories so one run cannot consume another
run's results. Multi-config builds honor the selected configuration, and test
processes default to `QT_QPA_PLATFORM=offscreen` unless the project supplies an
explicit platform.

### Adversarial review hardening

The six accepted Grok findings were fixed: usable JUnit failures are retained when
CTest exits nonzero; a supplied project path no longer bypasses changed-path
scoping; `import "."` cannot create duplicate ambiguity; `tst_*` C/C++ Quick Test
harness changes trigger the QML project; a missing structural `qmltypes` model no
longer drops its `qmldir` manifest; and exported QML aliases resolve to the
declared type name.

## Upgrade notes

- Source checkouts should restore the pinned `julie-extract 2.35.1` binary. Existing
  installations continue to use the normal extractor-version and artifact-freshness
  paths when a workspace needs a rebuild.
- Rebuild and restart a resident Miller server or continuous-testing daemon to load
  the new binary. `MILLER_SEMANTIC=off` remains a permanent zero-work guarantee,
  and lexical-only output remains byte-identical.
- The QML CT provider is intentionally limited to CMake/CTest Qt Quick Test
  projects. qmake projects, function-level QML coverage, and native QML coverage
  are unsupported in this release.
