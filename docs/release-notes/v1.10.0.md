# Miller v1.10.0 Release Notes

- **Audience:** Agents and teams relying on Miller's search/content recovery output, compact rendering,
  and session-level routing guidance.
- **Release shape:** Feature release for the agent-interaction improvements plan (recovery output,
  compact rendering, guidance delivery, session hooks, `miller rules`). No MCP tool, artifact schema, or
  index migration was added.
- **Pinned extractor:** `julie-extract 2.14.0` (unchanged).

## What Changed

### Search and content recovery

- Empty `search` results return a diagnosis with typed next actions instead of a bare no-results
  message; empty `content` searches get the same diagnosis-driven output.
- Identifier-like text-mode misses suggest near-matching symbols (did-you-mean); file-mode queries
  carrying path prefixes above the workspace root recover instead of missing.
- `content read` resolves suffix paths and offers near-path suggestions on a miss; oversized read
  windows are clamped to the document instead of erroring.

### Compact output

- `impact` compact output caps impacted rows at 40; `content` search compact output groups results by
  source; `edit`'s match-proof block compresses to at most two lines; signature truncation now has a
  single shared limit in `ToolRenderLimits`.

### Guidance and session hooks

- The embedded instruction core was rewritten with affirmative redirects, tool descriptions were swept
  for prohibitions lacking redirects, and truncated-refs `inspect` responses nudge toward `trace`.
- New session hooks deliver a canary-gated routing block at SessionStart and re-inject it at
  SubagentStart, wired into the Claude Code and Codex plugin manifests. Claude Code delivery is verified
  live; Codex plugin-local hooks are inert upstream
  ([openai/codex#16430](https://github.com/openai/codex/issues/16430)), so the shipped wiring activates
  when that runtime catches up. Opt out with `MILLER_SESSION_HOOKS=0`.

### CLI and docs

- New `miller rules` CLI verb prints the embedded routing block for a selectable harness and rejects
  unknown options with exit 2.
- Docs cover the instruction-tier install path and the Node.js requirement for plugin installs.

## Upgrade Notes

- Plugin manifests advertise version `1.10.0`.
- No configuration, schema, or index migration is required.

## Known Issue (fixed in v1.11.1)

- On Windows, workspaces containing Blazor components crash-loop server bootstrap with
  `Invalid URI: The hostname could not be parsed.` (introduced with v1.9.0's project-namespace
  inference). Upgrade to [v1.11.1](v1.11.1.md).
