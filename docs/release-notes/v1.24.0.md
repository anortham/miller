# Miller v1.24.0 Release Notes

- **Audience:** Continuous-testing users first — every finding from the 2026-08-26
  Tycho dogfood session is addressed. Search users gain MSBuild-file text search;
  every `inspect`/`trace`/`impact`/`edit` caller gains the `<file>::<symbol>` form.
- **Release shape:** Feature release. CT behavior changes, additive JSON contract
  fields on `tests`, one extractor pin bump. No breaking JSON changes; compact
  output gains lines.
- **Pinned extractor:** `julie-extract 2.37.1` (was 2.37.0) — claims MSBuild and
  .NET project XML extensions (`csproj`, `props`, `targets`, `vbproj`, `fsproj`,
  `slnx`, `nuspec`, `resx`) and bumps the extraction identity epoch to 7.
- **Pinned semantic sidecar:** `julie-semantic-sidecar 0.1.0`, unchanged.
- **Pinned sqlite-vec:** `0.1.9`, unchanged.

## What changed

### CT builds inside the workspace — repo-root tests pass with zero configuration

The dotnet provider's `--artifacts-path` pointed at `<os-temp>/miller-ct`, so a
test that walks up from `TestContext.TestDirectory` to find the repo root failed
only under CT (87 of 140 baseline failures in the dogfood workspace). The default
CT build root is now `<workspace>/.miller/ct/build/<project segment>` — invisible
to the watcher and the extractor, so it adds no index churn. A workspace root too
long for the Windows MAX_PATH budget falls back to the legacy temp root. Projects
need no Miller-specific settings; per-repo `MILLER_CT_WORKSPACE_ROOT` csproj
conditions are no longer the recommended path for repo-root discovery.

### The CT ledger stops lying under churn

- **Stale spikes fixed.** The fresh-watermark mechanism designed to keep
  unimpacted greens fresh across revision bumps had never seeded on real
  workspaces; every bump read the full selected set as stale before runs
  recomputed it down. Greens now seed watermarks correctly, and the revision
  poller can no longer advance its cursor past an interval whose staleness was
  not applied.
- **Reds stay standing.** An automatic revision advance rewrote red cases to
  stale, collapsing `failures` from 140 rows to 1 until a backfill re-ran the
  old cases. A red now keeps its state on every staling path; the stamped
  `stale_since_revision` records the owed rerun, impacted reds still execute,
  and no automatic red loop opens.
- **Disable retires cases.** `tests disable project=...` removed a project from
  the run roster but its red cases kept counting, so the verdict could never
  clear. A disabled project's cases now leave every read — verdict, counts,
  `failures` — and re-enable restores them exactly.

### tests status answers "which project, and why"

Every project row now carries `case_count`, `stale_count`, `red_count`,
`verdict` (projected at the same live key the workspace verdict uses), and
`last_run_at` (`never` when null) — additive JSON, richer compact lines. The
compact `covers_all` label names its project, closing the misreading where a
per-project fact printed beside workspace-scoped counts. A drain that selects
zero cases now logs `reason=no_selection`, and the daemon prints one startup
line into `daemon.out.log` naming its version, pid, and the shared
`.miller/logs/miller-<date>.log` diagnostics pair.

### tests run joins an active run

`tests run wait=true` during an active run returned `verdict=unknown` with
reason "not acknowledged" after the 5-second ack window, though the daemon held
the request and ran it. A missed ack now probes the live daemon status: a busy
daemon yields reason `run already active`, and `wait=true` waits for settle and
returns the real verdict. `wait.command_id` is JSON null on a joined wait.

### tests failures fits the budget and answers "what is actually broken"

The MCP `tests` output is bounded (12 KiB, honest `next: offset=N` paging — an
80 KB single-line response previously blew the client token cap), every rendered
`failure_summary` is capped at 400 bytes, `project=` filters the red set, and
`group=error_class` summarizes reds by exception class with an `infra_shaped`
flag separating environment-shaped failures (`DirectoryNotFoundException` and
kin) from real assertion failures.

### Search reaches MSBuild files; inspect takes `<file>::<symbol>`

`julie-extract 2.37.1` manifests MSBuild and .NET project XML, and Miller
classifies those files as workspace config — `search mode=content|source|all-text`
now finds text such as an MSBuild property or condition inside `.csproj` files.
`inspect target="src/Foo/Bar.cs::Method"` resolves as a file-scoped symbol
lookup instead of a misleading `file_not_indexed`; the shared resolver gives
`trace`, `impact`, `edit`, and the CLI the same form. Compact `tests status`
also renders an honest `run: none selected yet` line during inventory discovery
instead of omitting the run block.

## Upgrade notes

- **One forced full rebuild per workspace.** The 2.37.1 extractor bumps the
  extraction identity epoch, so the first leader claim after upgrade re-extracts
  the workspace (this is how MSBuild files enter the index). CT's freshness
  identity flips with it: every stored verdict reads stale until the next run —
  the standard rebuild fail-safe, not data loss.
- **CT build outputs move.** New CT builds land under `.miller/ct/build/`;
  abandoned `<os-temp>/miller-ct/build` directories age out through the existing
  7-day inactivity cleanup. No action needed.
- **Contracts:** all `tests` JSON changes are additive and documented in
  `docs/contracts/tests-cli-v1.md`. `MILLER_SEMANTIC=off` remains a permanent
  zero-work guarantee; lexical-only output remains byte-identical.
