# Miller v1.8.0 Release Notes

- **Audience:** .NET and Blazor teams using Miller to follow navigation, dependency injection, and Razor
  component relationships across application boundaries.
- **Release shape:** Minor release. Blazor navigation and component relationships now participate in Miller's
  existing trace and impact workflows, and pending C# dependency-injection relationships resolve into graph
  edges. No new MCP tool was added.
- **Pinned extractor:** `julie-extract 2.13.0` (was 2.12.0).

## What Changed

### Blazor navigation tracing

- `NavigationManager.NavigateTo(...)` calls can trace to Razor components through their `@page` routes.
- Route matching follows Blazor semantics for literal, parameter, optional-parameter, and catch-all segments,
  including catch-all routes that match an empty remainder.

### Razor component impact

- Razor component usage creates evidence-backed `uses` edges, so reverse impact can identify pages and
  components affected by a shared component change.
- Component resolution uses workspace symbols and leaves unmatched third-party component tags unresolved rather
  than creating speculative edges.

### Dependency-injection edges

- Pending C# dependency-injection registrations now resolve into `instantiates` edges when the target service is
  present in the workspace graph.
- Live acceptance coverage exercises `.razor`, `.razor.cs`, navigation, component use, and dependency injection
  together against the bundled extractor.

## Upgrade Notes

- Plugin manifests now advertise version `1.8.0`.
- The bundled extractor is `julie-extract 2.13.0`. Version-aware leadership handles the upgrade automatically:
  the first 2.13 leader runs a forced full rescan, and older instances remain readers until upgraded. Source
  checkouts should re-run `scripts/restore-julie-extract.sh` (or `.ps1`) after pulling.
- Existing MCP clients require no configuration change; this release expands the graph behind the existing
  `trace` and `impact` surfaces.

## Verification

- Pre-release local verification:
  - `dotnet build Miller.slnx -c Release`
  - `scripts/test.sh`
  - `scripts/test-plugin.sh`
- Independent Claude review found no critical or high-severity issues; its valid findings were fixed before the
