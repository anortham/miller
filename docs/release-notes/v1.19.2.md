# Miller v1.19.2 Release Notes

- **Audience:** All users, especially users of family-store relationship reads and Windows workspaces.
- **Release shape:** Performance and reliability recovery patch release. The MCP surface remains nine tools.
- **Pinned extractor:** `julie-extract 2.33.3`, raised from `2.33.2`.
- **Pinned semantic sidecar:** `julie-semantic-sidecar 0.1.0`, unchanged.
- **Publication:** Stable coordinated Miller release.

## What changed

### Recover hot-path startup and relationship reads

The recovery work bounds family-store reference plans and defers unnecessary full-index hydration for read
requests. The CLI and MCP bridge now use the lean read path where the measured contract permits it, reducing
avoidable startup and warm-read overhead while preserving the existing output contracts.

Semantic broker endpoint handling is also safe for long Unix socket paths, and the Windows process, fixture,
path, and cleanup paths used by the recovery gates are hardened for native execution.

### Adopt julie-extract 2.33.3

The pinned producer release supplies the corresponding bounded incremental resolution and unchanged-import
short-circuits. It preserves the existing relationship, recovery, fencing, schema, report, and store contracts;
the adoption evidence and live four-platform archive hashes are recorded in
[`docs/findings/2026-08-16-julie-extract-2.33.3-adoption.md`](../findings/2026-08-16-julie-extract-2.33.3-adoption.md).

### Keep the boundaries explicit

This release adds no MCP tool and no schema or report version. `MILLER_SEMANTIC=off` remains a permanent
zero-work switch, lexical-only output remains unchanged, and the semantic sidecar stays at 0.1.0.

Cold full indexing remains expensive. The recovery work bounds accidental repeated work, relationship reads,
startup paths, and extraction parallelism; it does not establish a new cold full-index latency budget or make a
large repository's first complete extraction instant.

## Upgrade notes

- Re-run `scripts/restore-julie-extract.ps1` on Windows or `scripts/restore-julie-extract.sh` on Unix after updating
  a source checkout. The build guard rejects a missing or stale 2.33.3 binary.
- Miller's schema and extract-contract gates are unchanged; the restored 2.33.3 binary must pass the release
  preflight before packaging.
- Existing workspaces may finish a producer or derived-sidecar convergence after upgrade. Run
  `miller workspace refresh` if status names a stale derived sidecar.

## Verification
