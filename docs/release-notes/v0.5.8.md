# Miller v0.5.8 Release Notes

- **Audience:** Agents using Miller for branch impact checks, source-region searches, and code-marker audits.
- **Release shape:** Patch release with agent workflow improvements and a search-sidecar schema bump.
- **Pinned extractor:** `julie-extract 2.5.3`.

## What Is New

- **Git-aware impact checks.** `impact` can now read the current git diff directly. Use `miller impact --git`, `miller impact --base origin/main`, or `miller impact --staged`; the MCP tool supports the same `git`, `base`, and `staged` inputs.
- **Actionable trace/impact empty states.** Empty trace and impact results now distinguish unresolved targets, no seed symbols, no graph dependents, and empty git diffs, so agents get better next-step guidance instead of a silent zero-result answer.
- **Source-region indexing is default-on.** The source-region sidecar now builds by default when search sidecars are enabled. `MILLER_REGION_INDEX=0` remains the explicit opt-out.
- **Search sidecar schema 6.** The sidecar records the region-index option used to build it, so toggling `MILLER_REGION_INDEX` triggers a rebuild instead of serving mismatched metadata.
- **TODO/FIXME/HACK/XXX marker audit.** `search --mode markers` lists code markers from comment and doc-comment regions, with marker, file:line, snippet, language, and containing symbol when available. `todos --json` remains a CLI compatibility alias for Eros/scripts.
- **Eros-facing contract updates.** `capabilities --json` now advertises `todos --json` and source-region defaults so fleet consumers can detect the surface without reading Miller private SQLite.

## Upgrade Notes

- Existing `.miller/search.db` files whose schema predates version `6` will rebuild on refresh.
- If a workspace intentionally avoids source-region indexing, set `MILLER_REGION_INDEX=0` before refresh.
- Public install links now point at `v0.5.8`.
