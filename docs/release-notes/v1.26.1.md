# Miller v1.26.1 Release Notes

- **Audience:** every MCP client, especially agents that search, inspect, trace, edit, or list workspaces.
- **Release shape:** Stable correctness patch. No MCP tools or public JSON contracts were added.
- **Pinned extractor:** `julie-extract 2.38.2` (was 2.38.1).
- **Pinned semantic sidecar:** `julie-semantic-sidecar 0.1.0`, unchanged.
- **Pinned sqlite-vec:** `0.1.9`, unchanged.

## What changed

### Live MCP dogfood fixes

A full tool pass on miller 1.26.0 found ranking, paging, and compact-output defects. This patch closes
the product ones:

- Search no longer treats a trailing number in a missing identifier as a hit on a bare integer.
- `inspect depth=full` continuation starts at a line boundary instead of splicing a word.
- `insert_before` / `insert_after` previews add a newline so they cannot glue onto the symbol.
- Documented search/context examples no longer rank themselves as the first result.
- `trace mode=refs` on a C# type includes exact refs to its methods, not name-fallback only.
- Ambiguous overload inspect next-actions include symbol ids, matching trace.
- Default file inspect hides parameters and locals; pass `kind=` to see them.
- File-path `insert_before` refuses honestly instead of reporting the file as missing.
- An identical `replace_symbol_signature` is a no-op (`no_change`).
- Inspect reference lines omit line 0. Compact inspect prefers a signature accessibility token when
  it disagrees with stored visibility.
- `workspace list filter=error` matches state. A default cap keeps error rows inside the returned set.
- Unreadable `workspace health` returns a compact unavailable payload instead of an MCP error.
- Path-mode next-actions no longer search for a symbol hash as source text.
- Compact status says `STALE scan_failing` when the watermark matches and the scan is failing.
- Compact impact reports `likely_tests=` separately from the filename-heuristic `test_candidates`.
- Compact content `shape` labels token counts as `token counts (not log severity)`.

### julie-extract 2.38.2

2.38.2 bumps `EXTRACTION_IDENTITY_EPOCH` from 7 to 8. Family-store import therefore allocates new
file versions and rewrites C# `internal` visibility that epoch 7 stored as `private` (BRE-16).
Miller pins this extractor so `workspace full` and the next leading scan rewrite those rows for
real.

No MCP tools, public JSON contracts, or index formats change in this patch.

## Upgrade notes

- Restart resident Miller and dashboard processes to load the new binary.
- The extractor upgrade forces one full rescan per workspace on the new leader's first claim
  (version-aware leadership). C# `internal` values appear after that re-extract on family stores
  that still hold epoch-7 L1.
- Existing lexical-only output stays compatible. `MILLER_SEMANTIC=off` remains a permanent
  zero-work guarantee.
