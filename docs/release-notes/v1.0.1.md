# Miller v1.0.1 Release Notes

- **Audience:** Cursor, Claude Code, Codex, and other MCP clients that launch Miller from plugin, global, or project-local MCP configuration.
- **Release shape:** Patch release for MCP workspace binding and Cursor plugin startup reliability.
- **Pinned extractor:** `julie-extract 2.5.3`.

## What Is New

- **Workspace binding from MCP roots.** Miller now defers primary workspace bootstrap until the first tool call when startup cwd is not a usable workspace. It asks the MCP client for roots, binds to the selected project root, and keeps `MILLER_WORKSPACE_ROOT` as an explicit override for clients without roots support.
- **Safer plugin and global MCP launches.** Cursor user-global MCP and plugin-cache launches no longer need `${workspaceFolder}` placeholders or project-local `.cursor/mcp.json` files. Plugin cache, marketplace clone, home, filesystem root, and system roots fail closed instead of being indexed accidentally.
- **Roots-change handling.** Miller listens for `notifications/roots/list_changed` so cached client roots are invalidated when the editor switches projects.
- **Release-facing skill packaging.** The new `miller-orientation` skill is mirrored into plugin skill packages and covered by plugin manifest tests.

## Upgrade Notes

- Plugin manifests now advertise version `1.0.1`.
- Cursor users can remove the superseded project-local `.cursor/mcp.json` workaround once they install this release. A single user-global or plugin install should bind per editor window through MCP roots.
- Existing explicit `MILLER_WORKSPACE_ROOT` setups continue to work and still take precedence over client roots and cwd.
