# Miller v1.3.1 Release Notes

- **Audience:** Agents and teams using Miller patterns, trace bridge fallback guidance, and parser-backed web-stack route evidence.
- **Release shape:** Patch release for the `julie-extract 2.5.9` pin plus bridge/pattern hardening found during review.
- **Pinned extractor:** `julie-extract 2.5.9`.

## What Changed

- **Extractor pin update.** Miller now targets `julie-extract 2.5.9`.
- **Bridge structural-fact filtering.** Miller no longer loads `aspnet.minimal_api.route_group.v1` rows as direct bridge facts. Route-group prefixes still participate through route fact metadata and nearby literal fallback logic.
- **Trace fallback guidance.** Bridge no-match fallback actions now preserve the full current framework audit set, including htmx, Vue, React, Next.js, and Nuxt pattern checks.
- **Patterns tool cleanup.** Removed dead helper paths, simplified empty-reason handling, and reduced repeated structural-fact reader connection churn for query searches and summary fallbacks.
- **Bridge pattern catalog cleanup.** Bridge structural pattern IDs are centralized in Core and reused by the SQLite reader, bridge providers, and trace fallback hints.
- **File-route matcher coverage.** Optional catch-all file-route behavior now has an explicit regression test for non-trailing segments.

## Upgrade Notes

- Plugin manifests now advertise version `1.3.1`.
- No Miller schema migration is required.
- Source checkouts should rerun `bash scripts/restore-julie-extract.sh` so `.tools/julie-extract` matches the `2.5.9` pin.
