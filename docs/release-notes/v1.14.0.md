# Miller v1.14.0 Release Notes

- **Audience:** Julie users moving local coding-agent code intelligence to Miller, and existing Miller users
  adopting default-on local semantic retrieval.
- **Release shape:** Takeover feature release. The MCP surface remains nine tools; existing tools gain exact
  reference evidence, bounded output and continuation contracts, stronger ranking/context/impact behavior, and
  typed diagnostics.
- **Pinned extractor:** released `julie-extract 2.19.0`, with all four public package hashes pinned in Miller.
  This is a **breaking artifact change**: sqlite schema `4 → 5`, extract contract `3 → 4`, JSONL schema `4`.
  Resolution contract `2 → 3`, which forces a full re-resolution pass on the first scan.
- **Pinned semantic sidecar:** released prerelease `julie-semantic-sidecar v0.1.0-rc.4`, with all four public
  package hashes pinned in Miller and the complete manifest-verified runtime directory shipped in each archive.
  The `v0.1.0-rc.5` shared-broker source candidate is prepared locally but is not pinned here until publication,
  public-asset download, checksum verification, and broker smoke all succeed.

## What Changed

### Miller replaces Julie's local agent-tool core

- Exact resolved symbol identity now flows through inspect, context, trace, impact, and rename. Same-name
  fallback is provenance-bearing and cannot silently claim exact homonym attribution.
- Search uses shared reranking, container evidence, AND-to-OR relaxation, mixed file/symbol routing, and a
  default-on semantic arm without changing lexical-only bytes under explicit Off.
- Context returns task-ranked pivots with bounded implementation evidence. Impact ranks graph evidence, explains
  why each result matters, links exact tests where available, and supports revision deltas.
- Read and lifecycle tools use typed success, empty, and error outcomes. Large inspect bodies and reference
  pages use stateless checksum-bound continuation; content export is CLI-only.
- Agent-facing output is bounded where calibration exposed runaway payloads: every MCP Search route has a
  12 KiB ceiling and Unicode-safe snippet bounds, while file-inspect rows, search/inspect signatures, inspect
  bodies and callees, context serialization headroom, pattern-search row prefixes, and MCP workspace summaries
  retain their tool-specific limits. Search also rejects unknown modes, keeps explicit source search
  lexical-only, and records source-rescue telemetry only when that query runs. Exact coverage counts,
  continuations, typed oversize refusals, and CLI-only exhaustive reports preserve access to complete data.
- Context marks sufficient bundles as answer-ready, trace JSON exposes exact call-site spans and containing
  symbols, and the paired evaluator tells both roles to submit semantic actions for the outcome and evidence
  they report rather than mirroring incidental tool calls.
- Rename is exact by default, coverage-gated, preview-first, and atomic across files. `trace auto` and MCP
  content export were removed rather than retained as deprecated aliases.
- The migration guide maps every Julie tool/workflow to the supported Miller surface.

### Extraction and semantics

- `julie-extract 2.19.0` adds a static-type receiver resolution tier and recognizes C# file-scoped namespaces.
  Measured on this repository: C# `member_access` resolution rose from 0.2% to 12.0%, `call` from 19.4% to
  25.7%, overall from 11.1% to 14.7%, and `namespace X;` sources went from 0 to 655 namespace symbols — so C#
  types are now parented to their namespace where previously they were unparented. External receivers
  (`Assert.Equal`, `Path.Combine`) still resolve to zero by design.
- Because the new tier binds a receiver that no recorded type fact backs, `rename_symbol` now reports which
  exact sites came from a heuristic tier rather than a scope-proved binding: `inferred_count` and
  `min_confidence` per coverage row, a top-level `inferred_exact_count`, and a compact review note. Those sites
  are still renamed — omitting them would make the rename incomplete — but they no longer render as
  indistinguishable from a proved binding. `trace` already reported tier and confidence and is unchanged.
- `julie-extract 2.19.0` expands exact reference-resolution coverage across all 36 supported languages and
  publishes strict coverage and data-quality evidence. Coverage is **measured, not complete**: per-language
  resolution tiers and their open gaps are declared in the artifact's `language_capabilities` /
  `language_capability_gaps` tables, and references Miller cannot resolve exactly are returned as
  provenance-bearing fallbacks rather than silently claimed as exact. It adds the canonical reference-site contract
  (`reference_sites` with `is_exact`/`provenance`), typed relationship site attestation, and parser-backed
  marker facts, which Miller consumes for reference evidence and marker audits.
- The packaged semantic sidecar adds the RC4 protocol/platform hardening and the macOS x64 Metal package lane.
- Concurrent Miller sessions with the same broker/protocol/model identity share one broker and one loaded model.
  A user-global accelerator lease allows at most one broker identity to own acceleration; non-holders use CPU,
  and proven accelerator resource exhaustion demotes the holder to CPU. Status and health expose broker identity,
  owner/non-owner role, wire server version, model/backend, lease state, reconnect/spawn/retired-owner counts, and
  separate ownership/backend degradation reasons without compact output leaking the broker endpoint path or
  owner PID. One-shot CLI status/health passively observe an existing broker within a 500 ms total bound and
  never elect or start one; runtime health refreshes after accelerated calls so a later CPU demotion stays visible.
- BGE-small remains the production default. The frozen five-task Phase 9 comparison tied correctness (1/5),
  wrong-action rate (0.2), and relevance (zero) across both arms. CodeRankEmbed used fewer calls, tokens, and
  wall time on the one jointly correct task, but that isolated signal did not offset its roughly 6x memory and
  10x warm-query cost without a correctness or relevance gain. CodeRank remains evaluator-only.
- Semantic retrieval is on when `MILLER_SEMANTIC` is unset or blank. `MILLER_SEMANTIC=off|0|false` remains a
  permanent zero-work guarantee: lexical-only output stays byte-identical, and no broker path, model, process,
  accelerator, vector artifact, or semantic telemetry is touched.

### Derived-artifact generation safety

Every derived sidecar now proves which extract generation it was built from, not merely which revision. A full
rebuild promotes a new artifact whose revision counter restarts at 1, so a workspace already at revision N that
force-rebuilds lands back on N — a collision that revision comparison alone reads as "fresh" and would serve
pre-rebuild data from indefinitely. The `artifact_metadata.artifact_id` is the only field that separates the two.

- `search.db` (symbol and region arms), `content.db`, and the in-process index cache all compare the artifact id
  on the read path, not only when deciding whether to rebuild. A sidecar from a superseded generation now fails
  with an actionable "run `miller workspace refresh`" error instead of answering.
- `workspace status` reports such a sidecar as `stale` rather than `current`, matching what the read gates do.
- An artifact whose identity cannot be established is classified rather than lumped together: a genuine
  pre-stamping extract accepts only an equally unstamped sidecar, while an `artifact_metadata` table that exists
  but yields no id — a shape the pinned extractor never emits — is refused rather than trusted.
- Read gates refuse what they cannot prove, including when `symbols.db` is missing or unreadable. A lock is
  likeliest during the promote whose rename is the very moment the generations differ, so treating "cannot
  read" as "keep serving" would fail open exactly when it matters; symbol search degrades to its in-memory
  index rather than answering from an unproven sidecar. Build gates take the opposite view for an unreadable
  artifact, since they cannot rebuild from a source they cannot read.
- The edit path's indexed candidates and indexed-source diagnostics are gated too: a candidate from a
  superseded generation could aim an edit plan at the wrong region of the current file, and a stale
  "the indexed source still contains it near line N" message could drive a pointless converge retry.
- `miller content export` exits `3` with an actionable diagnostic instead of exporting workspace-derived rows
  from a superseded generation. Import-only exports (`--kind external_file|web`) are unaffected.
- An interrupted vector promote that cannot be recovered now skips the converge cycle instead of creating an
  empty active artifact, which would have made the leftover shadow unadoptable and forced a full re-embed. That
  skip schedules a delayed retry rather than waiting for an index-convergence wake that a quiet workspace never
  produces.

## Upgrade Notes

- Plugin manifests advertise version `1.14.0`.
- **Every pre-1.14.0 `symbols.db` is incompatible and must be fully rebuilt.** The bundled extractor advances
  from 2.16.0 to 2.19.0, moving the artifact from sqlite schema 4 / contract 3 to schema 5 / contract 4. An
  incremental `workspace refresh` cannot upgrade a schema-mismatched DB.
  - Under MCP, the first tool call after upgrade triggers a one-shot forced full rebuild automatically.
  - Under the CLI — and for any scripted or Eros consumer — every index-reading verb exits `3` with a
    plain-text diagnostic on stderr (stdout stays empty) until you run `miller workspace full`.
  - If the bundled `.tools/julie-extract` is older than 2.19.0, re-run `scripts/restore-julie-extract.sh`
    first; a force rebuild only heals the DB once the binary itself matches the pin.
- `trace mode=refs` now reports how many references exist beyond the requested `limit` and returns a
  `next_actions` entry with a limit that reaches them all.
- Existing vector artifacts remain tied to their five-field generation identity: encoder fingerprint, storage
  schema, corpus generation, reader compatibility, and fusion profile. Any incompatible identity rebuilds into
  a new generation before promotion.
- Published archives contain Miller, the matching extractor and semantic-sidecar binaries, sqlite-vec, the
  dashboard executable, and local dashboard assets for all four supported targets.
- Julie is not uninstalled and `.julie/` is not modified. Follow
  [`docs/migration-from-julie.md`](../migration-from-julie.md), validate Miller in each important workspace, and
  keep Julie available until its separate retirement announcement defines the final support window.

## Verification

- Publication is permitted only from the exact frozen candidate that passes the fast suite, Scale suite,
  warning-free Release build, evaluator suite, CLI/MCP contracts, plugin and mirror checks, Native AOT, and the
  package-only four-platform workflow.
- Package smoke must initialize the staged executable, assert all nine expected MCP tool names, run the pinned
  extractor and semantic pair, load sqlite-vec, and validate the packaged artifacts on each target. Promotion
  separately verifies the generated archive checksum sidecars.
- Takeover activation additionally requires nine clean tool-specific Claude reviews, one clean broad review, a
  full visible calibration, and the operator-controlled sealed decision. Only the allowlisted safe aggregate
  and exact-hash-bound Miller product attestation may cross the sealed boundary.
- Live package and release verification is recorded in `docs/findings/` after publication.
