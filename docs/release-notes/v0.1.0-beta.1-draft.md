# Miller v0.1.0-beta.1 Draft Release Notes

- **Status:** Draft product/release language, not a published release.
- **Audience:** Developers and coding-agent users trying Miller from a source checkout.
- **Release shape:** Source-checkout beta first. Packaged prerelease archives are configured but require an
  explicit tag/publish decision.
- **Pinned extractor:** `julie-extract 2.1.3`.

## Product Summary

Miller is the free local code-intelligence core for coding agents. It keeps a current SQLite-backed view of a
workspace and exposes the same structural read paths through MCP and a one-shot CLI.

Use Miller when an agent needs to answer local code questions without spending tokens on broad file reads:

- find symbols and files;
- inspect a symbol or file;
- build a focused context bundle;
- trace structural relationships;
- assess likely impact before a change;
- check workspace freshness and telemetry from a local dashboard.

Miller deliberately stays deterministic and embedding-free. Eros remains the higher-level commercial layer for
agent guidance, confidence/evidence workflows, and semantic/vector retrieval.

## What Is In This Beta

- MCP stdio server plus matching CLI verbs for `search`, `inspect`, `context`, `impact`, `trace`, `workspace`,
  `dashboard`, `version`, and `serve`.
- Workspace registry and selectors by display ID, unique prefix, full workspace ID, `current`, `primary`, or
  registered root path.
- Default-on symbol search sidecar with C# BM25 ranking retained as the source of ranking truth.
- Content search for docs/prose via `--mode content`.
- Opt-in source-region search for comments, doc comments, and string literals with `MILLER_REGION_INDEX=1`.
- Projection-specific read paths for beta CLI/MCP workflows so `search`, `inspect`, graph-only `context`,
  `impact`, non-bridge `trace`, and workspace status/list avoid unnecessary full graph hydration.
- Provider-scoped bridge tracing for the current `dotnet-web` surface.
- Loopback dashboard for registered workspaces, index facts, telemetry, latency/failure signals, and refresh
  troubleshooting.
- Cross-platform restore and test wrappers for macOS/Linux shells and Windows PowerShell.

## Source Checkout Quick Start

```bash
bash scripts/restore-julie-extract.sh
dotnet build Miller.slnx -c Release
dotnet run --project src/Miller.Server -c Release -- workspace open --path /path/to/repo --full
dotnet run --project src/Miller.Server -c Release -- search "WorkspaceIndexProvider" --limit 5
dotnet run --project src/Miller.Server -c Release -- dashboard
```

Windows PowerShell:

```powershell
scripts/restore-julie-extract.ps1
dotnet build Miller.slnx -c Release
dotnet run --project src/Miller.Server -c Release -- workspace open --path C:\source\repo --full
dotnet run --project src/Miller.Server -c Release -- search "WorkspaceIndexProvider" --limit 5
```

For MCP source-checkout use, [`mcp-config.json`](../../mcp-config.json) runs:

```bash
dotnet run --project src/Miller.Server -c Release -- serve
```

That means the MCP client machine needs the .NET 10 SDK on `PATH`.

## Known Beta Limits

- No embeddings or semantic/vector retrieval in Miller. Use Eros for that product layer.
- Source-region search is opt-in for beta and can fail closed when the region-capable sidecar is missing or
  stale.
- Ambiguous targets may require a file path, scope, or symbol ID.
- Bridge trace is provider-scoped. The current provider is `dotnet-web`; generic all-language bridge magic is
  not claimed.
- Native AOT is release-readiness work, not a beta blocker.
- A rebuilt MCP server appears only after the MCP client restarts the Miller subprocess. Use `miller version`
  and `workspace status`'s `pid` field to confirm which process is live.

## Not In This Beta

- Eros workflows, commercial dashboards, or next-action recommendations.
- Semantic/vector retrieval.
- Default-on source-region indexing.
- Native AOT release artifacts.
- Hosted accounts, team policy, billing, organization analytics, or remote portfolio search.
