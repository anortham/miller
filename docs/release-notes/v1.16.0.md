# Miller v1.16.0 Release Notes

- **Audience:** Existing Miller users, especially anyone opening large repositories or running several
  worktree agents against one machine — first-open latency and fleet stability are this release's themes.
- **Release shape:** Compatible minor release. The MCP surface remains nine tools; no Miller artifact schema,
  JSON/JSONL output contract, or semantic wire protocol changes. Existing artifacts keep working; a
  newer-extractor leader performs its usual forced rescan on claim.
- **Pinned extractor:** `julie-extract 2.25.0` (up from 2.21.0), with all four published archive hashes
  pinned. SQLite schema 5, extract contract 4, report schema 3, and JSONL schema 4 are all unchanged from
  v1.15.0 — the 2.22→2.25 adoptions added capabilities without a schema break.
- **Pinned semantic sidecar:** stable `julie-semantic-sidecar 0.1.0`, unchanged from v1.15.0.

## What Changed

### Progressive indexing levels: fast first open, full index in the background

- A fresh `workspace open` now builds a **symbols-level core first** (symbols, files, relationships — no
  identifier walk, no source regions or structural facts) and serves it immediately; the complete index
  converges afterwards through a background promote-based rebuild. On dotnet/runtime (~74k files) the first
  usable index arrived in **3.9 minutes instead of 23.7 minutes (6.1×)**, with the interim artifact at
  5.5 GiB instead of 20.4 GiB.
- Reference-layer tools are honest while converging: `trace`, `impact`, and reference-backed reads attach a
  converging diagnostic (with the `workspace status` / `workspace full` next steps) instead of silently
  returning thin results. `workspace status`/`health` surface the artifact's `index_level`.
- **`MILLER_INDEX_LEVELS=full` is the permanent zero-behavior-change escape hatch** (like
  `MILLER_SEMANTIC=off`): every build runs at full level, first open blocks on the whole index, argv
  byte-identical to pre-levels Miller. `symbols-only` pins a workspace at the core level; an unrecognized
  value fails closed to `full`. `MILLER_FULL_REBUILD_INPLACE=1` also forces full, because an in-place
  environment can never promote an upgrade rebuild.
- A killed upgrade leaves the served artifact intact — the upgrade is re-derived and re-owed, never
  half-applied. Workspaces that only ever see cross-workspace readers (no resident server) do not
  auto-upgrade yet; the served level stays visible in status, and `workspace full` upgrades on demand.

### Multi-worktree fleet safety (W1–W10)

Running many worktree agents against one machine no longer risks OOM cascades, spool floods, or rescan
storms:

- **Machine-wide scan governor**: whole-repo extractions across every Miller process share admission, so N
  worktrees no longer run N simultaneous all-core extractions. Governor state appears as `scan_governor` in
  `workspace status --json`/`health --json`.
- **Capped extraction parallelism**: every scan argv carries `--jobs` (default `min(4, cores/2)`;
  `MILLER_EXTRACT_JOBS` overrides, `0` restores rayon auto). An OOM-killed scan (exit 137) retries at
  `--jobs 1`.
- **Supervised scans** (julie-extract ≥ 2.22.0): each scan spools into the workspace's own `.miller/spool`
  (orphaned spools are reaped), writes a `scan.progress` liveness heartbeat, and self-terminates if Miller
  dies (`--parent-pid`). `MILLER_EXTRACT_SUPERVISION=off` restores the pre-2.22.0 argv.
- **Persisted scan-failure backoff**: `.miller/scan-failure.json` is shared by every process on the
  workspace and survives restarts (30s → 2m → 10m → 30m, jittered); an explicit user request bypasses the
  timer once. Every scan carries a typed intent, so repairs are never silently cleared by someone else's
  rebuild, and a downgraded serve is reported as `downgraded`, not success.
- **Worktree-aware watching**: linked worktrees watch their own `HEAD` (a branch switch is one reconcile,
  not a watcher-overflow rescan storm), and a removed-and-recreated workspace root is detected as a new
  checkout and rebound instead of served under the old index.
- **Invariant ignore file**: every scan is protected by a generated `.julieignore` that is never clobbered
  and never seeded over an unreadable inherited one.

### julie-extract 2.21.0 → 2.25.0

- **2.22.0** adds the scan-supervision flags Miller now drives (spool ownership, progress heartbeat,
  parent-pid).
- **2.23.0/2.23.1** survive dotnet/runtime-class repositories: generated sources with pathological CST
  depth no longer crash extraction (every walker is bounded by a shared traversal budget), and
  reference-site identity is deterministic across passes.
- **2.24.0** makes cold scans **3.2–4.1× faster** and drops five artifact indexes no query used (3.7 GiB
  on the dotnet/runtime artifact).
- **2.25.0** ships the two-level extraction contract behind the progressive levels above. Artifact level
  identity is recorded once and immutable; conflicting level requests are usage errors, unknown recorded
  levels fail closed.

### Windows semantic teardown fix

- Closing a semantic session against a silent or stalled broker no longer pays a ~1s reader-join stall on
  Windows: the transport is closed first, which unblocks the reader pump deterministically on every
  platform. Session teardown paths (including `workspace health` passive observation) are correspondingly
  faster.

## Upgrade Notes

- Plugin manifests advertise version `1.16.0`.
- No manual `symbols.db` migration is required. The bundled 2.25.0 extractor is newer than any pre-1.16.0
  artifact's recorded binary, so version-aware leadership performs its usual forced full rescan on first
  claim; with the default progressive policy that first rebuild serves a symbols-level core quickly and
  upgrades in the background.
- Set `MILLER_INDEX_LEVELS=full` before first start to keep pre-levels first-open behavior exactly.
- The semantic wire protocol and encoder policy are unchanged. `MILLER_SEMANTIC=off` remains the permanent
  zero-work guarantee, and lexical-only output remains byte-identical.
- Published archives contain Miller, `julie-extract 2.25.0`, the stable semantic-sidecar runtime,
  sqlite-vec, the dashboard executable, and local dashboard assets for all four supported targets.
