# Miller v1.4.1 Release Notes

- **Audience:** Eros (and any consumer) using `miller impact` for continuous-testing impact
  narrowing across an index-revision delta.
- **Release shape:** Additive patch release adding the `impact_index_revision_delta` capability and
  folding in the `julie-extract 2.8.1` pin with the 2.7/2.8 backend HTTP bridge consumer surface.
  No breaking changes; consumers that do not negotiate the capability are unaffected.
- **Pinned extractor:** `julie-extract 2.8.1`.

## What Changed

### Index-revision delta contract

- **`miller impact --from-index-revision <N> --from-artifact-id <ID>`** returns a typed R0
  envelope (`delta_status` ∈ {`complete`, `unavailable`}, `artifact_id`, `from_artifact_id`,
  `delta_reason`, `from_revision`, `to_revision`, `changed_paths`, `impacted`, `tests`) computed
  from julie-extract's own per-file change journal (`revision_file_changes`). A missing or
  `unavailable` `delta_status` is never inferred as "complete-empty" — an unreconstructable span
  (no journal, missing/mismatched artifact generation, pruned/rebuilt history, a base ahead of
  current, or a read failure) is reported honestly as `unavailable` so the caller falls back
  conservatively.
- **`workspace status --json` exposes `index.artifact_id`** so consumers can store the artifact
  generation with the revision watermark before asking for the next delta.
- **Capability negotiation.** `miller capabilities --json` advertises `impact_index_revision_delta`
  in a top-level `features` array when the running build can serve the delta, so a consumer degrades
  by negotiation rather than by interpreting a failed call.
- **Watched-path filtering (R2)** re-applies Miller's watch/ignore policy to the delta as
  defense-in-depth, and **Rust cross-language test classification** is pinned in the impacted payload.
- Contract: [`docs/contracts/impact-index-revision-delta-v1.md`](../contracts/impact-index-revision-delta-v1.md).

## Upgrade Notes

- Plugin manifests now advertise version `1.4.1`.
- No Miller schema migration is required; the extractor pin moves from `julie-extract 2.7.0` to
  `2.8.1` while the SQLite schema, extract contract, JSONL schema, and JSON report schema stay at `3`.
- The delta capability is additive and capability-gated: consumers below the negotiation floor
  continue to work unchanged.
