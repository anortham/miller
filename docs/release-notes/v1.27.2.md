# Miller v1.27.2 Release Notes

- **Audience:** agents that use Miller through the Claude Code, Codex, or Cursor plugins, or through
  the embedded MCP instructions and skills.
- **Release shape:** Patch release. No MCP tools, JSON contracts, or index formats changed. Only the
  `tests` tool description text changed.
- **Pinned extractor:** `julie-extract 2.39.0`, unchanged.
- **Pinned semantic sidecar:** `julie-semantic-sidecar 0.1.0`, unchanged.
- **Pinned sqlite-vec:** `0.1.9`, unchanged.

## What changed

### Every guidance channel now teaches the same rules

Miller delivers agent guidance through five channels: the embedded server instructions, the tool
descriptions, the session-start routing block, the `miller-*` and `handoff-*` skills, and the public
docs. A review of all five as one system found contradictions and gaps. This release fixes them.

- The session-start routing block now states that every workspace-bound call takes `workspace_id`
  from `workspace list` or `workspace open`. This rule was in the server core and the skills but
  missing from the one channel that is always in context.
- The embedded server core and the `tests` tool description agreed on nothing. The core called
  `tests` a runner for inner-loop tests. The description said the opposite. Both now describe
  continuous testing (CT) the same way: `status` is cheap and starts nothing, `run wait=true` after
  an edit executes only the stale set, and `enabled: false` means use the project's own test runner.
- The orientation, impact-analysis, and editing skills now include a CT verification step. The
  orientation table gained `tests` rows.
- `docs/agent-setup-snippet.md` now embeds the routing block verbatim. A new plugin test keeps the
  two files identical.
- The `miller-cross-workspace` skill no longer lists `current` and `primary` as valid MCP selectors.
  They remain CLI-only.
- The duplicated workspace-targeting block in eleven skills collapsed to a short form. The full rules
  live only in `miller-orientation`.
- `docs/agent-guidance.md` gained the `tests` tool and the CT workflow, a current skills list, and
  no longer names a `content export` MCP operation that does not exist.
- The README no longer claims the Codex plugin injects the session-start hook. Codex hooks are
  inert today, as `docs/install.md` records.

## Upgrade notes

- Restart resident Miller, dashboard, and CT daemon processes to load the new binary and the new
  `tests` description.
- Plugin users get the updated hook, skills, and docs on the next plugin update.
- No index rebuild, pin refresh, or configuration change is required.
