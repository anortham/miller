# Miller v1.14.1 Release Notes

- **Audience:** Existing Miller users and teams relying on exact C#, TypeScript, or JavaScript reference
  evidence and default-on local semantic retrieval.
- **Release shape:** Compatible dependency-adoption patch release. The MCP surface remains nine tools; no
  Miller artifact schema, JSON/JSONL output contract, or semantic wire protocol changes.
- **Pinned extractor:** `julie-extract 2.20.0`, with all four published archive hashes pinned. SQLite schema 5,
  extract contract 4, report schema 3, and JSONL schema 4 are unchanged; reference-resolution metadata advances
  from version 3 to 6.
- **Pinned semantic sidecar:** stable `julie-semantic-sidecar 0.1.0`, with all four published archive hashes
  pinned and the complete manifest-schema-2 runtime package shipped in each archive.

## What Changed

### Stronger reference resolution through the existing Miller reader

- C# locals and formal parameters now carry typed-symbol facts that let receiver-qualified calls resolve through
  the extractor's `tier3_receiver` path.
- TypeScript and JavaScript same-file static receivers now resolve through `tier3_static_type`; cross-file
  module-language resolution remains fail-closed unless imports corroborate the receiver.
- Miller consumes the new edges through its existing `ReferenceEvidenceReader` contract. A real-extractor Scale
  test proves C# typed parameter and local receivers, TypeScript and JavaScript static receivers, their producer
  resolution tiers, and artifact resolution metadata version 6.
- The active Patterns JSON contract now states its compatibility requirement as SQLite schema 5 plus extract
  contract 4 rather than treating the first producer version that shipped the contract as an exact pin.

### Stable shared semantic broker package

- The semantic sidecar moves from `0.1.0-rc.5` to stable `0.1.0` while preserving the
  `julie.embedding.sidecar` v1 protocol and shared-broker behavior.
- Stable packages use manifest schema 2 and include `LICENSE`, `README.md`, and
  `THIRD_PARTY-LICENSES.html` alongside the platform executable. Miller's restore path verifies every declared
  path, role, size, and SHA-256 before atomically installing the runtime directory.
- Current diagnostics and soak guidance point to the pinned restore scripts instead of prerelease-specific build
  instructions.

## Upgrade Notes

- Plugin manifests advertise version `1.14.1`.
- No manual `symbols.db` migration is required. When a 2.20.0-capable leader claims a workspace built by an older
  extractor, Miller's version-aware leadership performs the forced full rescan needed to emit the new reference
  facts.
- The semantic wire protocol and encoder policy are unchanged. `MILLER_SEMANTIC=off` remains the permanent
  zero-work guarantee, and lexical-only output remains byte-identical.
- Published archives contain Miller, `julie-extract 2.20.0`, the stable semantic-sidecar runtime, sqlite-vec,
  the dashboard executable, and local dashboard assets for all four supported targets.
