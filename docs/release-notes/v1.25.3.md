# Miller v1.25.3 Release Notes

- **Audience:** dashboard users, and anyone whose registry has collected dead agent-worktree rows.
- **Release shape:** Stable correctness and performance patch. No MCP tools or public JSON contracts
  were added.
- **Pinned extractor:** `julie-extract 2.37.2`, unchanged.
- **Pinned semantic sidecar:** `julie-semantic-sidecar 0.1.0`, unchanged.
- **Pinned sqlite-vec:** `0.1.9`, unchanged.

## What changed

### The dashboard stops blinking and reloading itself

Three separate causes were measured and fixed.

The panel-dimming rule applied to every element htmx was loading, and each polled panel is its own
requester, so the whole page dimmed twice a second. It now applies to the refresh button alone.

The aggregate index-facts cache returned before the cache whenever store mode was on — which is the
default — so the landing page reopened every workspace's index on every poll. It now caches in both
read modes, keyed on identity, with every changing input carried in a freshness stamp.

The refresh-status poll replaced the whole ten-panel detail stack every two seconds. It now targets
only itself, ends with an HTTP 286, and triggers one refetch of the stack when the refresh finishes.

Measured on a 59-workspace registry: the workspace fragment fell from 3.03 s to 0.02–0.03 s warm, the
landing page from 3.08 s to 0.09 s, and the refresh-status fragment from 4.51 s and 40,222 bytes to
0.002 s and 57 bytes.

### `workspace prune` can clear the worktree backlog it created

Every agent worktree registers a row, and nothing retires one on its own. Prune refused most of them
because its removal proof read `<repo>/.git/worktrees` — a directory git deletes on purpose once the
last worktree of a repository goes, which made a tidy cleanup permanently unprunable. The proof now
reads the repository's common directory, which only vanishes with the repository, and falls back to
the family-store tables for rows written before the registry recorded git lineage.

The proof is stricter, not looser. It requires the worktree's admin directory to sit in this
repository's `<common>/worktrees`, so a submodule or a `--separate-git-dir` checkout can never read as
a removed worktree. It refuses when a surviving admin entry's `gitdir` backlink still names the
workspace root, so an admin directory that was renamed rather than deleted is not mistaken for a
removal. Every failure direction refuses: an unmounted volume, an unreadable directory, or a listing
that throws all leave the row in place.

One run may now retire up to five views instead of one.

### An ambiguous selector can no longer pick a delete target

Read operations break an otherwise ambiguous workspace selector toward the root that still exists on
disk. That guess is wrong for a mutation — `workspace remove` means the dead row — and
`Directory.Exists` answers false on a permission fault as well as on absence. Mutating callers now
refuse the ambiguity instead of guessing, and every caller states which it is.

### Smaller dashboard fixes

- Relative timestamps only rewrite when the rendered text actually changes, and the timer stops while
  the tab is hidden.
- Sortable tables rehydrate only the swapped subtree.
- Table rows and error entries carry stable ids so the morph swap matches them across polls.
- A refresh that finishes while the reader has already started another no longer erases the new one's
  status panel.
- The workspace facts cache is bounded, so a workspace removed elsewhere no longer holds its facts for
  the life of the dashboard process.

## Upgrade notes

- Restart resident Miller processes to load the new binary. Existing indexes, continuous-testing
  state, and sidecars remain compatible.
- Run `workspace prune` as a dry run first to see which rows now qualify. Prune retires a family-store
  view and deletes that view's sidecars, so read the plan before applying it.
- `MILLER_DASHBOARD_INDEX_CACHE_SECONDS` sets the facts-cache window (default 120 seconds); `0`
  disables the cache.
