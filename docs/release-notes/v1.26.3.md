# Miller v1.26.3 Release Notes

- **Audience:** agents and dashboard users that call `workspace remove` or `workspace prune`.
- **Release shape:** Stable correctness patch. No MCP tools or public JSON contracts were added.
- **Pinned extractor:** `julie-extract 2.38.2`, unchanged.
- **Pinned semantic sidecar:** `julie-semantic-sidecar 0.1.0`, unchanged.
- **Pinned sqlite-vec:** `0.1.9`, unchanged.

## What changed

### MCP workspace remove no longer waits on `julie-extract`

MCP `workspace remove` captured the family-store view, then spawned `julie-extract store maintain retire-view --apply` and waited (default two minutes) before it deleted the registry row. A 30-second MCP timeout made a successful CLI remove look like a tool timeout.

This patch:

- Keeps CLI `miller workspace remove` and `miller workspace prune` waiting on producer retirement.
- Makes MCP and dashboard `remove`/`prune` write the owed reclaim record, delete the registry row, and return at once.
- Finishes `retire-view` plus sidecar reclaim on a serve-process worker. If that process dies, `.reclaim-owed` still names the view.
- JSON `workspace remove` includes `view_retirement_owed` when the producer work is still outstanding.

No MCP tools, public JSON contracts, or index formats change in this patch.

## Upgrade notes

- Restart resident Miller and dashboard processes to load the new binary.
- Existing lexical-only output stays compatible. `MILLER_SEMANTIC=off` remains a permanent zero-work guarantee.
