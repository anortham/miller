# Miller v1.23.0 Release Notes

- **Audience:** All users. Teams that run continuous testing or watch the
  dashboard get the most visible changes.
- **Release shape:** Minor release. The MCP tool surface is unchanged. The
  `tests` JSON contract gains additive fields. The producer pin moved.
- **Pinned extractor:** `julie-extract 2.37.0`, up from `2.35.1`.
- **Pinned semantic sidecar:** `julie-semantic-sidecar 0.1.0`, unchanged.
- **Pinned sqlite-vec:** `0.1.9`, unchanged.

## What changed

### The benchmark was rerun on v1.22.1, and the result held

The 2026-07-29 bare-agent comparison was repeated on 2026-08-25 with the same
15 tasks, five pinned repositories, model, seed, and budgets. The same agent
got 2.2x more tasks correct with Miller (11 vs 5 of 15) and halved the
wrong-action rate. A nine-repetition follow-up settled the semantic question
at tight budgets: the on-versus-off delta is noise (mean 0.2 tasks, scatter
1.9). Findings, raw evidence, and the public site were all updated.

### julie-extract 2.37.0

The extractor pin moved to 2.37.0 and Miller consumes its new contract:

- Files the extractor will never accept (oversized, hard-excluded, or an
  unsupported extension) now come back as a terminal `unsupported` state.
  Miller records them in the refusal ledger and stops resubmitting them.
  Before this, an unexpected disposition aborted the whole delta.
- Miller's own discovery now mirrors the extractor's published limits
  (1 MiB source-file cap and the hard-excluded directory set), so Miller no
  longer queues work the extractor is guaranteed to refuse.
  `MILLER_MAX_SOURCE_FILE_BYTES` overrides the mirror.
- A refused store add is remembered until the file's content changes, and the
  store request journal retires on any terminal row — a failed terminal
  request can only replay its failure, so Miller now retries with a fresh
  request instead.
- `workspace status` and `health` surface the family-store coordinator queue,
  including the new `quantum_overruns` count, and a blocked queue is named
  directly instead of advising a refresh that cannot work.
- `workspace prune` now runs the extractor's `store maintain gc --apply` per
  family, so dead request rows are reclaimed as part of normal lifecycle.

One policy note: a manifest file that grows past the extractor's 1 MiB limit
keeps serving its previously extracted symbols until the next full rebuild.
Miller stops the resubmit loop but does not yet mark the staleness; that
policy question is logged and will be decided with a real case in hand.

### Vector sidecar convergence fixes

Three defects found while dogfooding the benchmark rerun:

- Only the process holding the indexer lease drains vector work. Before this,
  a second resident process could race the leader on `vectors.db`.
- A promoted vector artifact that will not reopen is retried instead of being
  served broken.
- A whole-repo delta no longer stamps the vector store as a full rebuild, so
  semantic freshness tracking survives routine deltas.

### Continuous testing detects xUnit v2 instead of failing raw

CT runs the self-executing test assembly that only xUnit v3 produces. A v2
project used to surface as a raw discovery failure that read like a broken
build. Discovery now classifies the runner generation from the project's
package references:

- A v2-only project reports `framework: "xunit-v2"` with a plain
  `unsupported_reason`. The two packages both generations share decide
  nothing, and a project carrying both generations reads as v3.
- `tests enable` on a v2-only tree refuses with exit `3` and writes nothing.
  A mixed tree enables the v3 projects and reports the rest under
  `unsupported_projects`, so nothing is dropped in silence.
- As a backstop, a build that produced the test dll but no executable beside
  it fails with the same plain reason before the spawn, instead of the raw
  OS process error.

The JSON contract additions (`xunit-v2`, `unsupported_reason`,
`unsupported_count`, `unsupported_projects`) are additive at
`schema_version` 1. `docs/continuous-testing.md` is the authoritative
supported-frameworks matrix.

### The dashboard shows continuous testing

The workspace detail view has a new Tests section: verdict, stale and tracked
case counts, daemon state and build match, the run in flight, the selected
index key, the project inventory with per-project framework (including the
new `xunit-v2` reason), and the last red cases in the same one-line shape
`miller tests failures` prints.

The section is a read-only projection of the same status core the CLI and
MCP tool use, so it never disagrees with them. It creates nothing — no
`ct.db`, no `.miller/ct/`, no daemon — and it polls only while CT is enabled
for that workspace.

### The dashboard runs on one interaction stack

An audit of every dashboard interaction found htmx carrying all polling,
morphing, and POST actions while Alpine carried only a filter and two table
sorts. Those moved to the existing plain-JS file and the Alpine assets were
deleted. Each platform archive shrinks by the removed 72 KB of `wwwroot`
assets, and the dashboard remains local-first with no external requests.

### Empty results now hand you the next tool

High-traffic empty states across `search`, `trace`, `impact`, `inspect`, and
`patterns` now name the specific next call that can answer from the data that
failure actually has — for example, a `trace refs` miss offers string-literal
region search for uses the reference graph cannot link, and an `inspect` of a
name that resolves to nothing offers a cross-corpus search instead of
offering nothing at all. The hints are compact-output only; JSON
`next_actions` are byte-identical to v1.22.1, and no tool description or
instruction budget grew.

### `semantic prepare` says what happened

The verb used to end on a bare machine token such as
`semantic activation: still_not_ready`. It now prints a plain sentence naming
the outcome and the next step, and `MILLER_SEMANTIC=off` reports an honest
`semantic_disabled` instead of claiming a broker was looked for. Against a
sidecar that has not yet learned to flip ready in place, a session restart
after `prepare` remains the recovery, and the verb now says so.

### Documentation

- `docs/continuous-testing.md` is new: the supported languages and
  frameworks, discovery rules, safety bounds, and the dashboard view.
- `docs/contracts/cli-eros-v1.md` now documents the standalone JSON
  diagnostic envelope (`{schema_version, tool, diagnostic}`) that a refusal
  renders when there is no payload to attach to, and new guard tests pin it
  on `trace` and `impact`.
- Decision papers landed for workspace root safety and the MCP SDK 2.x
  evaluation; both are design-only in this release.

## Upgrade notes

- **The extractor pin moved, so the first leader claim on each workspace runs
  the automatic extractor-upgrade rescan.** This is the standard version-aware
  behavior: the newer extractor re-extracts the repository once in the
  background and promotes atomically. Expect one full-scan cost per workspace
  after upgrade; no user action is needed.
- The `tests` contract changes are additive. Consumers that ignore unknown
  fields are unaffected.
- Rebuild and restart a resident Miller server or CT daemon to load the new
  binary. `MILLER_SEMANTIC=off` remains a permanent zero-work guarantee, and
  lexical-only output remains byte-identical.
