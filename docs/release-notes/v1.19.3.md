# Miller v1.19.3 Release Notes

- **Audience:** All users, especially users opening workspaces through MCP and users with upgraded family stores.
- **Release shape:** Responsiveness and reliability follow-up patch release. The MCP surface remains nine tools.
- **Pinned extractor:** `julie-extract 2.33.4`, raised from `2.33.3`.
- **Pinned semantic sidecar:** `julie-semantic-sidecar 0.1.0`, unchanged.
- **Publication:** Release-prep candidate only; GitHub publication is intentionally pending.

## What changed

### Make MCP workspace open immediate

MCP `workspace open` now validates and registers the workspace, admits a bounded background prime, and returns
without waiting for extraction or the scan governor. The hosted prime queue deduplicates queued and running
workspaces, waits for bootstrap binding before resolving heavy services, and reports terminal lock, eligibility,
and failure states without erasing concurrent registry updates. CLI `workspace open` remains synchronous.

### Recover stale seeds without hiding failures

When a seeded family-store import fails Julie's typed `store_incompatible` validation, Miller retries exactly once
with `FromArtifact=null` and a fresh request fingerprint. Other import failures remain visible. This prevents an old
artifact from creating a permanent bootstrap deadlock while keeping unrelated failures actionable.

### Keep status and store mutations responsive and safe

Miller holds read transactions on the serving `store.db` generation and `coord.db` while a Julie mutation child runs,
preventing SQLite WAL shared-memory teardown races. `IndexerCore.HasPendingWork` now reports promptly while a scan
holds the coordination gate instead of making status/tool calls wait behind synchronous extraction.

### Adopt julie-extract 2.33.4

The producer update compacts genuinely accumulated scoped-resolution work into a fresh exact base, repairs the safe
additive writer read indexes on upgraded stores, and lets terminal resolve waiters return their durable result without
waiting for the request timeout. The four-platform hashes and tag provenance are recorded in the
[`julie-extract 2.33.4 adoption evidence`](../findings/2026-08-16-julie-extract-2.33.4-adoption.md).

### Timing and cold-index honesty

The isolated Miller gate measured MCP `workspace open` at 1.1 ms p95 and 3.8 ms maximum, with 20 small temporary
workspace primes reaching `Ready` in 2.21 seconds. Warm status, search, inspect, and context p95 timings were 7.3,
8.2, 7.9, and 38.1 ms. These are warm-reader and bounded-fixture measurements. A prior clean-worktree baseline
produced no open response after more than 180 seconds because extraction was inline; v1.19.3 removes that cold work
from the request path but does not promise an instant first full index for a large repository.

## Upgrade notes

- Re-run `scripts/restore-julie-extract.ps1` on Windows or `scripts/restore-julie-extract.sh` on Unix after updating
  a source checkout. The build guard rejects a missing or stale 2.33.4 binary.
- Existing workspaces may finish a producer or derived-sidecar convergence after upgrade. Run
  `miller workspace refresh` if status names a stale derived sidecar.
- A failed seeded import is retried only for Julie's typed `store_incompatible` result; other failures are not
  silently converted to a fresh scan.
