# Miller v1.23.2 Release Notes

- **Audience:** Dashboard users, most visibly on Windows. Anyone who clicks
  the Tests panel's **Run stale tests** button gets the fix.
- **Release shape:** Patch release. One dashboard fix plus a continuous-testing
  documentation update. The MCP tool surface, the CLI surface, and all JSON
  contracts are unchanged.
- **Pinned extractor:** `julie-extract 2.37.0`, unchanged.
- **Pinned semantic sidecar:** `julie-semantic-sidecar 0.1.0`, unchanged.
- **Pinned sqlite-vec:** `0.1.9`, unchanged.

## What changed

### The Run button reports its submit honestly

The Tests panel's **Run stale tests** action ran `miller tests run` and
showed whatever text came back. That text was the STANDING verdict — so a
click could answer "verdict=unknown" right after submitting a real run. Worse,
a daemon busy inside a drain missed the five-second ack and the CLI exited 3,
which the panel painted as a red failure while the daemon held the request
and ran it (2026-08-26 Windows field report: the button reported failure; the
log showed the submit enqueued across all four projects and the runs
completing).

The run action now asks the CLI for `--json` and rewrites the two known
submit shapes:

- An acked daemon submit reports "run submitted"; results land on the polling
  panel as they arrive.
- An unacked submit reports that the daemon is likely busy and holds the
  request, with normal styling instead of a false red error.
- A real refusal keeps the error notice with the CLI's reason, and non-JSON
  output passes through unchanged.

### Documentation: gate expensive MSBuild hooks for CT builds

`docs/continuous-testing.md` now documents how to gate expensive MSBuild
build hooks on the `MILLER_CT_WORKSPACE_ROOT` environment variable, which
Miller sets for every supervised CT build. A repo whose csproj hooks do heavy
work on every build (the 2026-08-26 watcher-overflow field report) can skip
that work for CT builds without changing what a developer build does.

## Upgrade notes

- The first dashboard launch from 1.23.2 replaces a running 1.23.1 dashboard
  through the version-aware, identity-checked replacement that shipped in
  1.23.1. The URL does not change.
- No sidecar, artifact, or JSON contract changes. `MILLER_SEMANTIC=off`
  remains a permanent zero-work guarantee, and lexical-only output remains
  byte-identical.
