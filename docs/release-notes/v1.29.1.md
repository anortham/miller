# Miller v1.29.1 release notes

- Audience: agents using Miller through plugins, MCP, or the CLI.
- Release shape: a patch for bounded idle shared-store inspection and retry scheduling. No new MCP tools.
- Extractor pin: `julie-extract 2.42.0`, unchanged.
- Semantic sidecar: `0.1.0`, unchanged.
- sqlite-vec: `0.1.9`, unchanged.

## What changed

- A leader with no source changes now inspects healthy shared-store sidecars once every 30 seconds instead of on
  every 250-millisecond debounce tick. This avoids repeatedly launching the store reader while the machine and
  agent sessions are idle.
- Source processing still requests an immediate sidecar inspection, and a sidecar that needs repair still enters
  the existing bounded 5-second, 15-second, and 30-second retry schedule.
- If an inspection fails after a repair target is armed, Miller retains that target and schedules the next attempt
  from the time the failure completes. A transient store-open failure can no longer cause a retry on every tick.

## Upgrade notes

- Restart resident Miller MCP servers, dashboards, and continuous-testing processes after upgrading.
- The extractor, semantic model identity, store schemas, and MCP tool surface are unchanged from v1.29.0.
