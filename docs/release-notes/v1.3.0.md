# Miller v1.3.0 Release Notes

- **Audience:** Agents and teams using Miller trace, patterns, and bridge evidence across ASP.NET, htmx, Vue, React, Next.js, and Nuxt projects.
- **Release shape:** Minor release for parser-backed web-stack structural facts, bridge trace support, and the `julie-extract 2.5.8` pin.
- **Pinned extractor:** `julie-extract 2.5.8`.

## What Changed

- **Broader structural-fact coverage.** Miller now bundles `julie-extract 2.5.8`, including the newer web-stack fact emitters used for htmx, Vue, React, Next.js, and Nuxt route evidence.
- **ASP.NET web bridge improvements.** The `dotnet-web` bridge can connect client-side route references from htmx, Vue, React, Next.js, and Nuxt facts back to ASP.NET route signals when the extracted facts provide matching URL evidence.
- **Framework file-route bridges.** `trace mode=bridge` now supports provider-scoped Next.js and Nuxt file-route navigation through a generic file-route bridge, including unresolved-route diagnostics when a reference is observed but no file route matches.
- **Patterns tool hardening.** The `patterns` MCP/CLI surface keeps structural fact browsing generic over extractor `pattern_id` values and returns clearer JSON/list/search behavior for agents that need to discover emitted web-stack facts before tracing.
- **Agent guidance and docs.** Miller instructions, skills, README, and trace JSON docs now describe the current bridge providers and the generic `file_route` trace node kind.

## Upgrade Notes

- Plugin manifests now advertise version `1.3.0`.
- No Miller schema migration is required.
- Existing `dotnet-web` bridge behavior remains provider-scoped. Next.js and Nuxt file-route traces should use `trace mode=bridge` with the matching provider.
- Trace JSON consumers should treat framework route nodes as `file_route`; this supersedes the earlier Next.js-specific `next_route` name.
- Source checkouts should rerun `bash scripts/restore-julie-extract.sh` so `.tools/julie-extract` matches the `2.5.8` pin.
