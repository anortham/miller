# Miller v1.11.1 Release Notes

- **Audience:** Windows users of Miller v1.9.0–v1.11.0 whose workspaces contain Blazor components.
- **Release shape:** Patch release for a Windows bootstrap crash-loop. No MCP tool, artifact schema, or
  index migration was added.
- **Pinned extractor:** `julie-extract 2.14.0` (unchanged).

## What Changed

### Windows bootstrap crash-loop fix

- On Windows, v1.9.0–v1.11.0 crash-looped server bootstrap in any workspace containing Blazor
  components: every tool call returned `bootstrap failed: Invalid URI: The hostname could not be
  parsed.` and `workspace status` reported a perpetually restarting bootstrap.
- Root cause: julie-extract records the artifact's `root_path` in Windows extended-length form
  (`\\?\C:\...`). The v1.9.0 Blazor namespace resolver passed project-file paths derived from that root
  to `XmlReader.Create(string)`, which URI-parses its argument; `\\?\` fails URI hostname parsing, and
  the resulting `UriFormatException` escaped the index loader and killed bootstrap.
- Fix: project files are now opened as a plain file stream, so no URI parsing occurs. A regression test
  covers extended-length workspace roots.
- The same defect was reachable from the CLI via `trace --mode bridge` (the one CLI verb that loads the
  full bridge graph); it is fixed by the same change.

## Upgrade Notes

- Plugin manifests advertise version `1.11.1`.
- No configuration, schema, or index migration is required. Existing artifacts — including those whose
  recorded root is extended-length — load as-is after upgrade.
- macOS and Linux installs are unaffected by the bug; upgrading keeps parity with the marketplace
  manifests.

## Verification

- Pre-release verification passed with a clean Release build, 3,582 fast tests (including the new
  extended-length-root regression test), and 52 Scale tests against the real julie-extract 2.14.0
  binary.
- The released `x86_64-pc-windows-msvc` binary was smoke-verified end-to-end against a previously
  crash-looping real workspace: the full index — including the Blazor component graph — loads and
  answers `trace --mode bridge` normally.
