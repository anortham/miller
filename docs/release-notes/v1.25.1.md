# Miller v1.25.1 Release Notes

- **Audience:** Everyone using Miller interactively, especially users of edit previews, context,
  impact, and worktree-heavy workflows.
- **Release shape:** Stable performance and correctness patch. No MCP tools or public JSON contracts
  were added.
- **Pinned extractor:** `julie-extract 2.37.2`, unchanged.
- **Pinned semantic sidecar:** `julie-semantic-sidecar 0.1.0`, unchanged.
- **Pinned sqlite-vec:** `0.1.9`, unchanged.

## What changed

### Interactive reads stop making the cursor wait

Edit previews now use the existing symbol lookup paths instead of hydrating the full workspace index.
When the search sidecar is behind the live revision, the complete-result path combines sidecar hits
with live revision facts so it stays fast without silently missing matches.

Context calls avoid the expensive fallback work that telemetry showed blocking otherwise simple reads.
Impact graph reads now fetch only the relationship directions the traversal can use. On the production
Miller workload, warm resident impact p95 fell from 8.296 seconds to 4.621 seconds while preserving the
exact 53-symbol, 147-test result and byte-identical output.

### Workspace health reports the window it actually measured

Workspace health and the dashboard now apply the requested telemetry window consistently. A seven-day
health view no longer mixes in older failures and then labels the result as recent, removing the
misleading warnings found during the machine telemetry audit.

### Removed worktrees no longer leave permanent filing-cabinet views

Workspace removal and pruning now retire the matching family-store view and reclaim its Miller-owned
sidecars. Pruning requires confirmed linked-worktree removal and passes one exact producer target per
call, so a missing path alone cannot retire a live checkout. If cleanup cannot finish, Miller records
the reclaim as owed instead of forgetting it.

The Miller session hook also reminds agents to prune the registered view after removing a worktree.

### Final external-review corrections

The approved Claude review found and closed two correctness edges: edit's complete-result mode now
preserves recall while the search sidecar lags, and stale-view pruning now proves linked-worktree
removal before producer retirement. The review retained the deliberate refusal to prune when the
pinned extractor is unavailable.

## Upgrade notes

- Restart resident Miller processes to load the new binary. Existing indexes and sidecars remain
  compatible; no full rebuild or producer migration is required.
- Worktree cleanup remains explicit and conservative. `workspace prune` only retires views it can
  prove belong to removed linked worktrees.
- `MILLER_SEMANTIC=off` remains a permanent zero-work guarantee, and lexical-only output remains
  byte-identical.
