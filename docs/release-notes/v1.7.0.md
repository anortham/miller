# Miller v1.7.0 Release Notes

- **Audience:** Agents and orchestrators consuming `impact --json`, `symbols export --jsonl`, and
  `workspace health --json`; anyone who wants impact results to say how much of the graph they actually
  covered and which reached symbols are positively classified as tests.
- **Release shape:** Minor release. Two new evidence surfaces on impact JSON (bounded traversal evidence and
  positive test-role evidence), test-role/currency evidence across the reader, search sidecar, and export
  feed, and verbatim structured capability gaps in workspace health. Extractor pin bumped to
  `julie-extract 2.12.0`; upgraded instances trigger the standard version-aware full rescan, and there is no
  Miller-side schema migration.
- **Pinned extractor:** `julie-extract 2.12.0` (was 2.11.0).

## What Changed

### Impact traversal evidence

- `miller impact --json --from-index-revision <N>` adds a `traversal` object: whether the bounded reverse
  traversal exhausted the frontier it could see, which changed paths seeded it, and which could not
  ([contract](../contracts/impact-traversal-evidence-v1.md), feature string `impact_traversal_evidence`).
- Evidence is deliberately scoped: `exhausted` is relative to seeded paths and currently indexed edges only,
  and zero-bound results stay honest (an empty `tests[]` never claims exoneration).
- The Reach computation stays off the traversal-evidence hot path, so normal impact latency is unchanged.

### Test-role evidence (julie-extract 2.12)

- Symbols now carry positive test roles (`test_case`, `test_container`, `test_lifecycle`) with a currency
  status backed by file status and parse-diagnostic facts; stale or unavailable backing evidence degrades to
  `unknown` with a named reason instead of a confident flag.
- `miller impact --json` reports per-reached-test role evidence plus a `test_evidence_scope` envelope
  (candidate-only, absence-unknown) in both normal and index-revision results
  ([contract](../contracts/impact-test-role-evidence-v1.md), feature string `impact_test_role_evidence`).
- `symbols export --jsonl` rows carry the same role and currency fields, and the export degrades to unknown
  evidence on older gate-passing artifacts that predate the evidence sources — matching the reader — instead
  of failing the feed.
- The search sidecar preserves test evidence across incremental converges, so sidecar-served results agree
  with the artifact.

### Workspace health capability gaps

- `workspace health --json` passes `kind_coverage` `open_gaps` entries through verbatim: legacy kind strings
  and julie-extract 2.12 structured gap objects (`kind`, `reason`, `required_closure`,
  `planned_closure_task`) both survive to consumers, and uninterpretable entries are never dropped — a
  declared gap can no longer silently read as a closed one
  ([contract](../contracts/workspace-health-v1.md)).

## Upgrade Notes

- Plugin manifests now advertise version `1.7.0`.
- The bundled extractor is `julie-extract 2.12.0`. Version-aware leadership handles the upgrade
  automatically: the first 2.12 leader runs a forced full rescan, and older instances become readers until
  upgraded. Source checkouts should re-run `scripts/restore-julie-extract.sh` (or `.ps1`) after pulling.
- Consumers of `workspace health --json` that parsed `open_gaps` entries as plain strings must accept the
  documented string-or-object shapes.
