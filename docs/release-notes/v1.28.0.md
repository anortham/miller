# Miller v1.28.0 release notes

Candidate notes. Dependency publication, pin update, and final package verification are pending.
The current checkout must not be published with the old extractor pin.

- Audience: agents using Miller through plugins, MCP, or the CLI.
- Release shape: shared-store reliability, sidecar recovery, cache accounting, and context internals.
  No new MCP tools.
- Intended extractor pin: `julie-extract 2.40.5`, pending publication and pin update.
- Semantic sidecar: `0.1.0`, unchanged.
- sqlite-vec: `0.1.9`, unchanged.

## What changed

### Shared-store reads and maintenance

Readers register which store data they still need so cleanup cannot reclaim it prematurely.
The release also includes the import-lock and WAL-maintenance repairs completed since v1.27.2.

Temporary reader contention now produces `reader_admission_busy` with retry guidance instead
of claiming that the index is missing. Reader protection is never bypassed to answer a query.

### Search and content sidecars

Search and content sidecars keep durable acknowledgements of the change history they have
consumed. Recovery records preserve unfinished work across crashes and view retirement.

The extractor cursor update no longer scans the entire store's garbage-collection history.
On the same million-entry fixture, measured p95 cursor advance fell from 2.368 seconds to
5.391 milliseconds; release fell from 2.445 seconds to 4.702 milliseconds. These are cursor
operation measurements, not end-to-end agent productivity results.

### Fact-cache lifetime and accounting

Owned cache leases keep active reads valid through eviction. Accounting distinguishes retained
data from data still held by readers without counting the same cache twice. Late loaders cannot
replace a newer cache identity.

The 256 MiB budget remains a soft retained-cache budget, not a limit on total process memory.

### Context consistency

CLI and MCP context requests share query, bundle-building, and rendering code. Existing public
behavior is covered by characterization tests and verification across all 40 supported languages.

### Agent evaluation tooling

Added a 36-task evaluation corpus, isolated runner, deterministic scoring, and offline
qualification checks. The paid agent comparison has not run. This release makes no claim
that Miller improves agent success rates, token use, or completion time from those dry runs.

### Windows verification

Shared store test fixtures now initialize their schema and seed data in one transaction instead
of 24 separate commits. Durability settings and test data are unchanged. The six-case Windows
measurement improved from a 4.42-second median to 0.78 seconds.

## Upgrade notes

- Restart resident Miller, dashboard, and CT processes after upgrading.
- The extractor upgrade can trigger an automatic rescan. New reader admissions may be
  temporarily refused while an import is active; retry the same call when it completes.
- `MILLER_SEMANTIC=off` remains the permanent zero-work switch for semantic retrieval.
- No paid evaluation campaign runs automatically.
