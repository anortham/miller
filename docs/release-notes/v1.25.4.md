# Miller v1.25.4 Release Notes

- **Audience:** users running store maintenance, workspace view retirement, or the dashboard refresh workflow.
- **Release shape:** Stable correctness patch. No MCP tools or public JSON contracts were added.
- **Pinned extractor:** `julie-extract 2.37.2`, unchanged.
- **Pinned semantic sidecar:** `julie-semantic-sidecar 0.1.0`, unchanged.
- **Pinned sqlite-vec:** `0.1.9`, unchanged.

## What changed

### Maintenance diagnostics survive nonzero exits

Store maintenance and view-retirement commands now preserve producer JSON diagnostics even when the
producer exits nonzero. A success-shaped retirement report can no longer outrank a nonzero exit, so
callers receive the failure outcome and its diagnostics together.

### Workspace selector intent is explicit

`WorkspaceTool` now passes an explicit Read or Mutate selector intent at every call site. MCP and CLI
therefore resolve the same ambiguous selector consistently, including leader handoff and refresh/full
operations that mutate the selected workspace.

### Dashboard refresh outcomes stay ordered

Dashboard refresh state is updated atomically, so a newer refresh cannot be replaced by a stale or
duplicate terminal outcome. htmx request ordering also protects newer refresh responses from older
requests arriving later.

### Malformed pruned-row reports are rejected safely

Pruned-row reports now reject wrong JSON kinds and negative counts instead of throwing while parsing.

No MCP tools, public JSON contracts, schemas, pins, or index formats change in this patch.

## Upgrade notes

- Restart resident Miller and dashboard processes to load the new binary.
- No reindex is needed; existing indexes, continuous-testing state, and sidecars remain compatible.
