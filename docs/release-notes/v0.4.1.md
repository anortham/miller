# Miller v0.4.1 Release Notes

- **Audience:** Fleet orchestrators (Eros) and anyone driving Miller against other registered workspaces — cross-workspace rebuilds, CLI workspace lifecycle, and exit-code-driven automation.
- **Release shape:** Patch release fixing the three 2026-06-11 Eros fleet-verification findings ([`docs/findings/2026-06-11-eros-fleet-verification-bugs.md`](../findings/2026-06-11-eros-fleet-verification-bugs.md)).
- **Pinned extractor:** `julie-extract 2.4.0` (unchanged).

## What Is New

- Added two bulk JSONL export feeds for fleet rollups (Eros H1 contract asks; see
  [`cli-eros-v1`](../contracts/cli-eros-v1.md) for field-level guarantees, both advertised in
  `capabilities --json` `supported_export_formats`):
  - `miller symbols export --jsonl [--workspace-id SELECTOR] [--workspace DIR]` — one deterministic row per
    symbol (id, name, kind, language, path, line+byte span, visibility, containment, signature, `has_doc`,
    `body_hash`, `is_test`) for per-repo symbol/doc-coverage/clone rollups without per-file `inspect` fan-out.
  - `miller complexity export --jsonl [--workspace-id SELECTOR] [--workspace DIR]` — one row per
    `complexity_metrics` row (file- and symbol-scope) for fleet-wide hotspot ranking; previously this data was
    only visible as `workspace health` aggregates.

## What Is Fixed

- Fixed the false-healthy `workspace full` loop against a schema-mismatched `symbols.db`. Three Miller-side causes (the bundled `julie-extract` heals correctly):
  - `symbols.db` readers now open with SQLite connection pooling disabled. A force rebuild heals an incompatible artifact by deleting and recreating the DB file; pooled handles in a live server pinned the unlinked old inode, so reads — including `patterns` — kept reporting the old schema error after the rebuild had already succeeded.
  - Cross-workspace refresh now derives `refreshed` vs `unchanged` from the extractor's report (`status=="no_change"`) instead of comparing revision numbers; a from-scratch rebuild restarts the revision counter and was misreported as `unchanged`.
  - The cross-workspace read cache evicts a workspace's entries when a refresh rewrote the artifact without advancing the revision, so a rebuild landing on the same revision number can no longer serve a stale in-memory index.
  - Cache keys now include the `symbols.db` file identity (last-write stamp + length), closing the cross-process variant of the same bug: a force rebuild run by ANOTHER process (the normal Eros fleet shape — CLI rebuild beside a live server) whose restarted revision counter lands on a cached number, while this process's own scan legitimately reports `no_change`.
- Fixed CLI `workspace status|health|refresh|full|remove` silently ignoring `--workspace` and `--workspace-id`: both are now accepted as aliases of `--path`/`--id` (the same selector flags every read verb takes; the path alias is normalized against the CLI's cwd), and a selector flag supplied without a value is a usage error (exit `2`) instead of a silent fallback to the current workspace.
- Hardened the read-command selector helper the same way: a valueless `--workspace-id` on `search`/`inspect`/`context`/`impact`/`trace`/`patterns`/exports is now exit `2` in every combination — previously it was silently masked by an accompanying `--workspace` flag, or fell back to the current workspace when alone.
- Fixed schema/contract/hash-mismatch failures exiting `1`: every CLI verb now maps an incompatible-extract error to exit `3` ("operational failure such as no usable index") per [`cli-eros-v1`](../contracts/cli-eros-v1.md), so callers can branch rebuild-and-retry (3) vs alert (1).

## Verification

- End-to-end repro: schema-2 artifact → `patterns` exits 3 → cross-cwd `workspace full --workspace <root>` rebuilds to schema 3 and reports `refreshed` → `patterns` exits 0.
