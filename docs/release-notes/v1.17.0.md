# Miller v1.17.0 Release Notes

- **Audience:** Everyone who opens git worktrees — especially multi-worktree agent fleets. A fresh linked
  worktree no longer pays a full extraction scan.
- **Release shape:** Minor feature release. The MCP surface remains nine tools. The artifact gains rebind
  provenance keys (`rebound_from_root`, `rebound_from_artifact_id`, `rebound_at`) in `artifact_metadata`;
  existing artifacts need no migration.
- **Pinned extractor:** `julie-extract 2.27.0` (the rebind release), up from 2.25.0.
- **Pinned semantic sidecar:** `julie-semantic-sidecar 0.1.0`, unchanged.

## Why this release exists

A linked worktree is almost always the same tree as its main checkout, plus a branch delta. Miller still
treated every fresh worktree as an unknown workspace and ran a full extraction scan — on a large repo,
tens of minutes per worktree, multiplied by every worktree an agent fleet opens.

v1.17.0 ships the worktree delta rebind program (P1–P4): a fresh worktree now copies the main checkout's
existing artifact and reconciles the branch delta instead of re-extracting the world.

## What Changed

### Copy-and-rebind bootstrap for linked worktrees

When a worktree has no index yet and its main checkout has a healthy one, bootstrap now:

1. Copies the source `symbols.db` with a page-stepped SQLite online backup — lock-free against the live
   leader, wall-clock budgeted (`MILLER_REBIND_COPY_BUDGET`).
2. Runs the julie-extract 2.27.0 `rebind` verb, which re-roots the artifact and hard-validates the
   extractor's parser/capability fingerprints.
3. Runs a normal delta scan over the worktree, so the branch difference converges incrementally.

Eligibility is conservative: same extractor version triple, healthy readable source, git-linked worktree
(resolved via the admin dir, no `git` subprocess). Anything ineligible falls back to the plain bootstrap
scan it would have run anyway, and now logs the reason.

Measured on real hardware (`docs/findings/2026-08-06-rebind-p4-scale-validation.md`):

| Scenario | Full scan | Rebind open | Speedup |
|---|---|---|---|
| 74k-file fixture, program baseline (W10) | 3,677 s | 240 s | 15.3× |
| dotnet/runtime (21.9 GB artifact), extraction phase | 1,345 s | 48 s | 27.8× |
| dotnet/runtime, fully converged | 1,730 s | 457 s | 3.8× |

Symbol tools become usable well before full convergence (44 s on the fixture; 192 s on dotnet/runtime).
Per-language parity between a rebound artifact and a fresh full scan is exact, including non-vacuous
relationship rows on the real repo. A SIGKILL mid-copy leaves the source byte-identical and the staging
debris is cleaned on the next attempt.

### Fleet bring-up no longer serializes on sidecar builds

Leaders released the machine-wide scan admission only after search/content sidecar convergence, so N
simultaneous worktree bootstraps formed a ladder and the last ones starved past the 10-minute admission
timeout. The admission is now released after the scan, before sidecar convergence. Re-validated: 8
simultaneous worktree opens all rebind and fully converge in ~20 minutes with zero admission timeouts
(pre-fix: 7 of 8, with the 8th requiring a restart).

Related hardening from the same validation round:

- A bootstrap that times out waiting for admission now self-retries once admission frees, instead of
  serving not-ready until restart; the retry re-validates that the root still exists.
- A worktree opened while the source scan's heartbeat is still fresh now waits out the window and
  rebinds, instead of silently falling back to a full scan.
- A cancelled heartbeat wait abandons the bootstrap instead of full-scanning on shutdown.
- Rebind refusals from the extractor (exit 3) carry `exit_code: 3` into the scan-failure journal.
- The post-OOM fallback scan keeps its `--jobs 1` clamp.
- A bootstrap failure for a root that vanished no longer recreates the root directory.

### Rebind provenance is visible

`workspace status --json` and `workspace health --json` carry a `rebound_from` object, the dashboard
shows "rebound from <source workspace>", and the Eros contract documents the keys
(`docs/contracts/cli-eros-v1.md`). Provenance is history, not state: later delta scans keep it; a full
rebuild clears it.

## Upgrade Notes

- Plugin manifests advertise version `1.17.0`.
- No `symbols.db` migration and no rescan are required. Rebind only affects a worktree's FIRST bootstrap;
  existing workspaces are untouched.
- `MILLER_WORKTREE_REBIND=off` is the kill switch: rebind is on by default, and `off` restores the
  previous always-full-scan behavior exactly.
- Search and content sidecars are not copied in v1 — they rebuild from the rebound artifact through the
  existing revision-keyed paths. On large repos this build dominates time-to-full-search-readiness
  (~200 s on dotnet/runtime); symbol tools are usable much earlier. Sidecar copying is the named
  follow-up.
- The pinned extractor moves to `julie-extract 2.27.0`. Release archives ship it; source checkouts
  re-run `scripts/restore-julie-extract.sh` (the build guard fails loudly on a stale binary).
