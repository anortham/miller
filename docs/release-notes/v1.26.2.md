# Miller v1.26.2 Release Notes

- **Audience:** dashboard users and agents that start, run, or stop continuous testing.
- **Release shape:** Stable correctness patch. No MCP tools or public JSON contracts were added.
- **Pinned extractor:** `julie-extract 2.38.2`, unchanged.
- **Pinned semantic sidecar:** `julie-semantic-sidecar 0.1.0`, unchanged.
- **Pinned sqlite-vec:** `0.1.9`, unchanged.

## What changed

### CT daemon poll no longer wedges the loop

A long `symbols.db` impact read ran inside the daemon main loop. While it ran, the loop did not tick and did not ack commands. `tests run` stayed unacked, and status reported a stalled loop after 90s.

This patch:

- Splits `PollAsync` into `ReadAsync` (impact read) and `ApplyRead` (cursor, enqueue, rebuild).
- Runs the read on a thread-pool thread. The loop ticks and acks commands while the read is in flight.
- Defers an explicit `run` until that read applies, then enqueues at the live key.
- Cancels in-flight reads on stop. A poll fault during shutdown no longer skips context release.

### Dashboard tests actions

- Start test daemon maps HTTP `start` to CLI `tests serve`.
- A run that returns `unacked` is treated as a busy submit, not a red failure.
- The workspace detail stack no longer sets `hx-target="this"`, so nested polls cannot replace the whole stack.

No MCP tools, public JSON contracts, or index formats change in this patch.

## Upgrade notes

- Restart resident Miller and dashboard processes to load the new binary.
- Existing lexical-only output stays compatible. `MILLER_SEMANTIC=off` remains a permanent zero-work guarantee.

## Verification

The release verification finding will record the Linux build/fast results, the local `win-test` fast-suite result on the release commit, exact-run package promotion, checksum validation, and published-asset smoke.
