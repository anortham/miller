# Miller v0.3.0 Release Notes

- **Audience:** Developers and coding-agent users using Miller as a local code-intelligence server.
- **Release shape:** Agent plugins, source checkout, and self-contained per-platform release archives.
- **Pinned extractor:** `julie-extract 2.1.3`.

## Product Summary

Miller is the free local code-intelligence core for coding agents. It keeps a current SQLite-backed view of a
workspace and exposes deterministic structural read paths through MCP and a matching CLI.

Use Miller when an agent needs to answer local code questions without spending tokens on broad file reads:

- find symbols, files, source text, docs, logs, and imported web content;
- inspect a symbol or file;
- build a focused context bundle;
- trace structural relationships;
- assess likely impact before a change;
- check workspace freshness and telemetry from a local dashboard.

Miller stays deterministic and embedding-free. Eros remains the higher-level commercial layer for guidance,
confidence/evidence workflows, semantic/vector retrieval, and commercial orchestration.

## What Is New In This Release

- Eros-facing CLI/export contracts are documented for `capabilities --json`, `refresh --json --wait`,
  `workspace status --json`, `content export`, `telemetry export --jsonl`, and stable read-command JSON such as
  `impact --json`.
- Release promotion now supports a two-step package-only validation and promotion flow, so publishing reuses
  already-validated artifacts instead of rebuilding the full platform matrix.
- Plugin metadata and public onboarding docs were refreshed for the agent-plugin-first install path.
- Workspace registry lock-busy recovery is more resilient when process shutdown leaves SQLite or lock state in a
  temporarily busy state.
- `miller workspace full` now uses a Windows-safe full-scan request path when a healthy MCP/server process owns
  `.miller/indexer.lock`; the lock-holding leader drains the request and the CLI waits for the readable revision
  and sidecars instead of requiring users to kill tasks.
- Incremental symbol-search sidecar updates were hardened against hidden `doc_id` reuse drift.
- Post-content-corpus search quality was retested with Miller-native cases and documented as ready for this
  release scope.
- Cross-workspace read workflows are documented: a session can stay in one repo and route `search`, `inspect`,
  `context`, `impact`, and `trace` to another registered workspace by `workspace_id`.
- The public GitHub Pages site now includes repeatable token-savings metrics from six cloned open-source repos:
  Flask, Express, Zod, Newtonsoft.Json, Gson, and jq.

## Release Archives

The release workflow builds one self-contained archive per pinned `julie-extract` platform:
`aarch64-apple-darwin`, `x86_64-apple-darwin`, `x86_64-unknown-linux-gnu`, and `x86_64-pc-windows-msvc`.

The main `miller` binary ships with Native AOT, so a release machine does not need the .NET SDK to run it.
Each archive extracts to a versioned top-level directory containing `miller`, platform native runtime libraries
such as SQLite and BLAKE3 bindings, the matching `.tools/julie-extract` binary, the packaged dashboard helper
under `dashboard/`, `LICENSE`, and `THIRD-PARTY-NOTICES.md`. A `.sha256` sidecar is uploaded next to each
archive.

## Quick Start

Most users should start with the agent plugin:

```bash
claude plugin marketplace add anortham/miller
claude plugin install miller@miller

codex plugin marketplace add anortham/miller
codex plugin add miller@miller
```

For source-checkout development:

```bash
bash scripts/restore-julie-extract.sh
dotnet build Miller.slnx -c Release
dotnet run --project src/Miller.Server -c Release -- workspace open --path /path/to/repo --full
dotnet run --project src/Miller.Server -c Release -- search "WorkspaceIndexProvider" --limit 5
dotnet run --project src/Miller.Server -c Release -- dashboard
```

Windows PowerShell:

```powershell
scripts/restore-julie-extract.ps1
dotnet build Miller.slnx -c Release
dotnet run --project src/Miller.Server -c Release -- workspace open --path C:\source\repo --full
dotnet run --project src/Miller.Server -c Release -- search "WorkspaceIndexProvider" --limit 5
```

## Known Limits

- No embeddings or semantic/vector retrieval in Miller. Use Eros for that product layer.
- Source-region search is opt-in and can fail closed when the region-capable sidecar is missing or stale.
- Ambiguous targets may require a file path, scope, or symbol ID.
- Bridge trace is provider-scoped. The current provider is `dotnet-web`; generic all-language bridge behavior
  is not claimed.
- The packaged `miller` release binary ships with Native AOT; the dashboard helper is still a self-contained
  ASP.NET executable because Razor Components do not currently support Native AOT.
- A rebuilt MCP server appears only after the MCP client restarts the Miller subprocess. Use `miller version`
  and `workspace status`'s `pid` field to confirm which process is live.

## Not In This Release

- Eros workflows, commercial dashboards, or next-action recommendations.
- Semantic/vector retrieval.
- Default-on source-region indexing.
- A Native AOT dashboard executable.
- Hosted accounts, team policy, billing, organization analytics, or remote portfolio search.
