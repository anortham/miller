# Miller v0.4.2 Release Notes

- **Audience:** Fleet orchestrators (Eros) and anyone rebuilding large registered workspaces or driving
  exit-code-based automation over `refresh`/`workspace full`.
- **Release shape:** Patch release resolving the two 2026-06-11 Eros field reports (the openclaw
  "julie-extract hang" and the `lock_busy` exit-code contract ask) plus new per-action duration telemetry.
- **Pinned extractor:** `julie-extract 2.4.0` (unchanged).

## What Is Fixed

- Fixed large-workspace rebuilds being killed by a fixed 600s total timeout. The bounded wait on
  `julie-extract` is now **progress-aware** (`ExtractWaitPolicy`): the child is killed only after 10 minutes
  with NO observable progress (artifact `db`/`-wal`/`-shm` byte changes plus output activity), with a
  60-minute absolute backstop. Field context: the openclaw force-scan (13,308 files, 660k symbols, ~2.0GB
  artifact) finishes in ~90s idle but exceeded 600s under a concurrent fleet sweep and was killed
  mid-rebuild while healthy. The two kill messages now distinguish "no extraction progress (likely hang)"
  from "still progressing but over the hard cap (load)" — so the next incident is self-diagnosing.

## What Changed (cli-eros-v1 contract)

- `lock_busy` now exits `0` (previously `3`) for `refresh` and `workspace refresh|full|open`: the latest
  readable DB is served and a live leader owns convergence, so the payload is ingestable. Freshness is NOT
  implied — consumers needing a confirmed-fresh index must gate on `status` (`refreshed`/`unchanged`) or
  `index_fresh: true`. Exit `3` is reserved for genuinely unusable-index outcomes (`missing_root`,
  `missing_index`, `failed`, `ineligible_extractor`). This was Eros's preferred option; it removes the need
  to parse exit-3 stdout against the "non-zero = non-ingestable" rule.
- `workspace full` exiting `0` on `status: failed` (the other half of the field report) did **not**
  reproduce on v0.4.1 — `failed` already maps to exit `3`; verified empirically and pinned by
  `RefreshExitCode_MapsStatusesToContractExitCodes`.

## What Is New

- Workspace action JSON (`refresh --json`, `workspace refresh|full|open --json`, and the MCP
  cross-workspace path) now reports durations:
  - `scan_duration_ms` — wall time of the `julie-extract` attempt. Present even for a FAILED/killed scan
    (a timeout kill reports roughly the timeout), `null` when no scan ran (e.g. `lock_busy`). Gives fleet
    sweeps per-workspace extract durations for free.
  - `duration_ms` — wall time of the whole refresh attempt (lock wait + scan + sidecar convergence).
  Compact output shows both lines only when measured.

- Live verification: `lock_busy` payload exits 0 against a lock-holding server; cobra refresh reports

  pinned binary.
