# Miller v1.25.2 Release Notes

- **Audience:** QML continuous-testing users with CMake/CTest projects and macOS daemon users.
- **Release shape:** Stable correctness patch. No MCP tools or public JSON contracts were added.
- **Pinned extractor:** `julie-extract 2.37.2`, unchanged.
- **Pinned semantic sidecar:** `julie-semantic-sidecar 0.1.0`, unchanged.
- **Pinned sqlite-vec:** `0.1.9`, unchanged.

## What changed

### Selected QML tests run under real CTest

Miller now emits selection expressions supported by CTest's regular-expression engine. Selected QML
runs no longer fail during CTest argument parsing before any test executes or JUnit report is written.
The expression still matches only the requested CTest target names and escapes regular-expression
metacharacters in those names.

### Failed CMake builds are retried from a valid generation

The CMake backend now records build completion only after the build succeeds. Configure-time files are
no longer enough to mark a generation reusable, so an interrupted or failed build cannot leave a
half-built tree that later discovery or execution mistakes for a completed build.

### macOS keeps daemon shadow copies when liveness is uncertain

macOS allows a running executable to be opened for writing, so that operation cannot prove a stale
daemon copy is unused. If Miller cannot complete its normal live-process scan, cleanup now keeps any
macOS copy whose executable still exists. This prevents an inconclusive fallback sweep from deleting
files that a running daemon may load later.

## Upgrade notes

- Restart resident Miller processes to load the new binary. Existing indexes, continuous-testing
  state, and sidecars remain compatible.
- QML projects do not need to change their CMake or CTest configuration.
- `MILLER_CT=off` remains a permanent zero-work guarantee.

## Verification

Local source gates, package validation, promotion, published-asset checksums, and the Windows release
gate are recorded in the v1.25.2 release-candidate and release-verification findings.
