# Miller v1.23.1 Release Notes

- **Audience:** All users. Anyone who upgrades through the plugin marketplace
  or runs continuous testing gets the visible fixes.
- **Release shape:** Patch release. The MCP tool surface is unchanged. The
  `dashboard` CLI verb gains an additive `replaced` status and a `--stop`
  flag. Producer pins are unchanged.
- **Pinned extractor:** `julie-extract 2.37.0`, unchanged.
- **Pinned semantic sidecar:** `julie-semantic-sidecar 0.1.0`, unchanged.
- **Pinned sqlite-vec:** `0.1.9`, unchanged.

## What changed

### A stale dashboard is replaced, not reused forever

A plugin upgrade used to leave the old `Miller.Dashboard` process serving
forever: the launcher reused any healthy dashboard, recorded no version, and
no verb could stop it. On Windows the stale executable also pinned its
plugin-cache directory against pruning (observed 2026-08-26: a 1.22.1
dashboard still serving after the 1.23.0 upgrade).

The dashboard now follows the CT daemon's version-aware pattern:

- `dashboard.json` records the build version and the spawned process's own
  start time. `/healthz` names the version behind the stable
  `miller-dashboard ok` prefix, so existing probes keep working.
- A launch from the same build reuses. A launch from a newer build stops the
  old dashboard and starts its own — the kill is identity-checked (pid plus
  process start time) and runs under the launch lock, with the record re-read
  under that lock, so a recycled pid or a concurrent launcher can never kill
  the wrong process. A record with no version predates the field and counts
  as older; that is exactly the stale dashboard this replaces.
- A launch from an older build reuses and reports the mismatch honestly.
- New: `miller dashboard --stop [--json]` stops the recorded dashboard with
  the same identity check and clears the record. Not-running is a success.

### The first edit after enabling CT now runs tests

Field evidence showed every save on a freshly enabled workspace logging
`no-run outcome=Unknown stale=0`, forever. The cause was a deadlock: test
discovery ran only inside a drain, a drain only followed an enqueued run,
and an empty case store made every selection return Unknown, which never
enqueues. Only an explicit `tests run` escaped.

An Unknown selection on a project whose store holds no test cases at all —
nobody ever looked — now enqueues a discovery-owed pending. The drain runs
provider discovery, rebuilds the selection from the discovered cases, and
executes that backlog as the project's first baseline. The attempt happens
once per project per daemon lifetime, so a project with no tests never
respawns a provider on every save. The strict fail-closed rule is unchanged
for projects that have inventory: truncated or degraded impact still
executes nothing.

The compact outputs of `tests enable` and a started or replaced
`tests serve` now end with a `next:` line pointing at `operation=run` for
the first verdict. JSON output is byte-identical.

### The dashboard Tests panel can act, not just report

The Tests section gains buttons: **Enable continuous testing** (only for a
never-decided workspace with discovered projects — never to argue with a
recorded opt-out), **Start test daemon** (enabled, daemon stopped), and
**Run stale tests** (daemon running). Each posts behind the dashboard's
CSRF header and renders the outcome as a notice on the re-read panel. The
actions run the public `miller tests` CLI verbs, so the dashboard reuses
the CLI's refusal, family-daemon anchoring, and version-aware daemon
replacement instead of growing CT logic of its own.

### Panels no longer move on hover

The panel hover effect kept its shadow feedback and lost its translate; a
whole section shifting under the pointer read as the page dancing.

## Upgrade notes

- **The first dashboard launch from 1.23.1 replaces a dashboard left running
  by 1.23.0 or older.** Its record carries no version, which counts as
  older. This is a one-time, identity-checked replacement; the URL does not
  change.
- A CT daemon from an older build is still replaced on the next explicit
  `tests start`, as in 1.23.0.
- The `dashboard --json` status values gain `replaced`; `--stop --json`
  reports `stopped | not_running | failed`. Both are additive.
- Rebuild and restart a resident Miller server or CT daemon to load the new
  binary. `MILLER_SEMANTIC=off` remains a permanent zero-work guarantee, and
  lexical-only output remains byte-identical.
