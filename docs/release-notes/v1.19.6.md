# Miller v1.19.6 Release Notes

- **Audience:** All users, especially users who start Miller against an older
  index or who save C# files while another resolve is still running.
- **Release shape:** Startup and incremental-save patch. The MCP surface remains
  nine tools.
- **Pinned extractor:** `julie-extract 2.33.7`, raised from `2.33.6`.
- **Pinned semantic sidecar:** `julie-semantic-sidecar 0.1.0`, unchanged.

## What changed

### An extractor upgrade no longer pays a startup delta first

When the bundled `julie-extract` is newer than the artifact, Miller used to run
a whole-repo incremental reconcile and then the owed upgrade scan. The delta
generation was replaced immediately. Miller now runs only the upgrade scan.

### A missing resolution target is retryable

A concurrent overlapping store resolve can fail with `resolution target is not
visible`. Miller now treats that as a retryable producer miss when the failure
class is `resolution_failed`, keeps the prior view, and retries on the next
scan. Other `resolution_failed` errors stay hard failures.

### Small C# saves stay scoped

The pinned `julie-extract 2.33.7` drops ubiquitous names such as `Scan` from
delta-scope expansion. A three-file C# save stays scoped instead of crossing
over to a full-view resolve. The producer CLI, report, and schema contracts do
not change.

## Upgrade notes

- Re-run `scripts/restore-julie-extract.sh` or `scripts/restore-julie-extract.ps1`
  after updating a source checkout. The build guard rejects a missing or stale
  2.33.7 binary.
- Existing workspaces may run one extractor-upgrade resolve after first launch
  on 2.33.7. After that, a startup against a current artifact should skip the
  extra delta.
- `MILLER_SEMANTIC=off` remains a zero-work guarantee.
