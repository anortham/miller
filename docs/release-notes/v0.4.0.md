# Miller v0.4.0 Release Notes

- **Audience:** Agent swarms and multi-instance setups that need safe indexer leadership across extractor versions, plus anyone relying on search quality, index hygiene, and freshness convergence.
- **Release shape:** Feature release centered on version-aware indexer leadership, with substantial search, hygiene, and freshness hardening.
- **Pinned extractor:** `julie-extract 2.4.0`.

## What Is New

- Added version-aware indexer leadership: the artifact's extractor version never goes backwards. An instance bundling an older `julie-extract` than the artifact stays a permanent reader (with the reason surfaced in `workspace status`/`health`), a newer-extractor leader auto-runs a forced full rescan on claim, and a newer reader displaces an older live leader through a graceful `yield` request with a cooldown. Equal versions never yield, so same-version swarms cannot thrash. `MILLER_ALLOW_EXTRACTOR_DOWNGRADE=1` is the escape hatch for intentional downgrades.
- Gated one-shot refresh writers (`miller refresh`, `workspace refresh/full`) behind the same extractor-eligibility verdict, and surfaced eligibility plus leader identity in `workspace status` and `workspace health`.
- Updated Miller to consume `julie-extract 2.4.0`, including the 2.3.0 structural-fact depth data behind the broadened pattern catalog.
- Added index hygiene controls: watcher extension gating, skip-list parity between scan and watch paths, and automatic `.julieignore` generation for vendor directories.
- Added near-miss suggestions and a scope-mask fallback when a `search`/`inspect`/`trace` target is not found, so a misspelled or over-qualified target returns candidates instead of a dead end.
- Added a build-time guard that fails the build when a stale `julie-extract` binary (left over from before a pin bump) does not match `scripts/julie-pins.json`, plus runtime diagnostics for the same condition.
- Improved compact output: search groups repeated files, `context` trims hop=0 labels, content snippets are indented, and `inspect` no longer echoes signatures redundantly.

## What Is Fixed

- Fixed a writer-lock race in `workspace remove`: index data is now deleted while the cross-process writer lock is held, so a writer starting up in the release-to-delete window can no longer lose a live index; after release, only the emptied directory and lock file are removed best-effort. This builds on the earlier Windows fix that unblocked `.miller` removal (an open lock handle blocked the delete) and on the `delete --file` verbatim-prefix containment fix.
- Fixed search pipeline under-return: post-filtering now escalates overfetch instead of silently returning fewer results, trigram window ranking was corrected, and query parsing was hardened against malformed input.
- Hardened freshness convergence: the converge request queue gained TTLs, claim-by-rename, a leader short-circuit, and coalesced drains; the leader liveness probe recovers from stale identity after write failures; corruption-shaped sidecar converge failures escalate to delete-and-rebuild instead of looping.
- Fixed stale `edit` gates to self-heal, and `edit` symbol operations and renames now re-plan after gate-time freshness recovery instead of acting on pre-refresh line numbers.
- Refused plugin/marketplace cache directories as the MCP launcher working directory, so a no-workspace launch can no longer index the plugin install itself.
- Added a central friendly MCP error for missing-required-parameter tool calls instead of a raw protocol failure.
