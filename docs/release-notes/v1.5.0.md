# Miller v1.5.0 Release Notes

- **Audience:** Agents and users tracking workspace code-quality trends over time, dead-code candidates
  consumers, and users installing Miller through Claude Code, Cursor, or Codex plugins.
- **Release shape:** Minor release shipping the P4 metric history & trends feature, the julie-extract 2.11.0
  pin, and the verified-dead symbol deletions from the dead-code candidates gate pass.
- **Pinned extractor:** `julie-extract 2.11.0` (was 2.10.0; maintenance fixes, no data-model change).

## What Changed

### Metric history & trends (new)

- New append-only `<workspace>/.miller/history.db` sidecar records metric snapshots over time. Two write arms:
  the indexer leader records cheap SQL aggregates after each sidecar converge (`symbol_count`,
  `complexity_p90`, `clone_group_count`, `marker_total`, marker splits), and canonical/default-parameter runs
  of `miller metrics churn|risk`, `miller report`, and `miller references candidates` record their heavier
  computed metrics (including `dead_code_candidate_count`). Snapshots dedup on
  `(artifact_id, revision, source)`; writes never block indexing or the recording command.
- New read verb: `miller metrics history [--metric a,b,…] [--limit N] [--json]` — trend points ordered by
  append order (newest last), absent metrics rendered as absent (never `0`). Stable JSON contract:
  [`docs/contracts/metrics-history-v1.md`](../contracts/metrics-history-v1.md), advertised in
  `miller capabilities --json`.
- Dashboard workspace detail views render trend sparklines per metric; `workspace health` reports a
  `history_db:` status line (compact) and an `index.history_db` JSON block.
- Failure visibility: corruption recovery preserves the full `history.db` + WAL bundle aside (never deletes
  committed data); a present-but-unreadable sidecar fails visibly (CLI exit 3, dashboard "history unreadable",
  distinct health state) instead of masquerading as empty history.

### Workspace remove coordination (fix)

- `workspace remove` now acquires the content-corpus and metric-history write leases alongside the indexer
  lock before deleting `.miller/` contents, fixing a pre-existing race where a remove could delete
  `content.db` mid-import.

### Dead-code deletions

- Deleted the four zero-reference symbols confirmed by the 2026-07-07 dead-code candidates dogfood, plus two
  constants orphaned by those deletions. `miller references candidates` on this codebase now reports a single
  known false positive.

### Extractor pin

- `julie-extract` pin bumped to 2.11.0 (upstream release-audit fixes). No schema or contract change;
  dead-code `variable_ref` evidence verified identical to the 2.10.0 gate pass.

## Upgrade Notes

- Plugin manifests now advertise version `1.5.0`.
- Restore the `2.11.0` extractor pin (`scripts/restore-julie-extract.sh`) on source checkouts; release
  archives bundle it.
- Existing workspaces need no forced rebuild. `history.db` is created lazily on the first converge or
  recording command; trends appear after two or more snapshots (run `miller report` to seed one).
