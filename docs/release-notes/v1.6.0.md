# Miller v1.6.0 Release Notes

- **Audience:** Dashboard users managing many registered workspaces, agents using the `workspace` tool, and anyone tracking registry hygiene after the v1.5.x metric-history releases.
- **Release shape:** Minor release. New `workspace prune` operation and dashboard registry-lifecycle mutations (remove/prune), plus a broad dashboard polish and degrade-hardening pass. No extractor pin change and no index/schema migration.
- **Pinned extractor:** `julie-extract 2.11.0` (unchanged).

## What Changed

### Workspace registry lifecycle

- New `workspace prune` operation (CLI and MCP, with `dry_run`) removes registry rows whose root folders no longer exist.
- The dashboard can now remove a workspace registration and prune stale rows directly ([ADR-0002](../adr/ADR-0002-dashboard-registry-lifecycle-mutations.md)): antiforgery-protected `POST /workspace/remove` and `POST /workspaces/prune` endpoints share the same `WorkspaceRemoval`/`WorkspaceRegistryPrune` cores as the CLI, with the same refusals (live workspace, in-use lock) surfaced as inline notices.
- The remove control appears on every all-workspaces row (live and stale) and on the workspace detail page, each behind an expand-to-confirm step that states the consequence and the `workspace open` recovery path.
- The all-workspaces view separates live workspaces from stale registrations, auto-refreshes every 30s, and supports client-side sorting and filtering.

### Dashboard polish

- Server-side relative timestamps with a humanized activity-window label and a GB tier for byte formatting.
- Detail page: copyable id chips (display id, workspace id, root path, artifact id), refresh-status feedback, and trend sparklines on a shared scale.
- Single-definition theme tokens via `light-dark()` with AA-compliant muted contrast in both themes.
- Per-tool P95 latency is computed in a single pass, and recent errors name their workspace.

### Degrade hardening

- Page-spine readers degrade with visible notices instead of crashing on corrupt shared DBs (registry, telemetry) and on incompatible extract schemas; corrupt `telemetry.db` degrade carries its message; unhandled request errors are logged to the console.

## Upgrade Notes

- Plugin manifests now advertise version `1.6.0`.
- Existing workspaces need no rebuild and there is no schema migration. `workspace remove` (dashboard or CLI) deletes only that workspace's `.miller` index data; re-register any time with `workspace open`.
