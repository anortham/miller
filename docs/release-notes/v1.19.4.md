# Miller v1.19.4 Release Notes

- **Audience:** All users, especially users who restart MCP often or save one source file at a time.
- **Release shape:** Incremental-index patch. The MCP surface remains nine tools.
- **Pinned extractor:** `julie-extract 2.33.5`, raised from `2.33.4`.
- **Pinned semantic sidecar:** `julie-semantic-sidecar 0.1.0`, unchanged.

## What changed

### Startup stays incremental

When file hashes match, Miller skips store import and resolve. A restart with no source
changes now finishes the startup scan in well under a second instead of re-importing the
tree.

### File deltas stay file deltas

Changed hashes run per-file store update and one resolve. New files must be extractable
source (julie's claimed extensions). Cross-workspace refresh now receives that catalog
too; if the catalog is missing, discovery fails soft instead of adding nothing.

### Sidecars follow the store

Search and content sidecars apply store file changes in place. Vectors stay at the current
revision. The semantic broker warms at host start so status is not stuck at `not_started`
during a long scan.

### One-file resolve stays scoped

The pinned `julie-extract 2.33.5` keeps a one-file C# save scoped. Private locals are not
resolve keys. A Full+Crossover pass now actually compacts the overlay.

## Upgrade notes

- Re-run `scripts/restore-julie-extract.sh` or `scripts/restore-julie-extract.ps1` after
  updating a source checkout. The build guard rejects a missing or stale 2.33.5 binary.
- Existing workspaces may run one full resolve after the extractor upgrade (old journal
  names fail closed once). After that, one-file saves stay scoped.
- `MILLER_SEMANTIC=off` remains a zero-work guarantee.

## Verification

- Focused Miller suites for the coordinator, watcher filter, and indexer scan passed
  (187 tests).
- Live dogfood on this workspace: startup skip ~720 ms; one C# save scoped to 14 files
  (was 459 files / 226 s). After compact, the next save stayed in that band.
- Package validation, promotion, and four-platform checksums are recorded after
  publication.
