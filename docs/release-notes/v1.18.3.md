# Miller v1.18.3 Release Notes

- **Audience:** All users of Miller's default-on local semantic retrieval, including first-time installers.
- **Release shape:** Semantic pause-reporting and setup-documentation patch. The MCP surface remains nine tools.
- **Pinned extractor:** `julie-extract 2.32.1`, unchanged.
- **Pinned semantic sidecar:** `julie-semantic-sidecar 0.1.0`, unchanged.
- **Publication:** Stable coordinated Miller release.

## What changed

### Semantic pause reporting matches the recovery path

Workspace health and onboarding now honor a recorded semantic pause before falling back to a generic freshness
message. Users see the actual reason a vector store is not serving, such as an unprepared model, an open broker
circuit, or a disk block, instead of being sent to an unrelated refresh path.

Preparation guidance is limited to cases where model preparation can resolve the condition. Corrupt, unreadable,
incompatible, or otherwise unavailable vector artifacts retain their diagnostic state without suggesting an
irrelevant model download.

### Setup documentation matches default semantic retrieval

The installation guidance explains that the sidecar binary does not bundle model weights, that the default model
requires an explicit one-time `miller semantic prepare`, where the model cache lives on each platform, and when a
running server needs to be restarted after preparation.

## Upgrade notes

- Default semantic retrieval remains enabled; `MILLER_SEMANTIC=off` remains the permanent opt-out.
- The extractor pin, semantic sidecar pin, family-store schema, semantic model identity, and public commands are
  unchanged.
- Plugin and marketplace manifests advertise version `1.18.3`.
- The MCP surface remains nine tools.
