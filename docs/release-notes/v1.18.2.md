# Miller v1.18.2 Release Notes

- **Audience:** Users of the default versioned family store, especially large repositories and concurrent agent hosts.
- **Release shape:** Performance and resource-use patch. The MCP surface remains nine tools.
- **Pinned extractor:** `julie-extract 2.32.1`.
- **Pinned semantic sidecar:** `julie-semantic-sidecar 0.1.0`, unchanged.
- **Publication:** Stable coordinated Miller and producer release.

## What changed

### Interactive family-store reads stay bounded

Context, impact, trace, and inspect no longer hydrate and retain a complete repository index and graph in each
Miller process. They use the pinned read session, the generation-checked FTS sidecar, bounded graph frontiers, and
lazy bridge data. Freshness advances metadata without forcing the lazy repository graph.

The graph reader pushes family resolution, unresolved-name, and relationship work below compatibility-view UNION
barriers, batches frontier traversal, and keeps legacy-artifact behavior unchanged.

### Search and source rescue avoid repeated whole-candidate work

One request-local cache reuses exact repeated searches with fixed key and retained-row caps. Empty AND searches use
a cheap intersection probe, unused trigram work is skipped, and symbol FTS scores narrow token bodies before
hydrating only final rows. Multi-term scoring scans each candidate token stream once with a bounded pooled matrix.

Content search now opens metadata-only, scores narrow stored token bodies before raw hydration, analyzes raw text
once per survivor, and loads symbol spans only after final ordering and limit selection.

## Measured result

On the final rebuilt Linux candidate, warm inspect completed in 254.855 ms, context in 1,938.450 ms, impact in
1,260.196 ms, and trace in 145.721 ms. Context peaked at 151,516 KB PSS; the same host's post-read 3-second idle
sample peaked at 161,214 KB PSS. Outputs remained exact.

## Upgrade notes

- Plugin manifests advertise version `1.18.2`.
- The family-store schema, resolver epoch, semantic model identity, public commands, and MCP tool count are unchanged.
- `julie-extract 2.32.1` is pinned from its stable four-platform release. It keeps store schema v2 and format epoch 1
  while adding import reliability and the measured exact-writer improvement used by this release.
- Registry-path isolation for destructive-free `workspace open` dogfood remains follow-up work; the candidate does
  not repurpose `HOME`/`USERPROFILE` or mutate the shared registry during tests.
