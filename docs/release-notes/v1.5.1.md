# Miller v1.5.1 Release Notes

- **Audience:** Users of Miller `workspace health --json`, Eros consumers reading the workspace-health contract, and agents following the local backlog after the v1.5.0 metric-history release.
- **Release shape:** Patch release for v1.5.0 follow-up fixes. No extractor pin change and no index/schema migration.
- **Pinned extractor:** `julie-extract 2.11.0` (unchanged).

## What Changed

- `miller workspace health --json` now reports the metric-history sidecar status in `index.history_db`, matching the MCP `workspace health` path and the existing renderer contract. The field includes `present`, `unreadable`, `schema_version`, `snapshot_count`, `size_bytes`, and `corrupt_recovered`.
- The workspace-health JSON contract now documents `index.history_db` explicitly, so Eros and other process consumers do not have to infer the field shape from live output.
- `TODO.md` now reflects the shipped dead-code workflow split: Miller owns deterministic local fact surfaces (`references export`, CLI-only `references candidates`, and metric-history candidate counts), while Eros owns suppression persistence, cleanup tasks, richer ranking, and multi-workspace/fleet reporting.
- Public install links and plugin manifests now advertise `1.5.1`.

## Upgrade Notes

- Plugin manifests now advertise version `1.5.1`.
- Existing workspaces need no rebuild. `history.db` is a sidecar beside `symbols.db`; this release only fixes/document its health reporting.
