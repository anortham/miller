Why Benchmark Method Tools Install GitHub

Historical run 2026-07-29 · rerun 2026-08-25 on Miller v1.22.1

Same agent and tasks, with Miller or a restricted MCP adapter.

Most code-intelligence tools benchmark against each other. This visible calibration instead used a minimal MCP adapter exposing grep, read_file, and list_files. That adapter was a controlled baseline, not the agent's native shell and file tools, so these results are not a native-agent comparison.

We ran the same agent (Codex, gpt-5.6-sol) on 15 real code-navigation tasks across five pinned repositories, in paired runs: one arm with only grep / read_file / list_files, one arm with the published Miller v1.22.1 archive in its default configuration. Prompts, scoring, and the tool-call and token budgets (enforced by a recording proxy) were the same in both arms. We also ran both arms at doubled budgets.

The numbers on this page come from the 2026-08-25 rerun on Miller v1.22.1: same 15 tasks, same five pinned commits, same model, same seed, same budgets as the first run on 2026-07-29. Four things about the method did change, and they are stated in the finding: the bare-agent adapter was rewritten from its recorded spec because the original source was lost, the harness gained a void-retry limit, a defect in the recording proxy that could void a task pair was fixed, and two snapshots gained extraction-ignore files without changing indexed content. The bare arm is therefore a rebuilt baseline, not a byte-identical rerun of July's.

At the doubled budget, the observed correctness gap remained. The bare adapter stayed flat at 5 correct tasks and kept the same 26.7% wrong-action rate, while Miller went from 11 to 12 correct and from 13.3% to zero wrong actions. Miller is not perfect at either budget. At the frozen budget the bare adapter answered one task in 3 calls that Miller lost by spending all 8. Miller also failed both Run A efficiency gates, frozen and doubled. The gap is a Run A result, not a clean sweep.

Decomposition

Where the advantage comes from.

Five of the fifteen tasks need product-issued exact symbol identity: who references this specific function rather than everything sharing its name, the call path between two symbols, proof that a rename touches every site. The bare adapter could not produce those product identities and went 0 for 5 in every bare run across July and August. On the ten neutral tasks, August Run A scored 7 for Miller and 5 for the adapter at both budgets.

The bare adapter often finds the right evidence and then fumbles it. Counting evidence found regardless of answer quality, the arms are close: 0.72 for bare against 0.77 for Miller at the frozen budget, and 0.65 against 0.77 at the doubled budget. The rewritten baseline adapter finds more evidence than July's did (0.72 against July's 0.59 to 0.66) and still gets the same five tasks right. The result is consistent with failures in exact identity and action selection, but this calibration does not isolate a causal mechanism. Miller is also not the cheap option: it spent more calls and tokens on the both-correct tasks, and both Run A efficiency gates failed.

The lexical core carries most of the result, and the semantic question got its own experiment. After a single run showed the semantic arm losing two tasks at the frozen budget, we reran that off-versus-on pair nine times overnight. The lexical arm won 4 repetitions, the semantic arm won 4, and one tied; the mean on-minus-off difference was −0.2 tasks with a run-to-run standard deviation of 1.9. This experiment detected no average semantic lift on this task mix. It does not establish semantic equivalence or prove no harm, especially because only 2 of the 15 tasks are concept-search shaped. MILLER_SEMANTIC=off remains a supported switch, and lexical-only output is byte-identical either way.

Full method, per-run aggregates, and raw scorer rows are committed in the repository: the 2026-08-25 calibration finding and its evidence exports. The first measurement is kept beside it: the 2026-07-29 finding and its exports. Caveats stated there apply: one model, 15 author-written tasks, five author-controlled repos, and a restricted bare MCP adapter rather than native agent tools. Run A used one configuration run plus disagreement reruns; the semantic follow-up used nine paired repetitions. The harness is in-repo (scripts/bench-agent-efficiency.py) so the runs can be reproduced.

Try it

Run your own comparison.

/plugin marketplace add anortham/miller
/plugin install miller@miller
  • Miller is local-first: it stores SQLite artifacts in your workspace, uses no hosted service, and sends no telemetry off the machine.
  • Semantic retrieval is default-on and fully local; MILLER_SEMANTIC=off is a permanent zero-work switch.
  • Release archives ship the extractor and embedding sidecar, so there is nothing else to install.
