# Vector Artifact Contract v1 — `<workspace>/.miller/vectors.db`

Status: **frozen** (P1). This document is the complete specification of Miller's optional local vector
artifact: its generation identity, invalidation rules, convergence cursors, storage schema, shadow/rollback
lifecycle, writer discipline, and status vocabulary. Phase P2b's `VectorSidecar` writer implements exactly
what is written here; every later phase reads exactly these fields.

**Frozen means frozen.** An implementer may not add, rename, or repurpose a generation-identity field, a
meta key, a table, a column, or a status string. Every value, lane string, and rule below is a decision, not
a suggestion. A genuinely required addition is a **v2**: a new `vectors-v2.md`, a bumped `storage_schema`
schema revision where the change is on-disk, and a re-frozen invalidation matrix. Artifacts written under
different contract versions are never queried by a reader pinned to the other.

The one exception is **pre-ship amendment**: until P2b writes the first `vectors.db` under this contract, no
artifact exists that a v2 could protect, so a defect found in review is fixed in place at this version. No
amendments have been made. Once the first artifact is written, this exception is spent and the v2 rule is
absolute.

**Design source.** [Semantic integration design](../plans/2026-07-19-miller-semantic-integration-design.md)
§5.1 (sidecar class, five-field identity, status), §5.2 (corpus), §5.3 (convergence, writer discipline,
cross-workspace), §5.4 (storage schema). Evidence for the pinned lane:
[`docs/findings/2026-07-19-model-benchmark.md`](../findings/2026-07-19-model-benchmark.md); evidence for the
sqlite-vec runtime: [`docs/findings/2026-07-19-sqlite-vec-aot-spike.md`](../findings/2026-07-19-sqlite-vec-aot-spike.md).

**Ownership posture (ADR-0003).** This artifact is optional, local-first, and off-switchable. Vectors are
generated by the pinned shared `julie-semantic-sidecar` binary
([protocol contract](semantic-sidecar-protocol-v1.md)), never by Miller. Lexical output is byte-identical
whether or not this artifact exists: `search.db` stays lexical-only and the semantic arm is fused after
lexical ranking.

## File placement and activation

| Fact | Value |
|---|---|
| Live artifact | `<workspace>/.miller/vectors.db` (plus `-wal` / `-shm`) |
| Shadow generation under construction | `<workspace>/.miller/vectors.db.rebuild` (plus its `-wal` / `-shm`) |
| Ownership | Miller-owned derived artifact, revision-keyed — same class as `search.db`, `content.db`, `telemetry.db`. Never a source of truth. |
| Source of truth | `symbols.db` (symbol cards) and `content.db` (docs/config chunks). Deleting `vectors.db` loses nothing but compute. |
| Activation env | `MILLER_SEMANTIC` — three-state: `off | shadow | on`. `0` aliases `off`. |

`MILLER_SEMANTIC=off` is a **permanent zero-work guarantee**, not a query-time skip: no model download, no
sidecar child process, no `vectors.db` open, create, or write, no GPU probe, no sqlite-vec extension load,
and zero added latency on any code path. An implementation that opens the artifact "just to report status"
under `off` violates this contract; the status is `disabled`, derived without touching the filesystem.

The writer path mirrors [`SymbolSearchSidecar`](../../src/Miller.Indexing/SymbolSearchSidecar.cs)
(`src/Miller.Indexing/SymbolSearchSidecar.cs:12`) exactly: an `EnvVar` constant, a `Disabled` singleton, a
non-throwing `TryOpen` probe for tests and evaluation, an `OpenRequired` production routing path that fails
visibly (`run \`miller workspace refresh\``) when enabled-but-missing/stale, and an `EnsureCurrent`
lock-holding writer entry point. Enabled-but-broken must never silently degrade to an in-memory fallback;
it degrades to lexical **with a reason**.

## Generation identity

A **generation** is one complete, self-consistent set of vectors in the artifact, identified by five
independent fields stored in `vectors_meta`. Identity is deliberately **not** a single monolithic
fingerprint: a monolith would force re-embedding the whole corpus on every revision stamp or fusion-weight
tweak (design §5.1, doubt-pass correction).

| # | Field | Composition | Governs |
|---|---|---|---|
| 1 | `encoder_fingerprint` | model sha256 + model revision, output dims, tokenizer identity, prompt-template identity, pooling mode, normalization mode | Query compatibility. **A generation is queryable by any encoder whose `encoder_fingerprint` matches, and nothing else about the reader must match.** |
| 2 | `storage_schema` | vector schema revision, quantization lane, element type, dims, distance metric | On-disk vector layout. |
| 3 | `corpus_generation` | card-schema version + chunker/truncation-policy version + corpus scope flags | Which text was embedded. |
| 4 | `reader_compatibility` | writer (Miller) version + **minimum reader version** | Which Miller binaries may open the artifact. Never triggers re-embedding. |
| 5 | `fusion_profile` | RRF k, arm weights, policy version | Query-time ranking only. Lives with the reader, is recorded in telemetry, and **never** invalidates stored vectors. |

### Pinned initial values

**`encoder_fingerprint`** is the lowercase hex SHA-256 of the following newline-joined canonical string,
prefixed with the algorithm tag. Fields appear in exactly this order; a missing value is the empty string,
never omitted:

```
encoder-v1
model_id=<bench-pins candidate id>
model_sha256=<gguf sha256>
model_revision=<gguf file name>
dims=<emitted dims>
pooling=<last|cls>
eos_append=<appended token, or empty>
query_instruction=<verbatim, \n escaped>
document_instruction=<verbatim, \n escaped>
normalization=l2
```

Rendered as `sha256:<64 hex>`. Both pinned models, from
[`eval/model-bench/bench-pins.json`](../../eval/model-bench/bench-pins.json) (single source for model
identity — never re-derive these values):

|---|---|---|

| Model | `Qwen3-Embedding-0.6B`, f16 GGUF | `bge-small-en-v1.5`, f32 GGUF |
| `model_sha256` | `421a27e58d165478cc7acb984a688c2aa41404968b0203e7cd743ece44c54340` | `bf40c42ad7d89382e9ba7376d5c4b73f6b556cb541fab37aaa1da9c320149b65` |
| `model_revision` | `Qwen3-Embedding-0.6B-f16.gguf` | `bge-small-en-v1.5-f32.gguf` |
| Native dims | `1024` (MRL) | `384` (no MRL) |
| Emitted `dims` | `512` (MRL lane) | `384` |

| `eos_append` | `<|endoftext|>` — appended to every input before tokenization | *(empty — no EOS append)* |
| `query_instruction` | `Instruct: Given a code search query, retrieve the code or documentation that answers it\nQuery: ` | `Represent this sentence for searching relevant passages: ` |
| `document_instruction` | *(empty string)* | *(empty string)* |
| `normalization` | L2, always | L2, always |
| `storage_schema` | `vec0-int8-512-cosine-v1` | `vec0-int8-384-cosine-v1` |

> The P1 plan's Global Constraints name the fallback pins entry `bge-small-f32`; the actual key in
> `bench-pins.json` is `bge-small-en-v1.5-f32`. The pins file wins — it is the single source for model
> identity — and this contract records the real key.

**`storage_schema`** format: `vec0-<element>-<dims>-<metric>-v<schema rev>`. Pinned default lane
`vec0-int8-512-cosine-v1`; fallback lane `vec0-int8-384-cosine-v1`. The schema revision suffix is bumped by
any change to table shapes, column names, mapping semantics, or metadata-column set — not by a dims or
element change, which are already encoded in the string.

**`corpus_generation`** starting value: **`cards-v1-chunks-v1`**. Format
`cards-v<card schema>-chunks-v<chunker + truncation policy>`. Card text v1 and the docs/config chunk corpus
are specified in design §5.2; scope flags (all-source chunks, enriched cards, clone body vectors) are
opt-in extensions that bump the corresponding component.

**`reader_compatibility`** is two values: `writer_version` (the full Miller build string `semver+gitsha`, as
stamped everywhere else) and `min_reader_version` (semver only). A reader whose version is below
`min_reader_version` treats the generation as `incompatible` and degrades to lexical — it must not delete or
rebuild it, because an older binary must be able to keep reading its own compatible generation through a
newer binary's upgrade (see [Shadow generations and rollback](#shadow-generations-and-rollback)). Version
strings are not lexicographically orderable as text (`'1.9.0' > '1.13.0'`); comparisons parse semver
components.

**`fusion_profile`** is recorded for telemetry and reproducibility only. It is written by the reader into
telemetry, and stored in `vectors_meta` solely as the profile the writer's own reader-side default was at
build time. Changing it is a reader-side configuration change.

**Quantization order is pinned: slice → renormalize → quantize.** A native vector is first sliced to the
lane dims (MRL), then re-L2-normalized, then quantized to the lane element type. Any other order produces
incompatible vectors under the same `storage_schema` and is a conformance failure.

**Division of labor (settles the question `semantic-sidecar-protocol-v1.md` § Model knob table defers
here):** slice and renormalize live **inside the sidecar shim** — the sidecar serves L2-normalized f32
vectors at the lane dims its `health` declares, and callers never pass MRL knobs (design §4.1: knobs are
keyed by model identity inside the shim). Quantization to the lane element type is the **writer's** job at
storage time, and the **reader's** job at query time (a query vector is quantized identically before KNN
against an int8 lane). The wire therefore never carries quantized vectors.

## Invalidation matrix

Changing a generation-identity field has exactly one defined consequence. Nothing here is discretionary.

| Field | What a change invalidates | Mechanism |
|---|---|---|
| `encoder_fingerprint` | **Every** stored vector — the vector space itself changed. Queries embedded by the new encoder are meaningless against old vectors. | **Shadow rebuild.** Build a full new generation beside the live one; the old generation stays queryable by any reader whose encoder still matches. Atomic promote, then GC after the soak window. |
| `storage_schema` | Every stored vector's on-disk representation (dims, element type, metric, or table shape). | **Shadow rebuild.** Same lifecycle as above; the live vec0 tables cannot be altered in place. |
| `corpus_generation` | Only the corpus units whose constructed text changed under the new card/chunk policy. The vector space is unchanged. | **Targeted re-embed.** Re-construct unit texts, hash-gate on `embed_text_hash`, embed only changed units, in-place. Escalates to shadow rebuild if the changed-unit ratio exceeds the escalation threshold. |
| `reader_compatibility` | **No vectors.** Only which binaries may open the artifact. | **Reader gate.** A too-old reader reports `incompatible` and degrades to lexical; it never rebuilds or deletes. |
| `fusion_profile` | **Nothing.** Never invalidates stored vectors, never triggers re-embedding, never gates readers. | **Nothing.** Query-time only; recorded in telemetry. |

Only changes to fields 1–3 require embedding work: 1 and 2 via shadow rebuild, 3 via targeted re-embed.

Two consequences worth stating explicitly, because getting them wrong is the invalidation bug class this
five-field split exists to prevent:

- A revision stamp advancing does **not** change any identity field. Ordinary convergence re-embeds only the
  units whose source files changed.
- A fusion-weight tweak, an RRF `k` change, or a new fusion policy version does **not** touch the artifact.
  Deployments may ship fusion changes with no rebuild cost at all.

## Cursors

There is **no durable job queue.** julie's `revision_file_changes` table in `symbols.db` is the durable work
log (read through `FreshnessReader.ChangedSince`; the incremental-convergence pattern is the one
`SymbolSearchSidecar.EnsureCurrent` already uses for `search.db`). `vectors.db` holds **two independent
desired-state cursors**, because symbol cards and docs/config chunks have different sources with different
failure and lag behavior (design §5.3, doubt-pass correction).

| Cursor | Meta keys | Source of truth |
|---|---|---|
| Symbol cursor | `symbol_completed_revision`, `symbol_target_revision`, `symbol_last_error`, `symbol_last_error_at` | `symbols.db` |
| Chunk cursor | `chunk_completed_revision`, `chunk_target_revision`, `chunk_last_error`, `chunk_last_error_at`, `chunk_content_schema_version` | `content.db`, itself derived from `symbols.db` |

**Each cursor carries its own last-error.** A failing chunk corpus must never stall symbol-card convergence,
and vice versa. `*_last_error` is a bounded, scrubbed reason string — never query text, source text, or an
absolute path (the RPC-boundary scrubbing rule in design §3 applies to anything persisted here).

**Chunk-cursor precondition (load-bearing).** The chunk cursor advances to revision *R* only after
`content.db` itself proves current at *R*: `content_meta.workspace_revision >= R` **and**
`content_meta.schema_version` equals the value recorded in `chunk_content_schema_version`
([content corpus contract](content-corpus-v1.md) pins `schema_version = 2`). Content-corpus convergence
failures are caught-and-continued today, so a chunk cursor that trusted the workspace revision alone would
claim a revision whose chunks do not exist. If `content.db` is missing, behind, or on a different schema
version, the chunk cursor holds its `completed_revision`, records the reason in `chunk_last_error`, and the
symbol cursor proceeds independently.

**Atomic cursor-advance-with-staged-batch (load-bearing).** Inference happens **outside** any gate: snapshot
the changed-path inputs under the gate, release, embed in bounded batches, reacquire briefly, re-validate
generation identity and `artifact_id`, then commit. The commit is **one short transaction** containing the
vec0 deletes, the vec0 inserts, the mapping-table updates, and the cursor advance. There is no state in
which the cursor claims a revision the artifact only partially contains. If the process dies at any point
before that commit, the next drain recomputes from the unchanged `completed_revision` — replay is idempotent
because re-embedding is gated on `embed_text_hash` per unit.

**Model swap mid-flight:** in-flight inference is cancelled, and any response produced for a previous
generation is never committed. The re-validation step before commit is what enforces this.

**Wake signal:** a bounded, coalescing in-memory signal (capacity 1) connects the indexer-side converger,
which only stamps target revisions and wakes, to the drain loop. The signal is not durable and does not need
to be — the cursors plus `revision_file_changes` fully determine the outstanding work after any restart.

### Escalation to shadow full rebuild

The incremental path escalates to a [shadow full rebuild](#shadow-generations-and-rollback) when **any** of:

1. Delta history is missing — `revision_file_changes` cannot explain the span from `completed_revision` to
   `target_revision`.
2. The changed-vector ratio exceeds the escalation threshold (bulk refactors, mass renames).
3. Any of `encoder_fingerprint`, `storage_schema`, or `corpus_generation` changed.
4. `artifact_metadata.artifact_id` in `symbols.db` changed — a full rebuild was promoted underneath us
   ([`FullRebuildPromotion`](../../src/Miller.Indexing/FullRebuildPromotion.cs) restarts julie's revision
   counter, so rebuilds are **never** detected by revision comparison alone).
5. The per-revision transaction would be too large to commit in one short transaction.

### Status reports the laggier cursor

The compact status line reflects **the laggier of the two cursors**. Exact per-cursor revisions, coverage
counts, fingerprints, and last-errors appear only in JSON `workspace status` / `workspace health`, never in
the compact line.

## Storage schema

**Runtime.** sqlite-vec, pinned per-RID in [`scripts/spike-pins.json`](../../scripts/spike-pins.json) —
version **`0.1.9`**, loaded as a SQLite loadable extension from an absolute packaged path via
`Microsoft.Data.Sqlite` `LoadExtension`. `vec_version()` is verified at open and must equal the pinned
version; a mismatch is `unavailable (sqlite-vec <found> != pinned <expected>)`, not a silent downgrade. Pins
carry per-RID sha256 for all four release RIDs (`osx-arm64`, `osx-x64`, `linux-x64`, `win-x64`), proven by
the P0 Native-AOT hard-gate spike. No alpha-line APIs: **integer vec0 rowids with ordinary mapping tables**;
text-primary-key vec0 is alpha and is not used.

> The P0 spike exercised `float[8]`; the pinned lanes use `int8[...]`. Verifying `int8` vec0 tables on the
> exact pinned extension across all four RIDs is a P2b implementation gate, not a re-litigation of the lane
> choice.

All DDL below is written for the **pinned default lane** `vec0-int8-512-cosine-v1`. `{element}` and `{dims}`
are taken from the lane string: `int8` / `512` for the default, `int8` / `384` for the fallback
`vec0-int8-384-cosine-v1`. Column names, types, constraints, and vec0 declarations are contract-level and
must match; incidental SQLite details (page size, index names beyond those stated, `PRAGMA` tuning) are not.

### `vectors_meta`

```sql
CREATE TABLE vectors_meta (
    key   TEXT PRIMARY KEY,
    value TEXT NOT NULL
) STRICT;
```

| Key | Value |
|---|---|
| `contract_version` | `1` |
| `encoder_fingerprint` | `sha256:<64 hex>` per the composition above |
| `storage_schema` | `vec0-int8-512-cosine-v1` (or the fallback lane) |
| `corpus_generation` | `cards-v1-chunks-v1` |
| `writer_version` | Miller build string `semver+gitsha` |
| `min_reader_version` | semver |
| `fusion_profile` | Reader-side profile id at build time |
| `artifact_id` | `artifact_metadata.artifact_id` of the `symbols.db` this generation was built from |
| `hash_algorithm` | `blake3` — matches the extract artifact's guard |
| `symbol_completed_revision`, `symbol_target_revision`, `symbol_last_error`, `symbol_last_error_at` | Symbol cursor |
| `chunk_completed_revision`, `chunk_target_revision`, `chunk_last_error`, `chunk_last_error_at`, `chunk_content_schema_version` | Chunk cursor |
| `build_state` | `building` \| `ready` — a generation is queryable only at `ready` |
| `build_progress_percent` | Integer 0–100, meaningful only while `building` |

A reader that finds `vectors_meta` missing, unreadable, or missing any of `contract_version`,
`encoder_fingerprint`, `storage_schema`, `corpus_generation` treats the artifact as corrupt (see
[Corruption recovery](#corruption-recovery)).

### Vector tables

```sql
CREATE VIRTUAL TABLE symbol_vectors USING vec0(
    embedding int8[512] distance_metric=cosine,
    path      TEXT,
    kind      TEXT,
    is_test   INTEGER
);

CREATE VIRTUAL TABLE chunk_vectors USING vec0(
    embedding int8[512] distance_metric=cosine,
    path      TEXT,
    kind      TEXT,
    is_test   INTEGER
);
```

- Element type and dims are **parameterized by `storage_schema`** — `int8[512]` for the default lane,
  `int8[384]` for the fallback. The distance metric is `cosine` in both pinned lanes and is encoded in the
  lane string; an implementation must derive the declaration from the lane string rather than hard-coding it.
- `path`, `kind`, `is_test` are vec0 **metadata columns** (filterable at query time). `language` is a
  partition key only if benchmarks later justify it; `path` is **never** a partition key (high cardinality).
- `is_test` is stored for every unit. Test symbols **do** get cards (unlike Julie) and are excluded from
  default search recall via the metadata filter, while remaining available to impact's likely-test ranking
  and explicit test-scoped queries.
- vec0 rowids are integers assigned by the writer and are stable within a generation. They carry no meaning
  across generations.

### Mapping tables

```sql
CREATE TABLE symbol_vector_map (
    rowid_ref       INTEGER PRIMARY KEY,
    symbol_id       TEXT NOT NULL UNIQUE,
    embed_text_hash TEXT NOT NULL,
    revision        INTEGER NOT NULL
) STRICT;

CREATE TABLE chunk_vector_map (
    rowid_ref       INTEGER PRIMARY KEY,
    chunk_id        TEXT NOT NULL UNIQUE,
    path            TEXT NOT NULL,
    embed_text_hash TEXT NOT NULL,
    revision        INTEGER NOT NULL
) STRICT;

CREATE INDEX symbol_vector_map_revision ON symbol_vector_map(revision);
CREATE INDEX chunk_vector_map_path      ON chunk_vector_map(path);
CREATE INDEX chunk_vector_map_revision  ON chunk_vector_map(revision);
```

`rowid_ref` is the vec0 rowid. `embed_text_hash` is the hash of the **constructed** card/chunk text (not the
file content hash): a unit re-embeds only when its constructed text changed, which is what makes replay
idempotent and makes editing one symbol not invalidate its callers' cards. `revision` is the revision at
which the row was last written, and is what a targeted re-embed and the escalation ratio are computed over.

### Query rules

**Determinism.** KNN results are ordered by distance, then by integer vec0 rowid. Ties never resolve
arbitrarily. Dedupe happens before fusion. A generation is queryable **only** by an encoder whose
`encoder_fingerprint` matches exactly and whose version satisfies `min_reader_version`, and only when
`build_state = ready`.

**Glob scoping uses the prefiltered manual-distance path.** vec0 metadata columns do not support `LIKE` or
`GLOB`, so a glob-style `file_pattern` scope must **not** be expressed as a metadata constraint. Instead:
resolve the matching `rowid_ref` set from the mapping table first (ordinary SQL over `path`), then
brute-force distance over that subset. Equality-shaped filters (`kind`, `is_test`, exact `path`) use vec0
metadata constraints directly.

**Oversampling is approximate and is documented as such.** Where prefiltering is impractical, a query may
over-fetch KNN candidates and filter afterwards. This is an approximation — the true top-k under the filter
is not guaranteed — and it is used **only** where prefiltering is impractical, never as the default path for
glob scoping.

**Concurrency.** Inference happens before the write transaction. The write is delete + insert + mapping +
cursor advance in one short transaction. WAL mode, with an autocheckpoint policy and short reader snapshots
(long-lived readers block checkpointing). Fragmentation past threshold triggers a shadow rebuild rather than
in-place compaction.

## Shadow generations and rollback

The shadow lifecycle follows the lessons already encoded in
[`FullRebuildPromotion`](../../src/Miller.Indexing/FullRebuildPromotion.cs)
(`src/Miller.Indexing/FullRebuildPromotion.cs:69`): **build beside, then promote — never merge into the live
served file.**

1. **Build.** The shadow generation is written to `vectors.db.rebuild`, a fresh sibling in the same directory
   (same directory ⟹ same filesystem ⟹ atomic overwrite-move on POSIX). Any stale `.rebuild` trio
   (`.rebuild`, `-wal`, `-shm`) is deleted first. The live `vectors.db` stays fully queryable throughout;
   readers see no interruption and no partial generation.
2. **Self-containment.** Before promote, the shadow's WAL is folded into its main file, and the live
   artifact's old `-wal`/`-shm` are removed so the promoted file can never pair with stale sidecars
   (cross-inode WAL replay reads garbage pages). Every reader connection to this artifact opens with
   pooling disabled, exactly as extract-DB opens do, so wholesale file replacement is safe.
3. **Promote.** Overwrite-move the shadow over the live path. A failed promote leaves the live artifact
   untouched — strictly better than a failed in-place merge. The caller must hold Miller's single-writer
   lock. Where antivirus or held handles need longer retries, the same promote-retry timeout policy as the
   extract artifact applies.
4. **Rollback.** The last compatible generation is preserved through an incompatible upgrade: an older
   Miller binary, or a reader whose `encoder_fingerprint` still matches the previous generation, keeps
   reading it until GC. Rollback is therefore "do not GC yet", not a restore operation.
5. **GC.** Abandoned and superseded generations are deleted after a soak window. GC never runs while a
   compatible reader is known to be live against the generation, and never deletes the only `ready`
   generation.

Full rebuilds **promote, never merge.** An implementation that points a full rebuild at the live served
`vectors.db` violates this contract for the same reason the extract path forbids it: live readers keep the
WAL from checkpointing and the in-place merge collapses to a crawl.

## Writer discipline

- **Only the writer-lock holder embeds corpus units or mutates `vectors.db`.** Corpus embedding, vec0
  mutation, mapping writes, cursor advances, promotes, and GC are all leader-only.
- **Any reader process may embed queries.** A reader embeds through its own embedding session against a
  generation whose `encoder_fingerprint` is compatible; query embedding writes nothing to the artifact. This
  is what lets a swarm of reader instances serve semantic search without contending for the writer lock.
- **Cross-workspace rule.** Foreign workspaces get vector *convergence* only from their own leader. The
  cross-workspace refresh write-lease ends when the refresh call returns, so asynchronous foreign embedding
  is illegal and the cross-workspace refresh service performs **no** vector convergence. Cross-workspace
  **reads** use an already-`ready`, compatible generation when one exists, and degrade lexically when none
  does, with the reason `vectors: not built — open workspace to build`.
- **Backpressure.** Bounded batches, a retry budget, poison-input isolation (a unit that repeatedly fails to
  embed is flagged and skipped, never retried forever), and a disk-space preflight requiring 2–3× the
  expected artifact size including WAL and temp files. Failing preflight is `disk-blocked`, not a crash.
- **Initial build** runs in the background with progress in status. The semantic arm is not offered until
  the generation is `ready`; lexical behavior is untouched throughout.
- **Fail-visible, never fail-silent.** Missing, stale, incompatible, or corrupt artifacts degrade to lexical
  with the reason surfaced in `workspace status` / `workspace health` and telemetry — the same posture as
  the search sidecar.

### Corruption recovery

`vectors.db` registers with
[`SidecarCorruptionRecovery`](../../src/Miller.Server/Hosting/SidecarCorruptionRecovery.cs)
(`src/Miller.Server/Hosting/SidecarCorruptionRecovery.cs:7`), which detects corruption-shaped failures
(`SQLITE_CORRUPT` / `SQLITE_NOTADB`, primary or extended, anywhere in the exception chain) and responds by
deleting the derived artifact and rebuilding it.

Recovery for this artifact is **per generation**: a corrupt generation is deleted and rebuilt on its own.
Recovery **never touches `symbols.db`** — the source of truth is unaffected by any vector corruption, and
the worst case is recomputed embeddings. If the rebuild itself fails, the failure is logged and retried on
the next convergence; the reported status is `unavailable (<reason>)` in the meantime.

## Status vocabulary

The compact status line uses **exactly** these strings — this vocabulary is verbatim from design §5.1 and is
frozen. Availability and convergence are separate concerns; this vocabulary deliberately does not overload
one enum with both.

```
vectors: ready | ready (updating; N files pending) | building 42% (not queryable) |
         downloading | unavailable (reason) | incompatible | circuit-open | disk-blocked | disabled
```

| Status | Meaning |
|---|---|
| `ready` | A `ready` generation exists, both cursors are caught up, and the reader's encoder is compatible. |
| `ready (updating; N files pending)` | Queryable and serving, but the laggier cursor is behind by `N` files. |
| `building 42% (not queryable)` | Initial build or shadow rebuild in progress; percentage from `build_progress_percent`. No semantic arm is offered. |
| `downloading` | The sidecar is acquiring its pinned model; no vectors yet. |
| `unavailable (reason)` | Enabled but unusable — missing artifact, failed open, sqlite-vec version mismatch, failed rebuild. The reason is always stated. |
| `incompatible` | A generation exists but the reader's `encoder_fingerprint` does not match, or the reader is below `min_reader_version`. Degrades to lexical; never rebuilds. |
| `circuit-open` | Repeated sidecar failures tripped the circuit breaker; convergence is paused. |
| `disk-blocked` | Disk-space preflight failed; convergence is paused rather than filling the disk. |
| `disabled` | `MILLER_SEMANTIC=off`. Derived without touching the filesystem. |

Exact revisions, coverage counts, per-cursor errors, and all five identity fields appear in JSON
`workspace status` / `workspace health` output only, never in the compact line. Facts flow through the
existing workspace-facts assembly and render paths, exactly as search-sidecar facts do.

## Conformance

An implementation conforms to this contract when:

1. All five generation-identity fields are present in `vectors_meta` with the composition specified above,
   and each field's change produces exactly the mechanism in the [invalidation matrix](#invalidation-matrix).
2. Both cursors exist independently, each with its own last-error; the chunk cursor never advances past what
   `content.db` proves; and no observable state has a cursor ahead of its staged batch.
3. Table shapes, column names, and vec0 declarations match the [storage schema](#storage-schema) for the
   declared `storage_schema` lane, and `vec_version()` matches the pin at open.
4. Quantization follows slice → renormalize → quantize, and emitted vectors satisfy the frozen tolerance
   policy in the [sidecar protocol contract](semantic-sidecar-protocol-v1.md): dims exactly equal to the
   lane, L2 norm within `1e-3` of 1.0, cosine similarity `≥ 0.999` to the CPU-generated golden vectors in
   [`eval/sidecar-conformance/`](../../eval/sidecar-conformance/).
5. `MILLER_SEMANTIC=off` performs zero work by the definition in
   [File placement and activation](#file-placement-and-activation).

The invariant this contract exists to guarantee: **two independent implementations of this document produce
artifacts each can query, and neither can produce an artifact the other silently misreads** — because every
way they could disagree is either pinned here or encoded in an identity field that gates the read.
