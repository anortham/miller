## Review Findings

1. **Package-only validation has not run for `0.3.0` yet.**

   Run the release workflow with `publish=false` after the version bump is committed and pushed:

   ```bash
   gh workflow run release.yml \
     -f version=0.3.0 \
     -f prerelease=false \
     -f publish=false \
     -f allow_overwrite=false
   ```

   This is the required release gate because it exercises all four platform packages, checks archive shape,
   verifies `miller version`, verifies the pinned `julie-extract`, and runs packaged MCP smoke checks.

2. **Local `main` is ahead of `origin/main`.**

   At review time, `origin/main` pointed at `c3d830b`, while local `HEAD` was `6f893d4` before this bump. The
   package-only workflow must run from pushed release-candidate commits, not a local-only tree.

3. **The latest failed release workflow is not a `0.3.0` blocker.**

   GitHub run `27108384446` was the tag-push workflow for the already-published `v0.2.0` tag. The platform build
   jobs completed, then the publish job refused to overwrite a published stable release without overwrite approval.
   That is the intended guardrail, not evidence that the package matrix is broken.

4. **Current TODO items are not automatic release blockers.**

   `TODO.md` still contains:

   - Eros contract hardening as concrete Eros workflows need more stable facts or operations.
   - Product-fit triage for ideas from `~/source/julie/TODO.md`.

   Neither is a must-fix for `0.3.0` unless the release goal changes to include those new product surfaces.
