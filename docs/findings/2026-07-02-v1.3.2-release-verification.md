## Incident Context

`v1.3.2` was published a day late. The release-prep commit `07232c0` reached `origin/main` on
2026-07-01 without a published release, so marketplace clients immediately advertised 1.3.2 while
the plugin launcher's `releases/download/v1.3.2/…` URLs returned 404 (field report on 2026-07-02:
marketplace update failed to find the archive; the user rolled back to 1.3.1). Publishing was
completed on 2026-07-02.

## Source And CI

- Release prep commit: `07232c0 release: prepare Miller 1.3.2`.
- Prep push CI: `28552058436` passed.
- Tag `v1.3.2` pushed at `07232c0` on 2026-07-02.
- Tag release run `28592841424`: all four platform builds passed; the `publish GitHub release`
  job failed with `HTTP 403: Resource not accessible by integration`. GitHub requires the
  ungrantable `workflows: write` scope to create a release targeting a commit whose diff against
  the default-branch HEAD touches `.github/workflows`, and workflow-touching commits had landed
  on `main` while the tag build was running.
- Promote dispatch `28593597828` refused the source run (overall conclusion `failure`).
- Published locally from the tag run's verified artifacts: `gh run download 28592841424`, then
  `scripts/release-promote.sh --version 1.3.2 --artifacts-dir <dir> --target 07232c0… --prerelease false`
  (dry run first; all four archives matched their `.sha256` sidecars before upload).
- `git ls-remote --tags origin v1.3.2` resolves to `07232c033ae7b6d8b0ebfa9311539197cf29c2dd`.
- `gh release list` marks `Miller v1.3.2` as Latest; `prerelease=false`, `draft=false`.
- Follow-up hardening: `scripts/release-promote.sh` now omits `--target` when the tag already
  exists, so tag-push publishes no longer trip the workflow-scope check.
