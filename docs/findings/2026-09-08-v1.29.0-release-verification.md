# Miller 1.29.0 release verification

This is the pre-publication verification record for Miller 1.29.0. The candidate is prepared locally; no commit
has been pushed, no package workflow has been dispatched, and no release or marketplace update has been
published.

## Scope

Miller 1.29.0 improves agent guidance, navigation, context, editing, search truthfulness, continuous-testing
workflows, and shared-store reader freshness. It adds no MCP tools. The release advances the bundled extractor
to `julie-extract 2.42.0`, raises Miller's independently qualified reader capability to 2.42.0, and keeps the
semantic sidecar at 0.1.0 and sqlite-vec at 0.1.9. Miller's SQLitePCLRaw runtime is SQLite 3.53.4.

All seven release version fields are aligned at 1.29.0: `Directory.Build.props`, `miller-plugin.json`, the
Claude, Cursor, and Codex plugin manifests, and both version fields in the Claude marketplace manifest.

## Qualification status

- Public `julie-extract 2.42.0` release, tag, commit, four archive hashes, internal binary hashes, and Linux
  version output are recorded in the [extractor adoption finding](2026-09-08-julie-extract-2.42.0-adoption.md).
- The extractor keeps artifact schema 7, extract contract 4, JSONL schema 5, report schema 3, family-store schema
  2, format epoch 1, and extraction identity epoch 10. New families stamp reader floor 2.42.0; existing families
  retain their prior floor. Miller refuses unqualified 2.42.1 and 2.43.0 floors.
- The 1.29.0 candidate Release build passed with zero warnings and errors.
- Linux fast suite passed 10,457 tests with 9 expected skips and zero failures.
- Linux Scale suite passed 233 tests with 38 expected skips and zero failures.
- Reader-to-leader protocol and caller qualification passed 694 tests with one expected skip and zero failures.
- Two-process MCP fixtures proved blocking no-change and edited reads, nonce isolation after timeout, bounded
  background settling, and direct recovery after leader exit. Both reader and leader must restart onto 1.29.0
  before the new reconcile operation is available.
- Plugin tests passed 100 cases. Cursor-style launcher smokes from `/` and a non-Miller project completed
  `initialize` and `tools/list` with all ten tools at candidate source commit `46fb8cc1`. These checks must be
  repeated after the 1.29.0 manifest change.

## Windows gate status

The first Windows fast run at `46fb8cc1` completed 10,405 tests, skipped 58, and reported three failures. Two
were cross-platform test expectation defects: a JavaScript recipe expected the Unix executable name instead of
the configured Windows executable path, and the multi-file edit convergence assertion compared a normalized
Windows path with a mixed-separator string. Their combined Linux focused scope passed 45 tests after correction. The
third failure was the existing five-second CT acknowledgement test under full-suite contention; all four theory
rows passed in a focused Windows rerun without changing production code or its deadline.

A complete Windows fast rerun against the committed 1.29.0 candidate remains required. Package-only workflow
validation, promotion, public asset checks, release-body equality, and live marketplace verification also remain
pending.

## Publication boundary

The public README still names the latest published release, 1.28.1. It must change only after live GitHub release
facts exist. The release-prep commit and GitHub release must be published in the same approved session because
marketplaces serve manifests from `origin/main`.
