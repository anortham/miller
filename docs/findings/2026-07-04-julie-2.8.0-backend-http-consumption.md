# julie-extract 2.8.0 backend-HTTP consumption — dogfood evidence (2026-07-04)

Miller's pin moved `2.7.0 → 2.8.0` and the `backend-http` bridge provider now consumes the full v2.8.0
"finish the HTTP boundary lane" surface: six more backend stacks (NestJS, Kotlin+Spring, Laravel, Phoenix,
axum, actix) and four more `http.client_request.v1` languages (Kotlin, PHP, Elixir, Rust). Upstream spec:
`~/source/julie-extractors/docs/plans/2026-07-03-miller-http-boundary-consumer-followup.md`.

## What Miller consumes now

- **Zero-code (pin only):** Kotlin+Spring routes reuse `spring.request_mapping.v1` (upstream extended its
  `languages` to `[java, kotlin]`); Kotlin/PHP/Elixir/Rust client calls reuse the non-language-gated
  `http.client_request.v1`. Both join with no consumer change.
- **6 plain route families → `BackendRoutePatternIds` (now 16):** `nestjs.route.v1`, `laravel.route.v1`,
  `phoenix.route.v1`, `axum.route.v1`, `actix.attribute_route.v1`, `actix.scope_route.v1`. Each carries
  `normalized_route_template` (actix.scope also `effective_route_template`), so `TryReadBackendRoute` joins them
  with no family-specific read. actix's two provenances (attribute macros + scope call routing) mirror the
  shipped ASP.NET attribute-vs-call split.
- **2 resource-declaration families → Rails-style expansion:** `laravel.resource_route.v1`
  (`resource`=7 routes / `api_resource`=5, update answers PUT+PATCH) and `phoenix.resource_route.v1` (8 routes,
  destroy action `delete`). These carry no `normalized_route_template` — they are aggregate declarations, expanded
  to concrete verb-known handlers in `BackendHttpBridgeProvider`, exactly as `rails.resource_route.v1` already was.
  Laravel controller actions bind by the `controller` reference's leaf name. Phoenix bases on
  `normalized_resource_path` (which ALREADY folds in the same-file `scope` prefix) and therefore does NOT re-apply
  `route_group_prefix` — a scoped `scope "/api" do resources "/posts" end` expands once to `/api/posts…`, not twice.
- **4 prefix/mount families → whitelist + `IsMountFactPattern` + `RouteFamilyForMount`:** `axum.nest.v1`
  (→ axum.route), `actix.mount.v1` (→ actix.attribute_route; the `web::scope(...).configure|.service` case),
  `phoenix.forward.v1` (→ phoenix.route), all anchored cross-file by `mount_target` via the existing
  `AnchorByIdentifier`; `laravel.route_prefix.v1` carries no `mount_target`, so it is target-less evidence
  (unanchored, composes nothing — its same-file effect already rides `effective_route_template` on the route
  facts).

Total backend route/mount fact families the provider spans: **28** (16 from 2.7.0 + 12 from 2.8.0).

## Consumer read side (correctness note E)

`SqliteBridgeReader.ReadStructuralFacts` loads every whitelisted row (`ORDER BY path, start_byte,
structural_fact_id`) with **no** fact-id dedup, and `BackendHttpBridgeProvider` never dedups by `FactId`. So
same-span multi-verb facts (Laravel `Route::match`, Rails `via:`) are never dropped on Miller's read side; the
fact-id-collision concern is julie's write path (pre-existing, tolerated). ✓

## Adversarial review → 4 fixes (the tests were lying)

A multi-agent adversarial review against the upstream contract caught **four real defects** that the first cut of
the tests MASKED by using contract-unfaithful fixture data (and that the scale test missed by using the *easy*
shapes). Each produced a missing/wrong bridge edge on real v2.8.0 data. All four are fixed; the masking tests were
corrected to contract-faithful data and the scale fixture upgraded to the hard shapes.

1. **Phoenix scoped-resource double-prefix (high).** `ExpandPhoenixResource` based routes on
   `normalized_resource_path` (which already folds in the `scope` prefix) AND re-applied `route_group_prefix` →
   `/api/api/posts`. Fix: use the normalized path verbatim and do not re-apply the prefix; apply the prefix only on
   the raw-`resource_path` fallback. (`BackendHttpBridgeProvider.ExpandPhoenixResource`.)
2. **Phoenix `forward` never anchored namespaced modules (high).** `AnchorByIdentifier` leaf-stripped
   `MyAppWeb.AdminRouter` to `AdminRouter`, but Elixir names the module symbol by its full dotted alias → miss on
   all real (namespaced) Phoenix. Fix: new `AnchorByModuleName` matches the whole module-name target.
3. **Rust `::`-qualified mount targets dropped (medium).** `.nest("/api", api::routes())` /
   `.configure(admin::configure)` emit `mount_target` with `::`, which `ExtractIdentifier` rejected. Fix: fold `::`
   to `.` before taking the leaf identifier.
4. **Laravel `{id?}` optional param unmatchable (medium).** `effective_route_template` preserves the raw `{id?}`;
   `FileRouteMatcher.SuffixStart` treated the `?` as a query separator and truncated to `/…/{id`. Fix: recognize the
   brace-optional marker (`?}`) so the segment stays dynamic. (`FileRouteMatcher`.)

One reviewer finding was correctly **rejected**: `actix.mount` mapping only to `actix.attribute_route` (not also
`actix.scope_route`) is a documented single-provenance limitation, not a wrong edge.

## Not done (intentional)

No publish/release has been performed from this evidence. The consumer work is landed in the working tree and
verified; the release decision is the user's. Upstream-documented exclusions (`nestjs.global_prefix`, Ktor server routing,
`RouterFunction`/`coRouter`, Symfony `#[Route]`, axum 0.7 `:id`, all interpolated/`format!`/heredoc/sigil route
args) need no Miller work — they never emit.
