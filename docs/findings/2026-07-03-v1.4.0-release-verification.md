## Incident Context

The first `v1.4.0` tag (at prep commit `8335635`) failed all four platform builds in release run
`28633117793`. Root cause: the new backend-http code path
(`BackendHttpBridgeProvider.ParseActionList`) used reflection-based
`JsonSerializer.Deserialize<List<string>>`, an IL2026/IL3050 **error** under the release
workflow's Native AOT publish. Normal CI never AOT-publishes, so the branch was green everywhere
until the tag build. A workflow wrinkle masked the real failure: the `Publish` step runs in
PowerShell, where a failed `dotnet publish` does not abort the step, so the jobs failed later at
`Verify packaged … extractor` on `missing packaged … miller`.

Fix `4f7b841` parses with AOT-safe `JsonDocument` (same JSON-array-else-tolerant-split
semantics). Because no release had been created from the broken tag, `v1.4.0` was deleted and
re-pushed at the fix commit. Unlike v1.3.2, the tag-push `publish GitHub release` job succeeded
directly — the range contained no workflow-touching commits, so the workflow-scope 403 did not
apply.

Hardening candidates recorded (not yet implemented): enable AOT analyzers
(`IsAotCompatible`) on the library projects so reflection-JSON regressions fail ordinary CI, and
make the workflow `Publish` step fail fast on a failed `dotnet publish`.
