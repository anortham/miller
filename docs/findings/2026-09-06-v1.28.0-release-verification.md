## Initial live dogfood

The leader imported the merged source in 156.363 seconds. Its manifest was published about
11 seconds into the import, followed by deep-fact extraction. The producer correctly rejected
new reader registrations while its writer lease was live. The import completed without a
process kill or a live database repair.

Two defects gate publication:

1. A temporary reader-admission `Busy` became `artifact_missing`. Readability probes swallowed
   the typed exception, selected a foreground refresh, and treated the unavailable probe as
   a missing artifact. The repair must preserve a retryable admission diagnostic and must
   not bypass retention or serve an unprotected legacy artifact.
2. Sidecar cursor acknowledgement timed out. The extractor maintenance command inspected
   all manifests and calculated garbage-collection facts before changing a single cursor.
   The live store had 3,464 manifests, 7,128,961 manifest entries, and 14,619 versions.
   Cursor children consumed a CPU core until Miller's 10-second deadline killed them;
   retries caused approximately 60-second failed convergence phases. A producer repair
   must remove unrelated inspection work while preserving cursor safety and report semantics.

The Miller diagnostic repair now passes 289 focused Debug tests, including nine new
regression/control cases. Five cases failed for the intended reasons before the repair.
The exact Busy refusal propagates through readiness checks and renders
`reader_admission_busy` with retry guidance. Other retention failures retain their prior
classification. No reader protection is bypassed, and the running Release output is unchanged.

The producer correction is committed on `fix/cursor-command-cost` at `1b1584d6`.
It retains reader-compatible cursor eligibility even when the store's fact writer is newer.
Cursor reports add `measurement_scope=cursor_only`; unrelated GC measurements are explicitly
unmeasured. Existing coordinator mutation checks remain in force.

On the same million-entry fixture, alternating released and patched Release binaries after
warm-up, three measured runs gave p95 advance 2.368428 s to 5.390608 ms and release
2.445090 s to 4.701579 ms. The Windows diagnostic suite remained active in the background.
The corrected source passed 4,816 default tests, 376 contract tests, and the unchanged 119-test
xtask scope; Release build, Clippy and formatting passed. Producer Windows checks remain pending.

The patched binary also completed read-only cursor plans against the live seven-million-entry
store. After warm-up, advance took 3.05–4.22 ms and release 3.01–4.00 ms. These were plan-only
calls: no live cursor was created, advanced, or removed. Those live timings used the initial
candidate before removal of its overly restrictive writer-version check; final paired fixture
timings above cover the compatibility-corrected source.

After the import and search-sidecar convergence, live symbol search and inspect found
`StoreSidecarCursorSession` and `ContextQueryService`. Context with an explicit cursor-class
anchor and usage references selected that class and its dependencies. Content search found
the release-process document. These checks establish partial recovery, not release readiness.

## Windows gate

The dedicated NTFS guest successfully synced the exact initial source commit. The fast-suite
command then stopped returning output. Subsequent read-only commands also hung during the
repository-existence preflight; a separately bounded command timed out after 30 seconds.
The guest reported running. No test result, completed log, or Windows pass is claimed.

The command eventually returned a build failure, not a test failure: the guest still had
extractor 2.40.3 while the source pinned 2.40.4. The guest recovered without a restart.
After syncing source `8350661f` and restoring the verified 2.40.4 archive, the next full run
timed out at 900 seconds. Buffered output showed continued progress without failed assertions.
A diagnostic rerun with per-test hang detection completed 8,268 passing and 52 skipped cases
before cancellation for targeted performance investigation. Neither incomplete run is a pass.

A captured stack was constructing `StoreFixture` in SQLite. Its 24 schema/seed statements
each committed separately. The six-case
`BoundedFactsEnvironmentSwitchRestoresTheWholeGenerationLoad` filter passed in every baseline
run; measured test-duration sums were 4.416356, 4.5120318 and 4.3372587 seconds after warm-up.

The fixture repair wraps the existing SQL in one transaction without changing durability,
pooling, schema, data, or coordinator initialization. A real-fixture regression failed with
file change counter 24 before the repair and passed with counter 1 afterward. Integrity,
table/row counts and visible manifest facts also pass; 508 focused Linux tests are green.
Controlled Windows after-measurement and the complete Windows gate remain pending.
