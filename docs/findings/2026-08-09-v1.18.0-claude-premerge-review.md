# Miller v1.18.0 Claude pre-merge review

The release candidate at `0ff6c060` received one fresh, read-only Claude Code adversarial review before
publication. Claude inspected the complete 15-commit branch range: 116 files and about 12,000 changed lines.
A second security-focused pass attacked the same range. No external-model policy was declared, so the full
diff was sent to Anthropic. The combined verdict was `needs-attention`.

The two passes reported 22 findings before overlap was removed. The lead verified each claim against the
source and executable contracts rather than accepting the review wording. The release stayed paused while
the confirmed defects were repaired.

## Confirmed and fixed

- Store subprocess waits now use progress-aware stall detection plus the existing configurable hard cap.
- Rollback export is one-shot. A stale, missing, moved, or unreadable store pointer warns and returns to the
  ordinary legacy reconcile path instead of permanently blocking bootstrap.
- Store reads reject generation, database, resolution-base, symlink, absolute-path, and parent-path escapes
  before opening or attaching SQLite files.
- `patterns`, usage-enriched `context`, content imports/search/reads, and content-backed editing all use the
  active store snapshot and store content sidecar.
- Store request identities survive a Miller process restart in a locked workspace journal. Nonterminal
  retries reattach to the original Julie request; terminal observation removes the journal.
- Freshness identity includes the family, view, generation, manifest, and resolution binding instead of the
  constant family UUID alone.
- Revision deltas compare the pinned view's immutable manifests and report exact changed/deleted paths.
- Vector convergence consumes those exact paths; resolution-only store-log advances no longer enumerate the
  full vector corpus.
- A failed first import that created a store directory but no `CURRENT` pointer remains retryable.
- Dashboard reads contain expected pointer, SQLite, format, and I/O failures as typed unavailable facts.
- Cross-workspace sidecar failures now reach the refresh warning instead of disappearing in an empty catch.
- Store scan supervision uses the workspace `.miller` directory, creates its spool directory, and no longer
  writes scan progress into the producer-owned family store.
- Existing legacy artifacts loaded through the compatibility conversion now carry their real metadata and
  revision snapshot rather than a fabricated revision-zero snapshot.

## Reviewed and not changed

- Store repair intents all run a Full producer import. The public store operation is the repair boundary, so
  preserving the legacy intent label inside that operation would not change the healing behavior.
- Store sidecars live under the family store by design, in producer-separated `sidecars/` paths. Miller does
  not mutate producer tables or generation contents.
- The compatibility projection currently materializes a view-scoped manifest for each read session. This is
  a measured Ph5 default-on decision, not a Ph3 correctness defect; v1.18.0 keeps store mode opt-in.
- Invalid `MILLER_INDEX_STORE` values fail fast instead of guessing operator intent.
- Nonexistent artifact paths used by pure tests retain an explicit deferred compatibility snapshot. Real
  existing artifacts open and read their actual snapshot, and production callers use the session factory.
