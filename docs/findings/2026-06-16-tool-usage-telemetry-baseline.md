Findings:

- Historical rows often have `error_kind` but blank `error_message` and `error_detail`.
- Current HEAD has tests proving `TelemetryScope.SetError()` persists message/detail for the main catch paths.
- The first current defect is log correlation, not error persistence: JSONL logs did not carry a `cid` for normal
  tool calls unless the tool body itself logged inside the call.
- Follow-up log correlation showed most old `IncompatibleExtractException` rows were expected operational failures
  during extractor/schema upgrades, and many old `InvalidOperationException` rows were graceful tool-level error
  strings rather than protocol-level `tools/call` failures.

This branch fixes that by adding one Miller-owned per-call diagnostic line from the central filter, inside the
existing `cid` scope. That gives every call at least one log row joinable to `tool_telemetry.id`.

The same follow-up found one current UX defect: invalid `search(regions=...)` input returned only
`regions must be a comma list...`, which was technically accurate but gave no call-shaped example. This branch
changes that compact error to include `regions=comment` and `regions=doc_comment,string_literal` examples without
touching server instructions or tool descriptions.

## Telemetry Added For Next Pass

This branch keeps the telemetry schema stable and records new dimensions in the existing `op` column and
`metadata_json` object. It deliberately avoids raw query, target, path, snippet, and source text values.

New `op` coverage:

- `search`: requested mode, or `regions` when source-region search overrides the mode
- `content`: operation (`import`, `add_markdown`, `search`, `read`, `list`, `remove`, `export`)
- `patterns`: operation (`list`, `summary`, `search`)
- `inspect`: `summary` or `full`
- `trace`: mode (`auto`, `path`, `bridge`)
- `impact`: input kind (`target`, `changed_paths`, `diff`, `missing_input`)
- `context`: reference mode (`off`, `usage`)
- `edit`: requested edit operation

New `metadata_json` keys used where applicable:

- `search_backend`, `route`, `format`, `limit_bucket`
- `content_kind`, `workspace_all`, `has_workspace_selector`
- `has_regions`, `has_file_pattern`, `has_language`, `has_scope`, `has_kind`, `has_path`, `has_where`
- `has_pattern_id`, `has_to`, `has_entry_symbols`, `has_failing_test`, `has_stack_trace`
- `max_depth_bucket`, `depth_bucket`, `max_hops_bucket`, `reference_depth_bucket`, `token_budget_bucket`
- `exclude_tests`, `apply`, `allow_stale`
- `empty_reason`: query-safe enum such as `no_symbol_hits`, `no_content_hits`, `no_pattern_facts`, `not_found`,
  `no_trace_edges`, `no_path`, `no_bridge_path`, `no_impacted_symbols`, `no_context_symbols`, `edit_noop`
- `error_category`: query-safe enum such as `bad_input`, `unknown_workspace`, `not_found`,
  `stale_or_incompatible_index`, `missing_file`, `filesystem`, `internal`

Example next-pass query:

```sql
SELECT tool,
       COALESCE(op, '(none)') AS op,
       json_extract(metadata_json, '$.empty_reason') AS empty_reason,
       COUNT(*) AS calls
FROM tool_telemetry
WHERE outcome = 'empty'
GROUP BY tool, op, empty_reason
ORDER BY calls DESC;
```

Polish targets:

1. Improve `search` empty-state text first. This branch changes symbol-search misses from `No results.` to a
   one-line hint that suggests a shorter symbol query or the explicit `mode=source`/`mode=content` text modes.
2. Improve invalid `search(regions=...)` text. This branch keeps the valid values compact and adds example syntax.
3. Keep `inspect` empty-state text under observation. Current tests already cover not-found, near-miss, wrong-scope,
   and ambiguity guidance.
4. Keep `trace` under observation. Current tests already cover no-neighbour, no-path, bridge-not-on-chain, and
   JSON diagnostic outputs.
5. Keep `content`, `patterns`, and `edit` discoverability changes small. Claude Code has server-instruction and
   tool-description character limits; `MILLER_AGENT_INSTRUCTIONS.md` is guarded by a 12,000-character
   CRLF-normalized test budget.

## Reproduction Query Shape

The baseline can be reproduced from the telemetry ledger with read-only SQLite:

```sql
SELECT tool,
       COUNT(*) AS calls,
       SUM(CASE WHEN outcome = 'error' THEN 1 ELSE 0 END) AS errors,
       SUM(CASE WHEN outcome = 'empty' THEN 1 ELSE 0 END) AS empty,
       ROUND(AVG(duration_ms), 1) AS avg_ms,
       MAX(duration_ms) AS max_ms,
       COALESCE(SUM(est_tokens), 0) AS est_tokens,
       MAX(ts) AS last_ts
FROM tool_telemetry
WHERE ts < '2026-06-16T00:00:00.000Z'
GROUP BY tool
ORDER BY calls DESC, tool ASC;
```

For error triage:

```sql
SELECT tool,
       COALESCE(error_kind, '(none)') AS error_kind,
       COUNT(*) AS calls,
       MIN(ts) AS first_ts,
       MAX(ts) AS last_ts
FROM tool_telemetry
WHERE ts < '2026-06-16T00:00:00.000Z'
  AND outcome = 'error'
GROUP BY tool, error_kind
ORDER BY calls DESC, last_ts DESC;
```

For empty-result triage:

```sql
SELECT tool,
       workspace_root,
       COUNT(*) AS calls,
       MIN(ts) AS first_ts,
       MAX(ts) AS last_ts
FROM tool_telemetry
WHERE ts < '2026-06-16T00:00:00.000Z'
  AND outcome = 'empty'
GROUP BY tool, workspace_root
ORDER BY calls DESC
LIMIT 40;
```
