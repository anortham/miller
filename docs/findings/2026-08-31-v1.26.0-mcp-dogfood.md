## High defects (product)

### F1. Nonsense query with a trailing number returns junk hits

**Call:** `search query="doesnotexistxyzzy123"` on miller.

**Got:** ranked hits on `pid = 123` / `pid=123` in `scripts/tests/test_perf_recovery.py`, plus `next: inspect target="pid"`.

**Control:** `search query="doesnotexistxyzzy"` returned empty (`diagnostic_code=no_symbol_hits`).

The tokenizer or numeric fallback treats a unique garbage token as a match on the
trailing integer. That is worse than empty: the agent follows a wrong inspect
target.

### F2. `inspect depth=full` continuation splices the body mid-word

**Call:** `inspect target=FullRebuildPromotion depth=full`, then the returned
continuation token.

First page ended at byte 4096 on the letters `pr` of `private`. The continuation
page opened:

```
ivate static void FoldWalIfPresent(string rebuildDb)
```

The two pages cannot be concatenated into source. Continuation should start at a
line (or token) boundary, or repeat enough overlap to reassemble the body.

Also: `depth=full` still printed `... 2 more children (use depth=full)` on both
pages. The continuation only advances the body, not the children list. The
nudge is a lie.

### F3. `insert_before` / `insert_after` previews omit a newline

**Call (preview only, not applied):**

- `edit operation=insert_before target=RebuildDbPathFor old_text="public static string RebuildDbPathFor(string absDbPath)" new_text="// dogfood preview only"`

```
+    // dogfood preview onlypublic static string RebuildDbPathFor(string absDbPath)
```


Applying either preview would produce invalid C#. `replace_text` on the same

### F11. Inspect full refs include line `0,0`

`inspect target=FileOperationRetryOptions depth=full`:

```

```

Line 0 is not a source location. Visibility also printed `private` for an
`internal readonly record struct`.

**Line 0:** fixed on `fix/v1.26.0-mcp-dogfood` (`FormatGroupedReferenceLines`
omits null/`StartLine` ≤ 0). Compact inspect also prefers a leading signature
accessibility token when it disagrees with `symbols.visibility`.

**Stored `private`:** not a `record_struct_declaration` extract gap.

- Pinned `julie-extract` 2.38.1 writes `visibility=internal` on a fresh scan
  of `FullRebuildPromotion.cs` and of a tiny `internal readonly record struct`.
- Family-store epoch 7 still had `private` after `workspace full` (rev 62324 →
  62617, `swapped: no`). Every C# `internal…` signature at epoch 7 was stored

- Cause: BRE-16 changed C# `internal` to `Visibility::Internal` and marked

  Store import reuses a completed `(path, content_hash, epoch)` identity.
  `workspace full` in store mode therefore cannot rewrite those rows.
- Local repair on this family store (2026-08-31): `UPDATE symbols SET
  visibility='internal' WHERE language='csharp' AND visibility='private' AND
  signature LIKE 'internal%'` (13020 rows). Live MCP inspect then returned
  `visibility: internal` for `FileOperationRetryOptions`.
- Leftover `.miller/symbols.db` still says `private`; miller reads the family
  store, so inspect is correct. Product fix is F19.

### F12. Default `workspace list` hides the error row; filter cannot select by state

`workspace list` (default limit 20) ended with
`errors: 1 workspace(s) in error state — filter or raise limit to see them`

does not include this until the branch ships.

### F13. `workspace health` on an unreadable workspace is an MCP tool failure

Status for the same selector returns a compact payload (`store_failed`,
warnings). Health returns the same facts **and** the MCP layer marks the call
failed (`diagnostic_code=workspace_health_unavailable`). Agents treat that as
a crash instead of a usable unavailable health report.

Compact health on the live miller workspace itself was `usable_with_warnings`
and omitted `groups=6 unavailable=0 rows=160 warnings=2 actions=2`. The 2
capability-gap warnings are visible; the 160 omitted rows are not.

**Fix on `fix/v1.26.0-mcp-dogfood`:** unavailable health is a successful payload
(`verdict.state=unavailable`). It no longer attaches
`workspace_health_unavailable` or sets the MCP error channel. Live 1.26.0 MCP
does not include this until the branch ships. The compact omitted-row summary
is a separate compact-budget issue, not this MCP error.
