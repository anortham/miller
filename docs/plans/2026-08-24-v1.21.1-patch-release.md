# Miller v1.21.1 Patch Release Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use razorback:subagent-driven-development when subagent delegation is available.

**Goal:** Publish Miller v1.21.1 as a stable patch containing the verified Linux/Windows dogfood repairs since v1.21.0.

**Architecture:** This is a metadata-and-publication release over the already-verified Miller source tree. Producer pins remain unchanged. Package validation builds the full platform matrix once; promotion reuses that successful run.

**Tech Stack:** .NET 10, GitHub Actions, GitHub Releases, Claude/Cursor/Codex plugin manifests.

**Architecture Quality:** No architecture impact. Release prep changes version metadata, documentation, and verification evidence only.

## Global Constraints

- Stable version is exactly 1.21.1 and tag is v1.21.1.
- julie-extract stays 2.35.0.
- julie-semantic-sidecar stays 0.1.0.
- sqlite-vec stays 0.1.9.
- Every plugin manifest and marketplace version stays aligned with Directory.Build.props.
- The pushed prep commit and published GitHub release happen in the same working session.
- Do not use tag-push publication because the unpushed range touches .github/workflows/ci.yml.
- Do not overwrite an existing release.
- Reviewer choice: none.

## Verification Strategy

**Project source of truth:** AGENTS.md and docs/release-process.md.

**Worker red/green scope:** Version-alignment tests, release-note/map checks, plugin tests, and release metadata inspection.

**Worker ceiling:** Focused release/version/plugin tests only.

**Worker gate invariant:** Every advertised version is 1.21.1; release notes accurately describe the shipped fixes and unchanged pins.

**Lead affected-change scope:** Release metadata diff, README links, documentation map, plugin smokes, git state, and live GitHub facts.

**Branch gate:** Reuse exact-tree Release/Linux/Windows fast+Scale evidence where the source tree is unchanged; run final Release build, plugin tests/smokes, git diff check, and CLAUDE/AGENTS parity on the release-prep tree.

**Security scope:** security-secrets is gitleaks detect --source . --no-banner. security-deps is dotnet list Miller.slnx package --vulnerable --include-transitive. Any secret or high/critical dependency finding blocks publication.

**Replay/metric evidence:** Package validation and promotion workflow conclusions are hard gates. Four archives plus four checksum sidecars, stable release status, notes body, and version smoke are hard gates.

**Escalation triggers:** Any pin, workflow, package composition, or source-code change invalidates reused evidence and requires its owning specialist gate.

**Assigned verification failure:** Workers stop and report failures; the lead diagnoses and repairs before any push.

**Verification ledger:** Record command, SHA, result, timestamps, workflow run IDs, asset names, checksums, and release URL.

### Task 2: Verify release candidate

**Files:** Read-only, except corrections to Task 1-owned metadata.

**What to build:** Prove metadata alignment, documentation accuracy, plugin launch behavior, security gates, and clean release source control. Reuse source-tree test evidence only where later commits are metadata-only.

**Acceptance criteria:**
- [ ] Release build has 0 warnings and 0 errors.
- [ ] Version/plugin tests and plugin smokes pass.
- [ ] gitleaks reports no findings.
- [ ] Dependency audit reports no high/critical vulnerabilities.
- [ ] git diff check and CLAUDE/AGENTS parity pass.
- [ ] Main and release worktrees are clean and all intended commits are accounted for.

### Task 3: Integrate and push main

**Files:** Git refs and origin/main.

**What to build:** Fast-forward local main to the verified prep commit and push main. Do not leave origin/main advertising 1.21.1 without continuing immediately to publication.

**Acceptance criteria:**
- [ ] Local main and origin/main name the exact prep commit.
- [ ] No dirty, untracked, or stranded release work remains.

### Task 4: Validate, promote, and verify

**Files:** GitHub Actions and GitHub Release v1.21.1; add final release evidence locally only after live facts exist.

**What to build:** Dispatch release.yml with publish=false, wait for success, then dispatch publish=true with promote_run_id. Set the release body from v1.21.1 notes and verify the stable release plus eight assets.

**Acceptance criteria:**
- [ ] Package-only workflow succeeds for version 1.21.1.
- [ ] Promotion workflow succeeds using that run ID.
- [ ] v1.21.1 is stable, non-draft, and carries the notes file as its body.
- [ ] Four platform archives and four checksum sidecars exist and verify.
- [ ] Marketplace downloads resolve and Miller version smoke reports 1.21.1.
- [ ] Final release verification evidence is committed and pushed.
