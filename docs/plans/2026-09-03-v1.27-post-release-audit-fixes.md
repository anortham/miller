# v1.27 post-release audit fixes implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use razorback:subagent-driven-development when subagent delegation is available. Fall back to razorback:executing-plans for single-task, tightly-sequential, or no-delegation runs.

**Goal:** Repair the CT idle-drain upgrade loop found during v1.27.0 dogfooding and make compact Miller output the explicit agent default.

**Architecture:** Workspace-scope idle drains will reuse the existing provider-discovery path before rebuilding their selection. Agent guidance will state one shared format rule without changing tool schemas or output contracts.

**Tech Stack:** .NET 10, xUnit, Markdown, Node.js tests.

**Architecture Quality:** CT stays inside `ContinuousTestDaemonQueue` and its existing `RefreshInventoryIfNeededAsync` seam. The caller-facing interfaces do not change. Risk is medium because idle-drain discovery mutates persisted inventory; caller-level queue tests must prove stale inventory is refreshed before execution. Guidance has no architecture impact.

## Global constraints

- Preserve the existing CT rules for explicit runs, impact runs, red cases, and inventory seeds.
- Do not filter or silently discard provider results whose case IDs are absent from stale inventory.
- Use compact output by default. Request `format=json` only for machine-readable fields or chaining, and extract only the required fields.
- Keep `MILLER_AGENT_INSTRUCTIONS.md` at or below 1,900 characters and `hooks/miller-routing-block.md` at or below 3,000 characters.
- Do not add a new MCP tool or change an existing tool schema.

## Verification strategy

**Project source of truth:** `CLAUDE.md` testing rules and guidance-delivery budgets.

**Worker red/green scope:** Task 1 runs `dotnet test --filter "FullyQualifiedName~ContinuousTestIdleDrainTests"`. Task 2 runs `dotnet test --filter "FullyQualifiedName~AgentInstructionsTests"` and `node --test tests/plugin/hooks-routing-block.test.cjs`.

**Worker ceiling:** The assigned focused test classes and routing-block test only.

**Worker gate invariant:** Task 1 proves an idle drain refreshes provider inventory before selecting cases. Task 2 proves both guidance channels carry the compact-default rule and remain within size budgets.

**Lead affected-change scope:** Run both focused .NET classes and the routing-block Node test after integration.

**Branch gate:** `dotnet test` once on final HEAD. Run `scripts/test.sh scale` because CT execution changed.

**Security scope:** none declared.

**Replay/metric evidence:** Re-enable and start CT after the code fix, then confirm one full idle drain commits without SQLite FK failures or immediate retry. Runtime duration is report-only; zero FK failures and a terminal run are hard gates.

**Escalation triggers:** Any change outside the owned queue/guidance files, a new public interface, or a second behavioral fix requires plan review.

**Assigned verification failure:** Workers stop and report when assigned verification fails unless this plan explicitly updates that gate.

**Verification ledger:** Record invariant, command, scope, commit SHA, result, and timestamp. Reuse passing evidence only for the same HEAD and scope.
