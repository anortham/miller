# Miller v1.25.0 CT Review Fixes and Release Prep Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use razorback:subagent-driven-development when subagent delegation is available. Fall back to razorback:executing-plans for single-task, tightly-sequential, or no-delegation runs.

**Goal:** Close the verified CT review findings, prepare a verified Miller v1.25.0 candidate, and publish it through the repository's two-step validation and promotion flow after the user's explicit release approval.

**Architecture:** Keep each correction inside its existing provider/selection seam. Qmake argument encoding must fail closed or preserve values across make and the recipe shell; Vitest discovery must apply runner defaults whenever `exclude` is absent; Go impact scoping must consume the provider's persisted `gowork` identity instead of rereading manifests. Release prep is metadata and documentation over the verified source commit.

**Tech Stack:** .NET 10, xUnit, Qt qmake/Make, Vitest discovery patterns, Go workspace metadata, GitHub release metadata.

**Architecture Quality:** Medium risk in the qmake command boundary and low risk elsewhere. No new MCP surface or dependency is allowed; provider-specific behavior remains local to existing provider and selector modules.

## Verification Strategy

**Project source of truth:** `AGENTS.md`, `docs/continuous-testing.md`, and `docs/release-process.md`.

**Worker red/green scope:** One focused test or changed test class with `dotnet test --filter "FullyQualifiedName~<TestClassName>"`; each worker records the expected RED and GREEN outputs.

**Worker ceiling:** The worker-owned test class only. Workers do not run the fast, Scale, Windows, build, plugin, or security gates.

**Worker gate invariant:** The new regression fails on `4ebce0bb` for the reviewed defect, passes after the minimal correction, and the owned test class remains green.

**Lead affected-change scope:** The combined QML, JavaScript discovery, and impact-selector test classes plus `git diff --check` after Batch A.

**Branch gate:** `dotnet build Miller.slnx -c Release`; bare `dotnet test`; `scripts/test.sh scale`; local `win-test` fast suite on the clean committed candidate; focused version checks; `scripts/test-plugin.sh`; required Cursor-style launcher smokes; `cmp -s CLAUDE.md AGENTS.md`; and `git diff --check`.

**Security scope:** `security-secrets`: `gitleaks detect --source . --no-banner --log-opts=HEAD`. `security-deps`: `dotnet list Miller.slnx package --vulnerable --include-transitive`. Any secret finding or high/critical dependency finding blocks release readiness.

**Replay/metric evidence:** Test counts, Scale skips, Release build warning/error counts, Windows counts, plugin smoke results, pin versions, and version-alignment results are hard gates. Package validation/promotion IDs remain unavailable until push/release approval and are explicitly out of this local prep run.

**Escalation triggers:** CT provider changes require Scale. Manifest changes require plugin tests and both no-workspace and non-Miller-workspace launcher smokes. Any Windows-only failure requires focused `win-test` diagnosis before rerunning the Windows fast gate.

**Assigned verification failure:** Workers stop and report when assigned verification fails unless this plan explicitly says to update that gate.

**Verification ledger:** Record invariant, command, scope label, commit SHA, result, and timestamp. Reuse only evidence from the exact same HEAD.

### Task 1: Harden qmake `TESTARGS` encoding

**Files:**
- Modify: `src/Miller.Testing/Providers/Qml/QmakeQuickTestTooling.cs:60-90,309-318`
- Test: `tests/Miller.Tests/Testing/Providers/Qml/QmakeQuickTestToolingTests.cs:53-99`

**Interfaces:**
- Consumes: `QmakeQuickTestTooling.BuildCheckArguments(string, QtVersion, IEnumerable<string>?)` and qmake's `TESTARGS` make-variable contract.
- Produces: command arguments that cannot escape into recipe-shell syntax; unsupported path text is refused before make runs.

**Contract inputs:** The verified GNU Make reproduction using a legal path with backslash-plus-quote must no longer execute trailing shell text. Windows qmake may select nmake/jom/mingw make, so the fix must not claim one shell dialect is universal. Official contracts: Qt documents `make check TESTARGS="-o result.xml,junitxml"` at <https://doc.qt.io/qt-6/qmake-common-projects.html>; GNU Make requires `$$` for a literal recipe dollar at <https://www.gnu.org/software/make/manual/html_node/Variables-in-Recipes.html>; NMAKE has a different special-character grammar at <https://learn.microsoft.com/en-us/cpp/build/reference/contents-of-a-makefile?view=msvc-170>.

**File ownership:** `src/Miller.Testing/Providers/Qml/QmakeQuickTestTooling.cs`; `tests/Miller.Tests/Testing/Providers/Qml/QmakeQuickTestToolingTests.cs`

**Serialization required:** No

**Dependency reason:** None - safe parallel batch.

**What to build:** Add a caller-visible regression for the unsafe value and implement the smallest cross-platform fail-closed or correctly encoded boundary. Preserve normal paths, spaces, `$`, and backticks where the selected dialect can carry them without alteration.

**Approach:** Keep command construction write-free. Prefer a small explicit make/shell value encoder or an actionable refusal over partial backslash quoting. Do not add a shell process or a new provider abstraction.

**Acceptance criteria:**
- [x] A focused regression fails on the reviewed implementation and proves trailing command text cannot escape.
- [x] Normal result/import paths still render the expected qmake check arguments.
- [x] The qmake tooling test class passes and the change is handed to the lead under `parallel-lead-commit`.
