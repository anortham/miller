## Verification Strategy

**Project source of truth:** Julie `AGENTS.md` and `docs/release.md`; Miller `AGENTS.md`, `docs/release-process.md`, and `.github/workflows/release.yml`.

**Worker red/green scope:** Reuse the committed repair evidence and run release metadata preflight after each version bump.

**Worker ceiling:** No delegated workers; release operations are serialized in this session.

**Worker gate invariant:** Version metadata, release notes, package manifests, and pinned archive checksums name the exact published versions.

**Lead affected-change scope:** Julie formatting, xtask tests, default, contract, Clippy, release preflight, and package list; Miller Release build, fast suite, Scale suite, plugin/site contracts, pin restore, vulnerability audit, and diff checks.

**Branch gate:** Each repository's documented release gate on the exact commit pushed to `origin/main`, followed by live archive and checksum verification.

**Security scope:** `gitleaks detect --no-banner` when available; `cargo audit` for Julie and `dotnet list package --vulnerable --include-transitive` for Miller. High/critical dependency findings or any secret finding block publication.

**Replay/metric evidence:** Julie's 2:24.54 exact Miller-corpus replay and Miller's zero-delta no-rewrite tests are hard behavioral evidence; hosted workflow duration is report-only.

**Escalation triggers:** Any test failure, tag mismatch, missing archive, checksum mismatch, release-body mismatch, or marketplace version without matching assets blocks closeout and must be repaired before proceeding.

**Assigned verification failure:** Diagnose and repair failures; do not weaken gates or overwrite published assets.

**Verification ledger:** Record exact commits, workflow run IDs, archive checksums, release URLs, and gate results in release evidence and Goldfish checkpoints.
