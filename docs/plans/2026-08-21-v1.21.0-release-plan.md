# Miller v1.21.0 Release Plan

**Status:** planned 2026-08-21. Publication needs explicit user approval; nothing in this plan
publishes on its own.

**Scope:** 117 commits since the `v1.20.1` tag (`5cf2a52b`), 88 of them not yet pushed to
`origin/main`. HEAD at planning time: `3c8ab6ce`. Late additions expected before the prep commit:
the FindByName index-attribution instrumentation (open question 3) and the updated context-latency
findings doc.

**Version choice: 1.21.0 (minor).** The range ships new user-visible capability (the CT
watermark-freshness program, worktree adoption, the shadow-copy daemon) plus many fixes. Nothing
breaks an existing contract; `ct.db` migrates itself in place. Not a patch; not a major.

## What the release contains (release-notes outline)

- **Continuous testing: watermark freshness.** CT freshness is keyed on the index generation
  identity; a revision advance carries fresh green results forward and marks only the impacted
  set stale. Explicit runs retry every red case. Auto-runs debounce and fail closed on truncated
  impact. `ct.db` migrates automatically (shared selectors, one row per theory data row).
- **Continuous testing: family worktree adoption.** One family daemon adopts registered,
  opted-in linked worktrees; enablement inherits from the main checkout with a local tombstone
  opt-out; detach/stop records never recreate a removed worktree's control plane.
- **Continuous testing: daemon robustness.** The daemon runs from a private per-build shadow
  copy and never locks the install or build output. Build awareness compares versions
  numerically; a newer daemon is never replaced by an older build. A wedged main loop is
  reported from the record's own stamps (report only). A test process silent for 10 minutes is
  killed and its run failed. Windows hardening throughout.
- **Workspace lifecycle: store-sidecar reclaim.** `workspace remove`/`prune` reclaim the
  per-view content/search/vector sidecars a workspace pinned in the shared family store
  (crash-durable, race-safe, owed-record retries). This closes ~350-410 MB leaked per removed
  worktree. The julie-extract side (`store maintain retire-view`) ships separately.
- **Read-path latency.** Named-workspace reads serve the pinned view and refresh in the
  background (coalesced). `inspect`/`context`/`impact` serve a readable lagging search sidecar
  instead of rebuilding a projection. One-shot CLI reads load reference facts bounded, per file
  (byte-identical output; `MILLER_BOUNDED_FACTS=off` escape hatch). The context tool's
  whole-index linkage scan is gated behind a costless existence probe, and promotion reads are
  batched. Measured: CLI `context` 13.6 s to 7.2 s; CLI `inspect --depth overview` 4.9 s to
  1.1 s on this repo.
- **Telemetry honesty.** The status line reports a 7-day window, busiest and slowest tools, a
  drop signal, and reads one snapshot.
- **Pinned extractor:** julie-extract **2.34.1 → 2.34.4** (store-recovery hotfixes; view-id
  minting fixes on the Miller side).
- **Review hardening.** Two external codex review rounds (pre-merge + adversarial) resolved;
  security pass defects closed.

## Steps (per docs/release-process.md)

1. **Write release notes** `docs/release-notes/v1.21.0.md` (existing format: audience, release
   shape, pinned extractor, What Changed, Upgrade Notes, Verification). Move the
   `docs/README.md` "latest release notes" pointer.
2. **Prep commit** `release: prepare Miller v1.21.0`: bump `Directory.Build.props` `<Version>`,
   `miller-plugin.json`, `.claude-plugin/plugin.json`, `.claude-plugin/marketplace.json`,
   `.cursor-plugin/plugin.json`, `.codex-plugin/plugin.json`, plus the notes + map pointer.
3. **Push main.** LOAD-BEARING: the marketplaces serve manifests from `origin/main` HEAD, so
   the push makes updates advertise v1.21.0 immediately. The release must be published in the
   same working session.
4. **Validate packages:** `gh workflow run release.yml -f version=1.21.0 -f prerelease=false
   -f publish=false -f allow_overwrite=false`; wait for success.
5. **Promote the validated run:** same command with `-f publish=true
   -f promote_run_id=<run-id>`.
6. **Set the release body:** `gh release edit v1.21.0 --notes-file
   docs/release-notes/v1.21.0.md`.
7. **Verify:** four platform archives + four `.sha256` sidecars on the release; `miller
   version` smoke output in the workflow log; README current-release facts updated from the
   live release.

## Sequencing with the julie-extract retire-view work

Independent. Miller v1.21.0 ships against the already-released julie-extract 2.34.4 pin. The
`retire-view` verb lands in julie-extractors as its own release (2.35.0); Miller adopts it in a
later pin bump, together with any `workspace remove` integration. Do not hold v1.21.0 for it.

## Approval gate

The user must explicitly approve: (a) pushing the ~88 commits + prep commit to `origin/main`,
and (b) publishing the v1.21.0 release. Per CLAUDE.md, a pushed prep commit is a live
marketplace release — approval for (a) without (b) is not a valid state.
