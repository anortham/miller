**Security scope:** No new dependency, network, credential, authorization, or public mutation surface; verify `dotnet list package --vulnerable --include-transitive` and scan the diff for secrets-like additions before push.

**Replay/metric evidence:** Test counts and timings are report-only; zero failures, package checksums, archive smoke, and release asset presence are hard gates.

**Escalation triggers:** Any store-off byte change, stale legacy fallback, producer contract mismatch, store concurrency failure, or Windows file-handle failure expands verification to the relevant Scale/lifecycle tests.

**Assigned verification failure:** Workers diagnose and repair assigned failures; they do not weaken or skip gates.

**Verification ledger:** Record invariant, command, scope, commit, result, and timestamp in the release evidence document.
