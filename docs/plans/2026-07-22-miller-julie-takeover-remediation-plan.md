# Miller Julie Takeover Remediation Plan

> **For coding agents:** Execute in phase order. Use test-driven development for behavior changes, architecture-quality review for shared interfaces, and verification before every completion claim. A phase is complete only when its evidence gate passes.

**Goal:** Make Miller strictly better than Julie at delivering relevant, actionable code evidence with fewer calls, tokens, and wall-clock time, while preserving Miller's stronger lifecycle, contracts, content, structural-fact, bridge, and atomic-edit foundations.

**Architecture:** Keep the nine MCP tools. Deepen shared internals around exact reference evidence, typed diagnostics, candidate ranking, and bounded rendering. Consume parser facts from `julie-extract`; do not move extraction into Miller. Keep semantic retrieval local, optional, and generated by `julie-semantic-sidecar`.

**Decision cadence:** Evidence-gated, not calendar-gated. Run the paired Miller/Julie decision immediately after the implementation and platform gates pass; do not wait for an arbitrary multi-week canary.

**Primary evidence:** [`../findings/2026-07-22-miller-julie-takeover-matrix.md`](../findings/2026-07-22-miller-julie-takeover-matrix.md)

## Claude Review Requirement

The completed audit used one broad Claude review and nine fresh tool-specific Claude reviews. That requirement continues through implementation: a tool is not remediation-complete until a fresh Claude pass inspects that tool's diff, focused tests, contract changes, and evaluator evidence, and the lead classifies every material claim as accepted, corrected, rejected, or unproven against local evidence. The final gate repeats all nine tool-specific reviews and adds one broad architecture/evidence review; a single general review cannot substitute for them.

## Invariants

- `MILLER_SEMANTIC=off` remains a permanent zero-work path.
- Parser recognition and resolution emission remain in `julie-extractors`.
- `Miller.Core` remains pure and I/O-free.
- No new MCP tool is added by this plan.
- Every extractor-backed capability is gated across all supported languages.
- Compact output is bounded; JSON is deterministic and machine-readable on success, empty, refusal, and failure.
- Exact and fallback evidence are never blended without provenance.
- Existing Eros CLI/JSONL contracts remain compatible unless explicitly versioned.

## Completion Gates

| Gate | Requirement |
|---|---|
| Correctness | Exact-reference, caller, callee, impact-edge, and rename fixtures have no cross-homonym contamination. |
| Language | A committed all-language artifact report states exact/fallback coverage by language and identifier/relationship kind. |
| Retrieval | Miller meets or beats Julie on sealed nDCG@6, MRR, top-1, and true no-hit recovery. |
| Agent efficiency | Miller meets or beats Julie on calls, tokens, and wall time to first correct action, with no higher wrong-action rate. |
| Bounds | Compact context, impact, health, list, and content responses stay within their documented budgets. |
| Reliability | JSON requests always return valid JSON or a classified MCP error; no hard failure masquerades as success text. |
| Platform | Local semantic retrieval passes RC3 conformance and acceleration checks on macOS, Windows, and Linux. |
| Product | A sealed paired agent run supports retiring Julie without losing a Julie-only workflow. |
| Independent review | All nine tool-specific Claude implementation reviews and the broad final Claude review are recorded and locally validated. |

## Dependency Order

Execute the numbered phases in order: evaluator gap-close, exact symbol-ID reference evidence, typed diagnostics plus deterministic output-budget/continuation contracts, reference consumer and rename migration, shared search ranking/routing, bounded one-call context, risk-ranked impact, remaining-surface cleanup, all-language extractor coverage, RC3 completion, then the sealed paired decision and reviews.

Search remains before context because context consumes the shared ranking signals. RC3 protocol, package, and platform preflight may begin after Phase 0, but that early lane does not complete Phase 9 or choose the default model. Final BGE-small versus CodeRankEmbed selection remains after the Phase 4 search and Phase 5 context behavior gates pass.

## Architecture Quality

**Affected modules:** reference readers, repository graph, resolution, nine tool shells, search/context ranking, edit planning, telemetry/diagnostics, public contracts.

**Caller-facing interface:** the nine existing MCP tools plus existing CLI/JSONL contracts.

**Depth/locality:** exact/fallback policy, ranking, and diagnostics move into shared deep modules so tool shells stop knowing storage details.

**Test surface:** behavior is proved through each tool and public contract, with pure-core tests for ranking/dedup and Scale tests for real artifacts.

**Seams/adapters:** SQLite readers remain internal indexing adapters; semantic sidecar and extractor process boundaries remain existing owned seams.

**Rejected shortcuts:** per-tool reference patches, semantics inside reference truth, more MCP tools, stateful spillover, Julie's partial rename transaction, and calendar-based promotion.
**Architecture risk:** high, controlled by phase gates and compatibility tests.
