# Miller v1.18.3 Patch Release Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use razorback:subagent-driven-development when subagent delegation is available. Fall back to razorback:executing-plans for single-task, tightly-sequential, or no-delegation runs.

**Goal:** Correct semantic remediation guidance, publish matching documentation, and release Miller 1.18.3.

**Architecture:** Keep `VectorSidecarFacts` unchanged and narrow user guidance through the existing state plus reason evidence. Preserve pause-first classification. Release metadata remains synchronized across the build, plugin manifests, tests, documentation map, and release notes.

**Tech Stack:** .NET 10, xUnit, JSON plugin manifests, GitHub Actions and GitHub Releases.

**Architecture Quality:** Local behavior correction with medium output blast radius across CLI, MCP, and dashboard renderers; no new API, schema, module, dependency, or MCP tool.

## Global Constraints

- Version is exactly `1.18.3` and the release is stable.
- Recommend `miller semantic prepare` only for `model-not-prepared` or a genuinely absent vector artifact.
- Restart guidance is conditional on activation not reaching `activated`.
- Preserve the user-owned `TODO.md` change.
- Do not push release-prep metadata without publishing and verifying `v1.18.3` in the same session.

## Verification Strategy

**Project source of truth:** `AGENTS.md` and `docs/release-process.md`.

**Worker red/green scope:** Focused `VectorSidecarClassificationTests`, `WorkspaceVectorFactsRenderTests`, `WorkspaceRenderTests`, and `SemanticPrepareCliTests` filters.

**Worker ceiling:** Focused tests only; Sol owns broad release gates.

**Worker gate invariant:** Non-preparation failures never recommend model preparation; preparation and restart advice matches the actual activation result; version surfaces agree.

**Lead affected-change scope:** Miller impact review plus focused semantic tests and plugin tests.

**Branch gate:** `dotnet build Miller.slnx -c Release`, `scripts/test.sh`, `scripts/test.sh scale`, plugin/site/dependency/secrets/agent-doc/manifest/diff checks required by release evidence.

**Security scope:** Repository secrets scan and dependency audit commands from the existing release-candidate evidence.

**Replay/metric evidence:** Package workflow, archive checksums, package semantic smoke, and live release assets are hard gates; local wall time is report-only.

**Escalation triggers:** Any public contract change, pin change, workflow change, semantic soak failure, package failure, or mismatch among release versions.

**Assigned verification failure:** Workers stop and report when assigned verification fails unless the packet explicitly authorizes a test correction.

**Verification ledger:** Record command, scope, commit SHA, result, and timestamp in the release evidence/checkpoint.
